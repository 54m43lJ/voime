BUILD — Voime

README USER CORE PROVIDER

本文面向构建、安装、运行与排查 Voime 的开发者。产品行为、接口与内部实现分别以 USER、CORE 与各组件 PROVIDER 为准； 本文只重复构建入口、路径、命令与验证步骤。

1. 构建环境与产物

↑

项目要求 / 说明
Rust根 workspace 要求 rust-version = 1.92；rust-toolchain.toml 固定工具链，首次构建由 rustup 安装。
Cargo根 workspace、两个 GPU worker 与 Windows 前端各自使用独立 Cargo workspace / Cargo.lock。
Linux 核心依赖cc、make、pkg-config、ALSA 开发库、OpenSSL 开发库；voimed 需要音频设备与用户会话。
Fcitx5 addon额外需要 CMake、C++20 编译器、Fcitx5 开发包与 pkg-config；要求 Fcitx5 ≥ 5.1.23。
Linux 服务user systemd；安装脚本写入 ~/.config/systemd/user/voime.service。
Windows 核心Rust MSVC 工具链与 Windows SDK；Windows 前端使用 windows crate 与 eframe/egui。
Python仅安装期需要 Python 3.10+：scripts/install-core-models.py 与 scripts/install-gpu-models.py 负责模型下载、缓存与 schema 5 manifest 生成；运行期不需要 Python。
GPU 依赖FireRed 需要所选 ONNX Runtime GPU EP（CUDA / DirectML；Linux AMD 的 MIGraphX 当前无法编译固定图）；Qwen3 需要所选 llama.cpp backend（Vulkan / CUDA）及系统图形驱动。

  • FireRed 的 EP 在编译 feature 中固定：Linux / Windows NVIDIA 用 cuda，Windows AMD / Intel 用 directml；Linux AMD 的 migraphx 构建仍存在，但当前固定图在 MIGraphX 2.15 上编译失败，AMD Linux 应使用 Qwen3（Vulkan）。一次构建只包含一个 EP。
  • Qwen3 的 llama.cpp backend 在编译 feature 中固定：vulkan 或 cuda；AMD Linux 只使用 vulkan。
  • 独立 workspace 不参与根 cargo test --workspace；需要分别进入目录构建与测试。

2. 从源码运行

↑

2.1 核心与 CLI

# 构建
cargo build --release -p voimed -p voime

# 首次准备核心模型；--source-dir 指向包含 firered-vad / sensevoice-small 的离线目录
python3 scripts/install-core-models.py \
  --model-root "$HOME/.local/share/voime/models" \
  --source-dir /path/to/core-models \
  --no-download

# 直接运行 daemon（不安装 systemd 服务时）
target/release/voimed \
  --model-dir "$HOME/.local/share/voime/models" \
  --endpoint /tmp/voime-dev/voimed.sock \
  --verbose

# 另开终端连接
target/release/voime --endpoint /tmp/voime-dev/voimed.sock
target/release/voime ctl status --endpoint /tmp/voime-dev/voimed.sock
  • voimed 只从配置文件读取 [final].backend，没有 --backend 选项；默认 cpu。
  • 手动运行时的端点只影响当前进程；平台前端默认仍使用各自的默认端点。联调时请让前端与 daemon 使用同一端点。
  • 未安装 Fcitx addon 或 Windows 托盘时，仍可用 voime ctl 与 TUI 验证 daemon、音频、模型与 Final 后端。

2.2 GPU worker

# FireRed：按平台选择 feature
cd crates/voime-gpu-firered
cargo build --release --features cuda
# 或 --features migraphx / directml

# Qwen3：按平台选择 feature
cd ../voime-gpu-qwen3
cargo build --release --features vulkan
# 或 --features cuda

worker 由 voimed 按配置启动，不提供独立用户界面。安装时的 --source-dir/bin/ 可提供预编译 worker；否则安装脚本会在对应 crate 内按 runtime feature 构建。

2.3 Fcitx5 addon

cmake -S frontends/fcitx -B build/fcitx -DCMAKE_BUILD_TYPE=Release
cmake --build build/fcitx -j"$(nproc)"

# 仅 addon 需要 sudo；库与描述文件必须写入 Fcitx5 系统目录
LIBDIR="$(pkg-config --variable=libdir Fcitx5Core)"
sudo install -d "$LIBDIR/fcitx5" /usr/share/fcitx5/addon
sudo install -m 0755 build/fcitx/voime.so "$LIBDIR/fcitx5/voime.so"
sudo install -m 0644 build/fcitx/voime.conf /usr/share/fcitx5/addon/voime.conf

# 重启 Fcitx5，使系统 addon 生效
fcitx5 -r
  • Voime 不安装 inputmethod/voime.conf，也不加入输入法组；它只作为系统 addon 后台加载。
  • addon 不读取用户目录，不设置 FCITX_ADDON_DIRS；不要用用户级前缀替代系统安装。
  • 没有可用 Fcitx UI 时临时窗口不显示，但 commitString 提交仍正常。

2.4 Windows 前端

cd frontends/windows
cargo build --release
# 产物：frontends/windows/target/release/voime-tray.exe
  • Windows 前端是独立桌面进程；托盘是 voimed.exe 的唯一所有者，退出托盘会停止 daemon。
  • 前端不加载模型、不感知 Final 后端；GPU worker 由 voimed 启动。
  • 可选 TSF 子工程不参与默认安装；未启用 TSF 时不影响托盘听写。

3. 安装

↑

3.1 Linux 核心安装

选项 / 环境变量行为
--prefix <dir>用户安装前缀，默认 $HOME/.local；可执行文件写入 <prefix>/bin。
--model-dir <dir>模型根目录，默认 ${XDG_DATA_HOME:-$HOME/.local/share}/voime/models。
--source-dir <dir>核心模型离线源；隐含 --no-download。
--no-addon跳过系统 Fcitx5 addon；不申请 addon 安装权限。
--no-models跳过核心模型安装。
--no-service不安装 user systemd 服务。
--install-deps在 Arch Linux 上通过 pacman 安装缺失依赖；其他发行版只提示手工检查。
--uninstall删除核心二进制、addon 与服务；模型目录保留。
VOIME_PREFIX / VOIME_MODEL_ROOT分别覆盖默认前缀与模型根目录。
# 完整核心安装
scripts/install-core.sh

# 无系统 addon 的桌面/CI 安装
scripts/install-core.sh --no-addon

# 离线模型安装
scripts/install-core.sh --source-dir /path/to/core-models

# 卸载核心（保留模型）
scripts/install-core.sh --uninstall
  • addon 安装失败或拒绝 sudo 时安装失败并提示 --no-addon；不会静默改写到用户目录。
  • 核心模型缺失或校验失败会让 daemon 启动失败；GPU 模型 / runtime 缺失只让对应 Final 后端不可用。
  • 安装后重启 voimed 与 Fcitx5；用 voime ctl status 与 voime doctor 验证。

3.2 Windows 核心安装

参数行为
-Prefix <dir>默认 %LOCALAPPDATA%\Programs\Voime；托盘、daemon 与 CLI 安装到同一目录。
-ModelDir <dir>默认 %LOCALAPPDATA%\voime\models。
-SourceDir <dir>核心模型离线源；通过 Python 模型安装器校验并生成 manifest。
-NoModels跳过核心模型安装。
-Uninstall删除核心可执行文件与当前用户启动项；模型目录保留。
powershell -ExecutionPolicy Bypass -File scripts/install-core.ps1
powershell -ExecutionPolicy Bypass -File scripts/install-core.ps1 -NoModels
powershell -ExecutionPolicy Bypass -File scripts/install-core.ps1 -SourceDir D:\voime-core-models
powershell -ExecutionPolicy Bypass -File scripts/install-core.ps1 -Uninstall
  • 安装脚本写入当前用户 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 的 Voime 值，启动 voime-tray.exe；不使用 Session 0 服务。
  • 未提供 -SourceDir 时，模型安装需要 Python 3.10+；运行期仍不需要 Python。

3.3 GPU 模块安装

选项LinuxWindows
安装范围--firered / --qwen3；不指定时两者都安装。-Firered / -Qwen3；不指定时两者都安装。
FireRed runtime--firered-runtime cuda|migraphx；Linux 拒绝 directml。AMD Linux 的 migraphx 当前会被启动自检拒绝，建议改用 Qwen3。-FireredRuntime cuda|directml；未指定时按显卡厂商选择。
Qwen runtime--qwen-runtime vulkan|cuda；AMD Linux 只接受 vulkan。-QwenRuntime vulkan|cuda。
后端选择--backend cpu|firered|qwen3；只写配置，不热切换。-Backend cpu|firered|qwen3；只写配置。
模型默认下载并缓存；开始前显示体积并要求确认。选项：--yes / --model-dir / --source-dir / --no-models。默认下载并缓存；开始前显示体积并要求确认。选项：-Yes / -ModelDir / -SourceDir / -NoModels。
卸载--uninstall；只删除选中的后端、runtime 与模型目录。-Uninstall；同样只删除选中后端。
# Linux：只装 FireRed，NVIDIA CUDA；模型下载前会要求确认
scripts/install-gpu.sh --firered --firered-runtime cuda

# 非交互安装：跳过模型下载确认
scripts/install-gpu.sh --firered --firered-runtime cuda --yes

# Linux：安装 Qwen，AMD Vulkan
scripts/install-gpu.sh --qwen3 --qwen-runtime vulkan

# 离线模型包：不联网，从 --source-dir// 读取
scripts/install-gpu.sh --firered --source-dir /path/to/gpu-models

# 安装后显式选择 Final，重启 daemon 生效
scripts/install-gpu.sh --firered --backend firered
systemctl --user restart voime.service

# 卸载 FireRed，不影响 Qwen 与核心
scripts/install-gpu.sh --firered --uninstall
  • GPU 安装脚本要求核心已安装；缺少核心时失败，不创建孤立 GPU 模块。
  • 安装 GPU 模块不会自动切换 final.backend；必须显式使用 --backend 或 voime ctl backend。
  • 未指定 --source-dir 时，模型由 scripts/install-gpu-models.py 从固定上游 revision 下载并缓存；存在同文件的 ModelScope 镜像时优先 ModelScope，否则回退 Hugging Face。公开模型使用匿名直链，不需要账号；也可通过 MODELSCOPE_API_TOKEN / HF_TOKEN（及常见别名）提供 token，交互安装缺失时会提示输入，可回车跳过。开始前显示体积并要求确认，--yes 跳过确认与 token 提示。指定 --source-dir 时只复制离线包，不联网。
  • 离线模型包放在 --source-dir/<model-id>/，可选预编译 worker 放在 --source-dir/bin/，可选 FireRed ORT runtime 放在 --source-dir/runtime/firered/。没有预编译包时脚本会在对应 crate 内按 runtime feature 构建；安装脚本不再回退到仓库根目录的 models/。
  • FireRed 的 ORT 动态库与所选 EP provider 复制到 <prefix>/lib/voime/firered/；daemon 只对 worker 子进程设置 ORT_DYLIB_PATH 与库搜索路径，不写全局环境。

3.4 模型准备

模型目录所属安装来源 / 说明
firered-vad/核心install-core-models.py；包含 manifest.json、ONNX 权重与可选 cmvn.ark。
sensevoice-small/核心install-core-models.py；包含 manifest.json、int8 ONNX 与 tokens.txt。
fireredasr2-aed/FireRed默认由 install-gpu-models.py 下载、缓存并生成 manifest；--source-dir 时从离线包复制。
fireredpunc/FireRed同上；随 FireRed 模块安装。
qwen3-asr-1.7b/Qwen3同上；BF16 主模型与 BF16 mmproj 必须同版本。
# 核心模型安装器的独立用法
python3 scripts/install-core-models.py \
  --model-root "$HOME/.local/share/voime/models" \
  --cache-dir "$HOME/.cache/voime" \
  --source-dir /path/to/core-models \
  --no-download

# 强制重新生成 manifest 与复制文件
python3 scripts/install-core-models.py --model-root /path/to/models --force
  • 模型根目录下是一模型一目录；目录名是稳定标识，版本写在 manifest.json，不拼进目录名。
  • 运行期只读；启动时校验 schema 5、目录 id、kind、文件大小与 SHA-256。
  • 仓库不提交权重文件，安装脚本也不从仓库根目录的 models/ 取模型；默认下载会生成 schema 5 manifest.json。离线源目录中的每个模型目录必须自带同版本 manifest。

4.1 systemd 用户服务

systemctl --user daemon-reload
systemctl --user enable --now voime.service
systemctl --user status voime.service
systemctl --user restart voime.service

# 查看服务日志（需先设置 VOIME_LOG）
journalctl --user -u voime.service -f
  • 服务文件由 packaging/linux/voime.service 生成，@BINDIR@ 替换为用户安装前缀下的 bin。

5. 验证与测试

↑

目标命令 / 检查
核心与共享 cratecargo test --workspace
FireRed workercd crates/voime-gpu-firered && cargo test --features cuda
Qwen3 workercd crates/voime-gpu-qwen3 && cargo test --features vulkan

voime ctl start

6. 升级、卸载与排查

↑

6.1 升级

# Linux 核心：重新构建并安装，然后重启服务
scripts/install-core.sh
systemctl --user restart voime.service

# Fcitx addon 更新后重启 Fcitx5
fcitx5 -r

# Windows 核心：重新运行安装脚本，退出并重新启动托盘
powershell -ExecutionPolicy Bypass -File scripts/install-core.ps1
  • 升级 addon 后旧 Fcitx 进程仍加载旧 voime.so；必须重启 Fcitx5。
  • 升级 daemon 后旧进程仍运行旧二进制；必须重启 voime.service 或托盘。

6.2 卸载

scripts/install-core.sh --uninstall                 # Linux 核心；模型保留
scripts/install-gpu.sh --firered --uninstall        # Linux：只删 FireRed
scripts/install-gpu.sh --qwen3 --uninstall          # Linux：只删 Qwen

powershell -ExecutionPolicy Bypass -File scripts/install-core.ps1 -Uninstall
powershell -ExecutionPolicy Bypass -File scripts/install-gpu.ps1 -Firered -Uninstall
powershell -ExecutionPolicy Bypass -File scripts/install-gpu.ps1 -Qwen3 -Uninstall

6.3 排查

现象检查 / 处理
daemon 启动失败查看 stderr / voime doctor；确认两个核心模型目录与 manifest / SHA 校验通过，音频设备存在。
daemon 已运行启动第二个 daemon 会幂等退出；用 voime ctl status 或端点连接确认。
GPU Final 未生效确认 final.backend 不是 cpu，对应 worker 与模型已安装；voime doctor 查看 worker 状态；重启 daemon。
FireRed 在 AMD Linux 不可用固定 ONNX 图当前无法被 MIGraphX 编译；doctor 会显示启动自检失败。改用 --qwen3 / final.backend = qwen3，等待 MIGraphX 或模型更新。
GPU 崩溃 / 显存不足当前段回退 CPU SenseVoice；查看日志中的错误码；修复 worker / runtime 后重启 daemon。
Fcitx 热键无效确认 Fcitx5 运行、系统 addon 描述与 voime.so 存在、ABI 匹配；重启 Fcitx5；voime doctor 的 fcitx 段。
Windows 热键无效确认托盘已连接 daemon、热键注册未被系统占用；查看托盘状态与日志；必要时重新录制热键。
目标失焦不提交行为符合契约；最终文本保留在 daemon 历史与 TUI，可重新聚焦后重试。
没有日志文件设置 VOIME_LOG=1 或自定义目录后重启对应进程；检查目录权限与磁盘空间。
addon 安装失败确认 Fcitx5 ≥ 5.1.23、开发包与 CMake 存在；拒绝 sudo 时使用 --no-addon 跳过。
  • 不要把日志中的识别文本当作可公开内容；正常日志只记录长度、耗时、错误码与后端名。
  • 任何失败都不得把文本注入到非目标窗口；无法确认目标时保留历史，不重试其他窗口。
  • GPU 失败只影响 Final；VAD、Preview 与 CPU Final 仍可用。
