BUILD — Voime

README USER CORE PROVIDER

1. 环境

↑

项目要求
平台AMD x86_64 Linux 或 Windows；验收平台为 AMD x86_64 CPU。
Ruststable 工具链（rust-toolchain.toml）。首次构建需要网络下载 crate 与 ONNX Runtime 预编译库。
Linux 构建依赖ALSA 开发头文件；Arch：alsa-lib；Debian / Ubuntu：libasound2-dev。
Linux 安装依赖Python 虚拟环境支持；Debian / Ubuntu 需要 python3-venv。
模型安装期Python 3.10+、网络与磁盘空间；只用于 scripts/install_models.* 与 tools/，不进入运行时。
运行期无需网络、GPU、Python 或系统输入法框架；需要 TTY、UTF-8、ANSI 转义与可用录音设备。

2. 构建

↑

cargo build --release
产物说明
target/release/voime（Windows voime.exe）完整应用；ONNX Runtime 随 ort 构建时链接进可执行文件。
模型包由安装脚本生成在用户数据目录，不进入版本库；应用只读。
  • 构建过程通过 ort 的 download-binaries 获取 ONNX Runtime；构建完成后运行期不联网。
  • 发布时只需分发可执行文件与模型包；不要分发 target/ 或安装虚拟环境。
  • 若 ONNX 使用 external data，模型目录中的 *.data 或分片文件必须与 .onnx 一起复制，否则会话加载失败。

3. 安装模型

↑

# Linux
scripts/install_models.sh

# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -File scripts\install_models.ps1
行为契约
默认目录Linux $XDG_DATA_HOME/voime/models（未设置时 ~/.local/share/voime/models）；Windows %LOCALAPPDATA%\voime\models。
虚拟环境Linux ~/.cache/voime/venv；Windows %LOCALAPPDATA%\voime\cache\venv。依赖见 tools/requirements-export.txt。
网络下载 FireRed 官方权重与 FireRedASR2S 源码；完成后应用离线运行。
磁盘下载缓存约 5 GB；默认 int8 模型包约 1.3 GB。FP32 导出包更大。
安装方式在目标目录同盘创建临时目录，导出、校验、写 manifest.json 后原子替换。
量化默认导出并动态量化为 int8；量化后优先把 external data 内联成单个 .onnx，无法内联时保留分片并随主文件一起复制，同时清理不再被引用的旧分片。--no-quantize 可保留 FP32。
# 常用参数
scripts/install_models.sh --model-dir /path/to/models
scripts/install_models.sh --source-dir /path/to/official/weights
scripts/install_models.sh --no-quantize

# 单独校验已有模型包（会重写 manifest.json）
~/.cache/voime/venv/bin/python tools/verify_models.py --model-dir /path/to/models
# Windows
%LOCALAPPDATA%\voime\cache\venv\Scripts\python.exe tools\verify_models.py --model-dir C:\path\to\models
  • --source-dir 目录需包含 FireRedASR2-AED/ 与 FireRedPunc/；若同时提供 FireRedVAD/pretrained_models/onnx_models/ 则跳过 VAD 下载。
  • 需要从 HuggingFace 下载且未检测到 HF_TOKEN 时，安装脚本会警告并提示输入；直接回车或非交互环境会继续未认证下载。输入的 token 只用于当前进程，不写入磁盘。
  • 模型包内容与张量契约见 PROVIDER §4.2；安装脚本不写入用户音频或识别历史。

4. 运行

↑

target/release/voime                       # PTT 模式
target/release/voime --mode continuous     # 持续监听
target/release/voime --input-device "USB Microphone"
target/release/voime --threads 4
现象处理
模型清单格式错误 / 模型文件缺失 / 校验失败重新运行安装脚本；确认 --model-dir 指向包含 manifest.json 的目录。
终端不可用必须从真实终端启动；重定向 stdin / stdout 时不会进入 TUI。
没有可用输入设备 / 未找到输入设备检查系统录音设备；设备名必须与操作系统暴露的名称完全一致。
剪贴板初始化失败Linux 需要 X11 或支持 wayland-data-control 的 Wayland 合成器；无剪贴板环境时应用拒绝启动。

5. 测试

↑

cargo test
cargo clippy --all-targets
cargo fmt --all --check
~/.cache/voime/venv/bin/python tools/verify_models.py --model-dir <DIR> --no-write
  • tests/segmenter.rs 覆盖端点、静音自动结束与最大段长（MaxDuration）；tests/clipboard.rs 覆盖会话文本拼接。
  • 模型包校验包含 SHA-256、张量名称、类型、形状与真实 ONNX Runtime 推理；不含音频内容。
  • 开发中发现的文档未覆盖细节与实现差异见 IMPL.md。

6. 发布检查

↑

cargo build --release
target/release/voime --help
target/release/voime --version
scripts/install_models.sh
  • 发布包应包含可执行文件、scripts/、tools/ 与安装说明；模型权重由安装脚本按需下载。
  • 运行验收：PTT 下一段识别、空语音段、静音自动结束、continuous 切分、剪贴板覆盖、滚动与退出终端恢复。
  • 长语音（>10 s）应正常分成多段；PTT 按住期间不丢后续语音。
