BUILD — Voime

README USER CORE PROVIDER

根 BUILD 负责多构建根编排、从源码安装、共享模型安装与发布。单个 crate 或前端的构建、测试与安装细节 在其自己的 BUILD 中维护；本文只保留跨构建根的步骤。

1. 环境

↑

项目要求
平台Linux + Fcitx5（当前验收平台）；Windows 10 / 11 x64（P2 / P3 已实现）。
Fcitx5≥ 5.1.23，运行中；fcitx5-configtool 用于配置 Mode / Hotkey；没有模型选择项。
Ruststable 工具链（rust-toolchain.toml）；首次构建需要网络下载 crate 与 ONNX Runtime。
Linux 构建依赖ALSA 开发头文件；Arch：alsa-lib；Debian / Ubuntu：libasound2-dev。
addon 构建依赖C++20、CMake、Fcitx5Core 开发头文件；Arch：fcitx5；Debian / Ubuntu：libfcitx5core-dev 等，按发行版为准。
Windows 构建依赖Rust MSVC 工具链、Visual Studio / Windows SDK、CMake（TSF 可选阶段）。x86_64-pc-windows-gnu 没有 ONNX Runtime 预编译包；daemon / CLI 的构建与验收以 MSVC 为准。
模型安装期Python 3.10+、网络；默认 VAD + SenseVoice 约 229 MiB，--gpu 另加 FireRed FP16 约 2.2 GB 与 Punc；只用于 scripts/install_models.* 与 tools/。
GPU 可选依赖Linux AMD：ROCm 7.2.1 + MIGraphX（P0）；Windows AMD：DirectML；NVIDIA：独立 CUDA / TensorRT runtime 包。基础安装与 CPU 路径不需要这些依赖。
运行期平台前端加载、voimed 运行中、可用录音设备；voime TUI 需要 TTY；daemon 不需要 TTY。
运行期不需要网络、Python 或独立输入法前端；默认不需要 GPU。Windows 设置窗口使用 OpenGL（glow）渲染。

  • 构建过程通过 ort 的 download-binaries 获取 ONNX Runtime；构建完成后运行期不联网。

3. 从源码安装

↑

以下步骤从干净检出的仓库开始，安装 voimed、voime、Fcitx5 addon、 systemd 用户服务与固定模型目录。默认把二进制安装到 ~/.local/bin，把 addon 安装到 /usr 前缀；所有命令在仓库根目录执行。

3.1 准备构建环境

↑

依赖用途 / 安装包示例
Rust stablerust-toolchain.toml；首次构建需要网络下载 crate 与 ONNX Runtime。
ALSA 开发头文件Arch：alsa-lib；Debian / Ubuntu：libasound2-dev。
C++20 / CMake / Fcitx5CoreArch：fcitx5；Debian / Ubuntu：libfcitx5core-dev 等。
Python 3.10+ 与网络仅用于安装模型；运行期不需要网络或 Python。

3.2 构建并安装 Rust 二进制

↑

cargo build --release -p voimed -p voime

# 安装到 ~/.local/bin，并生成 ~/.config/systemd/user/voime.service
scripts/install_voimed.sh --no-build
scripts/install_voime.sh --no-build

根 scripts/install_*.sh 是 packaging/linux/install_*.sh 的入口； 首次构建可省略 --no-build，由安装脚本重新执行 release 构建。

脚本默认行为
scripts/install_voimed.sh安装 voimed 到 ~/.local/bin，并从 packaging/linux/voime.service 生成 systemd 用户服务。
scripts/install_voime.sh安装 voime（TUI / ctl / doctor）到 ~/.local/bin。
  • 自定义前缀：scripts/install_voimed.sh --prefix /usr/local；ExecStart 会替换为实际的 $BINDIR/voimed。
  • 不安装 systemd：scripts/install_voimed.sh --no-systemd，之后手动运行 ~/.local/bin/voimed。
  • 也可以手动安装：install -Dm755 target/release/voimed ~/.local/bin/voimed 与 install -Dm755 target/release/voime ~/.local/bin/voime。
  • 手动安装 systemd 用户服务：install -Dm644 packaging/linux/voime.service ~/.config/systemd/user/voime.service；默认 unit 使用 %h/.local/bin/voimed。

3.3 构建并安装 Fcitx5 addon

↑

cmake -S frontends/fcitx -B build/fcitx -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build/fcitx
sudo cmake --install build/fcitx

安装结果包含 voime.so 与 addon 描述文件；addon 不注册 inputmethod 条目， 因此不需要把 Voime 加入输入法组。

  • 只重新编译、不安装：cmake --build build/fcitx；产物为 build/fcitx/voime.so。
  • 使用 /usr/local 前缀时，确认 Fcitx5 会搜索该前缀下的 addon 与库。

3.4 安装模型

↑

# 默认：VAD + SenseVoice；Final 走 CPU

项目契约

登录启动写入 HKCU\Software\Microsoft\Windows\CurrentVersion\Run；-NoStartup 跳过。

4. 安装模型

↑

# Linux：默认 VAD + SenseVoice
scripts/install_models.sh

# 追加 FireRed AED + Punc；重启 voimed 后自动尝试 GPU Final
scripts/install_models.sh --gpu --punc-source-dir /path/to/fireredpunc
scripts/install_models.sh --gpu --punc-source-dir /path/to/fireredpunc \
    --source-dir /path/to/exported/aed --aed-version v2

# 指定模型根目录 / 缓存目录
scripts/install_models.sh --model-root /path/to/models
scripts/install_models.sh --gpu --model-root /path/to/models \
    --punc-source-dir /path/to/fireredpunc

# 可选 GPU runtime
scripts/install_runtime.sh --runtime linux-migraphx

# Windows
powershell -ExecutionPolicy Bypass -File scripts\install_models.ps1
powershell -ExecutionPolicy Bypass -File scripts\install_models.ps1 -ModelDir D:\voime\models
powershell -ExecutionPolicy Bypass -File scripts\install_models.ps1 -Gpu -PuncSourceDir D:\fireredpunc
powershell -ExecutionPolicy Bypass -File scripts\install_models.ps1 -Runtime windows-directml
行为契约
固定目录模型根目录下只有四个固定子目录：vad、sense-voice、fire-red-aed、punc。每个目录一份 manifest.json；没有 active 文件、package_id 或“模型包”目录层。
默认安装tools/install_models.py 只写入 vad + sense-voice，对应 CPU Final。Linux 入口 scripts/install_models.sh；Windows 入口 scripts/install_models.ps1。
GPU 安装--gpu（Windows -Gpu）额外写入 fire-red-aed 与 punc。Linux 需要 --punc-source-dir 指向导出的 FireRedPunc 目录；--source-dir 可指定本地导出的 AED v2。
默认目录Linux：$XDG_DATA_HOME/voime/models（未设置时 ~/.local/share/voime/models）；Windows：%LOCALAPPDATA%\voime\models。
Windows 缓存scripts/install_models.ps1 在 %LOCALAPPDATA%\voime\cache 创建 Python venv，并按 requirements 文件的 SHA-256 哈希复用已安装依赖；-CacheDir 可覆盖。
VADvad/manifest.json + vad/stream-vad.onnx；kind 为 vad。
SenseVoicesense-voice/manifest.json + sense-voice/model.int8.onnx + sense-voice/tokens.txt；kind 为 sense-voice；固定 use_itn=true、内置标点。
FireRed AEDfire-red-aed/manifest.json + encoder.fp16.onnx + decoder.fp16.onnx + tokens.txt；kind 为 fire-red-aed。临时默认官方 v1 FP16 包 sherpa-onnx-fire-red-asr-large-zh_en-fp16-2025-02-16（7832 tokens，decoder self KV cache 固定 1024）；v2 FP16 为 8667 tokens，可通过 --aed-version v2 / -AedVersion v2 选择。
Puncpunc/manifest.json + model.onnx + vocab.txt + labels.json；kind 为 punc；只服务 GPU Final。
Manifestschema 3；kind 必须与目录名对应；每份清单只描述本目录的文件、SHA-256、张量与参数；没有跨目录的 requires 或 backend。
加载选择vad 与 sense-voice 始终加载；fire-red-aed 与 punc 两个目录都存在时尝试 GPU Final；只存在一个时启动失败并报告安装不完整；两个都不存在时使用 CPU Final。
GPU runtime按 OS + EP 拆分：voime-gpu-linux-migraphx / voime-gpu-windows-directml / voime-gpu-linux-cuda / voime-gpu-windows-cuda；独立目录、版本与 SHA，安装需显式 opt-in。
磁盘VAD + SenseVoice 约 229 MiB；FireRed FP16 约 2.2 GB，Punc 另计；runtime 包单独计量；空间不足时安装失败。
原子安装在模型根目录下的临时目录准备文件、计算 SHA-256、写 manifest，再替换目标子目录；模型目录不允许自带可执行文件。
  • 模型权重不提交到仓库；安装脚本只写入用户数据目录。
  • 仓库内 models/*/manifest.json 是结构模板，SHA-256 为全零且模型文件不完整；必须先运行安装脚本生成真实模型文件。
  • tools/install_models.py 组合调用 install_vad.py、install_sensevoice.py、install_firered.py 与 install_punc.py；tools/verify_models.py 按固定目录校验 schema / kind / SHA / token_count。
  • 安装不写任何选择指针；重启 voimed 才会重新扫描目录并决定 CPU / GPU Final。GPU 初始化失败时 daemon 自动回退 CPU SenseVoice。
  • 模型目录内容与张量契约见 voime-core PROVIDER §4.2 与 voime-gpu PROVIDER §4.2。

5. 运行

↑

# 1. 启动 daemon（推荐 systemd user service）
systemctl --user daemon-reload
systemctl --user enable --now voime.service

# 2. 安装 / 更新 addon 后重启 Fcitx
fcitx5 -r

# 3. 确认 addon 已在 Addons 页面加载；不需要加入输入法组
fcitx5-configtool

# 4. 可选 TUI / 控制 / 诊断
voime
voime ctl status
voime doctor

# 5. 安装 / 替换模型后重启 daemon，重新加载固定目录
systemctl --user restart voime.service

# Windows：托盘以子进程托管 daemon，启动托盘即可；手动启动仅用于无托盘排障
# （托盘启动时会停止已有 daemon 并替换为自己的子进程）
"%LOCALAPPDATA%\Programs\Voime\voime-tray.exe"
"%LOCALAPPDATA%\Programs\Voime\voime.exe" ctl status
"%LOCALAPPDATA%\Programs\Voime\voime.exe" doctor
现象处理
Fcitx Addons 页面没有 Voime确认 addon 描述文件安装到 Fcitx 前缀；重启 Fcitx；检查 voime.so 的 ABI / 依赖。
热键没有反应确认 Mode / Hotkey 已加载；热键未被 Fcitx trigger 或合成器绑定；当前窗口有文本焦点。
没有临时文本窗口确认 Fcitx UI addon 正在运行；当前 UI 可能不渲染 preedit；不影响最终提交。
最终文本没有上屏确认目标输入框在录音期间没有失焦；查看 voime doctor 与 Fcitx 日志。
daemon 未启动systemctl --user status voime.service；检查模型、音频与端点错误。
模型错误重新运行安装脚本；确认 vad 与 sense-voice 目录各有 manifest.json 与模型文件；GPU 安装后 fire-red-aed 与 punc 必须同时存在。
GPU Final 不可用确认 GPU runtime、驱动与显存；voime doctor 查看 worker 状态；Final 会自动回退 CPU SenseVoice。
没有录音设备检查系统录音设备；--input-device 必须精确匹配设备名。
  • voimed 不需要 WAYLAND_DISPLAY 或 DISPLAY；平台前端负责输入集成。
  • scripts/install_voimed.sh 生成 ~/.config/systemd/user/voime.service，并把 ExecStart 替换为实际 $BINDIR/voimed。
  • voime doctor 默认检查模型根目录下的四个固定目录与 /usr、/usr/local 下的 addon；目录缺失、SHA 不匹配或 FireRed / Punc 不成对都会报告。
  • TUI 的 q / Ctrl+C 只 detach；停止 daemon：Linux 使用 voime ctl quit 或 systemd，Windows 退出托盘即停止。
  • Windows 不使用 Session 0 服务；命名管道按当前会话与用户隔离，托盘以子进程托管 daemon，退出托盘即停止。

6. 测试与验收

↑

cargo test
cargo clippy --all-targets
cargo fmt --all --check

cmake --build build/fcitx
ctest --test-dir build/fcitx --output-on-failure

# Windows
cargo test --workspace
cargo test --manifest-path frontends\windows\Cargo.toml
cargo clippy --workspace --all-targets
cargo clippy --manifest-path frontends\windows\Cargo.toml --all-targets
  • tests/segmenter.rs 覆盖端点、静音自动结束、最大段长与预卷；tests/ipc.rs 覆盖握手 / 角色 / Mode / framing / 协议 4；tests/state.rs 覆盖快照默认值、清空历史与 status；tests/daemon.rs 覆盖 socket 存活、断线角色与 GPU 回退；tests/asr_sense_voice.rs 覆盖 CMVN / token id / greedy；10–60 s 真实解码仅在设置 VOIME_ASR_MODEL_DIR 时执行。
  • 清单测试覆盖 schema 3、四个固定目录的 kind、SHA 与 token_count；GPU / worker 测试用专用 runner 启用。
  • frontends/fcitx/tests 覆盖 mode / 热键字符串 / IPC 枚举 / target 空引用；不覆盖真实 Fcitx keymatch 或 preview 渲染。
  • RTF 验收参考（2 threads）：10 s ≤ 1.0 s、20 s ≤ 2.0 s、30 s ≤ 3.0 s；GPU 验收另见第 7 节。
  • 手工验收需同时在原生 Wayland、XWayland / XIM 与支持 text-input 的终端中测试热键、临时窗口与提交；Toggle 无语音时应出现空白窗口并保持到 toggle off 或目标失焦。
  • Windows 验收矩阵见 windows BUILD §4；frontends/windows 单测覆盖热键解析、配置、UTF-16 分块、UIA 目标标识与命名管道客户端握手。
  • CPU 隔离验收：在无 GPU runtime 的机器上启动，ldd / Process Explorer / /proc/<pid>/maps 不出现 GPU 库；移除 runtime 后 SenseVoice Preview 与 CPU Final 仍可用。

8. 升级 / 卸载

↑

操作步骤
升级 Fcitx重新编译并安装 voime.so；重启 Fcitx；确认 addon ABI，且输入法组中没有 Voime。
升级 Voime（Linux）停止 daemon；重新运行 scripts/install_voimed.sh / scripts/install_voime.sh；重新安装 addon 后重启 daemon 与 Fcitx。
模型升级默认 clean install：重新运行 scripts/install_models.sh（GPU 目录再加 --gpu），然后重启 voimed；旧 schema / 旧目录布局直接拒绝。上一版本可手工运行一次性 scripts/migrate-asr-v2.sh，安装器不检测、不调用。
配置迁移旧版本无后缀的 ~/.config/fcitx5/conf/voime 会在 addon 启动时迁移到 voime.conf，然后删除旧文件。模型由固定目录决定，不依赖旧配置。
卸载（Linux）systemctl --user disable --now voime.service；删除 addon 描述文件、voime.so、~/.local/bin/voimed、~/.local/bin/voime、可选 voime-gpu 与 ~/.config/systemd/user/voime.service；模型目录与 GPU runtime 按需保留或删除。
升级 / 卸载（Windows）重新运行 packaging/windows/install.ps1 覆盖二进制；卸载运行 uninstall.ps1，按需附加 -RemoveSettings / -RemoveModels / -RemoveRuntime。TSF 若启用需重新注册。
停止顺序Linux 先停止 daemon，再重启 / 关闭平台前端；Windows 停止服务即退出托盘。卸载后宿主不保留 Voime 条目；旧 active / legacy 布局不再读取。
