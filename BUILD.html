1. 环境

↑

项目要求
平台Linux + Fcitx5；验收平台为 AMD x86_64 CPU。
Fcitx5≥ 5.1.23，运行中；fcitx5-configtool 用于配置 Mode / Hotkey。
Ruststable 工具链（rust-toolchain.toml）；首次构建需要网络下载 crate 与 ONNX Runtime。
Linux 构建依赖ALSA 开发头文件；Arch：alsa-lib；Debian / Ubuntu：libasound2-dev。
addon 构建依赖C++20、CMake、Fcitx5Core 开发头文件；Arch：fcitx5；Debian / Ubuntu：libfcitx5core-dev 等，按发行版为准。
模型安装期Python 3.10+、网络与约 740 MiB 磁盘空间；只用于 scripts/install_models.* 与 tools/。
运行期Fcitx5 运行中、voimed 运行中、可用录音设备；voime TUI 需要 TTY；daemon 不需要 TTY。
运行期不需要网络、GPU、Python、自绘 GUI 或独立输入法前端。

2. 构建

↑

cargo build --release
scripts/install_voimed.sh
scripts/install_voime.sh

cmake -S fcitx-addon -B build/fcitx -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build/fcitx
sudo cmake --install build/fcitx
产物说明
target/release/voimedASR 守护进程；ONNX Runtime 随 ort 构建时链接。
target/release/voime可选 TUI / ctl / doctor。
scripts/install_voimed.sh安装 voimed 到 ~/.local/bin，并生成 systemd user unit。
scripts/install_voime.sh安装 voime TUI / ctl / doctor 到 ~/.local/bin。
build/fcitx/voime.soFcitx5 addon；安装到 $PREFIX/lib/fcitx5/。
addon 描述文件share/fcitx5/addon/voime.conf、图标。inputmethod 条目不安装，Voime 不进入输入法列表。
模型包由安装脚本生成在用户数据目录，不进入版本库；voimed 只读。
  • 构建过程通过 ort 的 download-binaries 获取 ONNX Runtime；构建完成后运行期不联网。
  • 两个安装脚本都支持 --prefix DIR、--bindir DIR、--no-build；install_voimed.sh 另有 --no-systemd。
  • addon 使用仓库内 fcitx-addon/third_party/nlohmann/json.hpp（MIT），不需要额外安装 JSON 库。
  • 发布时分别分发 Rust 二进制、addon、描述文件、systemd unit 与模型安装脚本。
  • 如果 ONNX 使用 external data，模型目录中的 *.data 或分片必须与 .onnx 一起复制。

3. 安装模型

↑

# Linux
scripts/install_models.sh

# 指定模型目录 / 本地官方包
scripts/install_models.sh --model-dir /path/to/models
scripts/install_models.sh --source-dir /path/to/official/weights
行为契约
默认目录$XDG_DATA_HOME/voime/models（未设置时 ~/.local/share/voime/models）。
ASRFireRedASR2-CTC int8：官方 .tar.bz2，解出 asr/model.int8.onnx 与 asr/tokens.txt。
VAD / PuncFireRedVAD 与 FireRedPunc 的 ONNX、词表、标签；由安装脚本下载 / 导出并校验。
Manifestschema 2；ASR kind = "fire-red-ctc"；max_segment_ms = 30000；SHA-256 写入清单。
磁盘下载缓存与模型包合计约 740 MiB 起；空间不足时安装失败。
原子安装在同盘临时目录下载、校验、写 manifest 后替换目标目录。
  • 模型权重不提交到仓库；安装脚本只写入用户数据目录。
  • 模型包内容与张量契约见 PROVIDER §4.2；模型事实与 RTF 见 ASR 研究。
  • 运行期不下载、不重新导出、不做动态量化。

4. 运行

↑

# 1. 启动 daemon（推荐 systemd user service）
systemctl --user daemon-reload
systemctl --user enable --now voime.service

# 2. 安装 / 更新 addon 后重启 Fcitx
fcitx5 -r

# 3. 确认 addon 已在 Addons 页面加载；不需要加入输入法组
fcitx5-configtool

# 4. 可选 TUI / 控制
voime
voime ctl status
voime doctor
现象处理
Fcitx Addons 页面没有 Voime确认 addon 描述文件安装到 Fcitx 前缀；重启 Fcitx；检查 voime.so 的 ABI / 依赖。
热键没有反应确认 Mode / Hotkey 已加载；热键未被 Fcitx trigger 或合成器绑定；当前窗口有文本焦点。
没有临时文本窗口确认 Fcitx UI addon 正在运行；当前 UI 可能不渲染 preedit；不影响最终提交。
最终文本没有上屏确认目标输入框在录音期间没有失焦；查看 voime doctor 与 Fcitx 日志。
daemon 未启动systemctl --user status voime.service；检查模型、音频与 socket 错误。
模型错误重新运行安装脚本；确认 --model-dir 指向包含 manifest.json 的目录。
没有录音设备检查系统录音设备；--input-device 必须精确匹配设备名。
  • voimed 不需要 WAYLAND_DISPLAY 或 DISPLAY；addon 负责与 Fcitx 交互。
  • TUI 的 q / Ctrl+C 只 detach；停止 daemon 使用 voime ctl quit 或 systemd。

7. 升级 / 卸载

↑

操作步骤
升级 Fcitx重新编译并安装 voime.so；重启 Fcitx；确认 addon ABI，且输入法组中没有 Voime。
升级 Voime停止 daemon；重新运行 scripts/install_voimed.sh / scripts/install_voime.sh；重新安装 addon 后重启 daemon 与 Fcitx。升级会删除旧版本残留的 inputmethod/voime.conf，并从输入法组移除 Voime。
卸载systemctl --user disable --now voime.service；删除 addon 描述文件、voime.so、~/.local/bin/voimed、~/.local/bin/voime 与 ~/.config/systemd/user/voime.service；模型目录按需保留或删除。
停止顺序先停止 daemon，再重启 / 关闭 Fcitx；卸载后 Fcitx 不保留 Voime 条目。
