BUILD — Voime

README USER CORE PROVIDER PLATFORM WINDOWS

根 BUILD 负责多构建根编排、从源码安装、共享模型安装与发布。单个 crate 或前端的构建、测试与安装细节 在其自己的 BUILD 中维护；本文只保留跨构建根的步骤。

1. 环境

↑

项目要求
平台Linux + Fcitx5（当前验收平台）；Windows 10 / 11 x64（P2 / P3 已实现）。
Fcitx5≥ 5.1.23，运行中；fcitx5-configtool 用于配置 Mode / Hotkey。
Ruststable 工具链（rust-toolchain.toml）；首次构建需要网络下载 crate 与 ONNX Runtime。
Linux 构建依赖ALSA 开发头文件；Arch：alsa-lib；Debian / Ubuntu：libasound2-dev。
addon 构建依赖C++20、CMake、Fcitx5Core 开发头文件；Arch：fcitx5；Debian / Ubuntu：libfcitx5core-dev 等，按发行版为准。
Windows 构建依赖Rust MSVC 工具链、Visual Studio / Windows SDK、CMake（TSF 可选阶段）。
模型安装期Python 3.10+、网络与约 740 MiB 磁盘空间；只用于 scripts/install_models.* 与 tools/。
运行期平台前端加载、voimed 运行中、可用录音设备；voime TUI 需要 TTY；daemon 不需要 TTY。
运行期不需要网络、GPU、Python、自绘 GUI 或独立输入法前端。

3. 从源码安装

↑

以下步骤从干净检出的仓库开始，安装 voimed、voime、Fcitx5 addon、 systemd 用户服务与模型包。默认把二进制安装到 ~/.local/bin，把 addon 安装到 /usr 前缀；所有命令在仓库根目录执行。

3.1 准备构建环境

↑

依赖用途 / 安装包示例
Rust stablerust-toolchain.toml；首次构建需要网络下载 crate 与 ONNX Runtime。
ALSA 开发头文件Arch：alsa-lib；Debian / Ubuntu：libasound2-dev。
C++20 / CMake / Fcitx5CoreArch：fcitx5；Debian / Ubuntu：libfcitx5core-dev 等。
Python 3.10+ 与网络仅用于安装模型；运行期不需要网络或 Python。

3.2 构建并安装 Rust 二进制

↑

cargo build --release -p voimed -p voime

# 安装到 ~/.local/bin，并生成 ~/.config/systemd/user/voime.service
scripts/install_voimed.sh --no-build
scripts/install_voime.sh --no-build

根 scripts/install_*.sh 是 packaging/linux/install_*.sh 的入口； 首次构建可省略 --no-build，由安装脚本重新执行 release 构建。

脚本默认行为
scripts/install_voimed.sh安装 voimed 到 ~/.local/bin，并从 packaging/linux/voime.service 生成 systemd 用户服务。
scripts/install_voime.sh安装 voime（TUI / ctl / doctor）到 ~/.local/bin。
  • 自定义前缀：scripts/install_voimed.sh --prefix /usr/local；ExecStart 会替换为实际的 $BINDIR/voimed。
  • 不安装 systemd：scripts/install_voimed.sh --no-systemd，之后手动运行 ~/.local/bin/voimed。
  • 也可以手动安装：install -Dm755 target/release/voimed ~/.local/bin/voimed 与 install -Dm755 target/release/voime ~/.local/bin/voime。
  • 手动安装 systemd 用户服务：install -Dm644 packaging/linux/voime.service ~/.config/systemd/user/voime.service；默认 unit 使用 %h/.local/bin/voimed。

3.3 构建并安装 Fcitx5 addon

↑

cmake -S frontends/fcitx -B build/fcitx -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build/fcitx
sudo cmake --install build/fcitx

安装结果包含 voime.so 与 addon 描述文件；addon 不注册 inputmethod 条目， 因此不需要把 Voime 加入输入法组。

  • 只重新编译、不安装：cmake --build build/fcitx；产物为 build/fcitx/voime.so。
  • 使用 /usr/local 前缀时，确认 Fcitx5 会搜索该前缀下的 addon 与库。

3.4 安装模型

↑

scripts/install_models.sh

模型默认写入 $XDG_DATA_HOME/voime/models（未设置时 ~/.local/share/voime/models）；模型目录、SHA-256 与离线安装选项见 §4。模型权重不随仓库或 release 包提交。

3.5 启动服务并验证

↑

systemctl --user daemon-reload
systemctl --user enable --now voime.service

# 安装 / 更新 addon 后重启 Fcitx
fcitx5 -r

# 验证端点、daemon、模型、音频与 addon
voime doctor
voime ctl status

# 可选 TUI
voime
  • 首次安装后可在 fcitx5-configtool 的 Addons 页面确认 Voime 已加载。
  • 若 ~/.local/bin 不在 PATH 中，使用绝对路径运行 voime，或把该目录加入 PATH。
  • 不安装 systemd 时，先手动启动 ~/.local/bin/voimed，再启动 voime 或 Fcitx。

3.6 Windows 从源码安装

↑

# 每用户安装：构建 voimed / voime / voime-tray，写入登录启动，安装模型
powershell -ExecutionPolicy Bypass -File packaging\windows\install.ps1

# 只安装二进制
powershell -ExecutionPolicy Bypass -File packaging\windows\install.ps1 -NoModels -NoStartup

# 启动托盘 / 查看状态
"%LOCALAPPDATA%\Programs\Voime\voime-tray.exe"
"%LOCALAPPDATA%\Programs\Voime\voime.exe" ctl status
"%LOCALAPPDATA%\Programs\Voime\voime.exe" doctor
项目契约
前缀默认 %LOCALAPPDATA%\Programs\Voime；-Prefix 可覆盖。
登录启动写入 HKCU\Software\Microsoft\Windows\CurrentVersion\Run；-NoStartup 跳过。
模型默认调用 scripts/install_models.ps1；-NoModels 跳过。
卸载packaging/windows/uninstall.ps1；-RemoveSettings / -RemoveModels 按需删除配置与模型。
  • Windows 不使用 Session 0 服务；托盘负责拉起 voimed.exe，并按登录会话隔离命名管道。
  • TSF（P4）为可选阶段；当前分支不构建或注册 TSF DLL。

4. 安装模型

↑

# Linux
scripts/install_models.sh

# 指定模型目录 / 本地官方包
scripts/install_models.sh --model-dir /path/to/models
scripts/install_models.sh --source-dir /path/to/official/weights

# Windows
powershell -ExecutionPolicy Bypass -File scripts\install_models.ps1
powershell -ExecutionPolicy Bypass -File scripts\install_models.ps1 -ModelDir D:\voime\models
行为契约
默认目录Linux：$XDG_DATA_HOME/voime/models（未设置时 ~/.local/share/voime/models）；Windows：%LOCALAPPDATA%\voime\models。
ASRFireRedASR2-CTC int8：官方 .tar.bz2，解出 asr/model.int8.onnx 与 asr/tokens.txt。
VAD / PuncFireRedVAD 与 FireRedPunc 的 ONNX、词表、标签；由安装脚本下载 / 导出并校验。
Manifestschema 2；ASR kind = "fire-red-ctc"；max_segment_ms = 30000；SHA-256 写入清单。
磁盘下载缓存与模型包合计约 740 MiB 起；空间不足时安装失败。
原子安装在同盘临时目录下载、校验、写 manifest 后替换目标目录。
  • 模型权重不提交到仓库；安装脚本只写入用户数据目录。
  • 仓库内 models/manifest.json 是结构模板，SHA-256 为全零且模型目录不完整；必须先运行安装脚本生成真实模型包。
  • --source-dir 只覆盖 FireRedPunc 权重、VAD ONNX / CMVN 与 FireRedASR2S 源码；FireRedASR2-CTC 仍从官方 .tar.bz2 下载，或复用 $XDG_CACHE_HOME/voime/ctc/ 缓存。
  • 模型包内容与张量契约见 voime-core PROVIDER §4.2。

5. 运行

↑

# 1. 启动 daemon（推荐 systemd user service）
systemctl --user daemon-reload
systemctl --user enable --now voime.service

# 2. 安装 / 更新 addon 后重启 Fcitx
fcitx5 -r

# 3. 确认 addon 已在 Addons 页面加载；不需要加入输入法组
fcitx5-configtool

# 4. 可选 TUI / 控制 / 诊断
voime
voime ctl status
voime doctor

# Windows：托盘负责拉起 daemon，也可手动启动
"%LOCALAPPDATA%\Programs\Voime\voime-tray.exe"
"%LOCALAPPDATA%\Programs\Voime\voimed.exe" --verbose
"%LOCALAPPDATA%\Programs\Voime\voime.exe" ctl status
"%LOCALAPPDATA%\Programs\Voime\voime.exe" doctor
现象处理
Fcitx Addons 页面没有 Voime确认 addon 描述文件安装到 Fcitx 前缀；重启 Fcitx；检查 voime.so 的 ABI / 依赖。
热键没有反应确认 Mode / Hotkey 已加载；热键未被 Fcitx trigger 或合成器绑定；当前窗口有文本焦点。
没有临时文本窗口确认 Fcitx UI addon 正在运行；当前 UI 可能不渲染 preedit；不影响最终提交。
最终文本没有上屏确认目标输入框在录音期间没有失焦；查看 voime doctor 与 Fcitx 日志。
daemon 未启动systemctl --user status voime.service；检查模型、音频与端点错误。
模型错误重新运行安装脚本；确认 --model-dir 指向包含 manifest.json 的目录。
没有录音设备检查系统录音设备；--input-device 必须精确匹配设备名。
  • voimed 不需要 WAYLAND_DISPLAY 或 DISPLAY；平台前端负责输入集成。
  • scripts/install_voimed.sh 生成 ~/.config/systemd/user/voime.service，并把 ExecStart 替换为实际 $BINDIR/voimed。
  • voime doctor 固定检查默认模型目录与 /usr、/usr/local 下的 addon；自定义前缀或 --model-dir 部署需手工确认。
  • TUI 的 q / Ctrl+C 只 detach；停止 daemon 使用 voime ctl quit 或 systemd。
  • Windows 不使用 Session 0 服务；命名管道按当前会话与用户隔离，托盘负责启动与重连 daemon。

↑

cargo test
cargo clippy --all-targets
cargo fmt --all --check

cmake --build build/fcitx
ctest --test-dir build/fcitx --output-on-failure

# Windows
cargo test --workspace
cargo test --manifest-path frontends\windows\Cargo.toml
cargo clippy --workspace --all-targets
cargo clippy --manifest-path frontends\windows\Cargo.toml --all-targets
  • tests/segmenter.rs 覆盖端点、静音自动结束与最大段长；tests/ipc.rs 覆盖握手 / 角色 / Mode / framing；tests/state.rs 覆盖快照默认值、清空历史与 status；tests/daemon.rs 覆盖 socket 存活与断线角色；tests/asr_ctc.rs 覆盖 CMVN / token id / greedy；10–60 s 真实解码仅在设置 VOIME_CTC_MODEL_DIR 时执行。
  • frontends/fcitx/tests 覆盖 mode / 热键字符串 / IPC 枚举 / target 空引用；不覆盖真实 Fcitx keymatch 或 preview 渲染。
  • RTF 验收参考（2 threads）：10 s ≤ 1.0 s、20 s ≤ 2.0 s、30 s ≤ 3.0 s。
  • 手工验收需同时在原生 Wayland、XWayland / XIM 与支持 text-input 的终端中测试热键、临时窗口与提交；Toggle 无语音时应出现空白窗口并保持到 toggle off 或目标失焦。
  • Windows 验收矩阵见 WINDOWS §7.2；frontends/windows 单测覆盖热键解析、配置、UTF-16 分块、UIA 目标标识与命名管道客户端握手。

8. 升级 / 卸载

↑

操作步骤
升级 Fcitx重新编译并安装 voime.so；重启 Fcitx；确认 addon ABI，且输入法组中没有 Voime。
升级 Voime（Linux）停止 daemon；重新运行 scripts/install_voimed.sh / scripts/install_voime.sh；重新安装 addon 后重启 daemon 与 Fcitx。
配置迁移旧版本无后缀的 ~/.config/fcitx5/conf/voime 会在 addon 启动时迁移到 voime.conf，然后删除旧文件。
卸载（Linux）systemctl --user disable --now voime.service；删除 addon 描述文件、voime.so、~/.local/bin/voimed、~/.local/bin/voime 与 ~/.config/systemd/user/voime.service；模型目录按需保留或删除。
升级 / 卸载（Windows）重新运行 packaging/windows/install.ps1 覆盖二进制；卸载运行 uninstall.ps1，按需附加 -RemoveSettings / -RemoveModels。TSF 若启用需重新注册。
停止顺序先停止 daemon，再重启 / 关闭平台前端；卸载后宿主不保留 Voime 条目。
