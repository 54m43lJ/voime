1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

桌面语音输入通常依赖云服务、独立输入法或 GPU 推理环境。Voime 把语音识别放在本机 CPU： 一个常驻 daemon 持有音频、VAD、ASR、标点与会话历史，平台前端只负责热键、目标输入位置、 临时文本与最终提交。Linux 前端运行在 Fcitx5 内；Windows 前端以独立桌面进程提供后台听写。 运行时不联网、不上传音频，也不需要 GPU 或 Python。

1.2 GOAL：什么算成功

  • Linux 上安装 voime addon 后，addon 随 Fcitx5 在后台加载，不注册输入法条目；Windows 上安装前端后，用户可在支持的桌面应用中按热键说话。
  • 前端配置一个模式：ptt（按住说话）、toggle（按一下切换）或 continuous（VAD 自动分段）。
  • 前端配置一个热键；ptt 按住说话，toggle 切换录音，continuous 忽略热键。
  • 说话期间显示当前段的临时文本；最终结果提交到语音段开始时聚焦的输入位置，失焦时不向其他窗口注入。
  • 音频、模型、VAD、FireRedASR2-CTC、FireRedPunc 与会话历史由独立 voimed 守护进程持有。
  • 可选 TUI 连接 daemon，显示模式、热键、临时结果与历史；关闭 TUI 不影响热键、临时窗口与上屏。
  • 运行时不需要网络、GPU 或 Python；模型由安装脚本生成，voimed 完全离线运行。

1.3 非目标

  • 不做拼音、形码、候选词或通用键盘输入法；Voime 只负责语音文本的提交。
  • 不实现跨平台统一 UI 抽象；各平台前端保留自己的热键、目标、预览与提交实现。
  • 不保证锁屏、安全桌面、提权窗口、游戏或未使用受支持输入协议的应用。
  • 不使用客户端 preedit 作为 Linux 临时文本；Fcitx 输入面板由宿主渲染。
  • 不引入第二个 ASR 模型或额外推理后端；不保存音频、按键或识别历史到磁盘。

2. 用户交互

↑

场景行为详细契约
Linux 安装 addon 把 voime.so 与 addon 描述文件安装到 Fcitx5，重启 Fcitx；Voime 作为后台 addon 加载，不需要加入输入法组。 fcitx-addon BUILD · fcitx-addon USER
配置 Linux 在 fcitx5-configtool 或 ~/.config/fcitx5/conf/voime.conf 中设置 Mode 与 Hotkey；Windows 在托盘设置中配置。 fcitx-addon USER §4.1 · windows USER §4.1
PTT 模式 Mode=ptt：按住 Hotkey 开始，松开结束；按住期间可被静音自动结束。 fcitx-addon USER §3.1 · windows USER §3.1
Toggle 模式 Mode=toggle：按一下 Hotkey 开始，再按一下结束；目标失焦时自动结束；Linux 会话期间没有语音也保持空白临时窗口，Windows 浮层隐藏。 fcitx-addon USER §3.1 · windows USER §3.1
Continuous 模式 Mode=continuous：忽略热键，VAD 检测到语音起点即开始、终点即结束；无需按键。 fcitx-addon USER §3.2 · windows USER §3.2
临时文本窗口 说话期间显示当前段的 Partial；Linux Toggle 会话在 Final/空段后保持空白窗口，Windows 浮层在 Final 后隐藏；直到再次按热键关闭或目标失焦。 fcitx-addon USER §3.3 · windows USER §3.4
最终结果 语音段结束后识别并加标点，提交到语音段开始时聚焦的输入位置；失焦则不提交。 fcitx-addon USER §4.2 · windows USER §4.2
普通输入 除热键外的按键全部由宿主或系统正常处理；Voime 不抓取、不转发普通按键。 fcitx-addon USER §2 · windows USER §2
TUI voime 可选连接 daemon，显示模式、热键、临时结果与历史；q 只 detach。 voime USER
停止 daemon voime ctl quit 或停止平台服务；前端继续运行，热键因 daemon 不可用而放行。 voimed USER §4.1 · voime USER §4.2
运行环境缺失 前端未加载、daemon 未启动或没有文本焦点时，在日志 / doctor 说明原因；不静默注入文本。 voime USER §4.4 · windows USER §4.5
