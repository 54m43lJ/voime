Voime — 本地语音输入

USER CORE PROVIDER voime-core voime-gpu-common voime-gpu-qwen3 voime-ipc voime-log voime-transport voimed voime fcitx windows

项目范围：项目包含跨平台源码、构建清单、脚本、模型清单与文档。 核心安装自带 CPU 推理与平台前端；GPU 推理是可选模块，只增加最终文本识别能力。

1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

桌面语音输入通常依赖云服务、外接输入法或 GPU 推理环境。Voime 把语音识别拆成两个安装单元： 核心安装自带音频、VAD、预览、最终识别、平台前端与 CPU 运行时，不装 GPU 模块也能完整使用； GPU 推理模块只负责最终文本识别，按需安装、按需选择。运行时不联网、不上传音频， 也不需要 Python；核心路径不需要 GPU。

1.2 GOAL：什么算成功

  • 只装核心即可在 Linux 与 Windows 完成热键、VAD、预览、CPU Final 与提交；GPU 不是运行前提。
  • VAD 固定 FireRedVAD，Preview 固定 SenseVoice；任何 Final 后端组合都不改变两者。
  • 提供 Qwen 可选 GPU Final 后端：Qwen 使用 Qwen3-ASR。
  • final.backend 默认 cpu；安装 GPU 模块不自动切换，用户通过 --backend 或 voime ctl backend 显式选择。
  • GPU 后端使用预编译 runtime；具体平台矩阵与依赖见 Qwen 组件文档。
  • 核心安装的组件树在 Linux 与 Windows 共用；平台安装入口与权限步骤由各组件文档定义。
  • voimed 持有音频、会话、Final 触发与后端选择；voime-core 持有 VAD / SenseVoice / CPU Final；GPU worker 持有自己的 Final 模型与 runtime。
  • 核心安装的模型与 GPU 模块的模型分开管理；一个模型一个目录，运行期只读。
  • GPU 崩溃、驱动缺失、显存不足或模型缺失时，Preview 与 CPU Final 仍然可用。

1.3 非目标

  • 不做 GPU VAD、GPU Preview、GPU Partial 或流式 GPU 识别；GPU 模块只接收完整语音段。
  • 不做 CPU Qwen3-ASR；GPU 失败不加载任何 CPU 大模型。
  • 不要求用户自行构建 GPU runtime；runtime 由安装脚本按组件预编译包部署。
  • 不做运行中 Final 后端热切换；切换配置后需重启 daemon。
  • 只支持当前 schema 5 模型包；CTC 与独立 CPU 标点模型不在产品路径内。
  • 不做拼音、形码、候选词或通用键盘输入法；Voime 只负责语音文本的提交。
  • 不实现跨平台统一 UI 抽象；各平台前端保留自己的热键、目标、预览与提交实现。
  • 不保证锁屏、安全桌面、提权窗口、游戏或未使用受支持输入协议的应用。
  • 不保存音频、按键或识别历史到磁盘。

场景用户可见结果详细契约

最终结果 最终文本提交到开始说话时聚焦的输入位置；目标失焦则不提交。 根 USER §4.4 · fcitx-addon USER §4.2 · windows USER §4.2
普通输入 除热键外的按键全部由宿主或系统正常处理。 fcitx-addon USER §2 · windows USER §2
TUI voime 可选调试 TUI，连接 daemon 显示模式、热键、临时结果与历史；不操作输入法、不提交文本。 voime USER
诊断 voime doctor 输出平台、模型与 Final 后端诊断；只读。 voime USER §4.4
停止 daemon 通过平台前端或控制入口停止 daemon；停止后语音输入不可用。 voimed USER §4.1 · voime USER §4.2
运行环境缺失 核心模型缺失时 daemon 启动失败；GPU 模型 / runtime 缺失时当前输入仍可使用 CPU Final。 根 USER §4.4 · voime USER §4.4
