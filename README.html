Voime — 纯本地语音输入法

USER CORE PROVIDER

1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

Linux 与 Windows 上的语音输入通常依赖云服务、整套输入法框架或带 GPU 的推理环境。 本项目希望用单个 Rust 可执行程序，在 AMD x86_64 CPU 上完成全部语音识别与标点， 不联网、不上传音频、不注册系统输入法，只通过一个极简终端界面完成“说话 → 看到文字 → 粘贴”的闭环。

1.2 GOAL：什么算成功

  • 用户启动 voime 后，在终端里按一次 Space 开始说话、再按一次结束； 连续模式下无需按键，按语音活动自动切分。
  • 语音链路固定为 FireRedVAD 切分 → FireRedASR2-AED 识别 → FireRedPunc 标点，全部在本机 CPU 上完成。
  • 终端界面只有两个元素：红色 recording 标记与识别内容；最终结果按行累积，直到退出程序。
  • 每次识别完成，整段会话文本自动写入系统剪贴板；用户也可以直接用终端选择复制任意可见行。
  • 单个可执行程序加本地模型包即可运行；Linux 与 Windows 的 AMD x86_64 行为一致；运行时不需要网络、GPU 或 Python。
  • ASR 固定使用 FireRedASR2-AED；FireRedASR2-LLM 不在本项目范围内。

1.3 非目标

  • 不监听全局热键，不向其他窗口模拟键盘输入，不注册 TSF / IBus / Fcitx 输入法。终端必须获得焦点。
  • 不提供 GUI、托盘、悬浮窗、设置界面或鼠标操作；所有运行参数在命令行确定。
  • 不联网，不调用云 ASR、云标点或模型下载服务；模型文件由用户事先放到本地目录。
  • 不支持 GPU、NPU、macOS、Linux ARM 或 Windows ARM；不承诺 Intel 平台上的性能与正确性，验收平台为 AMD x86_64。
  • 不保存音频或识别历史到磁盘；退出后只保留剪贴板中的会话文本。
  • 不做说话人分离、语种识别、翻译、文本润色或大模型改写。

2. 用户交互

↑

场景行为详细契约
启动（PTT） voime --mode ptt；--mode 省略时默认 ptt。进入全屏 TUI，等待按键。 USER §2 · USER §4.1
启动（持续监听） voime --mode continuous。进入 TUI 后立即开始监听，语音段自动切分。 USER §2 · USER §4.1
PTT 开始 / 结束 按一次 Space 开始一段识别；再按一次 Space 结束。语音后长时间静音也会自动结束。 USER §2 · USER §3.2
持续监听 VAD 检测到语音起点即开始一段识别，检测到语音终点即结束该段；无需按键。 USER §2 · USER §3.3
临时结果 录音过程中，当前行按固定节奏刷新未加标点的临时文本；不同语音段不共享同一行。 USER §5.2
最终结果 语音段结束后执行最终识别与标点，该行固化并保留到程序退出；下一次识别另起一行。 USER §2 · USER §5.2
自动复制 每次最终结果产生后，把当前会话的全部最终结果按行拼接后写入剪贴板。 USER §2 · PROVIDER §4.4
手动复制 用终端自身的鼠标选择与复制操作选取任意可见文本；应用不捕获鼠标。 USER §2
回看 结果超过一屏时用 PageUp / PageDown / Home / End 滚动；新结果不会打断已上翻的视图。 USER §5.2
退出 q 或 Ctrl+C 退出，恢复终端；剪贴板内容保留。 USER §2
启动失败 模型缺失、模型校验失败、没有可用录音设备或终端不是 TTY 时，在进入 TUI 前把原因写到 stderr 并以非零码退出。 USER §4.1 · PROVIDER §4.6
