Voime — 基于 Fcitx5 的本地语音输入法

USER CORE PROVIDER BUILD ASR

1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

Linux 上的语音输入通常需要云服务、独立输入法或额外的 GPU 推理环境。本项目把语音识别放进 Fcitx5：Fcitx 负责键盘、输入焦点与文本提交，Voime 作为 addon 把本地语音识别结果直接写入当前 输入框。音频、VAD、ASR 与标点全部在本机 CPU 上完成，运行时不联网、不上传音频，也不需要 GPU 或 Python。TUI 只是可选的监视器，不参与键盘与上屏路径。

1.2 GOAL：什么算成功

  • 安装 voime addon 后，addon 随 Fcitx5 在后台加载，不注册输入法条目；切换键盘输入法时不会切到 Voime。
  • addon 配置一个模式：ptt（按住说话）、toggle（按一下切换）或 continuous（VAD 自动分段）。
  • addon 只配置一个热键；ptt 模式按住说话，toggle 模式切换录音，continuous 模式忽略热键。
  • 热键由 Fcitx 捕获；普通按键照常输入，不被 Voime 拦截或转发。
  • 说话期间，Fcitx 输入面板显示当前段的临时文本窗口；PTT / continuous 最终结果产生后关闭，Toggle 会话保持空白窗口到 toggle off。
  • 最终文本通过 Fcitx 提交到语音段开始时聚焦的输入框；输入框失焦时不向其他窗口注入。
  • 音频、模型、VAD、FireRedASR2-CTC、FireRedPunc 与会话历史由独立 voimed 守护进程持有。
  • ASR 使用 FireRedASR2-CTC int8 单 ONNX；CPU 推理成本低，模型约 740 MiB；final 与临时结果共用同一模型。
  • TUI 可连接 daemon，显示模式、热键、临时结果与历史；关闭 TUI 不影响热键、临时窗口与上屏。
  • 运行时不需要网络、GPU 或 Python；模型由安装脚本生成，voimed 完全离线运行。

1.3 非目标

  • 不做拼音、形码、候选词或通用键盘输入法；Voime 只负责语音文本的提交。
  • 不实现自绘候选窗口、托盘或设置 GUI；输入法状态与配置由 Fcitx 提供。
  • 不保证桌面空白处、锁屏、未使用 Fcitx 的应用、没有文本输入焦点的窗口中的热键。
  • 不使用客户端 preedit；临时文本只显示在 Fcitx 输入面板的窗口中。
  • 不引入第二个 ASR 模型或额外推理后端；不保存音频、按键或识别历史到磁盘。
  • 不支持 Linux + Fcitx5 之外的平台形态；X11 仅通过 Fcitx XIM 覆盖。

2. 用户交互

↑

场景行为详细契约
安装 addon 把 voime.so 与 addon 描述文件安装到 Fcitx5，重启 Fcitx；Voime 作为后台 addon 加载，不需要加入输入法组。 BUILD §2 · USER §2
配置 在 fcitx5-configtool 或 ~/.config/fcitx5/conf/voime.conf 中设置 Mode 与 Hotkey。 USER §4.1
PTT 模式 Mode=ptt：按住 Hotkey 开始，松开结束；按住期间可被静音自动结束。 USER §2 · USER §3.2
Toggle 模式 Mode=toggle：按一下 Hotkey 开始，再按一下结束；会话期间没有语音也保持空白临时窗口。 USER §2 · USER §3.2
Continuous 模式 Mode=continuous：忽略热键，VAD 检测到语音起点即开始、终点即结束；无需按键。 USER §2 · USER §3.3
临时文本窗口 说话期间在 Fcitx 输入面板显示当前段的 Partial；Toggle 会话在 Final/空段后保持空白窗口，直到再次按热键关闭。 USER §3.4 · PROVIDER §4.4
最终结果 语音段结束后识别并加标点，通过 Fcitx 提交到语音段开始时聚焦的输入框；失焦则不提交。 USER §4.4 · PROVIDER §4.5
普通输入 除热键外的按键全部由 Fcitx 正常处理；拼音、候选、快捷键与组合键不受 Voime 影响。 USER §2
TUI voime 可选连接 daemon，显示模式、热键、临时结果与历史；q 只 detach。 USER §5
停止 daemon voime ctl quit 或停止 systemd user service；Fcitx 继续运行，热键因 daemon 不可用而放行。 BUILD §4 · USER §4.2
运行环境缺失 Fcitx 未运行、addon 未加载、daemon 未启动或没有文本焦点时，在 stderr / 日志说明原因；不静默注入文本。 USER §2 · BUILD §5
