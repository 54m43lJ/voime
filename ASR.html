ASR — FireRedASR2-CTC 替换 AED

README USER CORE PROVIDER PROPOSAL

1. 结论

↑

sherpa-onnx-fire-red-asr2-ctc-zh_en-int8-2026-02-25 是 离线 CTC 模型。本方案只是把现有 FireRedASR2-AED 换成 FireRedASR2-CTC， 用同一个 ort 运行时，降低 CPU 推理耗时和模型内存。 分段、VAD、临时结果（尾部重解码）和标点链路保持不变。

  • CTC 单模型约 740 MiB，CPU 上 RTF 约 0.08；10 s 约 0.7–0.8 s，30 s 约 2.3 s，60 s 约 5.6 s。
  • 仍按 VAD / PTT 分段，临时结果仍用当前段的尾部重解码。
  • 本机验收环境：AMD Ryzen 7 9800X3D，2 threads；模型与 test_wavs 来自官方 sherpa-onnx 包，SHA-256 与 Hugging Face 一致。

2. 模型事实

↑

项目事实
模型包 sherpa-onnx-fire-red-asr2-ctc-zh_en-int8-2026-02-25
文件 model.int8.onnx（775,861,420 bytes，SHA-256 ca3dbabd82170110cc0b343c2890866d449984bc9cd92b9a18371ff80a81bb99）、tokens.txt（77 KiB，SHA-256 1bc613de2112d257e61a349c3e72d1b1a9cf19c33d3ca954197ad2171e5ea07b）、test_wavs/；官方包不含 cmvn.ark。
来源 FireRedASR2-AED 的编码器 + CTC 分支；attention decoder 不导出。许可证 Apache-2.0。
结构 Conformer 编码器（非因果、全序列注意力）+ 线性 CTC head；没有帧级 cache 输入。
输入 x: float32[1, T, 80] fbank；x_lens: int64[1]。
输出 log_probs: float32[1, T', 8667]；log_probs_len: int64[1]。T' 约为 T/4。
CMVN 不在 ONNX 图内；从模型 metadata 的 cmvn_mean / cmvn_inv_stddev 读取，运行时做 (x - mean) * inv_stddev。
词表 每行 token id；id 0 是 <blank>；英文用 ▁ 表示词边界；中文 token 直接拼接。
  • 模型支持中文（普通话 + 20 多种方言）和英文；不包含 FireRedLID 或 FireRedPunc。
  • FireRedASR2-AED 的 60 s 输入上限同样来自编码器；实测 CTC 在 10 / 20 / 30 / 60 s 上都能正常解码，RTF 基本稳定。
  • int8 英文子词质量不是完美：官方 0.wav 在本机输出 MOAY TOAY … THEAY，而官方文档期望 MONDAY TODAY … THE DAY；1.wav 与方言样例正常。上线前要用真实麦克风数据评估。

3. 直接用 ort 跑 ONNX

↑

模型只有一个 ONNX 图，输入输出都是普通张量，没有 transducer 的 decoder/joiner 或帧级 cache。 项目现有的 ort、kaldi-native-fbank、Fbank 和 tokenizer 已经足够； 只需新增一个 CTC 前端、CMVN 和 greedy CTC 解码。

3.1 预处理必须与 sherpa 对齐

sample_rate = 16000
num_bins    = 80
frame_ms    = 25
shift_ms    = 10
dither      = 0
snip_edges  = true
low_freq    = 20
high_freq   = 0          # 注意：不是文档打印的 -400
use_power   = true
use_log_fbank = true
sample_scale  = 32768    # 输入到 fbank 前乘 32768
  • sherpa 的 FireRed-CTC 实现会在 Init() 中把 normalize_samples 设为 false、high_freq 设为 0、snip_edges 设为 true；命令行打印的 -400 / false 是覆盖前的配置，不能照抄。
  • 项目现有 asr/features.rs 已经使用 32768 缩放、snip_edges=true、默认 high_freq=0，与上面一致；主要新增的是 CMVN 与 CTC 解码。

3.2 推理

let features: Vec<Vec<f32>> = fbank.compute(&samples)?;
let mut flat: Vec<f32> = features.into_iter().flatten().collect();
for (i, value) in flat.iter_mut().enumerate() {
    *value = (*value - mean[i % 80]) * inv_stddev[i % 80];
}

let x = Tensor::from_array(([1, frames, 80], flat))?;
let x_lens = Tensor::from_array(([1], vec![frames as i64]))?;
let outputs = session.run(inputs![x, x_lens])?;
let log_probs = outputs["log_probs"].try_extract_array::<f32>()?;
let len = outputs["log_probs_len"].try_extract_array::<i64>()?[0];

// CTC greedy：argmax → 合并连续重复 → 去掉 blank 0
let mut prev = -1;
for t in 0..len {
    let id = argmax(log_probs[[0, t]]);
    if id != 0 && id != prev { push(id); }
    prev = id;
}
let text = tokenizer.decode(&ids);
  • cmvn_mean / cmvn_inv_stddev 可以直接用 ort::Session::metadata().custom("cmvn_mean") 读取，不需要 cmvn.ark。
  • token 文件是 token id 两列；现有 Tokenizer::load 需要新增“带 id 后缀”的解析，或新增 CtcTokenizer::load_sherpa。
  • CTC token 含 ▁ 和英文子词；解码后把 ▁ 替换为空格，并合并重复空格。

4. 本机实测

↑

测试平台：AMD Ryzen 7 9800X3D，2 threads，ONNX Runtime CPU；音频为官方 test_wavs。

输入长度解码耗时RTF结果
10 s0.66–0.78 s0.066–0.077正常
20 s1.40 s0.070正常
30 s2.26 s0.075正常
60 s5.64 s0.094正常，但端到端延迟偏高
样例输出
1.wav这是第一种第二种叫呃与 ALWAYSISE ALWAYS什么意思啊
0.wav昨天是 MOAY TOAY IS礼拜八二 THEAY AFTER TOMORROW是星期三（英文子词有缺失）
四川 / 天津 / 河南方言样例稳定，内容与官方测试基本一致。
  • 官方 1 thread 的 RTF 为 0.173（5.1 s 用 0.883 s）；本机 2 threads 约 0.08，属于正常加速。
  • 0.wav 的英文错误在其他运行方式（sherpa-onnx Python 1.12.27）下同样出现，不是本项目预处理错误；它是 int8 CTC 模型在该样本上的实际输出。
  • 如果最终准确率不达标，可以保留 FireRedASR2-AED 作为 legacy 后端，或评估 FP32 CTC（约 2.9 GB）但 CPU 成本更高。

5. 切换带来的代码与安装变更

↑

5.1 Manifest

{
  "schema": 2,
  "sample_rate": 16000,
  "fbank": { "num_bins": 80, "frame_ms": 25, "shift_ms": 10 },
  "max_segment_ms": 30000,
  "asr": {
    "kind": "fire-red-ctc",
    "model": "asr/model.int8.onnx",
    "tokens": "asr/tokens.txt"
  },
  "vad": { ... },
  "punc": { ... }
}
  • max_segment_ms 从 10_000 改为 30_000；PTT 硬上限固定 30_000，达到上限自动结束并开始下一段。
  • 保留 AED 作为 legacy 后端时，manifest 用 tagged enum：kind = "fire-red-aed" 时有 encoder/decoder，"fire-red-ctc" 时只有 model。
  • 安装脚本直接下载官方 .tar.bz2 并解出 model.int8.onnx / tokens.txt，不再需要 Python/PyTorch 导出 CTC；SHA-256 写入 manifest。

5.2 代码落点

  • voime-core/src/asr/firered_ctc.rs：单 ONNX 会话、CMVN、CTC greedy、token 解码。
  • voime-core/src/asr/engine.rs：AsrEngine enum，统一 AED / CTC 的 transcribe；默认 CTC，AED 作为 legacy。
  • voime-core/src/asr/tokenizer.rs：支持 token id 两列词表；decode 复用。
  • voime-core/src/pipeline.rs：final 和现有尾部 partial 都调用 CTC；保持 VAD / 分段 / 标点链路不变。
  • voime-core/src/model.rs / config.rs：manifest schema 2；AsrArtifact 改为 tagged enum。
