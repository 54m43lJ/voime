提案 — ASR v2：SenseVoice 基线 + 双 GPU Final 后端

README USER CORE PROVIDER BUILD ｜ 状态：待评审 · 未实现 · 2026-11-02

本文给出 ASR 的单一决策：保留 SenseVoice ITN 作为常驻 Preview 与 CPU Final 默认，删除 CTC、 SenseVoice + Punc 变体与所有 CPU AED / CPU Qwen 路径，增加两个可选的 GPU Final 后端： FireRedASR2-AED FP16 与 Qwen3-ASR 1.7B FP16。 两个 GPU 后端分别编译为独立 worker 模块，程序按模型 kind 硬编码选择；VAD 保持现状，不纳入本提案。

本文按 clean break 设计：运行期不承诺旧 schema、旧模型包、旧 active / legacy 布局、 旧前端协议兼容，也不建立兼容层。升级默认按“重新安装新版本 + 新模型包”处理； 另提供一个独立、可选、一次性的迁移脚本，由用户自行决定是否运行，它不属于安装脚本。 运行期失败回滚仍然保留，但它只回滚到本次运行已经加载的新 pipeline，不涉及旧版本迁移。

结论先行：SenseVoice 继续作为 Preview 与 CPU Final；GPU Final 不再绑定单一模型。 FireRedASR2-AED 用 OpenASR / ggml Vulkan，擅长中文精度与低显存；Qwen3-ASR 1.7B 用 llama.cpp Vulkan， 自带标点、英文格式更好、短音频更快。两者在 20–30 s 分段上的实测延迟接近，选择依据是目标语料质量、 显存 / 模型体积与英文 / 标点需求，而不是“谁能跑 GPU”。

2. 目标、非目标与设计边界

↑

2.1 目标

  • 保留 SenseVoice 作为常驻 Preview 后端与 CPU Final 默认；删除 CTC、SenseVoice-punc 与所有 CPU AED / CPU Qwen 路径。
  • 确定保留的 SenseVoice 改进是分段音频预卷，用于修复段首缺字；另做一次受控的 Rust ort 版本实验，有实际收益才采纳。
  • 增加两个可选 GPU Final 后端：FireRedASR2-AED FP16 与 Qwen3-ASR 1.7B FP16；Preview 始终由 SenseVoice 处理。
  • 安装脚本默认只装 SenseVoice + VAD；--firered 追加 AED + Punc，--qwen3 追加 Qwen3-ASR。
  • 每个 GPU 模型有独立 worker 模块与 runtime 包；voimed 按模型 kind 硬编码选择 worker。
  • 保留包级切换：models/active 只选择 Final 模型；切换不需要重装 SenseVoice 或替换二进制。
  • 失败可回滚：新 Final 加载或推理失败时恢复旧 Final；GPU 不可用时 Final 回退 CPU SenseVoice，Preview 不受影响。

2.2 非目标

  • 不做运行时双模型热切换，也不在录音 / 识别过程中切换 Final 后端。
  • 不做 CPU AED / CPU Qwen；GPU 失败不自动加载任何 CPU 大模型。
  • 不做 GPU Partial：Preview 固定由常驻 SenseVoice 产生，两个 GPU worker 都只接收完整语音段做 Final。
  • 不做通用 runtime 插件 / 动态 EP 发现；两个 worker 是固定编译单元，backend.runtime 只描述、不分派。
  • 不使用 ONNX Runtime GPU EP、MIGraphX 或 DirectML；GPU 路径统一走 ggml Vulkan / CUDA。
  • 不改 CPU SenseVoice 的 LFR / fbank / CMVN / 量化 / 语言参数；除受控的 ort 版本实验外，预卷是唯一确定改动。
  • 不更换、不调优、不评测 VAD：继续使用现有 FireRedVAD、模型与阈值。
  • 不实现文本后处理：不增加规则层、文本纠错模型、--rewrite、清单字段或 IPC 消息。
  • 不引入 Python 运行时、云端 API 或网络依赖到运行期；模型转换 / 评测脚本不属于运行期。
  • 第一批不接通用聊天 LLM；Qwen3-ASR 只作为 ASR 模型，不提供对话 / 摘要 / 翻译。
  • 运行期不承诺旧 schema、旧模型包、旧目录布局或旧前端协议兼容；只提供一个独立、可选的一次性迁移脚本。

3. 任务一：音频预卷与 ORT 版本实验

↑

3.1 结论与范围

实际使用中没有观察到 SenseVoice 的明显错别字；此前少量字符差异更可能来自已删除的 CTC 路径， 而不是 SenseVoice 模型。因此本提案不再展开 LFR 边缘处理、量化精度与语言参数的归因或改动， SenseVoice 保持当前推理路径。本任务只保留两项：分段音频预卷与受控的 CPU ORT 版本实验。 GPU 模型的前端与 decode 由各自 worker 负责，不属于本任务。

3.2 当前行为与问题

当前分段器在 VAD 判定语音起点后才开始保留音频，段首辅音 / 爆破音可能已被切掉， 表现为首字缺失或近音替换。该问题与 CTC / SenseVoice / GPU 模型选择无关，属于分段边界问题。

3.3 改进方案

Segmenter
├── 保持环形缓冲：最近 pre_roll_ms 音频

├── 从环形缓冲取 pre_roll_ms + 当前帧 → segment.samples
├── 保持 VAD 判定与端点参数不变
└── 将 segment.samples 交给 Preview / Final 路径
  • 预卷只影响 ASR 输入窗口，不改变 VAD 判定、端点延迟或 Continuous 状态机。
  • SenseVoice、FireRed、Qwen 共用同一预卷后的 segment.samples；不在 worker 内重复预卷。
  • 预卷长度从 200 ms 起测；PTT / Toggle / Continuous 分别验证，过长导致串音时回退。

3.5 CPU ort / ONNX Runtime 版本实验（条件项）

Rust 侧默认构建下，ort crate 版本决定绑定的 ONNX Runtime 版本；不通过 load-dynamic 混搭任意 runtime。 当前 POC 使用 ort 2.0.0-rc.12 / ONNX Runtime 1.24.2；可选的稳定路径有限： ort 2.0.0-rc.13（ONNX Runtime 1.28）与 ort 2.0.0-rc.15（ONNX Runtime 1.31； 以实际发布为准）。实验只升级 CPU SenseVoice 的 ort 依赖，不涉及 GPU worker。

项目契约

3.6 不在本任务中的改动

  • 不改 SenseVoice 的 LFR / fbank / CMVN / 量化 / 语言参数；预卷是唯一确定改动。
  • 不评估 Paraformer / Whisper 等 CPU 替代模型；SenseVoice 继续作为唯一 CPU 默认后端。
  • 不调整 CPU SenseVoice 的会话配置、图优化级别或执行提供者；GPU worker 的 Vulkan / CUDA 属于第 5 节。
  • 不把 CTC 的识别问题归因到 SenseVoice；CTC 按 §6.2 删除。

4. 目标架构：CPU daemon + 两个可选 GPU worker

↑

SenseVoice、VAD 与 Preview 路径始终留在 voimed / voime-core 内，使用 CPU-only ORT。 GPU 只作为可选 Final 能力：只有 active 选择 FireRed 或 Qwen 时才拉起对应 worker； 所有 Partial 仍由常驻 SenseVoice 处理。这样 CPU 路径不增加额外进程，GPU 也不污染 Preview 与 CPU 路径。

  • voimed / voime-core 使用 CPU-only ORT；不加载 Vulkan / CUDA / ROCm / ORT GPU 库。
  • SenseVoice 始终加载：所有 Partial 与 CPU Final 都由它处理。
  • voime-gpu-firered 与 voime-gpu-qwen3 是唯一加载 GPU runtime 的进程；active 选择一个。
  • VAD 始终在 daemon 的 CPU ORT 上；FireRedPunc 在 FireRed worker 内；Qwen 标点由模型自带。
  • Final 选择 CPU SenseVoice 时两个 worker 都不启动；切换回 CPU Final 时停掉 worker 并释放显存，SenseVoice Preview 不中断。
组件职责不负责
voimed 音频采集 / 重采样、环形缓冲、分段、前端 IPC、目标注入、Final 模型选择、worker 生命周期。 GPU 库、GPU 会话、具体 GPU 模型解码。
voime-core CPU-only ORT；FireRedVAD、常驻 SenseVoice（Preview + CPU Final）、fbank / LFR / CMVN、Partial / Final 文本。 GPU 模型、GPU runtime、前端 IPC、目标注入。
voime-gpu-firered OpenASR / ggml Vulkan；FireRedASR2-AED FP16 + FireRedPunc；返回已加标点的 Final 文本。 VAD、分段、Preview、CPU ASR、前端 IPC。
voime-gpu-qwen3 llama.cpp Vulkan；Qwen3-ASR 1.7B FP16 + mmproj；返回带内置标点的 Final 文本。 VAD、分段、Preview、CPU ASR、前端 IPC。
模型包 SenseVoice 基础包 + 可选 FireRed / Qwen Final 包；权重、清单、SHA、VAD / Punc。 不包含运行时库、不写日志、不联网。
GPU runtime 包 按模型 + OS + EP 拆分的 worker 二进制与 runtime 库；可选安装。 不进入模型目录，不被 active 直接选择。

  • Preview 由 daemon 的全局配置 preview.enabled 控制，默认 true；它不依赖 Final 包的 asr.options.partial。
  • Preview 永远不发往任一 GPU worker；worker 只接收完整语音段做 Final。
  • Final 选择 SenseVoice 时，Preview 与 Final 使用同一模型；Final 选择 FireRed / Qwen 时，Preview 仍是 SenseVoice。
  • FireRed 的标点由 FireRed worker 内的 FireRedPunc 处理；Qwen 与 SenseVoice 使用模型内置标点。
  • Final 直接输入，不改变现有呈现；Preview 只是临时候选，文本差异接受。
  • 任一 GPU Final 失败时回退 CPU SenseVoice Final；Preview 不中断；不加载 CPU AED / CPU Qwen。
  • 错误文案统一为 ASR 推理失败，不要把 Final 后端名称写死在前端或日志里。

4.3 SenseVoice CPU 推理契约

SenseVoice 是常驻后端：所有 Preview 都由它处理，CPU 档的 Final 也用它。包固定为 sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17， use_itn=1，punc=builtin；不再维护 noITN + FireRedPunc 变体。 GPU 档仍然加载它做 Preview，FireRed / Qwen 只负责 Final。

项目契约
模型234M 参数，int8 ONNX 约 229 MiB；输出 25055 类；固定 2024-07-17 权重。
fbank80 bin、25 / 10 ms、hamming 窗、snip_edges=true、normalize_samples=0（输入乘 32768）。
LFR窗口 7、帧移 6；保持当前完整窗口实现，不在本提案中切换边缘策略。
CMVN560 维；(x + neg_mean) * inv_stddev；长度必须等于 80 × 7。
输入x[1,T,560] f32、x_length[1] i32、language[1] i32、text_norm[1] i32。
输出logits[1,T',25055] f32。
解码贪心 CTC：argmax → 合并重复 → 去 blank 0；有效长度 min(T', T + 4)，跳过前 4 个语言 / 情感 / 事件 / 文本规整 token。
语言auto=0、zh=3、en=4、yue=7、ja=11、ko=12；默认 auto，不硬编码 zh。
ITN固定 use_itn=true；with_itn=14、without_itn=15；Partial 与 Final 使用同一模式。
标点模型内置；不加载 FireRedPunc。
Partial支持；所有 Preview 固定用它，CPU Final 也用它；沿用同一 text_norm，不额外加标点。
最大段长建议 20 s；用 20 / 30 s 样本验证后再冻结。
  • ONNX metadata 必须提供 lfr_window_size、lfr_window_shift、normalize_samples、vocab_size、blank_id、with_itn / without_itn、语言 id、neg_mean / inv_stddev；清单只声明期望值，启动时交叉校验。
  • 不要从 tokens.txt 推断语言 / ITN id；模型升级后容易错位。
  • SenseVoice 是常驻基础包：默认安装只装它；--firered / --qwen3 也必须安装它，GPU 只替换 Final。

5.1 目标与非目标

目标非目标
SenseVoice Preview 与 CPU Final 留在 daemon；GPU Final 放进模型专用 worker；CPU Final 不启动 worker。 不做 CPU runtime 独立进程；SenseVoice 本来就是常驻路径，再拆一个进程只增加 IPC 与生命周期成本。
两个 worker 与 daemon 库隔离；任一 GPU 崩溃不能带崩 CPU 路径。 不在 daemon 内直接加载 GPU runtime；不做线程级“伪隔离”。
每个模型有独立编译的后端模块与 runtime 包；可单独安装 / 升级 / 卸载。 不引入通用 GPU runtime 插件或动态 EP 发现；程序按 kind 硬编码映射。
CPU 路径无 GPU 依赖；GPU Final 不可用时 Final 回退 CPU SenseVoice，Preview 不中断。 不做 CPU AED / CPU Qwen；GPU 失败不自动加载大模型 CPU 路径。
GPU 只做 Final；Preview 固定由 CPU SenseVoice 提供。 不通过重复运行非流式模型伪造 Partial；不把任一 GPU worker 作为 Preview 后端。

5.2 方案比较

方案收益代价 / 风险结论
A. 在 daemon 内直接加载 GPU runtime 实现最短；复用 pipeline。 GPU 库进入 daemon；CPU 路径无法保证不加载；GPU 崩溃带崩 daemon。 不采用。
B. 单一通用 worker，按 manifest 动态加载 runtime 一个二进制覆盖所有模型。 动态插件 / ABI / EP 选择复杂；两个模型的前端与 decode 差异大；故障面扩大。 不采用。
C. 两个模型专用 worker，硬编码映射 每个后端只带自己的 runtime；隔离清晰；可按模型优化；CPU 路径干净。 两个构建单元与 runtime 包；CI / 发布矩阵变大。 采用。
D. 外部推理服务器（Python / vLLM） 生态成熟；Qwen 吞吐高。 Python / PyTorch / ROCm 依赖重；启动慢；桌面安装复杂。 只做离线评测。

5.3 worker 生命周期

  • daemon 启动时加载 SenseVoice Preview；Final 按 active 选择 CPU SenseVoice、FireRed 或 Qwen；只有 GPU Final 才启动对应 worker。
  • Final 选择 CPU SenseVoice 时两个 worker 都不启动；切换到 CPU Final 时先停 worker，释放显存，Preview 继续。
  • worker 退出即释放 GPU 内存；daemon 不持有 GPU 会话，也不初始化 GPU。

6.4 为什么否决文本后处理

问题结论
质量规则层覆盖有限；文本模型存在过度纠正、幻觉与语义改变风险。
延迟pipeline 单线程串行；增加一次文本推理会直接抬高收尾延迟。
维护需要额外模型、分词器、词表、清单字段、守卫、回退、测试与许可证。
定位产品链路只需要 ASR 文本；不做通用润色、改写、摘要或翻译。

9. 风险

↑

已接受的取舍：SenseVoice 常驻带来的 CPU / 内存开销可接受；Preview 与 Final 文本不一致可接受， Final 直接输入、不做呈现变化；Fcitx 动态枚举不可用时模型列表留空，不做补偿动作。

风险影响缓解
预卷把前一段尾音带入段首重复、串音或 CER 退化。从 200 ms 起测；按 PTT / Continuous 分别验证；端点延迟不退化；过长时回退。
ORT / ort 版本漂移或升级回归CPU int8 输出 / 延迟发生不可控变化；ort 升级可能编译失败。每个发布锁定 ORT 版本与 build info；ort 实验每次只升一个版本；目标语料 + 黄金文本双门槛；保留 rc.12 回退。
GPU 运行时泄漏进 daemonSenseVoice Preview / CPU Final 启动时被迫加载 Vulkan / CUDA，违背“CPU 不依赖 GPU”的目标。voimed / voime-core 只链接 CPU ORT；不依赖 worker crate；GPU 分进程、分 runtime 目录；CI 检查动态依赖与 /proc/<pid>/maps。
两个 GPU 后端维护成本两套模型包、runtime、CI 与文档；容易只测一个。共享 worker 协议 / 生命周期；每个后端独立金样与性能基线；发布回归两个都跑；不保留第三后端。
OpenASR 成熟度pre-v1；模型包格式 / API 可能变化；FireRed 路径依赖其实现。固定版本 / commit；对 FireRed 后端做协议隔离；保留 llama.cpp / 其他运行时作为替代评估；不把 OpenASR API 暴露给 daemon。
llama.cpp Qwen 支持Qwen3-ASR 音频路径仍标 experimental；输出带 language ... 标签；版本漂移。固定包含 Qwen3-ASR 支持的 release；worker 内解析 / 去标签；金样覆盖；升级前重跑目标语料。
FP16 数值稳定性极端样本出现重复、空输出或退化。F16 与 BF16 对照；目标语料 + 噪声 / 长段测试；FP16 失败即失败，不回退 FP32 / int8。
显存不足 / 热降频Qwen 约 5.2 GB，FireRed 约 2.6 GB；低显存卡可能失败或抖动。声明 min_vram_mb；加载前检查；失败保留旧 Final 或回退 CPU SenseVoice；Preview 继续。
模型包体积 / 安装时间SenseVoice 229 MiB + FireRed 2.4 GB + Qwen 4.4 GB；首次安装慢。按选项安装；默认只装基础包；runtime 独立；记录体积；不提交权重。
Windows / Vulkan 驱动差异不同 GPU / 驱动下 Vulkan 行为不一致；Windows 未实测。P0 先 Linux；Windows 作为 P1 单独验收；doctor 预检；失败回退 CPU。
英文 / 标点差异FireRed 输出无标点 / 全大写；Qwen 自带标点 / 大小写。FireRed worker 内 Punc；英文以 Qwen 为优先；质量门禁单列标点 / 大小写。
运行时包可执行文件安全runtime 包携带任意代码。只信任签名运行时；禁止模型包自带可执行文件；安装需显式 opt-in。
--firered / --qwen3 缺少 SenseVoice 依赖GPU Final 能装但 Preview / CPU Final 不可用。安装脚本强制安装并校验 requires；ListModels / doctor 报错；不允许只装 GPU 包。
模型包 SHA 变化官方重新上传导致校验失败。安装脚本重新计算并写入；运行期只信任本地清单。
active 或 SenseVoice 基础包缺失 / 错误启动失败、Final 加载错误，或 GPU 档缺少 Preview。启动时校验 Final + SenseVoice 基础包 / manifest / SHA / kind / requires；doctor 显示两者与解析目录；回滚只改 Final 指针。
重启 Final 加载失败新 Final 不可用。先校验再停旧 Final；失败时回滚 active 并恢复旧 Final；Preview 不受影响；旧 Final 也失败才退出 daemon。
前端协议不匹配旧 Fcitx / 旧托盘无法连接。daemon 与两个前端同版本发布；旧前端收到 VersionMismatch 并提示升级。
UI 选择与 active 不一致用户以为已切换但仍在旧模型。打开界面时读取 active；选择后显示“待重启”；ListModels 同时返回 active / running。
旧版本升级 / 旧包混淆旧包被拒绝；用户可能误装 CTC / punc / CPU 大模型。旧包明确拒绝；安装脚本只提供新选项；迁移脚本只覆盖上一版本 + 当前开发机。
