提案 — SenseVoice 可选后端、包级切换与重启后端

README USER CORE PROVIDER BUILD ｜ 状态：待评审 · 未实现 · 2026-10-31

本文验证“用 SenseVoice 替换 FireRedASR2-CTC 以降低错别字”的假设，并给出可选的迁移方案。 结论先行：技术可行，但“换 SenseVoice 就能减少错别字”目前没有证据支持，且大概率不是中文听写场景的精度升级。 SenseVoice 的定位是速度、多语种与内置 ITN，不是中文精度；迁移只使用 2024-07-17 版本，2025-09-09 是粤语微调版，已排除。 如果目标是精度，优先评测同一模型家族的 FireRedASR2-AED；SenseVoice 可以作为可选的快速 / 多语种后端保留。

决策更新（2026-10-31）：已确认不做运行时热切换，采用模型包级切换。 二进制一次构建同时支持 FireRed CTC 与 SenseVoice；之后切换只改模型目录 / models/active 指针并重启后端， 不重新安装、替换或重新编译任何二进制。首次获得 SenseVoice 支持仍需要一次正常的版本升级。 配置界面可以选择已安装模型：Windows 设置窗口提供模型下拉与“重启后端”按钮；Linux Fcitx 配置页提供模型下拉，保存配置即触发重启后端。

1. 摘要

↑

决策点建议
是否替换默认 ASR 否。默认继续使用 FireRedASR2-CTC；SenseVoice 先作为可选后端，不改变现有用户行为。
SenseVoice 选型 统一使用 sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17；不引入 2025-09-09。
切换方式 模型包级切换：固定模型根目录 + models/active 指针（或 --model-dir 显式覆盖）；切换 = 改指针 + 重启后端。不重装二进制，不做双模型常驻热切换。
配置入口 Windows 设置窗口：模型下拉 + “重启后端”按钮；Linux Fcitx 配置页：模型下拉，保存 / Apply 等同“重启后端”。另提供 voime ctl restart-backend 作为跨平台命令入口。
重启语义 只重建 ASR pipeline（停采集 / 卸载旧后端 / 加载 active / 重建 pipeline），不重启 daemon、不换二进制；要求空闲，录音中拒绝。
IPC 新增 ListModels / SetModel / RestartBackend 与对应状态消息；PROTOCOL_VERSION 提升到 2，两个前端一起升级。
精度升级路径 FireRedASR2-AED 纳入迁移，作为精度档；SenseVoice 作为速度 / 多语种档；三者通过同一配置界面切换。是否默认由 Phase 0 评测决定。
自由切换成本 包级切换 + 配置界面 + 重启后端包含在接入成本内；运行时热切换已确认不做，不纳入成本。
质量门禁 目标语料上 CER 相对下降 ≥ 10%，且任一类别不回归超过 2%；否则不切换默认后端。
初步成本 SenseVoice + FireRed AED 两个可选后端 + 包级切换 + 配置界面 / 重启后端约 19–30 人日；不含语料标注与模型下载时间。
  • 本文中的“SenseVoice”指 SenseVoiceSmall 的 sherpa-onnx 模型包，不是 sherpa-onnx 运行时；本项目仍然直接使用 ONNX Runtime。
  • 当前 README §1.3 的非目标写着“不引入第二个 ASR 模型”；接受本提案意味着要把该条改为“默认只运行一个 ASR 后端，可选模型包不并行加载”。
  • 如果只是验证效果，Phase 0 不需要改 Rust：用 sherpa-onnx Python API 在目标语料上做 A/B 即可，成本主要是语料标注；确认有效后再进入 Phase 1。
  • 本文是设计提案，不是产品契约；实现完成后，行为应迁移到 USER / CORE / PROVIDER / BUILD 的所有者章节。

按“田忌赛马”的定位，三个后端对应三档：FireRed CTC 最快、错别字多；SenseVoice 是中间档，速度接近 CTC、精度待验证；FireRed AED 最慢、精度最高。 包级切换的目录与 active 机制不绑定具体后端；CTC / SenseVoice / AED 已纳入，未来新增其他后端仍只需新增 AsrKind / 模型包，切换方式不变。

2. 目标与非目标

↑

2.1 目标

  • 验证 SenseVoice 是否能降低目标场景的错别字，而不是只改变错误分布。
  • 在不破坏现有 FireRedASR2-CTC 行为的前提下，引入可选的 SenseVoice 后端。
  • 支持模型包级切换：同一份代码可以加载 FireRed CTC 或 SenseVoice，不需要改代码、不需要重编译。
  • Windows 与 Linux 配置界面可以列出已安装模型并选择；选择后通过“重启后端”生效。
  • 复用现有 VAD、分段、音频采集、IPC、前端提交与 ONNX Runtime 边界。
  • 失败可回滚：SenseVoice 包缺失、校验失败或推理失败时，不影响 FireRed 包继续使用。
  • 为后续 FireRedASR2-AED、上下文偏置或重打分留出同一接缝。

2.2 非目标

  • 不承诺 SenseVoice 一定提升精度；不以“换模型”替代评测。
  • 不实现运行时双模型热切换，也不在录音 / 识别过程中切换后端；切换通过包级指针 + 重启后端完成。
  • 不在重启后端时静默丢弃当前录音；录音中请求重启必须被拒绝并提示用户。
  • 不引入第二个推理框架、GPU / NPU、Python 运行时或云端 API。
  • 不改变 IPC 消息、Final 语义、前端提交规则或目标绑定规则。
  • 不做模型微调、领域自适应训练或通用文本润色；如需领域适配，另立提案。
  • 不把 SenseVoice 的语言 / 情感 / 事件标签暴露给前端；一期只消费文本。

3. 现状与约束

↑

当前最终识别路径只有 CTC 与标点两个文本阶段：

Worker::finalize(segment)
├── Fbank::compute(segment.samples)
├── FireRedCtc::transcribe(features)
├── FireRedPunc::punctuate(&asr.text)
└── PipelineEvent::Final(text)
现有约束对 SenseVoice 的影响
项目直接使用 ort，不链接 sherpa-onnx 运行时 “同属 sherpa-onnx 模型包”只复用文件格式与 ORT，不复用 sherpa 的预处理 / 解码代码；SenseVoice 的 LFR、CMVN、四输入与特殊 token 需要在项目内实现。
ModelManifest::load 只接受 kind = "fire-red-ctc" 必须把 kind 变成可扩展的后端选择；否则 SenseVoice 包在启动时直接被拒绝。
punc 清单是必填，Worker::new 总是构造 FireRedPunc SenseVoice 可以用内置 ITN + 标点，或者继续使用 FireRedPunc；需要把标点策略变成清单字段，并允许 punc 缺省。
fbank 固定 80 bin、25 / 10 ms、默认窗函数、输入乘 32768 SenseVoice 需要 80 bin、25 / 10 ms，但窗函数必须是 hamming；需要把窗函数纳入清单 / FbankConfig。
CTC 输入 x[1,T,80] + x_lens[1]，输出 8667 类 SenseVoice 输入 x[1,T,560] + x_length + language + text_norm，输出 25055 类；需要 LFR 7/6 与 560 维 CMVN。
pipeline 只有一个工作线程，VAD / ASR / 标点串行 SenseVoice 单次推理更快，对收尾延迟有利；但 LFR / CMVN / 特殊 token 解析不能放进音频回调线程。
max_segment_ms 默认 30000 SenseVoice 官方示例的 VAD 段上限通常更短；建议 SenseVoice 包用 20000 ms，并用 20 / 30 s 样本验证长段稳定性。
模型清单是唯一契约；SHA-256、张量、词表都在启动时校验 SenseVoice 的 ONNX metadata 也要参与校验：LFR、CMVN、blank、ITN、语言 id 必须存在且与清单一致。
运行期不联网、不使用 GPU / Python；模型只读 模型下载与 SHA 写入仍然只在安装脚本中完成；运行期只读本地文件。
Fcitx 配置页由 FCITX_CONFIGURATION 自动生成 不能随意加按钮；模型下拉可用 EnumAnnotation 动态枚举，保存 / Apply 触发 setConfig，可在此时发送 SetModel + RestartBackend。
Windows 设置窗口是独立 egui 进程，托盘持有 daemon 子进程 下拉与按钮容易实现；重启请求应由托盘或设置进程通过 IPC 发给 daemon，不能直接杀进程。
Fcitx 是 C++ IPC，Windows 是 Rust IPC 新消息必须同时改两端与协议版本；不能只改 Rust 侧。
Linux 用 systemd，Windows 用托盘托管 daemon “重启后端”做成 daemon 内部重建 pipeline，避免依赖 systemd / 托盘各自重启进程。
  • “切换成本最小”只对模型下载、文件格式和 ORT 会话成立；代码侧仍有中等成本，不能按“只换一个 ONNX 路径”估算。
  • 现有 FireRedCtc 的 CMVN 在 80 维 fbank 上做；SenseVoice 的 CMVN 在 LFR 后的 560 维上做，二者不能共用同一段实现。

技术结论：可行，但不是“零成本切换”。 模型包替换本身很简单，代码侧需要新增 SenseVoice 预处理、四输入、特殊 token 解码与标点策略；规模大约是一个新 ASR 模块加清单 / pipeline 改造。

FireRed AED 项目契约 / 影响

预处理80 维 fbank + CMVN，与 FireRed CTC 相同；无 LFR。

4.4 结论

原假设验证结果
“已经在用 sherpa-onnx 跑 FireRedASR2” 看指什么。 如果指 sherpa-onnx 模型包，成立；如果指运行时，不成立——当前项目直接使用 ort，只复用模型文件与 ORT 会话。
“都是 sherpa-onnx 模型包，切换成本最小” 部分成立。 模型包、ORT 会话、词表格式可以复用；但预处理、四输入、特殊 token、标点策略需要新代码，属于中等成本。
“换 SenseVoice 能减少错别字” 不成立 / 证据不足。 公开数据与冒烟样例都不支持 SenseVoiceSmall 在普通话上优于 FireRedASR2；它更可能改变错误分布，而不是减少替换错误。
“后处理不满意，所以换模型” 方向可以理解，但选错了对照。 更值得先比较的是 FireRedASR2-AED（同家族、同语料、同标点）与 CTC + 上下文偏置 / 重打分；SenseVoice 不是精度对照的第一选择。

因此，本文建议把目标从“用 SenseVoice 替换 FireRed”改成： 先建立一个可重复的 A/B 评测，确认错别字到底来自声学模型、CTC 解码、ITN 还是领域词；再决定是否引入 SenseVoice 作为可选后端。 如果评测显示错别字主要来自 CTC 分支，FireRed AED 的收益会比 SenseVoice 更直接。

5. 方案选型

↑

方案收益代价结论
A. 直接用 SenseVoice 替换 FireRed CTC 模型更小、更快、多语种、内置 ITN。 普通话精度大概率下降；标点 / ITN 行为改变；需要新后端代码；许可证待确认。 不采用。
B. SenseVoice 作为可选后端，模型包级切换 保留 FireRed 默认行为；可对特定场景（粤语、多语种、低算力）启用；切换只改模型目录 / 指针，不重装二进制。 新增一个 ASR 模块与清单分支；同一 voimed 内需要维护多个 ASR 实现路径；模型包体积增加（按目录分开）。 采用。 作为实验 / 特定场景后端，不改变默认；已确认不做热切换。
C. 运行时热切换（同进程双后端） 用户可在设置里切换，无需重启。 双模型内存、会话状态、Partial 一致性、并发与生命周期复杂；与“默认只跑一个 ASR”冲突。 不做。 用户已明确不需要；切换通过包级指针 + 重启完成。
D. FireRedASR2-AED 作为精度升级 同家族、同语料、同标点；冒烟样例中明显修正 CTC 的同音 / 中英混合错误。 需要实现 encoder + decoder 自回归贪心解码（sherpa 目前只支持 greedy_search）；模型约 1.2 GB；RTF 约 0.2–0.4，收尾延迟更高；Partial 建议关闭。 纳入迁移计划。 作为第三个包与 CTC / SenseVoice 并列，可通过同一配置界面切换；是否默认由 Phase 0 评测决定。
E. CTC Partial + AED Final 混合 Partial 低延迟，Final 高精度。 两个模型常驻；Partial / Final 文本可能不一致；内存与复杂度最高。 未来选项。 不在本提案范围。
  • 方案 B 与 D 不互斥：本提案把 AED 作为第三个包纳入迁移，但实现按 Phase 分步；先复用同一 AsrBackend / active / 重启后端机制。
  • 如果最终目标只是“减少错别字”，D 的精度价值最高；B 的价值主要是速度、多语种与低资源。
  • “多后端”定义：本文指同一个 voimed 二进制内的多条 ASR 实现路径（FireRed CTC / SenseVoice / FireRed AED），不是两个 voimed 版本、不是两个 daemon、也不是两套安装包。发布仍是一个 voimed 版本；维护成本是测试、文档与模型契约的多路径覆盖。

6.1 目标架构

SenseVoice 的 transcribe 顺序固定如下：

SenseVoice::transcribe(features)
├── 判断 features.is_empty() → AsrOutput::default()
├── ApplyLfr(features, self.lfr_window, self.lfr_shift) → lfr_frames
├── 判断 lfr_frames 的维度 == 560
├── 逐帧 (x + neg_mean) * inv_stddev → cmvn_frames
├── 构造 x[1, T, 560] f32
├── 构造 x_length[1] i32 = T
├── 构造 language[1] i32
├── 构造 text_norm[1] i32 = with_itn / without_itn
├── Session::run({x, x_length, language, text_norm})
├── 取 logits[1, T', 25055]
├── valid = min(T' , T + 4)
├── greedy_decode(logits, valid, 25055) → ids
├── 判断 ids.len() >= 4 → 跳过前 4 个特殊 token
└── CtcTokenizer::decode(ids[4..])
  • greedy_decode 可复用现有实现；它已经处理 blank 0、连续重复与越界。
  • “跳过前 4 个解码 token”与 sherpa 的 ConvertSenseVoiceResult(start=4) 对齐；不是跳过前 4 帧。
  • 如果 ids 少于 4 个，说明模型没有输出完整的语言 / 情感 / 事件 / 文本规整前缀；应返回错误或空文本，而不是把剩余 token 当正文。
  • text_norm 不能只当格式开关：冒烟中 zh.wav 的 noITN 输出“开饭”，ITN 输出“开放”；两种模式必须分别评测。
  • 现有 greedy_decode 固定 blank 0；SenseVoice metadata 的 blank_id 也是 0，一期可以先断言 blank_id == 0，未来再把 blank 参数化。
  • 普通话为主时建议同时评测 language=zh 与 auto；固定 zh 可减少短段语言误判，但会失去多语种自动路由。

FireRed AED 使用独立的 encoder + decoder 两个 ONNX 会话：

pub struct FireRedAed {
    encoder: Session,
    decoder: Session,
    tokens: CtcTokenizer,
    cmvn_mean: Vec<f32>,
    cmvn_inv_stddev: Vec<f32>,
    sos_id: i32,
    eos_id: i32,
    max_len: usize,
    max_token_per_second: usize,
    num_decoder_layers: usize,
    num_head: usize,
    head_dim: usize,
    encoder_input_names: [String; 2],
    encoder_output_names: [String; 2],
    decoder_input_names: [String; 6],
    decoder_output_names: [String; 3],
}
FireRedAed::transcribe(features)
├── 判断 features.is_empty() → AsrOutput::default()
├── 逐帧 (x - cmvn_mean) * cmvn_inv_stddev → 80 维 fbank
├── 构造 x[1, T, 80] f32 / x_len[1] i64
├── encoder.run({x, x_len}) → cross_k / cross_v
├── 按 metadata 分配 self KV cache（num_decoder_layers / num_head / head_dim）
├── decoder.run(tokens=[sos], self_k, self_v, cross_k, cross_v, offset=0)
├── 循环：argmax(logits) → 追加 token / 更新 self KV cache / offset
├── 停止条件：eos / max_len / max_token_per_second
└── CtcTokenizer::decode(ids)
  • AED 的 fbank / CMVN 与 FireRed CTC 一致：80 维、povey 窗、normalize_samples=false、high_freq=0、snip_edges=true；不做 LFR。
  • sherpa-onnx 当前对 FireRed AED 只实现 greedy_search；本提案先对齐贪心解码，beam search 作为后续优化，不进入一期验收。
  • decoder 使用自回归 KV cache；不能复用 CTC 的 greedy_decode。必须从 encoder metadata 读取 sos / eos / max_len / cache 形状。
  • AED 默认 partial=false；如果 Phase 0 证明预览可接受，再通过 AsrOptions.partial 打开。
  • AED 标点固定 External，使用 FireRedPunc；与 SenseVoice 的 Builtin 互斥。

Windows 设置窗口 “模型”下拉列出已安装包；显示“当前运行 / 已选择”；“重启后端”按钮。--model-dir 固定时下拉禁用。 点击“重启后端”；若选择已变化，先 SetModel 再 RestartBackend。 设置窗口内显示进度 / 错误；失败时保留旧模型与旧选择。
Linux Fcitx 配置页 “模型”下拉由 EnumAnnotation 动态枚举已安装包；没有额外按钮。 点击配置页的“保存 / Apply”触发 setConfig；模型变化时发送 SetModel + RestartBackend。 写入 voimed 日志；voime doctor / voime ctl restart-backend 显示错误；配置页保留旧选择。
跨平台命令 voime ctl models 列出包；voime ctl use <id> 写选择；voime ctl restart-backend 重载。 显式命令；适合脚本、排障和无 GUI 环境。 命令返回非零并打印错误；不改变旧 pipeline。
  • Fcitx 配置页由 FCITX_CONFIGURATION 自动生成，不能任意加按钮；“保存 / Apply”就是原生重启入口。若必须有一个独立按钮，应加到 voime TUI 或独立设置程序，而不是修改 Fcitx 配置页。
  • Windows 设置窗口是独立进程；模型操作通过 voime-ipc 连接 daemon，不直接杀进程。托盘仍负责 daemon 子进程生命周期。建议新增 SettingsAction::RestartBackend，在现有动作线程中建立 Control 连接，避免阻塞 egui UI。
  • 选择写入后到重启完成前，界面必须显示“待重启”；不要显示为已生效，也不要在录音中自动重启。
  • Fcitx setConfig 要把“模型变化”和“模式 / 热键变化”分开：模型为空或等于当前 active 时只发 Configure，只有非空且变化时才发 SetModel + RestartBackend。
  • 重启后端不改变历史、不改变目标窗口；只影响之后的 Partial / Final 使用哪个模型。

6.8.2 IPC 契约

pub const PROTOCOL_VERSION: u32 = 2;

pub enum ClientMessage {
    /* ... 现有消息 ... */
    ListModels,
    SetModel { package_id: String },
    RestartBackend,
}

pub struct ModelInfo {
    pub id: String,           // 包目录名，例如 sense-voice-2024
    pub display_name: String, // manifest.display_name，缺省用 id
    pub kind: String,         // fire-red-ctc / sense-voice / fire-red-aed
    pub active: bool,         // 与 active 指针一致
    pub running: bool,        // 与 daemon 当前 Config 一致
}

pub enum BackendPhase {
    Restarting,
    Ready,
    Failed,
}

pub enum ServerMessage {
    /* ... 现有消息 ... */
    Models { models: Vec<ModelInfo> },
    ModelSelected { package_id: String },
    BackendState {
        phase: BackendPhase,
        model: Option<ModelInfo>,
        message: Option<String>,
    },
}
消息允许角色行为
ListModelsFrontend / Tui / Control扫描模型根目录；跳过无 manifest.json 或无法解析的目录；返回 active / running 标记。
SetModelFrontend / Control校验 package id 与目录；写 active；不加载模型；返回 ModelSelected。显式 --model-dir 时拒绝。
RestartBackendFrontend / Control仅空闲时执行；加载 active，重建 pipeline；返回 BackendState。
  • 新增消息变体需要提升 PROTOCOL_VERSION；旧前端会收到 VersionMismatch。Fcitx 与 Windows 前端必须同版本发布。
  • SetModel 只做结构校验（目录、manifest、kind、路径安全），不做全量 SHA；全量校验在 RestartBackend 加载时完成。
  • active 写入必须原子：同目录临时文件 + rename；失败时保留旧值。
  • RestartBackend 在录音 / 识别中返回 ErrorCode::Busy；前端按钮应在此之前禁用。
  • 显式 --model-dir 时，ListModels 只返回当前包（running=true，active=false）；前端禁用模型下拉，SetModel 返回错误。

6.8.3 重启后端流程

  • 重启后端只重建 pipeline，不重启 daemon，也不替换二进制；IPC 连接保持不变。
  • 录音 / 识别中拒绝重启；不会静默丢弃当前段。
  • 加载失败时回滚 active 并恢复旧 pipeline；旧 pipeline 也无法恢复时 daemon 退出，由 systemd / 托盘重启。
Daemon::restart_backend()
├── 判断 phase != Idle || current_segment.is_some() → Error(Busy)
├── 保存 old_config / old_model_id
├── config::resolve(args.clone()) → new_config
│   ├── 读取 active
│   ├── 校验 manifest / SHA / 张量 / 词表
│   └── 失败 → 回滚 active + 返回 BackendFailed
├── 广播 BackendState { phase: Restarting }
├── pipeline.shutdown()
├── audio.stop()
├── 创建新的 audio channel / pipeline / capture
├── 判断 新 pipeline 启动失败
│   ├── 回滚 active 为 old_model_id
│   ├── 尝试用 old_config 重建旧 pipeline
│   └── 旧 pipeline 也失败 → daemon 退出
├── 替换 self.config / self.pipeline / self.audio
└── 广播 BackendState { phase: Ready, model }

`Daemon` 需要保存启动参数（至少 `model_dir` 覆盖、输入设备、线程数），才能在重启时重新解析 `active`； `Config` 需要保存 `model_root`、`model_id` 与 `model_dir_override`，供 `ListModels` / `SetModel` / 回滚使用。

  • RestartBackend 是同步操作：daemon 主循环会阻塞到新模型加载完成；期间前端应显示“重启中”，不要发送 Start。
  • 模型加载可能耗时数秒；前端等待超时不应误判失败，应以 BackendState 或重连后的 ListModels 为准。
  • 如果用户在重启中关闭设置窗口，daemon 仍应完成重启；不要依赖前端连接存活。
  • 实现上建议把 Daemon 的 pipeline / audio 改为可替换的 Option 或提供 take/stop 辅助，避免在 Drop 中隐式停止导致重启路径不可控。

  • “CER 下降”与“错别字下降”不是同一个指标；必须单列替换错误率，否则插入 / 删除错误会掩盖问题。
  • 统计显著性建议用配对 bootstrap 95% 置信区间；只报平均值不够。

8.3 决策规则

结果决策
SenseVoice 相对 FireRed CTC：CER 下降 ≥ 10%，替换错误率下降 ≥ 10%，无类别回归 > 2%，内置标点 F1 / ITN 达标，20 / 30 s 长段稳定 可以把 SenseVoice 设为该场景的默认后端；仍保留 FireRed 包回滚。
SenseVoice 只在部分类别（如粤语、英文、多语种）更好 保留为可选后端；按语言 / 场景选择模型包，不做全局默认替换。
SenseVoice 没有显著提升，或普通话 / 专名 / 长段回归 不切换默认；保留实验后端或直接删除，避免同一 voimed 内长期维护多条后端路径。
FireRed AED 通过精度与 20 / 30 s 长段门禁，延迟在 AED 预算内 优先把 AED 作为精度升级；SenseVoice 只保留速度 / 多语种价值。
两者都不通过 保持 FireRed CTC；转向上下文偏置、术语表、重打分或数据侧改进。

10. 风险与待决策

↑

风险影响缓解
普通话精度回归错别字更多，用户直接感知。Phase 0 A/B；不达标不切换默认；保留 FireRed 包。
标点重复 / 缺失文本可读性下降。builtin 与 external 互斥；不做双标点；单独评测标点 F1。
ITN 不一致数字 / 日期格式与 FireRed 行为不同。按后端固定 use_itn；不要 Partial / Final 混用；评测 ITN 准确率。
许可证无法随安装包分发 SenseVoice 权重。Phase 0 完成模型许可证评审；未通过则只允许本地实验或放弃。
多 ASR 实现路径维护同一个 voimed 内三套 ASR 实现（CTC / SenseVoice / AED）的测试、文档、模型契约成本增加；不是两个 daemon 或两个版本。只有 Phase 0 证明有明确场景价值才保留；否则删除实验后端；共享 pipeline / active / 重启后端机制。
长段稳定性SenseVoice / AED / CTC 在 20–30 s 段上可能截断、重复或 CER 上升。Phase 0 纳入 20 / 30 s 长段评测；SenseVoice 默认 20 s；AED 与 CTC 用 30 s；不达标记为不可默认。
AED 内存 / 延迟两个 ONNX 会话 + KV cache，RSS 与收尾延迟明显高于 CTC；Partial 可能拖慢实时。默认 partial=false；单独 RSS / 延迟预算；加载失败回滚；只在精度收益足够时启用。
模型包 SHA 变化官方重新上传导致校验失败。安装脚本重新计算并写入；运行期只信任本地清单。
active 指向错误 / 缺失启动失败或加载错误包。启动时校验目标 manifest.json / SHA / kind；doctor 显示 active 与解析目录；回滚只改指针；旧布局兼容。
重启后端加载失败新模型不可用，用户当前无法听写。先校验再停旧 pipeline；失败时回滚 active 并恢复旧 pipeline；旧 pipeline 也失败才退出 daemon。
协议 v2 不兼容旧 Fcitx / 旧托盘无法连接。daemon 与两个前端同版本发布；旧前端收到 VersionMismatch 并提示升级；不静默降级。
Fcitx 动态枚举不可用配置页无法列出模型。退化到固定 enum（当前已知包）+ voime ctl use；不退回自由文本不校验。
UI 选择与 active 不一致用户以为已切换但仍在旧模型。打开界面时读取 active；选择后显示“待重启”；ListModels 同时返回 active / running。
Windows 设置进程无权限 / daemon 未启动点击重启失败。只写 active 并提示“下次启动生效”；由托盘启动 daemon；不直接杀进程。
与 README 非目标冲突产品文档自相矛盾。接受提案时同步修改 README §1.3，明确“默认单后端，可选包不并行加载”。

需要产品 / 维护者确认的事项：

  1. 目标场景是纯普通话听写，还是中英混合 / 多语种 / 粤语？这决定 SenseVoice 是否有价值。
  2. 是否接受 FireRed AED 带来的 3–6× 收尾延迟？如果接受，AED 应优先评测。
  3. SenseVoice 权重的许可证是否允许随安装包分发？
  4. 已确认只要包级切换、不做运行时热切换；配置界面选择 + “重启后端”已纳入设计。剩余要确认：Fcitx 是否接受“保存 / Apply 即重启”，还是必须在 voime TUI 里再做一个独立按钮。
  5. 是否接受 PROTOCOL_VERSION 提升到 2、两个前端必须同版本升级？如果不接受，需要另设兼容层。
  6. 是否接受在同一个 voimed 版本内长期维护三条 ASR 实现路径（CTC / SenseVoice / AED）？这不是两个 daemon / 两个二进制；如果只是实验，建议 Phase 0 后删除失败方案。
