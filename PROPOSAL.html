PROPOSAL — Voime 作为真正的输入法

1. 结论与决策

↑

可行。Hyprland 0.52.1 起支持 zwp_input_method_manager_v2。Voime 像 Fcitx5 一样成为 该 seat 上唯一的输入法：通过 zwp_input_method_v2 的 grab_keyboard 接收键盘事件， 在其中匹配 PTT 热键；通过同一个对象的 commit_string 把最终文本写入当前 text-input-v3 输入框。非 PTT 按键由 Voime 通过 zwp_virtual_keyboard_v1 原样转发，用户仍然可以正常打字。

这才是“Voime 取代 Fcitx5”的完整含义：占用同一个 input-method-v2 位置，接管键盘， 同时承担热键与上屏，而不是在输入法之外用 GlobalShortcuts portal 另挂一个热键。Wayland 每个 seat 只允许一个 input-method-v2 对象；Fcitx5 必须先停用。若 seat 已被占用，Voime 收到 unavailable 后按启动失败处理，并提示停用 Fcitx5 / IBus，不降级为粘贴：没有输入法对象 就没有键盘抓取，也就没有 PTT。XWayland 不使用 text-input-v3，commit_string 到不了，但 XWayland 使用 XIM：Voime 同时注册 XIM server，最终文本通过 XIM_COMMIT 直接送进 X11 应用；只有 XIM 也不可用时才回退剪贴板 + 粘贴。PTT 与普通按键转发不受影响。

决策项结论
目标平台 Hyprland / Wayland 优先；XWayland 兼容；X11 与 Windows 只预留适配接口，本版不实现。
ASR 模型 final 与现有尾部 partial 都改用 FireRedASR2-CTC int8（单 ONNX，直接 ort）；只做 CPU 推理加速，沿用现有 VAD 分段。
PTT 上限与倒计时 PTT 硬上限固定 30 s；TUI 在录音红点旁显示独立状态行 ● Remaining: xx s；达到 30 s 自动结束当前句并立即开始下一段。continuous 不显示倒计时。
与 Fcitx5 的关系 Voime 取代 Fcitx5，成为该 seat 的唯一输入法；不共存。Fcitx5 必须先停用；unavailable 为启动失败。
上屏方式 原生 Wayland：input-method-v2 commit_string；XWayland：XIM XIM_COMMIT；XIM 不可用或非 XWayland 且无 text-input：剪贴板 + 粘贴。
XIM Voime 在 DISPLAY 可用时注册 XIM server（XIM_SERVERS / voime），只做 commit，不请求 forward-event；键盘仍由 Wayland grab 统一处理。
全局热键 zwp_input_method_v2.grab_keyboard：Voime 持有键盘抓取，在 IM 内匹配“按住说话”和“按一下切换”；非 PTT 按键经 virtual-keyboard 原样转发。
键盘与普通输入 Voime 是真正的输入法：接管键盘，但不做拼音 / 候选；所有非 PTT 按键和修饰键透明转发，不改变用户正常打字。
TUI 角色 TUI 变成可选监视器；daemon 独立常驻，TUI 退出不影响热键与上屏。
托盘 voimed 内置最小 StatusNotifierItem 托盘：图标 + 右键菜单，菜单只有“退出”；没有托盘宿主时静默降级，不影响 daemon。
剪贴板 只在上屏回退时写入单条最终文本；保留识别文本，不恢复用户原剪贴板；TUI 不再自动复制整段会话。
Preedit v1 不做；临时结果只在 TUI 显示。Phase 2 可选用 set_preedit_string 把临时文本显示在输入框。
  • 上屏策略是分层的：IM commit → XIM commit → 剪贴板粘贴。原生 Wayland 走 input-method-v2，XWayland 走 XIM，只有 XIM 不可用（或非 XWayland 且无 text-input）才回退剪贴板。
  • virtual-keyboard 只负责按键转发与粘贴快捷键，不作为文本上屏后端。
  • 当前验收环境：Hyprland 0.56.2；Fcitx5 5.1.23 正在运行（用于验证 unavailable）；不再依赖 xdg-desktop-portal-hyprland。
  • 键盘抓取与普通按键转发是 input-method-v2 路线的一部分；不是可选优化，也不是“只抓 PTT 键”。
  • 本文件只是提案，不修改现有 README / USER / CORE / PROVIDER / BUILD。批准后按 §9 的顺序落笔。

2. 目标与非目标

↑

2.1 目标

  • Voime 成为 seat 上唯一的 input-method-v2 输入法：持有 grab_keyboard，在输入法内部匹配 PTT 热键，而不是依赖 portal。
  • 用户在任意窗口获得焦点时，用全局热键开始 / 结束录音，包括终端与 XWayland 窗口，不需要先切到 TUI。
  • 同时支持两种热键语义：按住说话（按下开始、松开结束）与按一下开始 / 再按一下结束；两者可分别绑定，互不冲突。
  • 普通键盘输入保持可用：除 PTT 键外，所有 key / modifiers 事件经 zwp_virtual_keyboard_v1 原样转发，普通字符、快捷键、组合键的行为不变。
  • 原生 Wayland 应用通过 input-method-v2 在光标处插入最终文本；中文、英文、标点和 emoji 都按 UTF-8 原样提交。
  • XWayland 应用通过 XIM 接收最终文本；XIM 不可用或应用不使用 XIM 时，才通过剪贴板 + 粘贴回退。
  • daemon 与 TUI 进程分离：daemon 拥有音频、模型、输入法、键盘抓取、按键转发、上屏与会话历史；TUI 只通过 Unix socket 观察和发命令。
  • TUI 关闭、崩溃或从未启动时，全局热键、正常打字与上屏仍然工作。
  • PTT 每次录音硬上限 30 s；TUI 在录音红点旁显示独立状态行 ● Remaining: xx s；达到 30 s 自动结束当前句并立即开始下一段，不丢后续语音。
  • 提供一个最小托盘：图标 + 右键菜单，菜单只有“退出”；退出等价于 voime ctl quit，不依赖 TUI。
  • 识别链路改为 FireRedVAD → FireRedASR2-CTC → FireRedPunc；CTC 用单个 int8 ONNX 直接走现有 ort。
  • final 与现有尾部 partial 共用 CTC 模型；沿用现有分段与临时结果机制。
  • 保留 PTT / continuous 两种分段模式，以及纯本地、无网络、无 GPU、无 Python 运行时的约束。

2.2 非目标 / 本版不做

  • 不实现拼音、形码、候选词、云输入等键盘输入法能力；Voime 只负责语音文本上屏。
  • 不与 Fcitx5 / IBus 共存为两个输入法；也不实现 Fcitx5 插件。运行 Voime 前必须停用 Fcitx5。
  • 不实现 X11 与 Windows 后端；只在 CORE / PROVIDER 中预留 XGrabKey、WH_KEYBOARD_LL、SendInput 等接口位置。XWayland 的 XTest 粘贴只是兼容路径，不等于支持 X11 桌面。
  • 不保证 XWayland 的 preedit、临时结果或光标位置；XIM 只保证最终文本能提交到当前 XIM 焦点输入框，失败才转剪贴板。
  • 不引入第二个 ASR 模型；本版只做 CTC 替换，沿用现有 VAD 分段与尾部 partial。
  • 不把 Voime 做成通用键盘输入法：抓取键盘只为 PTT 与透明转发。XIM 只用于提交最终文本，不实现拼音 / 候选 / preedit。
  • 虚拟键盘只用于转发物理按键和发送粘贴快捷键，不作为逐字文本上屏后端；XWayland 先走 XIM，XIM 不可用才走剪贴板。
  • 不保存音频或识别历史到磁盘；daemon 退出后会话历史丢失。
  • 不自动把整段会话写入剪贴板；剪贴板只在回退粘贴时承载单条最终文本。
  • 不提供设置界面、悬浮窗、通知或托盘菜单之外的 GUI；托盘只保留图标与右键菜单（仅“退出”），不显示录音状态、历史或设置项。所有配置在命令行或 Hyprland 配置中完成。

2.3 关键约束

约束影响
一个 seat 只能有一个 input-method-v2 对象 Voime 与 Fcitx5 必须二选一；Fcitx5 运行时 Voime 收到 unavailable，按启动失败退出并提示停用 Fcitx5。
XWayland 不实现 text-input-v3 input-method-v2 的 commit_string 到不了 XWayland 应用；必须注册 XIM server 并通过 XIM_COMMIT 上屏，XIM 失败才转剪贴板。

Hyprland 先处理合成器键绑定，再交给 IM grab PTT 组合键必须未被 Hyprland 绑定；已被绑定时合成器先消费，Voime 收不到该键。

最终文本最多 4000 字节 / 次 commit_string 超长文本按 UTF-8 字符边界分块提交。

4. 目标架构

↑

4.1 组件图

  • 热键与上屏走同一个 input-method-v2 对象：grab_keyboard 收键，commit_string 写入文本。
  • 非 PTT 按键经 zwp_virtual_keyboard_v1 原样转发；合成器键绑定仍然优先于 IM grab。
  • XWayland 应用优先走 XIM；XIM 不可用或应用不使用 XIM 时才走剪贴板 + 粘贴回退。
  • 粘贴快捷键优先用 virtual-keyboard 发送，XTest 只作兜底。
  • TUI 只通过 Unix socket 连接 daemon；daemon 不依赖 ratatui / crossterm。

4.2 分层图

  • Voime 进入 Layer 3（输入法层），与 Fcitx5 互斥；它不是 Layer 2 的应用内注入器。
  • XWayland 应用没有 text-input-v3，因此走 XIM；XIM 不可用才是剪贴板粘贴，而不是 input-method-v2。
  • 普通键盘输入经过 Voime：Voime 抓取全部按键，但只消费 PTT 组合键，其余按键经 virtual-keyboard 原样转发。

5. 键盘抓取与 PTT 热键

↑

5.1 主路径：input-method-v2 键盘抓取

项目契约
协议 zwp_input_method_v2.grab_keyboard() → zwp_input_method_keyboard_grab_v2。
抓取时机 daemon 启动、拿到 input-method-v2 对象后立即抓取，并在整个生命周期内持有；不随 deactivate 释放，否则终端 / XWayland 窗口里没有 PTT。
事件 keymap、key、modifiers、repeat_info；key 同时给出 press / release。
匹配 用 grab 的 xkb keymap 把 keycode + modifiers 转成 keysym，再与配置的 hold / toggle 组合键比较；只比较 Shift / Ctrl / Alt / Super，忽略 CapsLock / NumLock / group。匹配成功才消费。
转发 未匹配的 key / modifiers 通过同一 Wayland 连接上的 zwp_virtual_keyboard_v1 原样发送；keycode、state、time 保持不变。
keymap grab 收到新 keymap 时，同时更新 xkb state 与 virtual-keyboard 的 keymap；布局切换后转发仍然正确。
按键重复 优先让客户端按 repeat_info 自行重复；P0 若发现 virtual-keyboard 路径不触发客户端重复，则由 Voime 按 grab 的 rate / delay 合成重复 press，PTT 键的重复事件一律忽略。
合成器优先级 Hyprland 先处理 bind / bindr 等键绑定，再把剩余按键交给 IM grab；PTT 组合键必须未被 Hyprland 绑定。
失败 grab_keyboard 失败、启动后超时未收到 keymap，或 grab 被销毁：记录 GrabFailed，停止录音并退出；virtual-keyboard 发送失败：记录 KeyForwardFailed 并退出，不能继续持有 grab 却不转发。

    virtual_keyboard.keymap(format, fd, size)

on_key(serial, time, key, state):        // key 为 wl_keyboard 语义（evdev code）
    if hold_active and key == hold_keycode and state == pressed:
        consume; ignore                      // 重复 press / 多键盘
    if hold_active and key == hold_keycode and state == released:
        hold_active = false
        emit HotkeyEvent::HoldReleased; consume
    if toggle_latched and key == toggle_keycode and state == pressed:
        consume; ignore
    if toggle_latched and key == toggle_keycode and state == released:
        toggle_latched = false; consume
    keysym = xkb_state_key_get_one_sym(state, key + 8)
    match keysym + xkb modifiers against hold_key / toggle_key
    if hold press:      hold_active = true; hold_keycode = key
                        emit HotkeyEvent::HoldPressed;  consume
    if toggle press:    toggle_latched = true; toggle_keycode = key
                        emit HotkeyEvent::TogglePressed; consume
    if PTT auto-repeat: consume, ignore
    else:               virtual_keyboard.key(time, key, state)  // 原样 evdev code

on_modifiers(serial, depressed, latched, locked, group):
    xkb_state_update_mask(...)
    virtual_keyboard.modifiers(depressed, latched, locked, group)
组合键语义事件映射
hold_key 按住说话：按下开始，松开结束。 press → HotkeyEvent::HoldPressed；release → HoldReleased；两者都消费。
toggle_key 按一下开始，再按一下结束。 press → HotkeyEvent::TogglePressed；release 消费但忽略。
  • 两个组合键可分别配置；设为 none 表示禁用该项。两者不能相同；组合键必须包含一个非修饰键（不支持纯修饰键 PTT）。
  • continuous 模式下不做 PTT 匹配，所有按键（包括默认的 SUPER+F2 / SUPER+F3）都按普通按键转发；PTT 只在 PTT 模式生效。
  • hold 的按下按组合键匹配；松开按记下的 keycode 匹配，不依赖松开时的 modifiers：先松 SUPER 再松 F2 也能结束录音。
  • hold / toggle 键的重复 press（自动重复或多键盘）一律消费并忽略，避免重复开始或重复切换。
  • PTT 组合键不转发给应用；按下与松开都不会泄漏到前台程序。
  • 组合键中的修饰键（例如 SUPER）在按下时可能已被转发；应用会看到一次单独的修饰键 press / release，这是 Fcitx5 式转发可接受的噪声。
  • Hyprland 的合成器键绑定优先：若用户把 SUPER+F2 绑给了别的命令，Voime 收不到 PTT，应改用未绑定的组合键。
  • “inactive 时仍能收到 PTT”依赖 Hyprland 把按键继续路由给 grab；其他合成器不保证，P0 在 0.56.2 上实测。
  • 不需要 input 组、udev 规则或 evdev 权限；所有事件来自 input-method-v2。

5.2 为什么不再使用 GlobalShortcuts portal

方案热键来源与输入法的关系问题
GlobalShortcuts portal portal 另注册全局快捷键 输入法之外的第二条通道；不持有键盘 需要 portal 与用户确认；无法取代 Fcitx5 的键盘所有权；PTT 与上屏是两套机制。
input-method-v2 grab（本提案） IM 自己接收键盘事件并匹配 同一个 IM 对象负责 PTT、普通按键转发与上屏 必须完整转发非 PTT 按键；实现复杂度高于 portal，但这才是输入法。
  • Voime 的目标是取代 Fcitx5，而不是在 Fcitx5 旁边挂一个语音热键；热键必须来自输入法本身。
  • 保留 --hotkey none 仅用于调试：关闭 PTT 匹配，但键盘抓取与转发仍然运行。
  • 没有 portal / Hyprland global shortcuts / evdev 回退链；IME 不可用时直接启动失败，避免“看似输入法、实际靠粘贴”的半成品状态。
  • TUI 与 voime ctl 仍可手动 Start / Stop / Toggle，用于调试或没有 PTT 组合键时。

5.3 X11 / Windows 预留

平台预留接口行为
X11 XGrabKey + KeyPress / KeyRelease 在 root window 抓取热键并吞掉；支持 hold / toggle；本版不实现。
Windows SetWindowsHookEx(WH_KEYBOARD_LL) 低级键盘钩子观察按下 / 松开并吞掉热键；支持 hold / toggle；本版不实现。
文本注入 X11 XTEST / Windows SendInput(KEYEVENTF_UNICODE) 预留给 X11 / Windows 的上屏后端；本版只实现 Wayland / XWayland 路径。

6.2 input-method-v2

项目契约
连接 wl_display → wl_registry → wl_seat → zwp_input_method_manager_v2；virtual-keyboard 也在同一个 wl_display 上创建。
对象 get_input_method(seat) 创建唯一的 zwp_input_method_v2；每个 seat 最多一个。
激活 activate / deactivate 跟踪当前是否有 text-input-v3 输入框；unavailable 表示 seat 被其他输入法占用。
提交 commit_string(text) 后跟 commit(serial)；serial 等于已收到的 done 事件数，每次 done 递增。
长度 单次 commit_string 不超过 4000 字节；按 UTF-8 字符边界切块，逐块 commit。
键盘抓取 对象创建后立即 grab_keyboard，整个 daemon 生命周期持有；deactivate 不释放。否则终端 / XWayland 窗口没有 PTT。
普通按键 grab 的每个 key / modifiers 在 PTT 匹配后立即转发到 zwp_virtual_keyboard_v1；不缓存、不延迟、不改变 keycode / state。
unavailable 对象变为 inert；记录 ImUnavailable，提示停用 Fcitx5 / IBus，退出码 1。不重试，也不降级为粘贴。
Preedit v1 不调用 set_preedit_string；Phase 2 可选。临时结果始终在 TUI 显示。
焦点变化 commit_string 总是进入“Final 产生时”处于 active 的输入框；录音期间切换焦点不会回到旧窗口。
  • Hyprland 的 IM grab 是 seat 级：即使当前没有 text-input-v3 焦点，grab 仍然接收按键，因此 PTT 在终端和 XWayland 窗口也生效；P0 必须在 0.56.2 上实测确认。
  • 其他合成器可能只在 active 时路由按键；本版只承诺 Hyprland / Wayland，不承诺其他合成器的 grab 行为。
  • 多 seat 环境（多指针 / 多键盘组）需要为每个 seat 建立独立的 IM 与 grab；v1 只接管默认 seat，其余 seat 不保证。
  • 如果应用没有 text-input（例如 XWayland，或未启用 text-input 的原生应用），activate 不会发生：XWayland 走 XIM，其他应用走剪贴板回退。
  • 锁屏是 grab 的边界：P0 验证锁屏时按键是否仍进入 IM；若仍进入，则监听 Hyprland lock notify / logind Lock，在锁定期间释放 grab，解锁后重建。

6.2.1 为什么必须抓键盘并转发

方案热键来源普通键盘输入结论
不抓键盘 + GlobalShortcuts portal 输入法之外的 portal 合成器直接送给应用，Voime 不参与。 不是真正的输入法；PTT 与上屏是两套机制；无法取代 Fcitx5。已放弃。
grab_keyboard + virtual-keyboard 转发（本提案） IM 在 grab 内匹配按键 IM 把非 PTT 按键原样转发给应用。 与 Fcitx5 同一条输入法路线；PTT、普通打字、上屏共用一个 IM 对象。采用。
  • Fcitx5 抓键盘是为了把按键转成拼音 / 候选；Voime 抓键盘是为了 PTT 匹配与透明转发，不做拼音、候选或软键盘。
  • 转发必须完整：修饰键、布局、死键、组合键、快捷键、按住不放的重复都要保持行为；任何丢键都会直接破坏用户正常打字。
  • 转发路径不能等待 ASR：Wayland 线程只做 keymap / key / modifiers / PTT 匹配 / virtual-keyboard 发送；模型推理在 pipeline 线程。
  • Hyprland 会忽略“持有 IM grab 的同一客户端”注入的 virtual-keyboard 事件，避免转发回环；因此 IM 与 VK 必须共用连接。

6.3 XWayland：XIM 与剪贴板兜底

项目契约
XIM 注册 DISPLAY 可用时，在 root window 的 XIM_SERVERS 属性加入 voime，并持有 voime selection；TRANSPORT 返回 X/，LOCALES 返回当前 UTF-8 locale。XWayland 延迟启动时 daemon 周期性重试注册。XWayland 客户端使用 XMODIFIERS=@im=voime，或在只有 Voime 时按 first-fit 选中。
XIM 会话 处理 XIM_CONNECT / XIM_OPEN / XIM_CREATE_IC / XIM_SET_IC_FOCUS / XIM_UNSET_IC_FOCUS；记录当前 focused input context。
输入风格 只做 commit：不请求 forward-event，不实现 preedit / status / candidate；键盘与 PTT 仍由 Wayland grab 统一处理。
提交 XIM_COMMIT 发送 UTF-8 最终文本到 focused IC；客户端不接受 UTF-8 时使用当前 locale；超过 XIM 单包长度时按 UTF-8 字符边界分块。
兜底条件 没有 DISPLAY、XIM 注册失败、没有 focused IC、XIM_COMMIT 失败，或焦点不是 XWayland：写剪贴板 + 粘贴快捷键。
剪贴板 arboard::Clipboard::set_text(final)；内容为单条 Final，不含会话前缀；写入后不恢复。
粘贴键 普通 GUI：Ctrl+V；终端：Ctrl+Shift+V。优先经 zwp_virtual_keyboard_v1 发送 key press / release；XWayland 下若 VK 事件未被接受，再用 XTest 兜底。
终端识别 默认列表：kitty、foot、Alacritty、org.wezfurlong.wezterm、com.mitchellh.ghostty、XTerm；可用 --terminal-class 追加。
无焦点 / 粘贴失败 文本留在剪贴板；记录 DeliveryFailed；不弹窗、不写 TUI 错误行。
  • XIM 只保证最终文本能提交到当前 XIM 焦点输入框，不保证 preedit、临时结果或光标位置；XIM 失败才降级到剪贴板。
  • XWayland 的普通按键已经由 virtual-keyboard 送进 X11 应用；XIM server 不请求 forward-event，避免同一按键在 Wayland grab 与 XIM 两处重复处理。
  • 终端里粘贴的是命令文本，用户按热键时应当明确目标；本提案不额外做终端安全确认。
  • 剪贴板保留识别文本，不回滚用户原内容；这是为了避开 Wayland 异步剪贴板的恢复竞态。

6.4 virtual-keyboard：按键转发基础设施

项目契约
协议 zwp_virtual_keyboard_manager_v1 + zwp_virtual_keyboard_v1；与 input-method-v2 创建在同一个 wl_display 上。
用途 转发 grab 收到的非 PTT key / modifiers；发送粘贴快捷键（Ctrl+V / Ctrl+Shift+V）。
keymap 使用 grab 提供的 keymap，不另造布局；keymap 变化时同步更新。VK 在收到第一个 keymap 前不得发送 key，否则协议报错。
回环 Hyprland 忽略持有 IM grab 的同一客户端注入的按键；因此 IM 与 VK 必须共用连接，否则会把自己的转发再次送回 grab。
文本上屏 不以 transient keymap 逐字输入最终文本；最终文本走 commit_string、XIM 或剪贴板粘贴。
  • virtual-keyboard 是输入法存活的条件，不是可选后端；它失效时普通打字和粘贴都会失效。
  • 粘贴快捷键只发送一组 key 事件，不逐字输入文本；因此不会把识别文本拆成快捷键。

6.6 ASR：切换 FireRedASR2-CTC

详细数据、预处理和 ONNX 输入输出见 ASR 研究。本版只把现有 FireRedASR2-AED 换成 FireRedASR2-CTC：单 ONNX、直接走现有 ort， final 与现有尾部 partial 共用同一个模型，分段与临时结果机制不变。

项目方案
模型 FireRedASR2-CTC int8（740 MiB），单 model.int8.onnx + tokens.txt。
运行 现有 ort；CMVN 从 ONNX metadata 读取；greedy CTC。
RTF（2 threads） 10 s 约 0.077；20 s 约 0.070；30 s 约 0.075；60 s 约 0.094。
分段 10 s 提高到 30 s；PTT 硬上限 30 s；continuous 由 VAD 提前切分；倒计时规则见 §7.5。
  • CTC 仍是离线全序列编码器；沿用现有 VAD 分段与尾部 partial，分段策略不变。
  • 临时结果沿用现有尾部重解码机制，只把 ASR 后端换成 CTC；不进入历史、不写剪贴板。
  • 安装脚本直接下载官方 .tar.bz2，不再为 CTC 运行 Python/PyTorch 导出。
  • int8 CTC 在官方 0.wav 上有英文子词缺失；最终上线前用真实麦克风数据评估，必要时保留 AED legacy。

7.3 IPC

ClientMessage =
  | Hello { role: Tui | Control, version: u32 }
  | Start { source: TriggerSource }
  | Stop  { source: TriggerSource }
  | Toggle { source: TriggerSource }
  | ClearHistory
  | Status
  | Quit

ServerMessage =
  | Snapshot { mode, phase, partial, transcript, im, keyboard, xim, remaining_ms? }
  | State { recording, finalizing, remaining_ms? }
  | Partial { text }
  | Final { text, delivery }
  | Delivery { kind, ok, error? }
  | HistoryCleared
  | Status { ... }
  | Error { code, message }
  | Bye

TriggerSource = ImHold | ImToggle | Tui | Cli | Continuous
消息方向语义
Helloclient → daemon声明角色与协议版本；daemon 回 Snapshot。
Start / Stop / Toggleclient → daemon手动触发；与 IM PTT 共用同一状态机；Recording / Finalizing 时 Start 被忽略。
ClearHistoryclient → daemon清空已完成 transcript；保留 partial / recording / finalizing；不碰剪贴板。
QuitControl → daemon停止 daemon；TUI 的 q 不发送 Quit，只 Detach。
Snapshotdaemon → client连接时全量状态；新 TUI 不需要回放事件。
Statedaemon → clientrecording / finalizing / remaining_ms；PTT 录音时每秒更新，continuous 为 None。
Finaldaemon → client已尝试投递的最终文本；delivery 说明走的是 im / xim / clipboard / failed。
HistoryCleareddaemon → client任一客户端清空后广播；所有 TUI 同步清空本地 transcript 视图。
  • 慢客户端：每个 subscriber 一个有界队列；队列满时断开该客户端，不阻塞 daemon。
  • 多 TUI：允许同时连接；所有客户端收到相同事件；ClearHistory 作用于 daemon 的共享 transcript，并通过 HistoryCleared 广播。
  • transcript 只存在内存；建议上限 10_000 行或 1 MiB，超过时丢弃最旧行，避免 daemon 长期运行后无限增长。
  • 安全：只监听 Unix socket，不开 TCP；不做额外认证，依赖文件系统权限。
  • 若 XDG_RUNTIME_DIR 未设置，回退到 /tmp/voime-$UID/，目录仍为 0700；socket 路径可通过 --socket 覆盖。
  • daemon 关闭（ctl quit 或托盘“退出”）时向所有客户端发送 Bye 并关闭 socket；TUI 收到后恢复终端退出。

7.6 托盘（最小）

托盘由 voimed 持有，不是 TUI 的一部分。它只承担一件事：在没有终端、没有 TUI 的情况下， 让用户通过图标右键菜单退出 daemon。除此之外不显示状态、不提供设置、不触发录音。

项目契约
协议 StatusNotifierItem + DBusMenu，走 D-Bus session bus；由 ksni 的 blocking API 实现，不引入 tokio 运行时。
图标 32×32 ARGB32 IconPixmap（网络字节序）的麦克风剪影，带对比描边，编译进二进制；静态图标，不随录音状态变化。
Tooltip 标题 Voime；描述 语音输入法。不显示设备名、模式或错误。
右键菜单 DBusMenu 根菜单只有一项“退出”；无子菜单、无分隔线、无设置项、无“显示 TUI”。
左键 无动作（ItemIsMenu = false）；只有右键菜单。
退出 菜单项 activate 发送 TrayEvent::Quit 到 daemon 事件循环；与 voime ctl quit 走同一条 shutdown 路径。
宿主缺失 没有 StatusNotifierWatcher / 宿主时不显示图标，daemon 继续运行；只记录 warning。--no-tray 可显式关闭。
与 TUI 的关系 完全独立：TUI 退出不删除托盘；托盘退出会让已连接的 TUI 收到 Bye / socket EOF 并恢复终端退出。
录音中退出 取消当前语音段，不产生 Final，不写剪贴板，不等待 ASR；然后关闭 grab / VK / IM / socket。
  • 托盘图标不是录音状态指示器；“正在录音”只在 TUI 当前行和目标输入框（未来 preedit）中体现。
  • 托盘只负责退出；开始 / 结束录音仍然由全局热键、TUI 或 voime ctl 触发。
  • 最基础版不保证宿主重启后自动恢复图标；重启 voimed 可恢复。自动重注册放到 P4 可选增强。
  • 图标使用编译进二进制的像素图，不依赖 hicolor 图标主题或额外安装文件。

11. 风险与验证

↑

风险影响缓解
Fcitx5 / 其他输入法占用 seat Voime 收到 unavailable，无法成为输入法，也没有 grab 与 PTT。 启动失败并明确提示；文档要求先停用 Fcitx5 / IBus；voime doctor 检查 seat 占用。
XWayland 不支持 text-input-v3 无法 commit / preedit。 注册 XIM server，用 XIM_COMMIT 提交最终文本；XIM 注册 / focused IC / commit 失败才用剪贴板 + VK 粘贴（XTest 兜底）。
XIM 客户端未启用 / 无 focused IC XWayland 应用收不到 XIM_COMMIT，只能粘贴。 注册 XIM_SERVERS 与 voime selection；文档要求设置 XMODIFIERS=@im=voime；doctor 检查 focused IC；失败记录并回退剪贴板。
普通按键转发错误 用户无法正常打字、快捷键失效、字符错乱。 原样转发 keycode / state / time；同步 grab keymap 到 VK；P0 覆盖布局切换、修饰键、死键、组合键、长按重复。
ASR / 模型推理拖慢按键转发 打字延迟、丢键，严重时用户无法操作。 Wayland 线程只做转发，不执行推理；pipeline 独立线程；队列有界；必要时提高 Wayland 线程优先级并做延迟测试。
PTT 组合键被 Hyprland 绑定 合成器先消费，IM grab 收不到，PTT 无效。 文档要求 PTT 组合键不要写进 Hyprland bind；启动 / doctor 提示冲突；提供 --hold-key / --toggle-key 改键。
grab 与 virtual-keyboard 不同连接 Hyprland 把 IM 自己注入的按键再次送回 grab，形成回环。 IM、grab、VK 必须创建在同一 wl_display；代码层用同一个 Wayland 连接类型约束。
hold 松开事件丢失 录音不结束。 保留 VAD 静音自动结束兜底；松开事件幂等；P0 验证 grab 的 release 顺序。
锁屏期间 grab 仍生效 Voime 可能看到锁屏按键，或拦截锁屏输入。 P0 验证；必要时监听 Hyprland lock notify / logind Lock，锁定时释放 grab，解锁后重建。
输入法可见全部按键 Voime 与 Fcitx5 一样处于键盘信任边界内，能看到密码等输入。 不记录按键、不写磁盘、不联网；在文档中明确信任模型；发布包与代码可审计。
焦点在 Final 前切换 文本进入新窗口。 文档声明“投递到 Final 时的焦点”；不在本版实现目标窗口锁定。
Wayland 剪贴板异步竞态 粘贴到旧内容或空内容。 写入后短暂延迟再发粘贴键；保留识别文本，不恢复，降低竞态。
commit_string 4000 字节上限 长文本被截断或协议错误。 按 UTF-8 字符边界分块；测试长文本。
终端 / vim 误粘贴 文本被当作命令执行。 终端使用 Ctrl+Shift+V；文档提示用户确认焦点；不额外拦截。
systemd 环境缺 WAYLAND_DISPLAY daemon 连不上 Wayland。 推荐 exec-once = voimed；或导入环境后启动 user service。
没有 StatusNotifier 托盘宿主 看不到托盘图标，无法用菜单退出。 只记录 warning，daemon 继续；voime ctl quit 仍可用；--no-tray 明确关闭。
托盘宿主重启 / 图标主题缺失 图标消失或显示占位图。 图标用内嵌 IconPixmap，不依赖主题；最基础版重启 voimed 恢复，P4 再做自动重注册。
FireRed-CTC int8 英文子词准确率不足 0.wav 出现 MOAY TOAY 之类的英文错误。 用真实数据评估；保留 AED legacy 后端；必要时评估 FP32 或只对中文使用 CTC。
input-method-v2 协议不稳定 Hyprland 升级后编译 / 行为变化。 锁定 protocols/*.xml 版本；P0 / CI 做 Hyprland 回归。
