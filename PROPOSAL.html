1. 结论与决策

↑

可行。Fcitx5 是键盘与输入上下文的所有者：它通过 Wayland frontend 或 XIM 接收按键，维护 InputContext，负责 preedit、最终文本提交、候选窗口和输入法状态。Voime 提供一个 Fcitx addon：在 Fcitx 的 InputContextKeyEvent 管线里匹配 PTT 键，并在最终文本到达时调用 InputContext::commitString()。这就是“Fcitx 捕获热键、Fcitx 上屏”。

音频采集、VAD、ASR 与标点留在 Rust 的 voimed 守护进程；addon 只做桥接，避免把模型推理放进 fcitx5 进程。TUI 是可选的监视器与控制客户端，不拥有键盘或上屏路径。Fcitx5 的 Wayland frontend 只在有 text-input 焦点时持有键盘抓取，因此 PTT 只在 Fcitx 能收到按键的输入框里生效；这正好是最终 文本需要提交到的地方。

决策项结论
集成方式 Voime 实现为 Fcitx5 addon（voime.so，fcitx::InputMethodEngineV2），并在 Fcitx 输入法组中注册 Voime 条目。Fcitx 负责键盘、frontend、焦点、preedit 与提交。
模式 addon 配置 Mode 在 ptt / toggle / continuous 三选一；模式由 addon 持有，并通过 IPC 同步给 voimed 与 TUI。
热键 addon 只配置一个 Hotkey：ptt 模式下为按住说话，toggle 模式下为按一下切换，continuous 模式忽略。匹配在 InputContextKeyEvent 的 PreInputMethod 阶段完成，命中后 filterAndAccept() 消费。
上屏 addon 调用 InputContext::commitString(final)；Fcitx 通过当前 frontend（Wayland text-input-v3、XWayland/X11 XIM）把文本插入聚焦输入框。
进程边界 fcitx5 进程加载 addon；voimed 是独立 Rust 守护进程，拥有音频、模型、ASR、标点与会话历史；voime 是可选的 TUI 客户端。addon 与 voimed 通过 Unix socket 通信。
语音段目标 每个语音段在开始时绑定当时聚焦的 InputContext（PTT 按下、VAD 语音起点或 TUI/ctl Start）；最终文本只提交到仍存在且仍聚焦的同一输入框，否则保留在 daemon/TUI，不向其他窗口注入。
ASR 链路 FireRedVAD → FireRedASR2-CTC int8 → FireRedPunc。CTC 是单 ONNX（约 740 MiB），直接走现有 ort，运行时从 metadata 读 CMVN，greedy 解码；final 与尾部 partial 共用同一模型。VAD 分段、临时结果和标点链路保持不变，CPU 推理成本低。
分段上限 默认 max_segment_ms 取 30 s；PTT 达到上限自动切段并继续收集，continuous 由 VAD 提前切分。本提案不新增倒计时 UI。
临时文本窗口 使用 Fcitx 输入面板的 preedit 显示 Partial：inputPanel().setPreedit() + updateUserInterface()。说话过程中显示部分识别文本，Final / 停止 / 空段 / 断线时清空并关闭；不实现自绘窗口，不写客户端 preedit。
状态显示 使用 Fcitx 自己的输入法状态；录音状态在 v1 由可选 TUI 显示。
平台 Linux + Fcitx5 为验收平台；XWayland / X11 通过 Fcitx XIM 覆盖。
Fcitx 版本 要求 Fcitx5 ≥ 5.1.23；KeyEventMatchingMode::MatchAllNormalizedKeys 与 checkKeyList 的当前签名以该版本为准。
配置位置 Fcitx addon 配置 ~/.config/fcitx5/conf/voime.conf 只保留 Mode 与 Hotkey；socket 使用固定默认路径，模型、音频与线程数由 voimed 命令行决定。
生命周期 voimed 由 systemd user service 或桌面自启动拉起；addon 在 Fcitx 启动时加载并连接 socket，断线自动重连。TUI 可随时 attach / detach，不影响 PTT 与上屏。
  • Fcitx5 是宿主。Voime 与拼音、键盘布局、候选窗口等 Fcitx 能力共存；Voime 只增加一个语音输入法条目。
  • CTC 的目标是降低 CPU 推理耗时与模型内存：本机 2 threads 实测 RTF 约 0.066–0.094，模型约 740 MiB；详细事实、预处理和 ONNX 输入输出见 ASR 研究。
  • PTT 只在 Fcitx 能收到按键的输入上下文中生效：原生 Wayland 的 text-input 输入框、通过 Fcitx XIM 连接的 XWayland/X11 应用。桌面空白处、未使用 Fcitx 的应用、没有文本焦点的窗口不保证 PTT。
  • 最终文本通过 commitString 提交到目标输入框；没有目标时文本保留在 daemon/TUI。
  • 正式文档已按本提案落笔；本文件保留为设计记录，不进入正式文档导航，也不再作为实现契约。

2. 目标与非目标

↑

2.1 目标

  • 把 Voime 注册为 Fcitx5 输入法引擎：安装 addon 后，Fcitx 的输入法列表出现 Voime，可以加入输入法组。
  • addon 配置一个模式（ptt / toggle / continuous）与一个热键；ptt 为按住说话，toggle 为按一下切换，continuous 忽略热键并由 VAD 自动切分。
  • 由 Fcitx 捕获热键：命中后消费按键，普通按键完全交给 Fcitx。
  • 在任意聚焦的 Fcitx 输入框中工作：原生 Wayland 应用、通过 Fcitx XIM 的 XWayland/X11 应用，以及支持 text-input 的终端。
  • 最终文本通过 Fcitx 的 commitString 插入光标位置。
  • PTT 不要求当前输入法是 Voime；用户可以在拼音、键盘布局或其他 Fcitx 输入法处于活动状态时直接按 PTT。
  • 把音频、模型、ASR、标点与会话历史放进独立 voimed 守护进程；Fcitx addon 只负责热键、目标输入框、IPC 与提交。
  • 录音期间通过 Fcitx 输入面板显示临时文本窗口，内容是当前段的 Partial；Final、停止、空段或断线时立即清空。
  • TUI 变成可选监视器：显示模式 / 热键 / 历史、发送 Start / Stop / Toggle / Clear；关闭 TUI 不影响热键、临时窗口与上屏。
  • ASR 切换为 FireRedASR2-CTC int8：单 ONNX、ort CPU 推理、CMVN 从 metadata 读取、greedy CTC；降低 CPU 推理耗时与模型内存，同时保持 VAD 分段、临时结果与 FireRedPunc 不变。
  • 保留现有的纯本地、离线、无 GPU、无 Python 运行时约束；CTC 模型包由安装脚本下载，不在运行期联网或导出。
  • 把 Mode 与 Hotkey 暴露为 Fcitx addon 配置，可在 fcitx5-configtool 或配置文件中修改。
  • CTC 的 CPU 目标（2 threads）：RTF ≤ 0.1；10 s 音频 ≤ 1.0 s，30 s 音频 ≤ 3.0 s；真实麦克风数据上的 CER 达到发布门槛。
  • 提供可重复的安装 / 构建流程：Rust workspace 产物 + C++ addon + Fcitx 描述文件 + 可选 systemd user service。

2.2 非目标 / 本版不做

  • 不做拼音、形码、候选词或通用键盘输入法；Voime 只负责语音识别文本的提交。
  • Voime 是 Fcitx 的一个 addon，不实现通用输入法框架。
  • 不实现自绘候选窗口、状态图标或设置 GUI；这些由 Fcitx 及 fcitx5-configtool 提供。
  • 不保证桌面空白处、锁屏、未使用 Fcitx 的应用、没有 text-input 的窗口中的 PTT；这些场景没有可提交的输入上下文。
  • 不写客户端 preedit；临时文本只通过 Fcitx 输入面板显示，不显示在应用输入框内。
  • 不引入第二个 ASR 模型或额外推理后端。
  • 不改变 VAD 分段算法、临时识别节奏或 FireRedPunc；ASR 使用 CTC，默认 max_segment_ms=30_000。
  • 不承诺 int8 CTC 在英文子词上的完美准确率；官方 0.wav 的已知英文错误需要真实麦克风数据评估。
  • 不保存音频、按键或识别历史到磁盘；daemon 退出后会话历史丢失。
  • 不把 Fcitx 的按键事件或用户输入写入日志；addon 只记录连接状态与错误码。

2.3 关键约束

约束影响
Fcitx 必须运行且 addon 已加载 没有 Fcitx 就没有键盘捕获、InputContext 与提交通道；PTT 和上屏都不可用。addon 未连接 daemon 时按键应原样放行，避免破坏正常输入。
Fcitx 只把按键路由到有输入焦点的上下文 PTT 只在 Fcitx 能收到 InputContextKeyEvent 时触发；裸桌面、无文本字段的窗口不保证。最终文本也需要同一个聚焦上下文。
Wayland frontend 只在 text-input 激活时抓键盘 Fcitx 自己的 Wayland frontend 在 activate 时 grab_keyboard，deactivate 时释放；Voime 不能假设“整个桌面都能按 PTT”。
XWayland/X11 依赖 Fcitx XIM 只有通过 XIM 连接 Fcitx 的应用才会把按键交给 Fcitx；不使用 XIM 的 X11 应用既收不到 PTT，也无法通过 Fcitx 提交。
PreInputMethod 早于 Fcitx 全局热键处理 addon 在 Fcitx 的 trigger / alt-trigger / enumerate 键之前看到事件。Hotkey 不得与这些全局热键重叠，否则会先被 Voime 消费。
Mode 的唯一来源是 addon 配置 voimed 不通过命令行选择模式；它通过 addon 的 Hello / Configure 获得 ptt / toggle / continuous，TUI 从 Snapshot 显示同一值。
临时文本由 Fcitx 输入面板渲染 通过 InputPanel::setPreedit 写 preedit，由 Fcitx UI 显示窗口；不保证所有 UI addon 都渲染，且当前输入法可能更新同一面板。
commitString 没有返回值和确认 addon 无法知道应用是否接受文本；只能保证调用了 Fcitx API。目标输入框丢失时不提交，保留历史。
Fcitx 的 commit filter 会生效 最终文本可能被 Fcitx 的提交过滤器转换（例如全角、替换规则）；Voime 不绕过 Fcitx 的提交管线。
Wayland commit 单次有长度上限 Fcitx 的 Wayland frontend 会按 UTF-8 字符边界拆分长文本；Voime 不需要自己切块，但文档要说明最终文本经过 Fcitx。
addon 与 Fcitx ABI 绑定 voime.so 必须针对 Fcitx5 头文件构建；Fcitx 大版本升级后需要重新编译。最低版本 5.1.23。
addon 运行在 Fcitx 事件循环 socket 读写必须非阻塞；不能调用阻塞的 ASR、文件下载或长耗时操作，否则会卡住整个输入法。
CTC 是离线全序列模型 没有帧级 cache 或流式状态；仍按 VAD / PTT 切成完整语音段后一次性编码。分段不能无限增长，默认 max_segment_ms 取 30 s。
CTC 预处理必须对齐 sherpa 16 kHz / 80 bins / 25 ms 窗 / 10 ms 帧移 / snip_edges=true / high_freq=0 / 32768 缩放；CMVN 从 ONNX metadata 读取，不能依赖 cmvn.ark。
CTC 词表是 token id 两列 现有 tokenizer 需要支持 id 后缀；id 0 为 blank；英文 ▁ 需要转换为空格，中文 token 直接拼接。
int8 CTC 英文质量有限 官方 0.wav 存在英文子词缺失；发布前用真实麦克风数据评估 CER，并把该样本记录为已知限制。
单实例与多显示 一个 Fcitx 进程只加载一个 addon；只允许一个 Fcitx 角色连接 daemon。第二个连接被拒绝并记录日志。
安全边界 addon 与 Fcitx 一样能看到经过输入法的按键；不记录按键、不落盘、不联网，文档需要明确信任模型。

3. 目标形态

↑

目标形态是一个由 Fcitx5 承载的语音输入法：Fcitx 负责键盘、输入上下文和文本提交；Voime 提供 addon、ASR daemon 与可选 TUI。下面只描述本方案最终要落地的形态。

层面目标
输入宿主Fcitx5（≥ 5.1.23）运行并持有输入法 seat；Voime 作为 addon 加载。
Voime addonvoime.so 实现 InputMethodEngineV2，在 PreInputMethod 阶段匹配 PTT，消费 PTT 键，并通过 commitString 提交最终文本。
ASR daemonvoimed 独立进程：音频采集、VAD、FireRedASR2-CTC、FireRedPunc、会话历史与 Unix socket 服务。
临时文本窗口说话期间由 addon 把 Partial 写入 Fcitx InputPanel 的 preedit；Fcitx UI 显示，Final / 停止 / 空段 / 断线时清空。
TUIvoime 可选监视器：显示模式 / 热键 / 历史，发送 Start / Stop / Toggle / Clear；不拥有键盘或提交路径。
ASRFireRedASR2-CTC int8 单 ONNX，CMVN 从 metadata 读取，greedy CTC；final 与尾部 partial 共用；默认 max_segment_ms=30_000。
配置Fcitx addon 只配置 Mode（ptt / toggle / continuous）与 Hotkey；socket 使用默认路径；模型、音频与线程在 voimed 命令行。
平台Linux + Fcitx5；原生 Wayland、XWayland / X11 通过 Fcitx 对应 frontend 覆盖。
  • ASR 的模型事实、RTF、预处理与 manifest 差异集中到 ASR 研究；其他文档只保留结论与链接。
  • PTT 只在 Fcitx 能收到按键的输入上下文中生效；最终文本提交到语音段开始时聚焦的输入框。
  • TUI 关闭不影响 addon 与 daemon；voime ctl quit 只停止 daemon。

4. 目标架构

↑

4.1 组件图

  • Fcitx5 拥有键盘与输入上下文；Voime addon 只在 Fcitx 的事件管线中匹配 PTT，并通过 commitString 提交最终文本。
  • 普通按键完全由 Fcitx 处理，Voime 不转发、不缓存、不模拟按键。
  • voimed 不依赖 Wayland / X11 / Fcitx；它只依赖音频设备、模型与 Unix socket，便于独立测试与重启。
  • TUI 只通过 socket 观察和发命令；关闭 TUI 不影响 addon 与 daemon。
  • Fcitx 配置文件（addon / inputmethod / voime.conf）是 PTT 键与 addon 行为的权威来源；voimed 不复制这些配置。

4.2 进程与职责

进程 / 组件职责不负责
fcitx5 加载 addon 与输入法条目；持有 Wayland / X11 frontend；接收键盘；维护 InputContext 与焦点；处理 Fcitx 全局热键；执行 commitString 与 preedit；显示输入法状态。 音频、模型、ASR、标点、Voime 会话历史。
voime.so（addon） 实现 InputMethodEngineV2；注册 Voime 输入法；读取 Mode / Hotkey；在 PreInputMethod 阶段按模式匹配热键并消费；维护当前语音段的目标 InputContext 弱引用；通过 Unix socket 与 daemon 通信；把 Partial 写入 Fcitx InputPanel 的 preedit；调用 commitString。 音频采集、模型推理、ASR、标点、会话历史。
voimed 模型校验与加载；音频采集；VAD / ASR / 标点；语音段状态机；会话历史；Unix socket 服务；接收 addon 的 Mode / Hotkey 并同步给 TUI；TUI / ctl 命令处理；daemon 生命周期。 Fcitx API、键盘、输入上下文、最终文本提交、PTT 匹配。
voime（TUI） 可选监视器：连接 socket、显示模式 / 热键 / 临时结果 / 历史 / 状态；发送 Start / Stop / Toggle / Clear；手动复制使用终端原生选择。 音频、模型、键盘、上屏、PTT 配置。
voime ctl 一次性控制客户端：start / stop / toggle / status / clear / quit；供脚本和桌面快捷键调用。 长期驻留、显示历史、Fcitx 配置。

4.3 启动与生命周期

systemd --user（推荐）
└── voimed
    ├── config::Config::resolve(args)
    ├── model::ModelManifest::load / verify
    ├── infer::session::SessionFactory::new
    ├── pipeline::spawn(...)
    ├── audio::capture::start(...)
    ├── ipc_server::bind($XDG_RUNTIME_DIR/voime/voimed.sock)
    └── daemon::run(...)

fcitx5
├── 加载 share/fcitx5/addon/voime.conf        OnDemand=False
├── 加载 share/fcitx5/inputmethod/voime.conf  Addon=voime
├── VoimeAddon::VoimeAddon(instance)
│   ├── 读取 ~/.config/fcitx5/conf/voime.conf
│   │   └── Mode / Hotkey
│   ├── ipc::Client::connect(socket)（失败时重试）
│   ├── Hello { role: Fcitx, mode, hotkey }
│   └── watchEvent(InputContextKeyEvent, PreInputMethod)
└── 正常输入法路由

voime（可选）
└── ipc::Client::connect(socket)
    ├── Hello { role: Tui }
    ├── Snapshot
    └── 事件循环
  • voimed 与 Fcitx 的启动顺序不敏感：daemon 先起时 addon 直接连接；addon 先起时按退避间隔重连。任一进程重启都不需要重启另一个。
  • addon 未连接 daemon 时，不得消费 PTT 键；按键原样交给 Fcitx / 应用，并在 Fcitx 日志中记录一次 warning。这样不会因为 daemon 未启动而破坏正常打字。
  • 推荐使用 systemd user service 启动 voimed，因为它需要在登录后长期驻留，并且不依赖 TTY；也可以由桌面会话的 exec-once 启动。
  • 退出顺序：停止录音 → 取消当前段 → 关闭 socket → 停止 pipeline → 停止音频。addon 收到 EOF 后清除 hold / toggle 锁存、临时窗口与目标引用；Fcitx 继续正常运行。
  • voime ctl quit 只停止 daemon，不关闭 Fcitx；Fcitx 中的 Voime 条目仍存在，但 PTT 会因 daemon 不可用而放行按键。
  • addon 配置重载时向 daemon 发送 Configure { mode, hotkey }；模式变更在下一个语音段生效，当前段继续到结束。addon 断线时 daemon 停止 continuous 自动分段，保留 TUI / ctl 手动 Start / Stop。

4.4 状态机

Idle
├── Mode=ptt：Hotkey 按下 / Mode=toggle：Hotkey 按下
│   ├── 生成 segment_id，记录目标 InputContext
│   └── Start / Toggle → Recording
├── Mode=continuous：VAD 语音起点
│   └── SegmentStarted → Recording
└── TUI / ctl Start
    └── SegmentStarted → Recording

Recording
├── Mode=ptt：Hotkey 松开 / Mode=toggle：Hotkey 按下 / TUI Stop / ctl Stop
│   └── Finalizing
├── VAD 静音 / max_segment_ms
│   └── Finalizing
└── addon / daemon 断线，或 Fcitx 退出
    └── Idle（不提交，丢弃当前段）

Finalizing
├── ASR + Punc 成功且文本非空
│   └── Delivering
├── ASR / Punc 失败
│   └── Idle（记录 SegmentDropped）
└── 空文本
    └── Idle（不产生 Final）

Delivering
├── 清空临时文本窗口
├── 目标 InputContext 存在且 hasFocus()
│   └── commitString(text) → Idle
└── 目标丢失 / 失焦 / 不存在
    └── 保留在 daemon 历史与 TUI → Idle
  • 同一时刻只允许一个语音段；Recording / Finalizing 期间新的 Start 被忽略，toggle 在 Finalizing 期间不产生新段。
  • addon 按 Mode 产生 segment_id：ptt 松开时 Stop，toggle 再按时 Stop；continuous、TUI 与 ctl 由 daemon 产生。addon 用同一个 ID 关联目标输入框与最终文本。
  • continuous 模式不消费 Hotkey：所有按键按普通输入处理，VAD 自动开始 / 结束语音段；如果用户需要手动控制，使用 TUI 或 voime ctl。
  • 目标输入框只在语音段开始时绑定一次；录音期间切换窗口不会改变目标。最终文本不会进入录音开始之后才聚焦的另一个窗口。
  • 停止、空段、ASR 错误、目标失焦 / 销毁、daemon 断线时都先清空临时文本窗口；Final 提交前也先清空。
  • daemon 断线时 addon 立即清除当前段与目标；如果 daemon 之后恢复，未完成段不会补交。

5.1 主路径：Fcitx 事件管线

Fcitx 的 frontend 收到按键后，会构造 InputContextKeyEvent 并按阶段执行事件处理器。addon 在 PreInputMethod 阶段注册监听：它比当前输入法引擎更早看到按键，但晚于 Fcitx 的内部保留阶段。 命中 Hotkey 后，addon 调用 filterAndAccept()，按键不再进入当前输入法或应用；未命中的按键 完全不动，由 Fcitx 继续处理。

项目契约
监听 API Instance::watchEvent<EventType::InputContextKeyEvent>(EventWatcherPhase::PreInputMethod, handler)。
模式 addon 配置 Mode：ptt、toggle、continuous。模式只影响 addon 的热键语义；continuous 不匹配热键。
匹配 使用 addon 配置中的单个 Hotkey；KeyEvent::checkKeyList(keys, KeyEventMatchingMode::MatchAllNormalizedKeys)。
ptt 模式 按下匹配 → 记录目标 InputContext、生成 segment_id、发送 Start、filterAndAccept()；松开按记录的 raw keycode 匹配（不依赖松开时的 modifiers），发送 Stop，同样消费。
toggle 模式 按下匹配 → 若 Idle 则 Start，若 Recording 则 Stop；按下与松开都消费；Finalizing 期间按下只消费、不产生新段。
continuous 模式 不匹配、不消费热键；所有按键交给 Fcitx。daemon 根据 Mode=continuous 用 VAD 自动开始 / 结束语音段。
普通按键 不匹配时立即返回；Fcitx 将按键交给当前输入法或应用。Voime 不转发、不缓存、不改变 keymap。
自动重复 PTT 键的 repeat press 一律消费并忽略；hold 只触发一次 Start，toggle 只切换一次。
多个键盘 / 布局 hold 的松开按 keycode 匹配，避免先松修饰键导致匹配失败；布局切换不影响已开始的 hold 段。
当前输入法 PTT 监听与当前输入法无关；拼音、键盘布局或其他 Fcitx 引擎处于活动状态时仍可触发。Voime 条目不必是当前输入法。
消费语义 filterAndAccept() 阻止 PTT 键进入应用；不会产生空格、字符或快捷键副作用。
daemon 未连接 不消费 PTT 键，原样交给 Fcitx / 应用；记录一次 warning。连接恢复后重新启用匹配。
无目标输入框 不开始录音；即使收到按键，也不创建没有目标的语音段。
与 Fcitx 全局热键冲突 PTT 组合键不得与 Fcitx 的 trigger / alt-trigger / enumerate / preedit 切换键重叠：trigger / alt-trigger / enumerate 在 InputMethod 阶段处理，preedit 切换也在 PreInputMethod 阶段；Voime 的 watcher 可能先消费它们。
与合成器绑定冲突 Hyprland 等合成器先处理自己的 bind / bindr；PTT 必须选择未被合成器消费的组合键。这一点与 Fcitx 自身的热键限制相同。
X11 / XWayland 只有通过 Fcitx XIM 连接的应用才会把按键交给 Fcitx；不使用 XIM 的 X11 应用不保证 PTT。 
keyWatcher_ = instance_->watchEvent<fcitx::EventType::InputContextKeyEvent>(
    fcitx::EventWatcherPhase::PreInputMethod,
    [this](fcitx::KeyEvent &event) { handleKey(event); });

void VoimeAddon::handleKey(fcitx::KeyEvent &event) {
    if (!client_.connected()) {
        return;                                  // daemon 不可用时放行
    }
    if (config_.mode.value() == Mode::Continuous) {
        return;                                  // 连续监听：热键完全交给 Fcitx
    }

    const bool matches = event.checkKeyList(
        config_.hotkey.value(), fcitx::KeyEventMatchingMode::MatchAllNormalizedKeys);
    if (config_.mode.value() == Mode::Ptt) {
        handlePtt(event, matches);
    } else {
        handleToggle(event, matches);
    }
}

void VoimeAddon::handlePtt(fcitx::KeyEvent &event, bool matches) {
    if (holdActive_ && event.isRelease() && event.rawKey().code() == holdCode_) {
        holdActive_ = false;
        client_.stop(segmentId_, TriggerSource::Hold);
        event.filterAndAccept();
        return;
    }
    if (event.isRelease()) {
        if (matches) {
            event.filterAndAccept();             // 被忽略的 press 的 release 也不放行
        }
        return;
    }
    if (!matches) {
        return;
    }

    event.filterAndAccept();
    if (finalizing_ || recording_) {
        return;                                  // 收尾 / 已有段：消费但忽略
    }
    holdActive_ = true;
    holdCode_ = event.rawKey().code();
    segmentId_ = nextSegmentId();
    target_ = event.inputContext()->watch();      // 弱引用，IC 销毁后失效
    client_.start(segmentId_, TriggerSource::Hold);
}

void VoimeAddon::handleToggle(fcitx::KeyEvent &event, bool matches) {
    if (toggleCode_ && event.isRelease() && event.rawKey().code() == toggleCode_) {
        toggleCode_ = 0;
        event.filterAndAccept();
        return;
    }
    if (event.isRelease()) {
        if (matches) {
            event.filterAndAccept();
        }
        return;
    }
    if (!matches) {
        return;
    }

    event.filterAndAccept();
    toggleCode_ = event.rawKey().code();
    if (finalizing_) {
        return;
    }
    if (!recording_) {
        segmentId_ = nextSegmentId();
        target_ = event.inputContext()->watch();
        client_.start(segmentId_, TriggerSource::Toggle);
    } else {
        client_.stop(segmentId_, TriggerSource::Toggle);
    }
}
  • 上面的代码只表达匹配与消费顺序；错误处理、IPC 队列、配置重载与多段 ID 管理在实现中补齐。recording_ / finalizing_ 由 daemon 的 State 消息更新。
  • target_ 使用 TrackableObjectReference<InputContext>；不要保存裸指针，输入框销毁后裸指针会悬空。
  • hold 的松开必须在按下时记录 keycode，而不是再次比较完整组合键；用户可能先松 Super 再松 F2。
  • toggle 的按下与松开都要消费，避免松开事件进入应用；自动重复的 press 也消费但忽略。
  • 组合键中的修饰键可能在按下时已被 Fcitx 送到应用；应用会看到一次单独的修饰键 press / release，这是输入法热键可接受的噪声。

6. 文本上屏

↑

6.1 投递路径

voimed 产生 Final 后，把 { segment_id, text } 发给 addon。addon 用 segment_id 找到语音段开始时记录的 InputContext 弱引用；只有目标仍存在且 hasFocus() 为真时，才调用 ic->commitString(text)。Fcitx 自己选择 frontend 并完成实际插入。

项目契约
提交 API fcitx::InputContext::commitString(const std::string &text)。
目标 语音段开始时聚焦的 InputContext，以 TrackableObjectReference<InputContext> 保存。
前置检查 ref.get() != nullptr && ref.get()->hasFocus()；任一失败都不提交。
frontend 由 Fcitx 决定：原生 Wayland 使用 text-input-v3 commit_string；XWayland/X11 使用 XIM；其他 frontend 同理。Voime 不直接调用 Wayland/X11 API。
编码 UTF-8 纯文本；中文、英文、标点与 emoji 原样提交，不做换行转换。
长度 Fcitx 的 Wayland frontend 会按 UTF-8 字符边界拆分长文本；Voime 不自行截断，也不假设单次提交上限。
commit filter Fcitx 的 commitFilter 会生效；Voime 不绕过、不二次转换文本。
空文本 不调用 commitString，不产生结果行，不修改任何外部状态。
无目标 / 失焦 不注入其他窗口；daemon 保留 Final 到历史，TUI 可见。记录 CommitTargetLost。
提交确认 commitString 无返回值；addon 只能确认调用了 Fcitx，不能确认应用接受。文档不得承诺“必然上屏”。

6.2 目标输入框策略

6.3 临时文本窗口

说话期间，addon 把当前段的 Partial 写入目标 InputContext 的 Fcitx 输入面板： inputPanel().setPreedit(fcitx::Text(partial))，再调用 updateUserInterface(fcitx::UserInterfaceComponent::InputPanel)。Fcitx 的当前 UI 负责渲染一个简单的临时 文本窗口；Voime 不自绘窗口，也不使用客户端 preedit。

项目契约
显示 API InputPanel::setPreedit(Text) + InputContext::updateUserInterface(UserInterfaceComponent::InputPanel)。
内容 只显示当前语音段的 Partial 文本；没有候选词、按钮、历史或光标编辑。文本为空时不显示窗口。
显示条件 仅当语音段正在录音，且目标 InputContext 仍存在并 hasFocus()。
更新时机 每次收到 Partial 时整体替换 preedit；不追加、不保留上一段文本。
关闭时机 收到 Final、停止录音、空段、ASR 错误、目标失焦 / 销毁、daemon 断线时清空 preedit 并刷新 UI。
与最终提交的顺序 先清空临时窗口，再调用 commitString(final)；避免最终文本插入后窗口仍残留。
UI 可用性 是否显示由 Fcitx UI addon 决定；没有可用 UI 或当前 UI 不渲染 preedit 时不显示窗口，最终提交仍正常。
与当前输入法 临时窗口使用当前 InputPanel；如果当前输入法也在更新该面板，可能覆盖预览。Voime 在每次 Partial 时重设，停止时清空。
客户端 preedit 不调用 setClientPreedit / updatePreedit；文本不进入应用自己的 preedit 区域。
  • 临时窗口只在说话过程中存在；说话结束后关闭，最终文本进入历史与目标输入框。
  • TUI 的预览仍可作为可选监视器；Fcitx 输入面板是默认的说话中预览。
  • 不在窗口中显示候选、录音按钮或历史；录音状态仍由 TUI 的 recording 标记表达。

消息方向语义
Helloclient → daemon声明角色、协议版本；Fcitx 额外携带 { mode, hotkey }；daemon 回 Snapshot。
ConfigureFcitx → daemonaddon 配置重载时更新 mode / hotkey；mode 在下一个语音段生效。
Start / Stop / Toggleclient → daemon手动或 PTT 触发；带 segment_id 与来源。Recording / Finalizing 时 Start 被忽略；Stop 对已结束段幂等。
SegmentStarteddaemon → clientscontinuous / TUI / ctl 段开始时广播；addon 用它捕获目标 InputContext。
Finaldaemon → clients最终文本；addon 用 segment_id 找到目标、清空临时窗口并提交；TUI 用于显示历史。
Snapshotdaemon → client连接时全量状态；包含 mode、hotkey、addon 连接状态与 transcript。
Statedaemon → clientrecording / finalizing / 当前 segment_id。
Partialdaemon → client未加标点的临时文本；addon 写入 Fcitx InputPanel 显示临时窗口，TUI 同步显示。
ClearHistoryclient → daemon清空已完成 transcript；保留 current segment 与 partial。
QuitControl → daemon停止 daemon；TUI 的 q 不发送 Quit，只 detach。
Byedaemon → clientdaemon 关闭；TUI 恢复终端，addon 清除状态并等待重连。
  • 只允许一个 role=Fcitx 连接；第二个连接返回 Error 并断开，避免重复提交。
  • addon 的 Final / State 不可丢；Partial 可在队列满时丢弃。TUI 慢客户端使用有界队列，队列满时断开该 TUI，不阻塞 daemon。
  • addon 断线时 daemon 继续识别并保留历史；Final 照常广播给 TUI，但没有提交者。重连后不做历史补交；continuous 自动分段停止，保留 TUI / ctl 手动控制。
  • Start 被 daemon 拒绝（例如已有段）时，addon 必须清除该 segment_id 的目标与本地 recording 状态，不能保留一个不存在的段。
  • 如果 XDG_RUNTIME_DIR 未设置，回退到 /tmp/voime-$UID/，目录仍为 0700；addon 使用默认 socket 路径。

退出码含义
0正常退出 / 已有一个 daemon 在运行（幂等启动）。
1启动或运行期致命错误：模型、音频、socket、pipeline 初始化失败。
2命令行参数非法。
  • Mode 与 Hotkey 只在 Fcitx addon 配置中；voimed 不接受模式或热键参数。
  • daemon 从 addon 的 Hello / Configure 获取模式：continuous 时 VAD 自动切分，ptt / toggle 时等待 addon 的 Start / Stop。
  • voime doctor 检查 socket、daemon 版本、模型、音频、Fcitx addon 连接、Mode / Hotkey；输出到 stdout，不进入 TUI。
  • TUI 连不上 daemon 时写 stderr 并以 1 退出；它不尝试自行启动 daemon。

7.5 TUI 行为

项目行为
启动voimed 常驻；voime 可选连接；连不上时 stderr 报错退出。

7.6 Fcitx 状态

项目契约
输入法图标 使用 Fcitx 自己的状态图标；Voime 条目按 Fcitx 规则显示名称、Label 与 Icon。
临时文本窗口 由 Fcitx InputPanel 的 preedit 渲染；不是状态图标，也不是候选窗口。Partial 到达即更新，Final / 停止时清空。
录音状态 v1 由 TUI 的 recording 标记显示；没有 TUI 时不显示额外图标，临时窗口只显示 Partial。
Voime 不是当前输入法 Fcitx 图标显示当前输入法（例如拼音）；PTT 仍可通过 PreInputMethod 监听工作。不要把“图标不是 Voime”误解为 PTT 不可用。
退出 daemon 使用 voime ctl quit 或 systemd；Fcitx 继续运行，Voime 条目保留但 PTT 因 daemon 不可用而放行。

11.2 P0 必须实测的问题

  • Fcitx 在拼音 / 键盘布局 / Voime 三种当前输入法下，是否都把 Hotkey 送到 PreInputMethod watcher。
  • Fcitx 是否在终端、XWayland、无 text-input 的原生窗口中发送按键；哪些应用需要缩小承诺。
  • Mode=continuous 时，daemon 能否仅靠 addon 的 Hello / Configure 进入 VAD 自动分段；addon 断线后是否正确停止自动分段。
  • InputPanel::setPreedit 在当前 Fcitx UI 中是否显示为临时窗口；Partial 更新、Final 清空、目标失焦清空是否符合预期。
  • 拼音 / 其他输入法更新同一 InputPanel 时，临时窗口是否被覆盖；是否需要限制为 Voime 当前输入法才显示。
  • filterAndAccept() 是否完全阻止 PTT 键进入应用与当前输入法。
  • commitString 在 GTK4 / Qt6 / Firefox / Electron / XWayland XIM / 终端中的实际行为与长度限制。
  • Fcitx 的 commit filter 是否改变中文、英文、标点或 emoji。
  • addon 的 PreInputMethod watcher 与 Fcitx 自身 trigger / toggle-preedit watcher 的先后顺序。
  • Fcitx 重启、addon 重载、配置重载时 HandlerTableEntry 的生命周期与重复注册风险。
  • 目标 InputContext 在窗口关闭、切换 workspace、锁屏时的 hasFocus() 与销毁行为。
  • 多显示 / 多 seat 下 addon 收到的是哪个 InputContext，是否需要多目标表。
