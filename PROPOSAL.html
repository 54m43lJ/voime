1. 结论与决策

↑

可行，而且比 Voime 自己实现 input-method-v2、XIM、virtual-keyboard 或全局热键更贴合系统的输入法模型。 Fcitx5 已经是键盘的所有者：它通过自己的 Wayland frontend（input-method-v2）或 XIM 接收按键，维护 InputContext，负责 preedit、最终文本提交、候选窗口和输入法状态。Voime 只需要提供一个 Fcitx addon：在 Fcitx 的 InputContextKeyEvent 管线里匹配 PTT 键，并在最终文本到达时调用 InputContext::commitString()。这就是“Fcitx 捕获热键、Fcitx 上屏”。

音频采集、VAD、ASR 与标点仍留在 Rust 的 voimed 守护进程；addon 只做桥接，避免把模型推理放进 fcitx5 进程。TUI 变成可选的监视器与控制客户端，不再拥有键盘或上屏路径。Fcitx5 的 Wayland frontend 只在有 text-input 焦点时持有键盘抓取，因此 PTT 只在 Fcitx 能收到按键的输入框里生效；这正好是最终 文本需要提交到的地方。

决策项结论
集成方式 Voime 实现为 Fcitx5 addon（voime.so，fcitx::InputMethodEngineV2），并在 Fcitx 输入法组中注册 Voime 条目。Fcitx 负责键盘、frontend、焦点、preedit 与提交；Voime 不再实现独立输入法。
PTT 热键 addon 在 InputContextKeyEvent 的 PreInputMethod 阶段匹配 hold / toggle 组合键，命中后 filterAndAccept() 消费；不再由 TUI 的 Space 承担唯一入口，也不使用 portal、evdev 或 XGrabKey。
上屏 addon 调用 InputContext::commitString(final)；Fcitx 通过当前 frontend（原生 Wayland text-input-v3、XWayland/X11 XIM、IBus/DBus 等）把文本插入聚焦输入框。Voime 不写剪贴板、不注入按键。
进程边界 fcitx5 进程加载 addon；voimed 是独立 Rust 守护进程，拥有音频、模型、ASR、标点与会话历史；voime 是可选的 TUI 客户端。addon 与 voimed 通过 Unix socket 通信。
语音段目标 每个语音段在开始时绑定当时聚焦的 InputContext（PTT 按下、VAD 语音起点或 TUI/ctl Start）；最终文本只提交到仍存在且仍聚焦的同一输入框，否则保留在 daemon/TUI，不向其他窗口注入。
ASR 链路 FireRedVAD → FireRedASR2-CTC int8 → FireRedPunc。CTC 是单 ONNX（约 740 MiB），直接走现有 ort，运行时从 metadata 读 CMVN，greedy 解码；final 与尾部 partial 共用同一模型。VAD 分段、临时结果和标点链路保持不变，CPU 推理耗时与模型内存低于 AED。
分段上限 CTC 的 RTF 允许把 max_segment_ms 推荐值从 10 s 提高到 30 s；PTT 达到上限自动切段并继续收集，continuous 仍由 VAD 提前切分。本提案不新增倒计时 UI。
剪贴板 删除自动写入剪贴板的路径，也删除 arboard 依赖。TUI 仍可使用终端自身的鼠标选择 / 复制；最终文本的正式出口只有 Fcitx。
Preedit v1 不写客户端 preedit；临时结果只在 TUI 显示。Phase 2 可在 Voime 是当前输入法且用户显式启用时调用 inputPanel().setClientPreedit() + updatePreedit()。
托盘与状态 使用 Fcitx 自己的输入法状态 / 托盘；Voime 不实现 StatusNotifierItem、DBusMenu 或自绘托盘。录音状态在 v1 由可选 TUI 显示。
平台 Linux + Fcitx5 为验收平台。Windows 不在本版范围；X11 仅覆盖通过 Fcitx XIM 接收按键的应用，裸 X11 全局热键不在范围。
Fcitx 版本 要求 Fcitx5 ≥ 5.1.23；KeyEventMatchingMode::MatchAllNormalizedKeys 与 checkKeyList 的当前签名以该版本为准。
配置位置 PTT 组合键、socket 路径、可选 preedit 放在 Fcitx addon 配置 ~/.config/fcitx5/conf/voime.conf；模型、音频、模式与线程数仍由 voimed 命令行决定。
生命周期 voimed 由 systemd user service 或桌面自启动拉起；addon 在 Fcitx 启动时加载并连接 socket，断线自动重连。TUI 可随时 attach / detach，不影响 PTT 与上屏。
  • Fcitx5 不再是“必须停用”的冲突对象，而是宿主。Voime 与拼音、键盘布局、候选窗口等 Fcitx 能力共存；Voime 只增加一个语音输入法条目。
  • ASR 从 AED 切换到 CTC 的目标是降低 CPU 推理耗时与模型内存：本机 2 threads 实测 RTF 约 0.066–0.094，模型约 740 MiB；详细事实、预处理和 ONNX 输入输出见 ASR 研究。
  • PTT 只在 Fcitx 能收到按键的输入上下文中生效：原生 Wayland 的 text-input 输入框、通过 Fcitx XIM 连接的 XWayland/X11 应用。桌面空白处、未使用 Fcitx 的应用、没有文本焦点的窗口不保证 PTT。
  • 不实现独立的 input-method-v2 对象、virtual-keyboard、XIM server、StatusNotifierItem 托盘或剪贴板回退；这些职责全部交给 Fcitx 或删除。
  • 最终文本只有 commitString 一条正式路径；没有“提交失败就粘贴”的降级。没有焦点时文本保留在 daemon/TUI，用户可手动处理。
  • 本文件只是提案，不修改现有 README / USER / CORE / PROVIDER / BUILD。批准后按 §9 的顺序落笔；正式文档稳定后，本文件从正式文档集中移除。

2. 目标与非目标

↑

2.1 目标

  • 把 Voime 注册为 Fcitx5 输入法引擎：安装 addon 后，Fcitx 的输入法列表出现 Voime，可以加入输入法组。
  • 由 Fcitx 捕获 PTT 热键：按住说话与按一下切换两种语义都在 addon 内匹配，命中后消费按键；普通按键完全交给 Fcitx。
  • 在任意聚焦的 Fcitx 输入框中工作：原生 Wayland 应用、通过 Fcitx XIM 的 XWayland/X11 应用，以及支持 text-input 的终端。
  • 最终文本通过 Fcitx 的 commitString 插入光标位置，不再写剪贴板，也不再模拟粘贴按键。
  • PTT 不要求当前输入法是 Voime；用户可以在拼音、键盘布局或其他 Fcitx 输入法处于活动状态时直接按 PTT。
  • 把音频、模型、ASR、标点与会话历史放进独立 voimed 守护进程；Fcitx addon 只负责热键、目标输入框、IPC 与提交。
  • TUI 变成可选监视器：显示临时结果 / 历史、发送 Start / Stop / Toggle / Clear；关闭 TUI 不影响 PTT 与上屏。
  • ASR 切换为 FireRedASR2-CTC int8：单 ONNX、ort CPU 推理、CMVN 从 metadata 读取、greedy CTC；降低 CPU 推理耗时与模型内存，同时保持 VAD 分段、临时结果与 FireRedPunc 不变。
  • 保留现有的纯本地、离线、无 GPU、无 Python 运行时约束；CTC 模型包由安装脚本下载，不在运行期联网或导出。
  • 把 PTT 组合键、socket 路径、可选 preedit 暴露为 Fcitx addon 配置，可在 fcitx5-configtool 或配置文件中修改。
  • CTC 的 CPU 目标（2 threads）：RTF ≤ 0.1；10 s 音频 ≤ 1.0 s，30 s 音频 ≤ 3.0 s；真实麦克风数据上的 CER 不明显差于 AED。
  • 提供可重复的安装 / 构建流程：Rust workspace 产物 + C++ addon + Fcitx 描述文件 + 可选 systemd user service。

2.2 非目标 / 本版不做

  • 不做拼音、形码、候选词、云输入或通用键盘输入法；Voime 只负责语音识别文本的提交。
  • 不取代 Fcitx，不与 Fcitx 并列成为第二个输入法；Voime 是 Fcitx 的一个 addon。
  • 不实现独立的 input-method-v2 客户端、virtual-keyboard、XIM server、GlobalShortcuts portal、evdev 抓键或 XGrabKey。
  • 不实现自定义托盘、候选窗口、状态图标或设置 GUI；这些由 Fcitx 及 fcitx5-configtool 提供。
  • 不自动写剪贴板，不恢复用户原剪贴板，不通过 Ctrl+V / Ctrl+Shift+V 注入文本。
  • 不保证桌面空白处、锁屏、未使用 Fcitx 的应用、没有 text-input 的窗口中的 PTT；这些场景没有可提交的输入上下文。
  • v1 不写客户端 preedit，不显示输入框内的临时文本；临时结果只在 TUI。
  • 不引入第二个 ASR 模型、FireRedASR2-LLM、GPU / NPU 推理或云端识别；AED 只作为 legacy 对比后端，默认不启用。
  • 不改变 VAD 分段算法、临时识别节奏或 FireRedPunc；只替换 ASR 后端，并把默认 max_segment_ms 调整为 30 s。
  • 不承诺 int8 CTC 在英文子词上的完美准确率；官方 0.wav 的已知英文错误需要真实麦克风数据评估。
  • 不支持 Windows；X11 只覆盖通过 Fcitx XIM 收到按键的应用，不承诺裸 X11 全局热键。
  • 不保存音频、按键或识别历史到磁盘；daemon 退出后会话历史丢失。
  • 不把 Fcitx 的按键事件或用户输入写入日志；addon 只记录连接状态与错误码。

2.3 关键约束

约束影响
Fcitx 必须运行且 addon 已加载 没有 Fcitx 就没有键盘捕获、InputContext 与提交通道；PTT 和上屏都不可用。addon 未连接 daemon 时按键应原样放行，避免破坏正常输入。
Fcitx 只把按键路由到有输入焦点的上下文 PTT 只在 Fcitx 能收到 InputContextKeyEvent 时触发；裸桌面、无文本字段的窗口不保证。最终文本也需要同一个聚焦上下文。
Wayland frontend 只在 text-input 激活时抓键盘 Fcitx 自己的 Wayland frontend 在 activate 时 grab_keyboard，deactivate 时释放；Voime 不能假设“整个桌面都能按 PTT”。
XWayland/X11 依赖 Fcitx XIM 只有通过 XIM 连接 Fcitx 的应用才会把按键交给 Fcitx；不使用 XIM 的 X11 应用既收不到 PTT，也无法通过 Fcitx 提交。
PreInputMethod 早于 Fcitx 全局热键处理 addon 在 Fcitx 的 trigger / alt-trigger / enumerate 键之前看到事件。PTT 组合键不得与这些全局热键重叠，否则会先被 Voime 消费。
commitString 没有返回值和确认 addon 无法知道应用是否接受文本；只能保证调用了 Fcitx API。目标输入框丢失时不提交，保留历史。
Fcitx 的 commit filter 会生效 最终文本可能被 Fcitx 的提交过滤器转换（例如全角、替换规则）；Voime 不绕过 Fcitx 的提交管线。
Wayland commit 单次有长度上限 Fcitx 的 Wayland frontend 会按 UTF-8 字符边界拆分长文本；Voime 不需要自己切块，但文档要说明最终文本经过 Fcitx。
addon 与 Fcitx ABI 绑定 voime.so 必须针对 Fcitx5 头文件构建；Fcitx 大版本升级后需要重新编译。最低版本 5.1.23。
addon 运行在 Fcitx 事件循环 socket 读写必须非阻塞；不能调用阻塞的 ASR、文件下载或长耗时操作，否则会卡住整个输入法。
CTC 是离线全序列模型 没有帧级 cache 或流式状态；仍按 VAD / PTT 切成完整语音段后一次性编码。分段不能无限增长，默认 max_segment_ms 取 30 s。
CTC 预处理必须对齐 sherpa 16 kHz / 80 bins / 25 ms 窗 / 10 ms 帧移 / snip_edges=true / high_freq=0 / 32768 缩放；CMVN 从 ONNX metadata 读取，不能依赖 cmvn.ark。
CTC 词表是 token id 两列 现有 tokenizer 需要支持 id 后缀；id 0 为 blank；英文 ▁ 需要转换为空格，中文 token 直接拼接。
int8 CTC 英文质量有限 官方 0.wav 存在英文子词缺失；上线前用真实麦克风数据评估 CER，必要时保留 AED legacy 或评估 FP32。
单实例与多显示 一个 Fcitx 进程只加载一个 addon；只允许一个 Fcitx 角色连接 daemon。第二个连接被拒绝并记录日志。
安全边界 addon 与 Fcitx 一样能看到经过输入法的按键；不记录按键、不落盘、不联网，文档需要明确信任模型。

4. 目标架构

↑

4.1 组件图

  • Fcitx5 拥有键盘与输入上下文；Voime addon 只在 Fcitx 的事件管线中匹配 PTT，并通过 commitString 提交最终文本。
  • 普通按键完全由 Fcitx 处理，Voime 不转发、不缓存、不模拟按键；这与“自己成为 input-method-v2 输入法”的方案有本质区别。
  • voimed 不依赖 Wayland / X11 / Fcitx；它只依赖音频设备、模型与 Unix socket，便于独立测试与重启。
  • TUI 只通过 socket 观察和发命令；关闭 TUI 不影响 addon 与 daemon。
  • Fcitx 配置文件（addon / inputmethod / voime.conf）是 PTT 键与 addon 行为的权威来源；voimed 不复制这些配置。

4.3 启动与生命周期

systemd --user（推荐）
└── voimed
    ├── config::Config::resolve(args)
    ├── model::ModelManifest::load / verify
    ├── infer::session::SessionFactory::new
    ├── pipeline::spawn(...)
    ├── audio::capture::start(...)
    ├── ipc_server::bind($XDG_RUNTIME_DIR/voime/voimed.sock)
    └── daemon::run(...)

fcitx5
├── 加载 share/fcitx5/addon/voime.conf        OnDemand=False
├── 加载 share/fcitx5/inputmethod/voime.conf  Addon=voime
├── VoimeAddon::VoimeAddon(instance)
│   ├── 读取 ~/.config/fcitx5/conf/voime.conf
│   ├── ipc::Client::connect(socket)（失败时重试）
│   └── watchEvent(InputContextKeyEvent, PreInputMethod)
└── 正常输入法路由

voime（可选）
└── ipc::Client::connect(socket)
    ├── Hello { role: Tui }
    ├── Snapshot
    └── 事件循环
  • voimed 与 Fcitx 的启动顺序不敏感：daemon 先起时 addon 直接连接；addon 先起时按退避间隔重连。任一进程重启都不需要重启另一个。
  • addon 未连接 daemon 时，不得消费 PTT 键；按键原样交给 Fcitx / 应用，并在 Fcitx 日志中记录一次 warning。这样不会因为 daemon 未启动而破坏正常打字。
  • 推荐使用 systemd user service 启动 voimed，因为它需要在登录后长期驻留，并且不依赖 TTY；也可以由桌面会话的 exec-once 启动。
  • 退出顺序：停止录音 → 取消当前段 → 关闭 socket → 停止 pipeline → 停止音频。addon 收到 EOF 后清除 hold / toggle 状态与目标引用；Fcitx 继续正常运行。
  • voime ctl quit 只停止 daemon，不关闭 Fcitx；Fcitx 中的 Voime 条目仍存在，但 PTT 会因 daemon 不可用而放行按键。

│   └── SegmentStarted → Recording
└── TUI / ctl Start
    └── SegmentStarted → Recording

Recording
├── hold release / toggle press / TUI Stop / ctl Stop
│   └── Finalizing
├── VAD 静音 / max_segment_ms
│   └── Finalizing
└── addon / daemon 断线，或 Fcitx 退出
    └── Idle（不提交，丢弃当前段）

Finalizing
├── ASR + Punc 成功且文本非空
│   └── Delivering
├── ASR / Punc 失败
│   └── Idle（记录 SegmentDropped）
└── 空文本
    └── Idle（不产生 Final）

Delivering
├── 目标 InputContext 存在且 hasFocus()
│   └── commitString(text) → Idle
└── 目标丢失 / 失焦 / 不存在
    └── 保留在 daemon 历史与 TUI → Idle
  • 同一时刻只允许一个语音段；Recording / Finalizing 期间新的 Start 被忽略，toggle 在 Finalizing 期间不产生新段。
  • PTT 的 hold 与 toggle 都由 addon 产生 segment_id；continuous、TUI 与 ctl 由 daemon 产生。addon 用同一个 ID 关联目标输入框与最终文本。
  • continuous 模式不消费 PTT 键：所有按键按普通输入处理，VAD 自动开始 / 结束语音段；如果用户需要手动控制，使用 TUI 或 voime ctl。
  • 目标输入框只在语音段开始时绑定一次；录音期间切换窗口不会改变目标。最终文本不会进入录音开始之后才聚焦的另一个窗口。
  • daemon 断线时 addon 立即清除当前段与目标；如果 daemon 之后恢复，旧段不会补交。

5. 热键捕获

↑

5.1 主路径：Fcitx 事件管线

Fcitx 的 frontend 收到按键后，会构造 InputContextKeyEvent 并按阶段执行事件处理器。addon 在 PreInputMethod 阶段注册监听：它比当前输入法引擎更早看到按键，但晚于 Fcitx 的内部保留阶段。 命中 hold / toggle 后，addon 调用 filterAndAccept()，按键不再进入当前输入法或应用；未命中的按键 完全不动，由 Fcitx 继续处理。

项目契约
监听 API Instance::watchEvent<EventType::InputContextKeyEvent>(EventWatcherPhase::PreInputMethod, handler)。
匹配 使用 addon 配置中的 KeyListOption；KeyEvent::checkKeyList(keys, KeyEventMatchingMode::MatchAllNormalizedKeys)。
按住说话（hold） 按下匹配 → 记录目标 InputContext、生成 segment_id、发送 Start、filterAndAccept()；松开按记录的 raw keycode 匹配（不依赖松开时的 modifiers），发送 Stop，同样消费。
切换说话（toggle） 按下匹配 → 若 Idle 则 Start，若 Recording 则 Stop；按下与松开都消费；Finalizing 期间按下只消费、不产生新段。
普通按键 不匹配时立即返回；Fcitx 将按键交给当前输入法或应用。Voime 不转发、不缓存、不改变 keymap。
自动重复 PTT 键的 repeat press 一律消费并忽略；hold 只触发一次 Start，toggle 只切换一次。
多个键盘 / 布局 hold 的松开按 keycode 匹配，避免先松修饰键导致匹配失败；布局切换不影响已开始的 hold 段。
当前输入法 PTT 监听与当前输入法无关；拼音、键盘布局或其他 Fcitx 引擎处于活动状态时仍可触发。Voime 条目不必是当前输入法。
消费语义 filterAndAccept() 阻止 PTT 键进入应用；不会产生空格、字符或快捷键副作用。
daemon 未连接 不消费 PTT 键，原样交给 Fcitx / 应用；记录一次 warning。连接恢复后重新启用匹配。
无目标输入框 不开始录音；即使收到按键，也不创建没有目标的语音段。
与 Fcitx 全局热键冲突 PTT 组合键不得与 Fcitx 的 trigger / alt-trigger / enumerate / preedit 切换键重叠：trigger / alt-trigger / enumerate 在 InputMethod 阶段处理，preedit 切换也在 PreInputMethod 阶段；Voime 的 watcher 可能先消费它们。
与合成器绑定冲突 Hyprland 等合成器先处理自己的 bind / bindr；PTT 必须选择未被合成器消费的组合键。这一点与 Fcitx 自身的热键限制相同。
X11 / XWayland 只有通过 Fcitx XIM 连接的应用才会把按键交给 Fcitx；不使用 XIM 的 X11 应用不保证 PTT。 
keyWatcher_ = instance_->watchEvent<fcitx::EventType::InputContextKeyEvent>(
    fcitx::EventWatcherPhase::PreInputMethod,
    [this](fcitx::KeyEvent &event) { handleKey(event); });

void VoimeAddon::handleKey(fcitx::KeyEvent &event) {
    if (!client_.connected()) {
        return;                                  // daemon 不可用时放行
    }
    if (holdActive_ && event.isRelease() && event.rawKey().code() == holdCode_) {
        holdActive_ = false;
        client_.stop(segmentId_, TriggerSource::Hold);
        event.filterAndAccept();
        return;
    }
    if (toggleCode_ && event.isRelease() && event.rawKey().code() == toggleCode_) {
        toggleCode_ = 0;
        event.filterAndAccept();
        return;
    }
    if (event.isRelease()) {
        return;
    }

    const bool hold = event.checkKeyList(
        config_.holdKey.value(), fcitx::KeyEventMatchingMode::MatchAllNormalizedKeys);
    const bool toggle = event.checkKeyList(
        config_.toggleKey.value(), fcitx::KeyEventMatchingMode::MatchAllNormalizedKeys);
    if (!hold && !toggle) {
        return;                                  // 普通键交给 Fcitx
    }

    event.filterAndAccept();                     // PTT 键不进入应用
    if (finalizing_) {
        return;                                  // 收尾期间不接受新段
    }

    if (hold) {
        if (recording_) {
            return;                              // 已有段，忽略重复 Start
        }
        holdActive_ = true;
        holdCode_ = event.rawKey().code();
        segmentId_ = nextSegmentId();
        target_ = event.inputContext()->watch();  // 弱引用，IC 销毁后失效
        client_.start(segmentId_, TriggerSource::Hold);
    } else {
        toggleCode_ = event.rawKey().code();
        if (!recording_) {
            segmentId_ = nextSegmentId();
            target_ = event.inputContext()->watch();
            client_.start(segmentId_, TriggerSource::Toggle);
        } else {
            client_.stop(segmentId_, TriggerSource::Toggle);
        }
    }
}
  • 上面的代码只表达匹配与消费顺序；错误处理、IPC 队列、配置重载与多段 ID 管理在实现中补齐。recording_ / finalizing_ 由 daemon 的 State 消息更新。
  • target_ 使用 TrackableObjectReference<InputContext>；不要保存裸指针，输入框销毁后裸指针会悬空。
  • hold 的松开必须在按下时记录 keycode，而不是再次比较完整组合键；用户可能先松 Super 再松 F2。
  • toggle 的按下与松开都要消费，避免松开事件进入应用；自动重复的 press 也消费但忽略。
  • 组合键中的修饰键可能在按下时已被 Fcitx 送到应用；应用会看到一次单独的修饰键 press / release，这是输入法热键可接受的噪声。

6. 文本上屏

↑

6.1 投递路径

voimed 产生 Final 后，把 { segment_id, text } 发给 addon。addon 用 segment_id 找到语音段开始时记录的 InputContext 弱引用；只有目标仍存在且 hasFocus() 为真时，才调用 ic->commitString(text)。Fcitx 自己选择 frontend 并完成实际插入。

项目契约
提交 API fcitx::InputContext::commitString(const std::string &text)。
目标 语音段开始时聚焦的 InputContext，以 TrackableObjectReference<InputContext> 保存。
前置检查 ref.get() != nullptr && ref.get()->hasFocus()；任一失败都不提交。
frontend 由 Fcitx 决定：原生 Wayland 使用 text-input-v3 commit_string；XWayland/X11 使用 XIM；其他 frontend 同理。Voime 不直接调用 Wayland/X11 API。
编码 UTF-8 纯文本；中文、英文、标点与 emoji 原样提交，不做换行转换。
长度 Fcitx 的 Wayland frontend 会按 UTF-8 字符边界拆分长文本；Voime 不自行截断，也不假设单次提交上限。
commit filter Fcitx 的 commitFilter 会生效；Voime 不绕过、不二次转换文本。
空文本 不调用 commitString，不产生结果行，不修改任何外部状态。
无目标 / 失焦 不注入其他窗口；daemon 保留 Final 到历史，TUI 可见。记录 CommitTargetLost。
提交确认 commitString 无返回值；addon 只能确认调用了 Fcitx，不能确认应用接受。文档不得承诺“必然上屏”。
剪贴板 不读写剪贴板；不恢复原内容；不发送粘贴快捷键。

6.6 ASR：切换 FireRedASR2-CTC

详细数据、预处理和 ONNX 输入输出见 ASR 研究。本版把现有 FireRedASR2-AED 换成 FireRedASR2-CTC int8：单 ONNX、直接走现有 ort，final 与现有尾部 partial 共用同一个 模型；VAD 分段、临时结果和 FireRedPunc 标点链路保持不变。CTC 在 2 threads 下 RTF 约 0.066–0.094， 模型约 740 MiB，明显低于 AED 的 CPU 成本。

项目方案

分段 默认 max_segment_ms 从 10_000 提高到 30_000；PTT 达到上限自动切段并继续收集，continuous 由 VAD 提前切分。本提案不新增倒计时 UI。

Legacy 保留现有 AED 后端一个发布周期用于对比 / 回退；manifest 用 tagged enum 区分 fire-red-ctc 与 fire-red-aed，默认 fire-red-ctc。

握手: Hello { role, version }；版本不匹配返回 Error 并断开

ClientMessage =
  | Hello { role: Fcitx | Tui | Control, version: u32, hotkeys?: Hotkeys }
  | Start { segment_id: u64, source: TriggerSource }
  | Stop  { segment_id: u64, source: TriggerSource }
  | Toggle { segment_id: u64, source: TriggerSource }
  | ClearHistory
  | Status
  | Quit

ServerMessage =
  | Snapshot { mode, phase, partial, transcript, addon, hotkeys? }
  | SegmentStarted { segment_id: u64, source: TriggerSource }
  | State { recording, finalizing, segment_id?: u64 }
  | Partial { segment_id: u64, text }
  | Final { segment_id: u64, text }
  | HistoryCleared
  | Status { ... }
  | Error { code, message }
  | Bye

TriggerSource = Hold | Toggle | Tui | Cli | Continuous
消息方向语义
Helloclient → daemon声明角色与协议版本；Fcitx 额外上报热键用于 TUI 提示；daemon 回 Snapshot。
Start / Stop / Toggleclient → daemon手动或 PTT 触发；带 segment_id 与来源。Recording / Finalizing 时 Start 被忽略；Stop 对已结束段幂等。
SegmentStarteddaemon → clientscontinuous / TUI / ctl 段开始时广播；addon 用它捕获目标 InputContext。
Finaldaemon → clients最终文本；addon 用 segment_id 找到目标并提交；TUI 用于显示历史。
Snapshotdaemon → client连接时全量状态；包含 addon 连接状态与热键提示。
Statedaemon → clientrecording / finalizing / 当前 segment_id。
Partialdaemon → client未加标点的临时文本；TUI 显示，addon 可忽略或用于 Phase 2 preedit。
ClearHistoryclient → daemon清空已完成 transcript；保留 current segment 与 partial；不碰剪贴板。
QuitControl → daemon停止 daemon；TUI 的 q 不发送 Quit，只 detach。
Byedaemon → clientdaemon 关闭；TUI 恢复终端，addon 清除状态并等待重连。
  • 只允许一个 role=Fcitx 连接；第二个连接返回 Error 并断开，避免重复提交。
  • addon 的 Final / State 不可丢；Partial 可在队列满时丢弃。TUI 慢客户端使用有界队列，队列满时断开该 TUI，不阻塞 daemon。
  • addon 断线时 daemon 继续识别并保留历史；Final 照常广播给 TUI，但没有提交者。重连后不做历史补交。
  • Start 被 daemon 拒绝（例如已有段）时，addon 必须清除该 segment_id 的目标与本地 recording 状态，不能保留一个不存在的段。
  • 如果 XDG_RUNTIME_DIR 未设置，回退到 /tmp/voime-$UID/，目录仍为 0700；socket 路径可由 addon 配置覆盖。

11. 风险与验证

↑

风险影响缓解
Fcitx 未运行 / addon 未加载 没有 PTT、没有提交；用户以为程序坏了。 BUILD 明确安装步骤；addon 未连接 daemon 时放行按键；voime doctor 检查 Fcitx / addon / socket；Fcitx 日志记录加载失败。
PTT 只在部分应用生效 终端、非 XIM 的 X11 应用、无 text-input 的窗口按 PTT 无反应。 文档明确覆盖范围；P0 列出实测应用矩阵；不承诺裸桌面 / 锁屏；TUI 仍可手动录音。
PreInputMethod 监听不到非活动输入法的按键 如果 Fcitx 只在 Voime 是当前输入法时才送事件，PTT 需要先切换输入法。 P0 在拼音 / 键盘布局 / Voime 三种状态下实测；若必须切换，文档改为“使用前切到 Voime”，并评估是否接受。
其他 addon 先消费 / 后消费按键 PTT 被别的 addon 截获，或 Voime 截获了别的功能键。 PTT 使用不常见的组合键；P0 与拼音、clipboard、quickphrase 等常用 addon 共存测试；文档要求避开 Fcitx 全局热键。
目标输入框失焦 / 销毁 最终文本不出现，用户以为丢字。 固定“段开始时目标”策略；文本保留在 daemon/TUI；TUI 可查看；不向其他窗口误注入；文档说明。
commitString 无确认 应用拒绝或丢弃提交时 Voime 不知道。 文档不承诺“必然上屏”；voime doctor 做基础检查；失败时保留历史；不引入剪贴板降级。
Fcitx commit filter / 全角转换 最终文本与 ASR 输出不完全一致。 在 USER / PROVIDER 说明 Fcitx 提交管线会生效；测试中文、英文、标点、emoji；如需关闭 filter，另行提案。
长文本 / Wayland 4000 字节限制 长段文本被截断或协议错误。 依赖 Fcitx frontend 的分块逻辑；测试长文本；Voime 不自行截断；文档说明由 Fcitx 处理。
CTC int8 英文子词质量不足 英文识别出现缺失或错词；官方 0.wav 已复现。 用真实麦克风数据评估 CER；保留 AED legacy 与 manifest tagged enum；必要时评估 FP32（约 2.9 GB，CPU 成本更高）。
CTC 预处理 / CMVN / 词表不一致 文本整体错乱、空输出或 token 拼接错误。 固定 80 bins / 25 ms / 10 ms / snip_edges=true / high_freq=0 / 32768；CMVN 从 metadata 读取；token id 两列解析与 ▁ 处理加单元测试。
CTC 模型 / 安装包过大 下载与磁盘占用约 740 MiB，首次安装慢。 安装脚本显示进度与校验；不再保留 AED encoder/decoder 默认包；用户可选用本地 --source-dir。
默认分段提高到 30 s 的延迟 PTT 最长 30 s 才出 final，长段端到端延迟变高。 保留 VAD 提前切分；PTT 达到上限自动切段并继续收集；不新增倒计时 UI；用户可用更短 max_segment_ms。

Windows / 非 XIM X11 这些平台没有实现或不可用。 本版明确不支持；README / BUILD 标注范围；未来另立提案。

11.2 P0 必须实测的问题

  • Fcitx 在拼音 / 键盘布局 / Voime 三种当前输入法下，是否都把 PTT 键送到 PreInputMethod watcher。
  • Fcitx 是否在终端、XWayland、无 text-input 的原生窗口中发送按键；哪些应用需要缩小承诺。
  • filterAndAccept() 是否完全阻止 PTT 键进入应用与当前输入法。
  • commitString 在 GTK4 / Qt6 / Firefox / Electron / XWayland XIM / 终端中的实际行为与长度限制。
  • Fcitx 的 commit filter 是否改变中文、英文、标点或 emoji。
  • addon 的 PreInputMethod watcher 与 Fcitx 自身 trigger / toggle-preedit watcher 的先后顺序。
  • Fcitx 重启、addon 重载、配置重载时 HandlerTableEntry 的生命周期与重复注册风险。
  • 目标 InputContext 在窗口关闭、切换 workspace、锁屏时的 hasFocus() 与销毁行为。
  • 多显示 / 多 seat 下 addon 收到的是哪个 InputContext，是否需要多目标表。
