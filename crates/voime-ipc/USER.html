本文是 Voime 线协议的单一事实来源。daemon、TUI、Linux addon 与 Windows 前端都实现本文； 其他文档只链接具体小节，不复制消息定义。

1. TERMS

↑

术语定义
消息（message）一个 JSON 对象，带唯一外部标签；一行一个消息。
frame消息 JSON + 一个换行符 \n；换行是唯一的消息边界。
外部标签消息类型作为 JSON 对象的唯一键，例如 {"Hello": {...}}。
角色（Role）客户端身份：frontend（平台前端）、tui（监视器）或 control（一次性控制）。
模式（Mode）ptt / toggle / continuous；产品级定义见 根 USER §1。
触发来源（TriggerSource）段开始 / 停止的来源：hold、toggle、tui、cli、continuous。
阶段（Phase）daemon 当前状态：idle、recording、finalizing。
前端状态（FrontendState）平台前端是否连接到 daemon：connected / disconnected。
模型目录协议只传递后端选择，不传递模型列表；daemon 从资源包目录加载 default/ 与可选 firered/。前端只收到 Final 文本。
segment_iddaemon 为语音段分配的唯一整数；客户端发送的 ID 只是提示，最终以 SegmentStarted 为准。
Snapshot连接时的全量状态：模式、热键、后端、phase、partial、历史、前端连接状态。
Partial / Final临时结果 / 最终结果；产品级定义见 根 USER §1。
错误码（ErrorCode）稳定的 snake_case 标识；客户端按码处理，不解析文案。
协议版本PROTOCOL_VERSION；当前为 5；消息形状变化时提升。协议 5 增加后端选择与状态消息。

2. CONVENTIONS

↑

约定内容
编码UTF-8 JSON；每个消息一行；不得 pretty-print；不得包含未转义的换行。
framing消息以 \n 终止；缺少换行、超过 MAX_MESSAGE_BYTES 或不是合法 JSON 都是协议错误。
外部标签消息类型是对象的唯一键；字段平铺在标签对象内。
枚举值Mode / Role / TriggerSource / Phase / FrontendState 使用小写；ErrorCode 使用 snake_case。
握手顺序连接后第一条消息必须是 Hello；版本或角色不合法时 daemon 发送 Error 并断开。
角色只允许一个 frontend 连接；configure 只接受 frontend；quit 只接受 control。
配置Hello.config 可选；只有平台前端携带 mode / hotkey。daemon 不解析命令行模式。
后端不在 Hello 内后端由 daemon 设置持有，通过 SetBackend 修改；Hello 只携带 Mode / Hotkey。daemon 用 BackendChanged 与 Snapshot / Status 广播当前后端。
segment_iddaemon 分配；Start / Toggle 的 ID 只是提示；Stop 的非零 ID 在 PTT / Continuous 下需匹配当前段，0 表示当前段（Toggle 例外）。
背压Final / State 不丢弃；Partial 可在队列满时丢弃；慢客户端由 daemon 断开。
版本只有消息形状变化才提升 PROTOCOL_VERSION；新增平台前端不提升版本。
无持久化协议消息不写磁盘；历史只存在于 daemon 内存。

3. DIAGRAMS

↑

3.1 握手与角色

  • 版本不匹配或第二个 frontend 连接会收到 Error，随后连接被关闭。
  • TUI / Control 连接收到 Snapshot；前端连接还会触发 daemon 的前端状态更新。

3.2 语音段消息流

  • Start / Toggle 只是请求；SegmentStarted 携带 daemon 分配的最终 segment_id。
  • Partial 与 Final 都携带 segment_id；前端只处理当前目标的段。
  • Continuous 的段开始由 daemon 自动广播，无需客户端 Start。

3.3 资源包与后端选择

  • 模型目录不是 IPC 消息：daemon 从 default/ 与 firered/ 资源包加载模型。
  • 协议 5 只提供后端选择：SetBackend { cpu | gpu } 与 BackendChanged；没有模型列表或 package_id。
  • 安装、替换或删除资源包后重启 voimed；运行中切换后端只重建 Final 路径，客户端连接保持。
  • GPU 初始化失败时 daemon 内部回退 CPU SenseVoice 并广播 BackendChanged { cpu }，前端看到的仍是同一种 Final 消息。

4.1 常量与编解码

pub const PROTOCOL_VERSION: u32 = 5;
pub const MAX_MESSAGE_BYTES: usize = 1024 * 1024;

pub fn encode_message<T: Serialize>(message: &T) -> anyhow::Result<Vec<u8>>;
pub fn write_message<W: Write, T: Serialize>(writer: &mut W, message: &T) -> anyhow::Result<()>;
pub fn read_message<R: BufRead, T: DeserializeOwned>(reader: &mut R)
    -> anyhow::Result<Option<T>>;
项目契约
PROTOCOL_VERSION当前为 5；旧版本 / 旧前端拒绝连接，返回 version_mismatch。
MAX_MESSAGE_BYTES单行最大 1 MiB；编码与解码都检查。
encode_message序列化为 JSON，检查长度，追加 \n。
write_message编码后写入并 flush。
read_message读取一行；返回 Ok(None) 表示干净 EOF；缺少换行或超长返回错误。

4.5 消息语义

消息方向语义建议动作
Helloclient → daemon声明角色与版本；前端额外携带 Mode / Hotkey。daemon 校验版本与角色；失败发 Error 并断开。
Configure前端 → daemon配置重载时更新 Mode / Hotkey；新模式在下一段生效。daemon 更新快照并广播。
SetBackendFrontend / Control → daemon请求切换 cpu / gpu；仅空闲时执行并持久化。成功广播 BackendChanged + Snapshot；忙碌返回 busy，失败返回 inference。
Start / Stop / Toggleclient → daemon手动或热键触发；带提示 segment_id 与来源。daemon 返回 State / SegmentStarted 或 Error。
ClearHistoryclient → daemon清空已完成历史；保留当前段与 partial。daemon 广播 HistoryCleared。
Statusclient → daemon请求一次性状态。daemon 返回 Status。
QuitControl → daemon停止 daemon。daemon 广播 Bye 后退出。
Snapshotdaemon → client连接时全量状态，含当前后端。客户端初始化视图。
BackendChangeddaemon → clients当前生效后端变化；切换或 GPU 回退时广播。更新设置页与状态显示。
SegmentStarteddaemon → clients段开始；携带最终 segment_id 与来源。前端绑定 / 跟随目标。
Statedaemon → clients录音 / 收尾状态变化。更新录音标记与临时窗口。
Partialdaemon → clients临时文本；可丢弃。显示，不提交。
Finaldaemon → clients最终文本；不丢弃。清空临时文本并提交；加入历史。
HistoryCleareddaemon → clients历史已清空。清空 TUI 历史。
Statusdaemon → client一次性状态快照。打印 / 更新状态。
Errordaemon → client协议、角色、忙碌或推理错误。按 code 处理；不解析文案。
Byedaemon → clientsdaemon 即将退出。客户端清理并退出 / 等待重连。

4.7 错误码

错误码触发条件建议动作
invalid_messageJSON 非法、字段缺失，或角色不允许该命令。修正客户端；daemon 可断开。
version_mismatchHello.version 与 daemon 不一致。升级客户端或 daemon；重新连接。
role_conflict已有 frontend 连接。关闭重复前端；定时重试。
busy已有语音段、正在识别，或 segment_id 不匹配。等待 Idle 后重试；不要强制提交。
unavailable所需模型或后端暂不可用。daemon 保持运行；GPU 不可用时内部继续使用 CPU 后端。
no_input_context没有可用的输入目标。前端不开始语音段；提示用户聚焦输入框。
daemon_unavailable客户端无法连接 daemon。放行热键；定时重连。
inference单段识别 / 标点失败。丢弃该段；继续监听。
internaldaemon 内部错误。查看日志；必要时重启 daemon。

4.8 版本与兼容

变化版本策略
新增消息类型协议 5 内新增消息必须同步升级 daemon 与前端；不依赖旧客户端忽略未知标签。
修改现有消息字段 / 类型必须提升 PROTOCOL_VERSION；daemon 拒绝旧版本并返回 version_mismatch。
新增角色或平台前端不改变现有消息形状时保持版本；新增角色需 daemon 与客户端同时支持。
后端选择SetBackend / BackendChanged 与 Snapshot / Status 的 backend 字段属于协议 5；模型目录与加载顺序仍不属于协议。
worker 协议voime-gpu 协议版本独立管理，不因 worker 变化提升 voime-ipc 的 PROTOCOL_VERSION。
兼容窗口协议 5 是 clean break：协议 4 客户端收到 version_mismatch；不保留旧模型消息或旧角色值。
