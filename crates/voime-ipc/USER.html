本文是 Voime 线协议的单一事实来源。daemon、TUI、Linux addon 与 Windows 前端都实现本文； 其他文档只链接具体小节，不复制消息定义。

1. TERMS

↑

术语定义
消息（message）一个 JSON 对象，带唯一外部标签；一行一个消息。
frame消息 JSON + 一个换行符 \n；换行是唯一的消息边界。
外部标签消息类型作为 JSON 对象的唯一键，例如 {"Hello": {...}}。
角色（Role）客户端身份：frontend（平台前端；线协议同时接受 fcitx 别名）、tui（调试监视器）或 control（一次性控制）。
模式（Mode）ptt / toggle / continuous；产品级定义见 根 USER §1。
会话（session）PTT / Toggle 从开始到硬切分之间的一段交互；一个会话包含一个或多个语音段。
软切分 / 硬切分软切分由 VAD 终点触发，结束当前段并继续下一段；硬切分由 Stop / Toggle 关闭会话，结束当前段后不再续段。
触发来源（TriggerSource）会话 / 段开始与停止的来源：hold、toggle、tui、cli、continuous。
阶段（Phase）daemon 当前状态：idle、recording、finalizing。
前端状态（FrontendState）平台前端是否连接到 daemon：connected / disconnected；Rust 类型别名 AddonState 与它等价。
segment_iddaemon 为语音段分配的唯一整数；客户端发送的 ID 只是提示，最终以 SegmentStarted 为准。
Snapshot连接时的全量状态：模式、热键、phase、partial、历史、前端连接状态。
Partial / Final临时结果 / 最终结果；产品级定义见 根 USER §1。
错误码（ErrorCode）稳定的 snake_case 标识；客户端按码处理，不解析文案。
协议版本PROTOCOL_VERSION；消息形状、错误码或字段语义变化时提升。

2. CONVENTIONS

↑

约定内容
编码UTF-8 JSON；每个消息一行；不得 pretty-print；不得包含未转义的换行。
framing消息以 \n 终止；缺少换行、超过 MAX_MESSAGE_BYTES 或不是合法 JSON 都是协议错误。
外部标签消息类型是对象的唯一键；字段平铺在标签对象内。
枚举值Mode / Role / TriggerSource / Phase / FrontendState 使用小写；ErrorCode 使用 snake_case。
握手顺序连接后第一条消息必须是 Hello；版本或角色不合法时 daemon 发送 Error 并断开。
角色只允许一个 frontend 连接；configure 只接受 frontend；quit 只接受 control。tui 在 frontend 连接期间只观察，Start / Stop / Toggle 返回 busy；无 frontend 连接时可发送调试会话命令。
配置Hello.config 可选；只有平台前端携带 mode / hotkey。daemon 不解析命令行模式。
segment_iddaemon 分配；Start / Toggle 的 ID 只是提示；Stop 在 PTT / Toggle 下忽略 ID，在 Continuous 下非零 ID 需匹配当前段（0 表示当前段）。
会话命令Start 打开 PTT / Toggle 会话；Stop 硬切分会话；Toggle 按当前状态打开或硬切分。会话内 VAD 软切分多个段，不需要重复 Start。
背压Final / State 不丢弃；Partial 可丢弃；客户端落后不阻塞 daemon。
版本消息形状、错误码或字段语义变化时提升 PROTOCOL_VERSION；新增平台前端不提升版本。
无持久化协议消息不写磁盘；历史只存在于 daemon 内存。

3. DIAGRAMS

↑

3.1 握手与角色

  • 版本不匹配或第二个 frontend 连接会收到 Error，随后连接被关闭。
  • TUI / Control 连接收到 Snapshot；前端连接还会触发 daemon 的前端状态更新。

3.2 语音段消息流

  • Start / Toggle 只是请求；SegmentStarted 携带 daemon 分配的最终 segment_id。
  • PTT / Toggle 会话内每次 VAD 软切分都会再次广播 SegmentStarted；Stop 才硬切分会话。
  • Partial 与 Final 都携带 segment_id；前端只处理当前目标的段。
  • Continuous 的段开始由 daemon 自动广播，无需客户端 Start。

4.1 常量与编解码

pub const PROTOCOL_VERSION: u32 = 2;
pub const MAX_MESSAGE_BYTES: usize = 1024 * 1024;

pub fn encode_message<T: Serialize>(message: &T) -> anyhow::Result<Vec<u8>>;
pub fn write_message<W: Write, T: Serialize>(writer: &mut W, message: &T) -> anyhow::Result<()>;
pub fn read_message<R: BufRead, T: DeserializeOwned>(reader: &mut R)
    -> anyhow::Result<Option<T>>;
项目契约
PROTOCOL_VERSION当前为 2；消息形状、错误码或字段语义变化时提升。
MAX_MESSAGE_BYTES单行最大 1 MiB；编码与解码都检查。
encode_message序列化为 JSON，检查长度，追加 \n。
write_message编码后写入并 flush。
read_message读取一行；返回 Ok(None) 表示干净 EOF；缺少换行、超长或字段类型不合法返回错误。daemon 对未知 ClientMessage 返回 invalid_message；客户端应忽略未知 ServerMessage。

4.5 消息语义

消息方向语义建议动作
Helloclient → daemon声明角色与版本；前端额外携带 Mode / Hotkey。daemon 校验版本与角色；失败发 Error 并断开。
Configure前端 → daemon配置重载时更新 Mode / Hotkey；Mode 变化时，Idle 且无活动会话立即生效，否则立即结束当前段并在 Final / 丢弃后生效。daemon 更新快照并广播。
Startclient → daemonPTT / Toggle 下打开会话；Continuous 下开始手动段。带提示 segment_id 与来源。daemon 返回 State / SegmentStarted 或 Error。
Stopclient → daemon硬切分：PTT / Toggle 关闭会话并结束当前段；Continuous 停止当前段。带提示 segment_id 与来源。daemon 返回 State / Final 或 Error。
Toggleclient → daemonMode=ptt / toggle 时按当前状态打开或硬切分会话；Finalizing 时也可关闭。daemon 返回 State / SegmentStarted / Final 或 Error。
ClearHistoryclient → daemon清空已完成历史；保留当前段与 partial。daemon 广播 HistoryCleared。
Statusclient → daemon请求一次性状态。daemon 返回 Status。
DiagnosticsControl → daemon只读查询所选 Final 后端与 worker 状态；不启动、不重启 worker，不改变配置。daemon 返回 Diagnostics；非 Control 角色返回 invalid_message。
QuitControl → daemon停止 daemon。daemon 广播 Bye 后退出。
Snapshotdaemon → client连接时全量状态。客户端初始化视图。
SegmentStarteddaemon → clients段开始（含 PTT / Toggle 软切分续段）；携带最终 segment_id 与来源。前端绑定 / 沿用目标。
Statedaemon → clients录音 / 收尾状态变化。更新录音标记与临时窗口。
Partialdaemon → clients临时文本；可丢弃。显示，不提交。
Finaldaemon → clients最终文本；不丢弃。清空临时文本并提交；加入历史。
HistoryCleareddaemon → clients历史已清空。清空 TUI 历史。
Statusdaemon → client一次性状态快照。打印 / 更新状态。
Diagnosticsdaemon → Control所选 Final 后端与 worker 的只读快照；worker 状态只来自 daemon 内存，不读日志。voime doctor 打印；前端不得依赖该消息。
Errordaemon → client协议、角色、忙碌、整段丢弃或其它推理错误；segment_dropped 时 segment_id 指向被丢弃的段。按 code 处理；segment_dropped 时由前端决定是否清理 / 提示，后端不规定 UI 行为。
Byedaemon → clientsdaemon 即将退出。客户端清理并退出 / 等待重连。
  • tui 角色在 frontend 连接期间发送 Start / Stop / Toggle 会收到 busy；这些命令只用于无前端连接时的调试会话。

4.7 错误码

错误码触发条件建议动作
invalid_messageJSON 非法、字段缺失、角色不允许该命令。修正客户端；daemon 可断开。
version_mismatchHello.version 与 daemon 不一致。升级客户端或 daemon；重新连接。
role_conflict已有 frontend 连接。关闭重复前端；定时重试。
busy已有活动会话、正在识别，或 Continuous 的 segment_id 不匹配。等待会话结束 / Idle 后重试；不要强制提交。
no_input_context没有可用的输入目标。前端不开始语音段；提示用户聚焦输入框。
daemon_unavailable客户端无法连接 daemon。放行热键；定时重连。
unavailable服务暂时不可用。重试或查看日志。
segment_dropped单段因空音频、空识别结果或识别失败被丢弃；segment_id 必须为 Some(id)。前端自行决定是否清理临时文本 / 提示；后端不规定 UI 行为。
inference不属于单段丢弃的推理 / 标点错误。查看日志；按需要停止当前路径。
internaldaemon 内部错误。查看日志；必要时重启 daemon。

4.8 版本与兼容

变化版本策略
当前版本PROTOCOL_VERSION = 2；包含 Error.segment_id、segment_dropped 错误码与只读 Diagnostics。
新增消息类型纯增量消息不提升版本：客户端忽略未知的 ServerMessage 标签；旧 daemon 对未知 ClientMessage 返回 invalid_message 并断开。只有修改现有消息或错误码语义时才提升版本。
修改现有消息字段 / 类型 / 错误码必须提升 PROTOCOL_VERSION；daemon 拒绝版本不匹配的连接并返回 version_mismatch。
新增角色或平台前端不改变现有消息形状时保持版本；新增角色需 daemon 与客户端同时支持。
角色别名线协议同时接受 frontend 与 fcitx；Rust 类型名 FrontendState 与 AddonState 等价。
