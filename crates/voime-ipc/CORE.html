2. CONVENTIONS

↑

约定内容
无 OS 依赖只依赖 serde / serde_json / anyhow；不引用 socket、pipe、文件系统、线程或时钟。
单一来源消息类型、枚举、常量只在此 crate 定义；其他语言客户端按 USER 实现，不复制 Rust 代码。
序列化策略默认外部标签；枚举使用 rename_all；不使用 deny_unknown_fields，便于旧客户端忽略新增字段。
错误上下文编码 / 解码错误统一用 anyhow::Context 描述“序列化 / 写入 / 读取 / 解析”阶段。
长度检查encode_message 在追加换行前检查；read_message 读取整行后检查。
  • 仓库级依赖方向见 根 CORE §2；协议行为见 USER §2。

5. Call stack tree

↑

5.1 编码与写入

client::send(message)
└── voime_ipc::write_message(writer, message)
    ├── voime_ipc::encode_message(message)
    │   ├── serde_json::to_vec(message)
    │   ├── 判断 bytes.len() > MAX_MESSAGE_BYTES → anyhow::bail!
    │   └── bytes.push(b'\n')
    ├── writer.write_all(&bytes)
    └── writer.flush()

5.2 读取与解码

client::reader thread
└── voime_ipc::read_message(reader)
    ├── BufRead::read_until(b'\n', &mut line)
    ├── 判断 read == 0 → Ok(None)
    ├── 判断 line.len() > MAX_MESSAGE_BYTES → anyhow::bail!
    ├── 判断 line.last() != Some(&b'\n') → anyhow::bail!
    ├── line.pop()
    └── serde_json::from_slice::<T>(&line)
  • daemon 的 reader 线程不使用本函数，而是在 ipc_server 内复制同样的 framing 检查，以便生成 BadMessage 事件；协议规则仍由本文拥有。
  • 未知 JSON 字段由 serde 默认忽略；未知消息标签在客户端应映射为“忽略”。
