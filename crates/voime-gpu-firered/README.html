1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

CPU 核心的 SenseVoice 能独立完成预览与最终识别，但中文、方言与中英混合场景需要更强的 Final 模型，而 GPU 运行时又不能在核心进程里加载。FireRed 后端把这两个需求分开： 用独立的 GPU worker 承载 FireRedASR2-AED 与 FireRedPunc，只对完整语音段做一次最终识别， 把已加标点的文本交回 daemon。 核心的音频、VAD、Preview、分段与前端完全不受影响。

worker 使用 ONNX Runtime GPU Execution Provider 加载上游现成的 FP32 ONNX： FireRedASR2-AED 负责识别，FireRedPunc 负责中英文标点。模型、runtime 与进程都属于本组件； daemon 只负责选择、发送 PCM、接收文本与在失败时回退 CPU SenseVoice。

1.2 GOAL：什么算成功

  • 接收一个完整语音段的 16 kHz、单声道、f32 PCM（单段上限 30 s），返回已加标点文本与耗时；一次只处理一个 Final。
  • FireRedASR2-AED 以 FP32 ONNX 运行，使用 Kaldi fbank 80-bin、25 / 10 ms、snip_edges、16-bit 缩放与 CMVN；解码为 AED greedy，从 <sos> 开始、到 <eos> 停止；CTC head 不作为产品路径。
  • FireRedPunc 以 FP32 ONNX 在 worker 内做二次推理，把标点插入 AED 文本后返回；不返回半成品。
  • 两个模型合计约 5.1 GB（AED 约 4.7 GB + Punc 约 0.4 GB），均为 FP32；不加载 int8 / FP16 变体。
  • ORT GPU EP 按平台固定：Linux / Windows NVIDIA 用 CUDA，Windows 用 CUDA 或 DirectML；Linux AMD 的 MIGraphX 当前无法编译固定动态 shape 图，应改用 Qwen3。运行期不切换 EP / runtime。
  • 模型目录固定为 fireredasr2-aed/ 与 fireredpunc/，各自带 schema 5 的 manifest.json、SHA-256 与 runtime 声明；运行期只读。
  • 本组件是独立 crate、独立二进制、独立进程与独立 runtime 目录；不与 Qwen 后端共享 runtime，也不链接 llama.cpp / GGML。
  • 加载失败、设备不可用、崩溃或推理失败时，worker 报告错误码；超时由 daemon 计时并终止 worker。当前段是否回退 CPU SenseVoice 由 daemon 决定，worker 自己不做 CPU 推理。
  • 只处理 Final；不加载 VAD、不产生 Preview / Partial、不接触前端 IPC、热键、目标或会话历史。

1.3 非目标

  • 不加载 VAD、Preview、分段器或平台前端；不接收活动段增量音频，不做流式识别。
  • 不与 Qwen 后端共享 runtime、crate、二进制或动态库目录；不引入 llama.cpp / GGML / GGUF。
  • 不做 CPU FireRedASR2-AED 推理；GPU 失败不加载任何 CPU 大模型，也不把 CPU ORT 作为 worker 内部回退。
  • 不做运行期 EP / runtime 切换、模型重载或 EP 回退；一个 worker 进程只使用编译时选定的一个 EP。
  • 不做 int8 / FP16 量化回退；加载或推理失败即失败，不静默换精度。
  • 不做模型下载、导出、转换、量化或联网校验；这些只发生在安装脚本与发布流程。
  • 不做文本润色、纠错、翻译、摘要、大小写改写或规则后处理；只做 ASR 与 FireRedPunc 标点。
  • 不做模型目录自动发现、动态插件或通用 backend ABI；两个模型目录是固定契约。
  • 不记录识别文本、音频或历史到磁盘；日志只记录长度、耗时、错误码与后端名称。
  • 产品级术语见 根 USER §1；本组件的对外输入输出与错误语义见 USER。
  • 模型与 ORT GPU 的张量、tokenizer 与 SHA 契约见 PROVIDER；内部模块与调用栈见 CORE。
  • 帧格式、请求 / 响应字段与错误码由 voime-gpu-common USER 定义；本组件只实现边界行为。

2. 用户交互

↑

本组件没有终端用户界面，也不直接面向用户。用户通过 GPU 安装脚本安装；安装后由 voimed 在 final.backend = firered 时启动 worker。用户只能观察到 “最终文本带标点”或“GPU 失败后回退 CPU”的结果，不需要直接操作 worker。

角色交互结果
用户 运行 scripts/install-gpu.sh --firered（Linux）或 scripts/install-gpu.ps1 --firered（Windows）；可用 --firered-runtime 选择 EP。 安装 FireRed worker、ORT GPU runtime 与两个模型目录；不自动切换 final.backend。
用户 用 --backend firered 或 voime ctl backend firered 写配置，重启 daemon。 下一次 daemon 启动时拉起本 worker；运行中不热切换。
用户 使用语音输入，Final 由 FireRed 后端完成。 最终文本带标点；GPU 失败时当前段回退 CPU SenseVoice，Preview 不中断。
用户 运行 scripts/install-gpu.sh --firered --uninstall。 只删除 FireRed worker、本后端 runtime 与两个 FireRed 模型；不触碰核心与 Qwen。
  • 安装 / 卸载选项与回退语义见 USER §4.4 与 USER §4.3。
  • 本组件不提供 TUI、托盘、配置界面或临时文本窗口；这些属于平台前端。
  • GPU 模块安装失败或后端不可用不影响核心的 VAD、Preview 与 CPU Final。
