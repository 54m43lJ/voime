2. CONVENTIONS

↑

约定内容
无 runtime 依赖只依赖 serde、serde_json 与 anyhow；不引用 ORT、llama.cpp、GGML、tokenizers 或任何模型库。
无 OS 进程 / 传输不调用 std::process，不打开 socket / pipe，不访问文件系统；调用方提供实现了 Read / Write 的流。
同步 IO使用阻塞的 std::io 与 std::time::Duration；不引入 tokio / async-std，也不自带线程。
单一来源Request、Response、ErrorCode 与帧布局只在此 crate 定义；两个 worker 与 daemon 通过依赖使用，不复制消息结构。
序列化策略serde 外部标签；结构体字段使用 snake_case；枚举线值使用 snake_case；不使用 deny_unknown_fields，便于忽略新增字段。
长度检查先读长度，检查上限与 4 字节对齐，再分配；不得按未校验的 u32 直接分配缓冲区。
错误分层IO、长度、UTF-8 与 JSON 错误用 anyhow::Result 返回；协议层失败用 Response::Error 与 ErrorCode 表达。
不记录文本库不写日志；调用方不得对 Result.text 或 Frame.audio 使用默认 Debug 输出，只记录长度、耗时、错误码与后端名称；加载失败可附加模型路径与 SHA 前缀。
stdout 由调用方选择write_frame 写入调用方给出的 writer；worker 二进制负责把协议帧写到 stdout，把日志写到 stderr。
超时由调用方执行库只提供 HANDSHAKE_TIMEOUT / TRANSCRIBE_TIMEOUT / SHUTDOWN_TIMEOUT 常量；阻塞读的计时与杀进程属于 daemon。
平台无关Linux 与 Windows 使用同一帧格式；路径只按 UTF-8 字符串透传，不做平台路径解析。
无持久化不写音频、文本或协议日志到磁盘。
  • 协议行为与字段语义见 USER §2；帧布局见 USER §4.1。
  • 仓库级依赖方向见 根 CORE §2。

pub struct Frame { /* 见 USER §4.1 */ }

impl Frame {
    pub fn from_request(request: &Request, audio: &[f32]) -> anyhow::Result<Self>;
    pub fn from_response(response: &Response) -> anyhow::Result<Self>;
    pub fn request(&self) -> anyhow::Result<Request>;     // 见 USER §4.1
    pub fn response(&self) -> anyhow::Result<Response>;   // 见 USER §4.1
}

pub fn read_frame<R: Read>(reader: &mut R) -> anyhow::Result<Option<Frame>>;  // 见 USER §4.1
pub fn write_frame<W: Write>(writer: &mut W, frame: &Frame) -> anyhow::Result<()>;  // 见 USER §4.1
  • from_request 序列化 Request；只有 Transcribe 附带 PCM，其他请求要求音频为空。 from_response 序列化 Response，音频为空。
  • request / response 解析 header，并按 USER §4.1 校验音频长度约束；不检查 PCM 数值范围或时长。

4.4 lifecycle.rs 文件树

pub struct ReadyInfo {
    pub backend: GpuBackend,
    pub runtime: String,
    pub device: String,
    pub vram_mb: u32,
    pub punc: bool,
}

pub fn handshake<R: Read, W: Write>(
    reader: &mut R,
    writer: &mut W,
    hello: &Request,
) -> anyhow::Result<ReadyInfo>;

pub fn expect_result(response: Response, id: u64) -> anyhow::Result<Response>;

pub fn error_response(id: u64, code: ErrorCode, message: impl Into<String>) -> Response;
  • handshake 要求 hello 是 Request::Hello；写入后读取第一个响应，只接受 Ready，校验 protocol 与 backend 后返回 ReadyInfo。不内置超时。
  • expect_result 校验响应 id 与终态类型，返回原 Response 供 daemon 映射错误码。
  • error_response 构造单行 Error；不携带识别文本，消息长度由实现截断到上限。

5. Call stack tree

↑

5.1 握手

voimed::worker::Worker::spawn(model_dir, device)
├── std::process::Command::spawn()
└── voime_gpu_common::handshake(stdin, stdout, &Request::Hello { ... })
    ├── voime_gpu_common::write_frame(writer, &Frame::from_request(hello, &[]))
    ├── voime_gpu_common::read_frame(reader)
    ├── 判断 Response::Ready { protocol, backend, .. } → 校验 protocol 与 backend
    ├── 判断 Response::Error { code, .. } → anyhow::bail!(code)
    └── ReadyInfo { backend, runtime, device, vram_mb, punc }
  • handshake 是阻塞读；daemon 在独立 reader 线程或带超时的等待中执行 HANDSHAKE_TIMEOUT，到期后 kill worker。
  • 加载失败时 worker 发送 Error { id: 0, code: load_failed | runtime_missing | device_unavailable } 后退出；daemon 标记后端不可用。
  • 握手成功只表示 Ready；模型常驻与后续 Transcribe 由 daemon 的 worker 循环驱动。

5.2 读帧与解析

worker::run()
├── voime_gpu_common::read_frame(stdin)
│   ├── let n = std::io::Read::read(&mut header_len_bytes)
│   ├── 判断 n == 0 → Ok(None)
│   ├── std::io::Read::read_exact(&mut header_len_bytes[n..])
│   ├── u32::from_le_bytes(header_len_bytes)
│   ├── 判断 header_len == 0 || header_len > MAX_HEADER_BYTES → anyhow::bail!
│   ├── std::io::Read::read_exact(&mut header)
│   ├── std::str::from_utf8(&header)
│   ├── std::io::Read::read_exact(&mut audio_len_bytes)
│   ├── u32::from_le_bytes(audio_len_bytes)
│   ├── 判断 audio_len % 4 != 0 || audio_len > MAX_AUDIO_BYTES → anyhow::bail!
│   ├── std::io::Read::read_exact(&mut audio)
│   └── audio.chunks_exact(4).map(|b| f32::from_le_bytes([b[0], b[1], b[2], b[3]])).collect::<Vec<f32>>()
└── voime_gpu_common::Frame::request(&frame)
    ├── serde_json::from_str::<Request>(&frame.header)
    ├── 判断 非 Transcribe → 校验 frame.audio.is_empty()
    └── 判断 Transcribe → 校验 !frame.audio.is_empty()
  • 帧起点读到干净 EOF 时 read_frame 返回 Ok(None)；帧中间 EOF 是截断帧，返回错误。
  • 两个长度都在分配前检查；audio_len 不是 4 的倍数时不进入解码。
  • header 解析失败、未知标签或字段类型不符都关闭连接；不要尝试跳过该帧继续读取。

5.3 写响应

worker::reply(stdout, response)
├── voime_gpu_common::Frame::from_response(&response)
│   └── serde_json::to_string(&response)
└── voime_gpu_common::write_frame(stdout, &frame)
    ├── 判断 frame.header.is_empty() || frame.header.len() > MAX_HEADER_BYTES → anyhow::bail!
    ├── 判断 frame.audio.len() * 4 > MAX_AUDIO_BYTES → anyhow::bail!
    ├── std::io::Write::write_all(&(frame.header.len() as u32).to_le_bytes())
    ├── std::io::Write::write_all(frame.header.as_bytes())
    ├── 判断 frame.audio.is_empty() → std::io::Write::write_all(&0u32.to_le_bytes())
    ├── 判断 frame.audio 非空 → std::io::Write::write_all(&((frame.audio.len() * 4) as u32).to_le_bytes())
    ├── 判断 frame.audio 非空 → frame.audio.iter().try_for_each(|s| writer.write_all(&s.to_le_bytes()))
    └── std::io::Write::flush()
  • Response 的 audio_len 恒为 0；Request 的 Transcribe 才写入 PCM。
  • 每帧写完立即 flush，避免 daemon 等待长度前缀时死锁。
  • 写入失败（broken pipe）直接返回错误；worker 退出，daemon 按崩溃路径处理。

5.4 取消

voimed::worker::Worker::cancel(id)
├── voime_gpu_common::write_frame(stdin, &Frame::from_request(&Request::Cancel { id }, &[]))
├── 判断 该 id 在途 → 标记 cancelled
└── voime_gpu_common::read_frame(stdout)
    └── 判断 终态响应 id == cancelled → 丢弃，不触发 CPU 回退
worker::run()
├── 判断 Request::Cancel { id } == current.id → inference.abort()
└── voime_gpu_common::error_response(id, ErrorCode::InferenceFailed, "cancelled")
    └── voime_gpu_common::write_frame(stdout, &Frame::from_response(&response))
  • Cancel 不产生新的响应类型；worker 用 Error { code: inference_failed, message: "cancelled" } 结束被取消的 id。
  • 没有匹配 id 时 worker 忽略 Cancel，不回写任何帧。
  • 取消是协作式的；识别预算到期后 daemon 仍会强杀 worker。

5.5 关闭

voimed::worker::Worker::shutdown(self)
├── voime_gpu_common::write_frame(stdin, &Frame::from_request(&Request::Shutdown, &[]))
├── 判断 等待 Bye 超过 SHUTDOWN_TIMEOUT → child.kill()
├── 循环 voime_gpu_common::read_frame(stdout)  // 丢弃在途终态，直到 Bye
├── 判断 Response::Bye → child.wait()
└── 判断 退出码非零 → 记录错误并回收
worker::run()
├── 判断 Request::Shutdown → runtime.release()
├── voime_gpu_common::write_frame(stdout, &Frame::from_response(&Response::Bye))
└── std::process::exit(0)
  • Shutdown 可以中断在途 Transcribe；worker 不再发送该 id 的 Result / Error，直接释放资源并回 Bye。
  • 关闭预算 5 s；超时由 daemon 强杀，确保无孤儿进程。
  • daemon 未发送 Shutdown 就关闭管道时，worker 以非零退出；该路径不属于正常关闭。
