USER — voime-gpu-common

根：README USER CORE PROVIDER ｜ 本组件：README CORE

本文是两个 GPU worker 帧协议的单一事实来源。voimed、voime-gpu-firered 与 voime-gpu-qwen3 都实现本文；其他文档只链接具体小节，不复制帧格式、消息字段或错误码。 前端 IPC 不在本文范围内，见 voime-ipc USER。

1. TERMS

↑

术语定义
帧（frame）一次请求或响应在线路上的完整单元：u32 header 长度 + UTF-8 JSON header + u32 音频长度 + PCM。
header帧内的 UTF-8 JSON 值，承载一个 Request 或 Response。
音频载荷（audio）帧内的 f32le PCM；只有 Transcribe 使用，其他消息为空。
请求（Request）daemon → worker 的 header 类型。
响应（Response）worker → daemon 的 header 类型。
daemonvoimed；启动 worker、发送请求、执行超时与 CPU 回退。
workervoime-gpu-firered 或 voime-gpu-qwen3 的独立进程；加载自己的 runtime 与模型，只执行 Final。
GPU 后端（GpuBackend）firered 或 qwen3；与 worker 二进制一一对应。
Final一次完整语音段的最终识别；本协议不传增量音频，也不产生 Partial。
Transcribe携带完整 PCM 的请求；一个 id 对应一次 Final。
iddaemon 分配的 u64 请求标识；从 1 递增；0 保留给不属于某次 Transcribe 的错误。
Readyworker 完成加载后的响应；表示可以接受 Transcribe。
Byeworker 对 Shutdown 的确认；发送后退出。
错误码（ErrorCode）稳定的 snake_case 标识；daemon 按码处理，不解析 message。
协议版本GPU_PROTOCOL_VERSION；独立于 voime-ipc 的协议版本。
RTFreal-time factor；latency_ms / 1000 / 音频秒数；音频为空时为 0。
puncworker 是否加载了独立标点模型；Qwen3 由模型自带标点，故为 false。
model_dirdaemon 传入的模型目录绝对路径；目录布局由对应 worker 定义，本协议只透传。
deviceGPU 设备标识，例如 cuda:0、vulkan:0、migraphx:0、dml:0；worker 可以拒绝。
runtimeworker 自报的实现标识，例如 cuda、vulkan、migraphx、directml；daemon 只记录与展示。
加载预算从 daemon 发出 Hello 到收到 Ready / Error 的默认 120 s。
识别预算从 daemon 写完 Transcribe 到收到 Result / Error 的默认 60 s。
关闭预算从 daemon 写完 Shutdown 到收到 Bye 或 worker 退出的默认 5 s。
干净 EOF在帧边界读到 0 字节；帧中间读到 EOF 是截断帧，属于协议错误。
协议错误长度、UTF-8、JSON、消息顺序或版本不合法；连接不可继续。
取消（Cancel）daemon 放弃某个 id 的提示；worker 尽力中止，并以既有终态响应结束该请求。

2. CONVENTIONS

↑

约定内容
字节序所有 u32 长度与 f32 PCM 都是 little-endian；不使用主机字节序。
header 编码UTF-8 JSON，紧凑输出，不带 BOM、结尾 NUL 或额外换行；字段顺序不参与比较。
外部标签有字段的消息编码为 {"Name":{...}}；无字段消息编码为 JSON 字符串 "Name"；枚举值使用 snake_case。
长度单位header_len 与 audio_len 都是字节数；audio_len 必须是 4 的倍数。
长度上限header_len 不超过 MAX_HEADER_BYTES；audio_len 不超过 MAX_AUDIO_BYTES；超限即协议错误。
帧边界帧按顺序紧邻，无对齐填充；只有帧起点允许干净 EOF。
消息顺序Hello 必须是第一条请求；Ready / Error 之后才允许 Transcribe；Shutdown 是最后一条请求；Bye 是最后一条响应。
方向Request 只从 daemon 发往 worker；Response 只从 worker 发往 daemon；反向消息是协议错误。
并发同一 worker 一次只处理一个 Transcribe；daemon 在收到当前 id 的 Result / Error 前不得发送下一个 Transcribe。
音频格式单声道、16 kHz、f32le、范围 [-1, 1]；不做重采样、不做归一化。
音频载荷PCM 直接作为二进制写入帧；不做 base64、WAV 封装或文本转义。
采样率字段Transcribe.sample_rate 必须为 16000；其他值按 inference_failed 返回。
stdout / stderrworker 的 stdout 只写协议帧；所有日志、警告与 backtrace 写 stderr。daemon 不把 stderr 当协议解析。
文本保护不得记录 text 或 PCM；错误 message 也不得包含识别文本。日志只记录长度、耗时、错误码与后端名称；加载失败可附加模型路径与 SHA 前缀。
超时加载 120 s、识别 60 s、关闭 5 s；由 daemon 计时并执行；worker 自报的 timeout 不能替代 daemon 的硬超时。
取消Cancel 不引入新的响应类型；worker 用 Result 或 Error 结束被取消的 id；没有在途请求时忽略。
版本Hello 与 Ready 都携带 protocol；worker 发现不一致时返回 protocol_mismatch，daemon 发现不一致时终止 worker。
未知字段反序列化忽略未知字段；未知消息标签、未知错误码或字段类型不符按协议错误处理。
无持久化协议消息不写磁盘；音频与文本不落盘。
无前端语义协议不携带 segment_id、热键、目标、Partial 或提交状态。
错误文案message 是单行诊断文本，建议不超过 1 KiB；daemon 只用它写日志 / doctor，不作为分支依据。
数值范围vram_mb 为 u32；latency_ms 为 u64；rtf 为有限非负 f32。
  • 前端 IPC 的编码、framing 与版本规则见 voime-ipc USER §2；本协议不复用其换行 framing。
  • 协议不提升 voime-ipc 的 PROTOCOL_VERSION；两者独立演进。

3. DIAGRAMS

↑

3.1 worker 生命周期与消息顺序

  • spawn 不是协议帧；进程创建、管道与环境由 voimed 负责。
  • Hello → Ready 的加载预算为 120 s；Transcribe → Result / Error 的识别预算为 60 s；Shutdown → Bye 的关闭预算为 5 s。
  • Result 与 Error 是 Transcribe 的二选一终态；Cancel 不显示为独立响应。
  • worker 的模型加载与推理内部不展开；图中只保留跨越 daemon / worker 边界的消息。

4. INTERFACES

↑

4.1 帧格式

Frame
├── header_len   u32 LE     // header 字节数，1 .. MAX_HEADER_BYTES
├── header       UTF-8 JSON // Request 或 Response
├── audio_len    u32 LE     // audio 字节数，必须为 4 的倍数
└── audio        f32le mono 16 kHz PCM [-1, 1]
pub const GPU_PROTOCOL_VERSION: u32 = 1;
pub const MAX_HEADER_BYTES: usize = 64 * 1024;
pub const MAX_AUDIO_BYTES: usize = 64 * 1024 * 1024;

pub struct Frame {
    pub header: String,     // UTF-8 JSON
    pub audio: Vec<f32>,    // 采样，不是字节
}

impl Frame {
    pub fn request(&self) -> anyhow::Result<Request>;
    pub fn response(&self) -> anyhow::Result<Response>;
}

pub fn read_frame<R: Read>(reader: &mut R) -> anyhow::Result<Option<Frame>>;
pub fn write_frame<W: Write>(writer: &mut W, frame: &Frame) -> anyhow::Result<()>;
项目契约
GPU_PROTOCOL_VERSION当前为 1；消息形状、字段含义或错误码变化时提升。
MAX_HEADER_BYTES单帧 header 上限 64 KiB；读写两侧都检查。
MAX_AUDIO_BYTES单帧音频上限 64 MiB；读写两侧都检查。
header_len4 字节 little-endian；0 或超过上限都是协议错误。
headerUTF-8 JSON；必须是 Request 或 Response 中的一个外部标签。
audio_len4 字节 little-endian；0 或 4 的倍数；不是 4 的倍数即协议错误。
audioaudio_len / 4 个 f32le 采样；只有 Transcribe 非空，所有 Response 为空。
read_frame在帧起点读到干净 EOF 返回 Ok(None)；帧中间 EOF、超限或非法 UTF-8 返回错误；JSON 解析由 Frame::request / response 完成。
write_frame检查 header 与 audio 长度，依次写长度、header、audio_len、audio，最后 flush；header 已由调用方序列化。
Frame::request解析 header 为 Request；非 Transcribe 的帧必须没有音频。
Frame::response解析 header 为 Response；任何 Response 都不得携带音频。
  • Frame.audio 以采样数计；线上 audio_len 是字节数，等于 audio.len() * 4。
  • 写入前用 Frame::from_request / from_response 生成 header 与音频；签名见 CORE §4.2。
  • 帧头不携带总长度；读取方按两个长度字段顺序读取，不能跳过或重排。
  • header 不使用换行分隔；JSON 内部的换行只可能出现在字符串转义中。

4.2 Request

pub enum Request {
    Hello {
        protocol: u32,
        backend: GpuBackend,
        model_dir: String,
        device: String,
    },
    Transcribe {
        id: u64,
        sample_rate: u32,
        language: String,
    },
    Cancel {
        id: u64,
    },
    Shutdown,
}
消息字段类型语义
Helloprotocolu32daemon 的 GPU_PROTOCOL_VERSION；worker 必须相等，否则返回 protocol_mismatch。
backendGpuBackend必须是当前 worker 的后端；不匹配按 protocol_mismatch 拒绝。
model_dirString模型目录绝对路径；目录布局由 worker 定义；缺失或校验失败返回 load_failed。
deviceString请求的 GPU 设备；worker 不支持时返回 device_unavailable。
Transcribeidu64daemon 分配；从 1 递增；同一连接内不复用未完成的 id。
sample_rateu32必须为 16000；其他值返回 inference_failed。
languageString语言提示，如 zh、en 或 auto；worker 可以忽略。
Cancelidu64放弃该 id 的在途请求；没有匹配请求时忽略。
Shutdown——请求释放资源并退出；可以中断在途 Transcribe。
消息何时发送响应
Hello进程启动后的第一条，且只发送一次。Ready 或 Error；加载错误后 worker 退出。
Transcribe收到 Ready 后；一次只发一个，且等待当前 id 的终态。Result 或 Error；id 必须匹配。
Cancel需要放弃当前 id 时；不要求先停止等待。不引入新响应；被取消的 id 仍以 Result 或 Error 结束。
Shutdowndaemon 退出或切换后端前；不要求先取消在途请求。Bye；worker 随后退出。
  • Hello / Cancel / Shutdown 的 audio_len 必须为 0；Transcribe 的 audio_len 必须大于 0。
  • model_dir 只使用 UTF-8 路径；worker 不从全局配置或环境变量猜模型路径。
  • 重复 Hello、Ready 前发送 Transcribe、在途时发送第二个 Transcribe 都是协议错误；接收方可以返回 protocol_mismatch 后关闭连接。

4.3 Response

pub enum Response {
    Ready {
        protocol: u32,
        backend: GpuBackend,
        runtime: String,
        device: String,
        vram_mb: u32,
        punc: bool,
    },
    Result {
        id: u64,
        text: String,
        latency_ms: u64,
        rtf: f32,
    },
    Error {
        id: u64,
        code: ErrorCode,
        message: String,
    },
    Bye,
}
消息字段类型语义
Readyprotocolu32worker 的 GPU_PROTOCOL_VERSION；daemon 必须与自己的版本相等。
backendGpuBackendworker 身份；必须与 Hello 的 backend 一致。
runtimeString实际使用的 runtime 标识；例如 cuda、vulkan、migraphx、directml。
deviceString实际选中的设备；可以与 Hello 的请求不同，但必须是该 runtime 可用的设备。
vram_mbu32Ready 时 worker 估算的显存占用，单位 MB；未知时为 0。
puncbool是否加载了独立标点模型；Qwen3 由模型自带标点，故为 false。
Resultidu64对应 Transcribe 的 id；必须匹配。
textString最终文本；允许空串；不含结尾换行或 NUL；空串表示该段没有可提交文本。
latency_msu64worker 从接受请求到产出结果的耗时，单位毫秒。
rtff32实时率，等于 latency_ms / 1000 / 音频秒数；空音频为 0；有限且非负。
Erroridu64识别错误时为对应 Transcribe 的 id；握手 / 加载错误为 0。
codeErrorCode稳定错误码，见 §4.5；daemon 只按此字段分支。
messageString单行诊断信息；不得包含识别文本或 PCM；建议不超过 1 KiB。
Bye——Shutdown 的确认；worker 发送后释放资源并退出。
消息何时发送语义
ReadyHello 校验通过且 runtime / 模型加载完成后。握手成功；表示 worker 可以接受 Transcribe。
ResultTranscribe 成功完成。最终文本与耗时；daemon 可以提交或记录长度。
Error握手、加载、识别或协议失败。按 code 决定回退、重启或拒绝 worker；不解析文案。
Bye收到 Shutdown 并完成资源释放后。正常关闭；worker 随后以 0 退出。
  • 所有 Response 的 audio_len 必须为 0；Response 不携带 PCM。
  • worker 不发送 Partial、Snapshot 或状态广播；这些属于 daemon 与前端 IPC。
  • Result.text 已经是最终文本；daemon 不再做标点、大小写或语言后处理。

4.5 错误码与 daemon 动作

错误码触发条件daemon 动作
runtime_missingGPU runtime / backend 未安装或版本不匹配。标记该后端不可用；已启动则停止 worker；Final 回退 CPU；提示重装 GPU 模块。
device_unavailable无 GPU、驱动不匹配、显存不足或请求的设备不可用。不启动 worker；已启动则标记不可用；Final 回退 CPU；doctor 报告原因。
load_failed模型 / manifest / 张量校验失败。当前后端不可用；保留 CPU 路径；记录路径与 SHA 前缀。
inference_failed运行期推理失败，或 Transcribe 输入不合法。当前段回退 CPU；重启 worker；连续失败标记后端不可用。
timeout加载或识别超过预算。杀 worker；当前段回退 CPU；按崩溃路径重启。
protocol_mismatch协议版本不一致、Hello 的 backend 与 worker 不符，或收到不属于当前状态的消息。拒绝 worker；提示重装 GPU 模块。
  • daemon 主动发送 Cancel 后收到的 inference_failed 只用于释放请求槽，不对该段执行 CPU 回退。
  • 错误码是线协议的一部分；新增错误码提升 GPU_PROTOCOL_VERSION，不提升 voime-ipc 版本。
  • message 只用于日志与 doctor；daemon 不按文案分支，也不向最终用户展示原文。

4.6 JSON 示例

// daemon → worker：Hello（audio_len = 0）
{"Hello":{"protocol":1,"backend":"firered","model_dir":"/home/me/.local/share/voime/models","device":"cuda:0"}}

// worker → daemon：Ready
{"Ready":{"protocol":1,"backend":"firered","runtime":"cuda","device":"cuda:0","vram_mb":5120,"punc":true}}

// daemon → worker：Transcribe（3 s、16 kHz、mono、f32；audio_len = 192000）
{"Transcribe":{"id":42,"sample_rate":16000,"language":"zh"}}

// worker → daemon：Result
{"Result":{"id":42,"text":"明天的日程帮我确认一下。","latency_ms":860,"rtf":0.29}}

// worker → daemon：Error
{"Error":{"id":42,"code":"inference_failed","message":"inference aborted"}}

// daemon → worker：Shutdown（audio_len = 0）
"Shutdown"

// worker → daemon：Bye（audio_len = 0）
"Bye"
  • 示例只展示 header；实际线上字节前面还有 header_len，Transcribe 后面还有 audio_len 与 PCM。
  • Shutdown 与 Bye 是无字段消息，按外部标签编码为 JSON 字符串。
  • 示例中的文本仅用于说明字段；实现不得记录识别文本。

4.7 超时、取消与退出

阶段计时预算超时处理
加载daemon 写完 Hello → 收到 Ready / Error。120 s杀 worker；标记后端不可用；Final 回退 CPU；不阻塞 daemon 启动。
识别daemon 写完 Transcribe → 收到 Result / Error。60 s杀 worker；当前段回退 CPU；按崩溃路径重启。
关闭daemon 写完 Shutdown → 收到 Bye 或进程退出。5 s强杀 worker；确保无孤儿进程。
事件行为
Cancelworker 尽力中止当前 id；若成功中止，发送 Error { id, code: "inference_failed", message: "cancelled" } 作为该请求的终态；daemon 丢弃该终态，不执行 CPU 回退。若推理已经完成，Result 可能已在途，daemon 同样丢弃。
Cancel 无匹配 id忽略，不产生响应。
Shutdown 时有在途 Transcribeworker 放弃该请求，不再发送其终态；释放 runtime / 模型后直接发送 Bye。
正常关闭daemon 发送 Shutdown；worker 发送 Bye 并以 0 退出；daemon 回收进程。
worker 崩溃 / 管道断开daemon 视为失败；当前段回退 CPU，并按崩溃路径重启或标记后端不可用。
daemon 未发 Shutdown 就断开 stdout / stdinworker 视为异常关闭；释放资源后以非零退出。
帧级协议错误长度、UTF-8 或 JSON 不合法时直接关闭连接；不发送 Result / Error，也不映射为业务回退。
  • 取消是协作式的，不是强制终止；daemon 的识别预算到期后仍然强杀 worker。
  • 超时、崩溃与管道断开都不产生 Partial 或前端消息；回退与丢弃由 daemon 决定。
  • 关闭顺序固定为 Shutdown → Bye → 退出；daemon 不向 worker 发送 Bye。

4.8 版本与兼容

变化版本策略
当前版本GPU_PROTOCOL_VERSION = 1；Hello 与 Ready 都携带。
新增可选字段不提升版本；旧实现忽略未知字段。
修改字段类型 / 含义、删除字段、新增消息或错误码必须提升 GPU_PROTOCOL_VERSION；worker 在 Hello 阶段返回 protocol_mismatch，daemon 在 Ready 阶段检测到不一致则终止 worker。
新增 GPU 后端新增 GpuBackend 线值并提升协议版本；不影响前端 IPC。
与前端 IPC 的关系完全独立；本协议变化不提升 voime-ipc 的 PROTOCOL_VERSION，也不改变前端消息形状。
兼容窗口不提供多版本协商；daemon 与 worker 必须使用同一协议版本，随同一 GPU 模块安装。
  • 版本检查是双向的：daemon 检查 Ready，worker 检查 Hello；任一不一致都拒绝继续。
  • 协议版本与模型版本无关；模型校验属于各 worker 与 voimed 的加载路径。
