2. CONVENTIONS

↑

约定内容
线程模型pipeline 只有一个工作线程；音频回调线程只做格式转换与入队；不引入异步运行时。CPU Final 由 daemon 的 Finalizer 线程调用；核心只创建一个 SenseVoice 会话，Preview 与 CPU Final 通过锁串行使用。
音频通道容量由 audio::capture::AUDIO_CHANNEL_CAPACITY 拥有；回调使用 try_send，满时丢弃当前块，不阻塞设备线程。
命令通道有界；worker 使用 select_biased!，命令优先于音频，保证 Stop / CancelPreview 不被积压音频阻塞。
单活动段collecting / segmenter 保证同一时刻只有一个活动段；已采集时 StartSegment 被忽略；软切分后 reset_after_segment 立即开始下一段；FinishSegment 先排空音频再强制结束当前段。
完成段队列完成段队列有界；慢识别时丢弃最旧段，音频通道也可能丢弃，不承诺零丢失。
Fbank 生命周期StreamingFbank 只服务 VAD，保留滑动窗口与未消费样本；Fbank::compute 每次从完整段独立计算，服务 SenseVoice。两者不共享实例。
SenseVoice 预处理80-bin fbank、25 / 10 ms、hamming 窗、默认 LFR 7 / 6 与 560 维 CMVN、use_itn=true；fbank 参数取 FbankConfig::sensevoice()，LFR / CMVN / ITN token id / 语言 id 与 vocab_size 取 ONNX metadata（缺失时回退常量）。manifest 只声明身份、文件与 runtime，不承载这些参数。
LFR 唯一应用LFR 只能应用一次：正常链路只传 80-bin fbank，由 SenseVoice::transcribe_features 恰好展开为 80 * lfr_window 维（默认 560）；输入已是该维度时视为已 LFR，跳过展开。该方法是 LFR + CMVN 的唯一入口，调用方与 transcribe 都不得再应用 LFR。
Preview 门禁pipeline 持有 preview_gate；FinishSegment / CancelPreview 关闭门禁并丢弃未开始的预览任务；StartSegment 与软切分后的 reset_after_segment 重新打开。
模式切换清理SetMode 只在旧段 Final / 丢弃后由 daemon 调用，到达时不得有活动段。Worker 设置新 mode 后，无论目标模式都清空 collecting、resample_pending、frame_audio 与 partial 调度；旧段的 VAD / 分段器由 FinishSegment 的 reset_after_segment 重置，完成段队列由 FinishSegment 的 drain_queue 交付。不得把旧模式的 Partial、待处理音频、完成段或会话标志带入新会话。
Partial 门槛最小间隔、最小新增音频与尾部长度由 pipeline 模块常量拥有；一次慢推理会推迟下一次 Partial，避免立即重跑。
分段MIN_SPEECH_MS / AUTO_END_SILENCE_MS 由 segmenter 模块拥有；所有模式使用同一静音阈值，max_segment_ms 来自模型 manifest，达到上限时强制结束。
最长段MAX_SEGMENT_MS 固定 30 s 上限，推荐值 30_000；manifest 的 max_segment_ms 与长段测试使用同一上限。
模型校验加载 manifest 时校验 schema 5、id 等于目录名、kind 匹配；verify 校验文件存在、大小、非空与 SHA-256；rebase 拒绝绝对路径与 ..。
错误边界库内部使用 anyhow::Result + 上下文；音频错误类型保留 AudioError；pipeline 把可恢复错误转为 SegmentDropped。
无 OS 依赖不直接使用 Unix socket、named pipe、Fcitx、Win32 或 TUI API；config 只保留模型目录的平台默认值回退（Windows 读 LOCALAPPDATA，Unix 走 XDG / HOME）。
  • 仓库级依赖方向与进程边界见 根 CORE §2。
  • 工程常量不在此表赋值；具体值以源码为准，推荐值可写在签名注释中。

               config: FbankConfig) -> anyhow::Result<Self>;
    pub fn transcribe(&mut self, samples: &[f32])

fn read_cmvn(session: &Session) -> anyhow::Result<(Vec<f32>, Vec<f32>)>;
fn validate_features(features: &[Vec<f32>]) -> anyhow::Result<()>;
  • transcribe 对完整样本计算 fbank 后调用 transcribe_features，不得在自身内再调用 apply_lfr 或 apply_cmvn；transcribe_features 最多应用一次 LFR 7 / 6，再做 CMVN、推理、greedy / 模型内置解码与词表还原。
  • transcribe_features 是 LFR + CMVN 的唯一入口，按首帧维度区分输入：80-bin fbank 执行一次 LFR 展开为 80 * lfr_window 维（默认 560）；该维度输入视为已 LFR，跳过 LFR 直接做 CMVN。调用方不得自己再展开，避免累计两次。
  • LFR / CMVN / ITN token id / 语言 id 与 vocab_size 来自 SenseVoice ONNX metadata；tokens.txt 由 manifest 文件列表定位；manifest 本身不携带这些参数（见 PROVIDER §4.2）。
  • 固定 use_itn=true；标点由 SenseVoice 输出自带，不加载独立标点模型。
  • 空音频或空文本返回空结果；由调用方按空段处理。

5.2 音频、VAD、软切分与 Continuous

    │   └── 判断 AudioChunk → Worker::handle_audio(chunk)
    └── Worker::drain_queue()

Worker::handle_audio(chunk)
├── 判断 chunk.is_stream_error() → PipelineEvent::Recording(false)
├── 判断 !should_process() → 清空待处理音频并返回
├── 判断 resampler.is_none() → StreamResampler::new(chunk.sample_rate, chunk.channels)
├── StreamResampler::push(chunk)
└── Worker::process_pending_audio(false)
    └── Worker::process_vad_batch(batch, frame_samples)
        ├── FireRedVad::push(batch)
        └── 逐帧 Worker::handle_frame(frame, audio)
            └── Segmenter::push(frame, samples)
                ├── 判断 SpeechStart → PipelineEvent::Recording(true)
                ├── 判断 preview_gate 开启且达到 Partial 门槛 → Worker::emit_partial()
                └── 判断 SpeechEnd
                    ├── 判断 mode == Continuous → Worker::enqueue(segment)
                    ├── 判断 mode != Continuous → Worker::emit_segment(segment)
                    └── 判断 keeps_collecting_after_end(mode, reason)
                        ├── Worker::reset_after_segment()
                        └── PipelineEvent::Recording(true)
  • PTT / Toggle 的 SpeechEnd 是软切分：keeps_collecting_after_end 为 true，立即交付当前段并发送下一段的 Recording(true)；FinishSegment 才结束采集。
  • 软切分后的下一次 SpeechStart 会再次发送 Recording(true)，属于幂等重复；daemon 已有当前段时不再分配新段。
  • Continuous 的 SpeechEnd 进入容量有限的完成段队列，下一次 SpeechStart 自动开始新段。

5.3 会话采集、软切分与硬切分

Pipeline::start_segment()
└── PipelineCommand::StartSegment
    └── Worker::handle_command(StartSegment)
        ├── 判断 mode != Continuous && !collecting && !segmenter.is_active()
        ├── FireRedVad::reset()
        ├── Segmenter::reset()
        └── PipelineEvent::Recording(true)

Pipeline::finish_segment()
└── PipelineCommand::FinishSegment
    ├── Worker::prepare_command(FinishSegment)
    │   ├── 排空 audio_rx
    │   └── Worker::process_pending_audio(true)
    └── Worker::handle_command(FinishSegment)
        ├── Worker::cancel_preview()
        ├── Segmenter::force_end()
        ├── Worker::emit_segment(segment)
        └── PipelineEvent::Recording(false)

Pipeline::cancel_preview()
└── PipelineCommand::CancelPreview
    └── Worker::handle_command(CancelPreview)
        └── Worker::cancel_preview()

Pipeline::set_mode(mode)
└── PipelineCommand::SetMode(mode)
    └── Worker::handle_command(SetMode)
        ├── resample_pending.clear()
        ├── frame_audio.clear()
        └── Worker::reset_partial_schedule()
  • 调用栈只列调用与判断；collecting / preview_gate / mode 等字段赋值见 §2 与类型定义。
  • FinishSegment 与 CancelPreview 都幂等；重复取消不会产生新事件。
  • 软切分不调用 FinishSegment：reset_after_segment 保持 collecting=true，重置当前段状态并重新打开 Preview 门禁。
  • 当前段 Finalizing 期间 emit_partial 直接返回；硬切分后直到下一次 StartSegment 才重新打开。
  • 存在旧段时，SetMode 到达前 daemon 已通过 FinishSegment 结束旧段；FinishSegment 的 prepare_command 先排空音频并 drain_queue，VAD / 分段器由 reset_after_segment 重置。此路径不再截断活动段，但必须完成上述清理，避免旧音频、完成段或 Partial 进入新会话。

5.4 Preview

Worker::emit_partial()
├── 判断 !preview_gate → reset_partial_schedule()
├── 判断 !segmenter.is_active() → reset_partial_schedule()
├── 截取 active_samples() 末尾 PARTIAL_MAX_MS
├── Fbank::new(fbank).compute(tail)
├── SenseVoice::transcribe_features(features)   // LFR + CMVN 各执行一次
├── 判断 text 非空 → PipelineEvent::Partial(text)
└── Worker::finish_partial_schedule(started)
  • pipeline 只计算 fbank，不预做 LFR；LFR 与 CMVN 由 transcribe_features 统一执行一次。
  • 尾部被截断时文本前加省略号；Partial 不进入历史、不提交。
  • 慢推理会按耗时推迟下一次 Partial；具体调度见 finish_partial_schedule。

5.5 CPU Final

voimed::daemon::Daemon::finalize(segment)
├── 判断 backend == Cpu → Final::transcribe(segment.samples)
│   ├── 判断 samples.is_empty() → 返回空字符串
│   ├── SenseVoice::transcribe(segment.samples)
│   │   ├── Fbank::new(fbank).compute(segment.samples)
│   │   ├── 判断 features.is_empty() → 返回空字符串
│   │   └── SenseVoice::transcribe_features(features)  // LFR + CMVN 各执行一次
│   └── 返回 asr.text
├── 判断 text.trim().is_empty() → SegmentDropped
└── IpcServer::broadcast(Final { segment_id, text })
  • LFR 只在本路径应用一次：Final::transcribe 接收 PCM，SenseVoice::transcribe 计算 fbank 后交给 transcribe_features，调用方不预做 LFR。
  • CPU Final 只执行一次；GPU Final 不调用本路径，只有 GPU 失败回退时才调用。
  • Final 与 Preview 共用同一个 SenseVoice 会话；Final 阻塞等待推理锁，Preview 使用 try_lock，锁被 Final 占用时跳过本次 Partial，不阻塞 pipeline。

  • record_audio_error 递增音频错误计数；达到上限时由调用路径返回 Fatal。
