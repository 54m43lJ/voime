1. 环境

↑

项目要求
Ruststable 工具链（rust-toolchain.toml）；workspace 版本与依赖见根 Cargo.toml。
LinuxALSA 开发头文件（Arch：alsa-lib；Debian / Ubuntu：libasound2-dev）。
WindowsRust MSVC 工具链；cpal 使用 WASAPI，不需要 ALSA。
模型运行期需要 default/vad + default/sense-voice；GPU 后端还需 firered/fire-red-aed + firered/punc。编译与纯算法单测不需要权重。

2. 构建

↑

cargo build -p voime-core
cargo build --release -p voime-core
产物说明
libvoime_core.rlib供 voimed 与 voime doctor 链接的库；不产出独立可执行文件。
ONNX Runtime由 ort 构建时链接；构建期可能下载二进制，运行期不联网。
  • 根 workspace 的完整构建、源码安装与模型安装见 根 BUILD §2 / §3 / §4。
  • voime-core 不安装任何文件；部署由 voimed / voime 的 BUILD 负责。

3. 测试

↑

cargo test -p voime-core
cargo clippy -p voime-core --all-targets
cargo fmt -p voime-core --check
测试覆盖
单元测试重采样下混 / 降采样、fbank 帧数、greedy 解码、CMVN 解析、模型路径逃逸、分段端点、预卷、backend 文件、CPU / GPU 资源包解析。
tests/asr_sense_voice.rsCMVN / token id / greedy；真实 10–60 s 解码仅在设置 VOIME_ASR_MODEL_DIR 时执行。
tests/segmenter.rs端点、静音自动结束、最大段长与预卷；通过根 voime-tests 运行。
模型校验schema 3、资源包内各目录的 kind、SHA-256、张量名称 / 类型 / 形状、token_count 与 firered 包完整性；不校验音频内容。
  • 跨组件集成测试从根目录运行 cargo test；单 crate 测试不覆盖 daemon / 前端。
  • 真实 SenseVoice 测试需要安装 default 资源包；默认目录与安装命令见根 BUILD §4。
  • GPU / worker 测试不在本 crate；由 voime-gpu 与 voimed 的专用 runner 覆盖。
