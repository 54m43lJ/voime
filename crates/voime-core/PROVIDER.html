PROVIDER — voime-core

根：README USER CORE PROVIDER ｜ 本组件：README USER CORE

本文只记录 voime-core 实际消费的外部子集：cpal 音频接口、ONNX Runtime CPU 会话接口 与两个核心模型目录的文件契约。完整定义以官方文档为准；产品级下边界见 根 PROVIDER。

1. TERMS

↑

术语定义
cpal host平台音频后端；Linux 上通常为 ALSA，Windows 上为 WASAPI。
输入设备（device）cpal 枚举到的录音端点；本项目按设备名精确匹配。
输入流（stream）cpal 建立的回调流；数据回调交付 PCM，错误回调交付 StreamError。
样本格式（sample format）设备原生样本类型；当前只支持 I16 / U16 / F32。
ONNX Runtime 环境进程级推理环境；本项目核心只启用 CPU Execution Provider。
ONNX 会话（session）加载一个 ONNX 模型并可执行推理的运行时对象。
metadataONNX 模型自带的键值元数据；提供 LFR / CMVN / ITN / 语言 id 与 vocab_size 等推理参数。
Execution ProviderONNX Runtime 的推理后端；核心只使用 CPU。
fbankKaldi 风格梅尔滤波器组特征；VAD 与 SenseVoice 共用 80-bin、25 / 10 ms 参数；VAD 使用 povey 窗，SenseVoice 使用 hamming 窗。
LFR低帧率特征拼接；SenseVoice 默认使用 7 帧窗、6 帧移，输出 560 维；实际值由 ONNX metadata 提供，缺失时回退该默认值。
CMVN倒谱均值方差归一化；SenseVoice 使用 ONNX metadata 的 neg_mean / inv_stddev，VAD 使用可选文件 cmvn.ark。
模型目录firered-vad/ 或 sensevoice-small/；一模型一目录，包含 manifest 与权重。
manifest模型目录的权威描述；通用 schema、字段与合法 kind 见 根 CORE §4.8，核心固定值见 USER §4.3。
FileSpecmanifest 中一个文件条目；含相对路径、SHA-256 与字节大小。
SHA-256模型文件内容摘要；启动时逐文件校验。

2. CONVENTIONS

↑

约定内容
设备选择--input-device 按设备名精确匹配；未指定时使用 cpal 默认输入设备。
音频格式设备原生格式由核心转换为 16 kHz、单声道、f32；只接受 I16 / U16 / F32。
本地性音频、模型与推理都在本机完成；运行期不联网。
模型不可变模型目录运行期只读；启动时校验 manifest、大小与 SHA-256，失败不进入运行态。
清单一模型一目录核心只读取 firered-vad/manifest.json 与 sensevoice-small/manifest.json；不存在共享模型清单或 active 指针。
清单边界manifest 只声明模型身份、文件完整性与 runtime（backend / format / precision / max_segment_ms）；不携带 ONNX 张量名 / 形状、fbank / LFR / CMVN 参数或词表内容。推理参数的来源见 §4.2。
CPU 推理只启用 CPU Execution Provider；线程数由命令行决定。
精度SenseVoice 为 int8 ONNX，FireRedVAD 使用上游交付精度；运行期不做动态量化或精度回退。
SenseVoice 模式单 ONNX；80-bin fbank、默认 LFR 7 / 6 与 560 维 CMVN；固定 use_itn=true；标点由模型输出自带。
VAD 模式流式状态张量；状态由模型声明为固定形状，项目侧保存与更新；每个新语音段重置。
错误映射Provider 错误在边界处转换为项目错误并附上下文；启动期写日志 / 返回错误，运行期按 §4.5 处理。

3. DIAGRAMS

↑

3.1 音频采集边界

  • 回调只负责把设备样本转换为 AudioChunk 并入队；重采样与 VAD 在项目内部完成。
  • 错误回调与数据回调可能来自不同线程；错误以零长度哨兵写入同一有界通道。

3.2 模型加载与推理边界

  • 启动时读取并校验 firered-vad / sensevoice-small，然后创建 CPU 会话；每个语音段只重置解码状态，不重新加载权重。
  • VAD 与 SenseVoice 各自使用独立 ONNX 会话；核心不加载独立标点模型或 GPU EP。
  • ONNX 输入输出与预处理参数在运行时从会话 introspection / metadata 读取；manifest 只负责文件完整性与 runtime 声明。
  • 具体张量契约见 §4.2；GPU 模型与 runtime 见 voime-gpu-qwen3 PROVIDER。

4.2 核心模型目录

~/.local/share/voime/models/
├── firered-vad/
│   ├── manifest.json
│   ├── model.onnx
│   └── cmvn.ark          # 可选；模型已内置 CMVN 时不存在
└── sensevoice-small/
    ├── manifest.json
    ├── model.int8.onnx
    └── tokens.txt
{
  "schema": 5,
  "id": "sensevoice-small",
  "kind": "asr",
  "version": "2024-07-17",
  "license": "Apache-2.0",
  "files": [
    { "path": "model.int8.onnx", "sha256": "...", "size": 0 },
    { "path": "tokens.txt", "sha256": "...", "size": 0 }
  ],
  "runtime": {
    "backend": "cpu",
    "format": "onnx",
    "precision": "int8",
    "max_segment_ms": 30000
  }
}
项目契约
VAD 文件firered-vad/model.onnx + manifest.json；模型未内置 CMVN 时另有 cmvn.ark；流式状态张量固定形状。
VAD 输入80-bin fbank 特征与上一帧状态张量；状态由模型声明，核心按固定形状保存。
VAD 输出逐帧语音概率与更新后的状态；数量必须等于本批特征帧数。
SenseVoice 文件sensevoice-small/model.int8.onnx + tokens.txt + manifest.json。
SenseVoice 输入x: 80 * lfr_window 维 LFR fbank（默认 560）；x_length: 帧数；language / text_norm 控制张量；固定 use_itn=true。
SenseVoice 输出token logits；由模型内置解码与 tokens.txt 还原为带标点文本。
ONNX 张量输入 / 输出张量名、dtype 与 shape 在会话创建后由 input_specs / output_specs 从 ONNX 图读取并校验；不来自 manifest。
fbank 参数80-bin、25 / 10 ms 固定；VAD 使用 povey 窗，SenseVoice 使用 hamming 窗；不来自 manifest。
LFR 参数窗 / 步移取 ONNX metadata lfr_window_size / lfr_window_shift；缺失时回退 7 / 6；不来自 manifest。
SenseVoice CMVNneg_mean / inv_stddev 取 ONNX metadata；长度必须为 80 * lfr_window；不来自 manifest。
VAD CMVN模型未内置时读取 manifest 文件列表中的 cmvn.ark；文件为 Kaldi 二进制 DM / FM 矩阵，布局为 2 x (80 + 1)：第一行前 80 列为 sum、末列为 count，第二行前 80 列为平方和；按 count 计算 mean 与 inverse stddev。manifest 只记录文件路径 / SHA-256 / 大小，不记录参数值。
词表tokens.txt 由 manifest 文件列表定位并校验；内容不写入 manifest；每行为 token 与 id，token_count 必须等于 ONNX vocab_size 与输出类别数。
manifest通用 schema、字段与合法 kind 见 根 CORE §4.8；核心固定值：firered-vad 为 vad，sensevoice-small 为 asr，runtime 见本节目录示例。manifest 不包含张量 / 预处理参数或词表内容。
安装核心安装脚本下载固定 revision 的模型文件，写入 manifest；只接受当前 schema 5 模型包。
  • SenseVoice 使用上游 sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17；模型输出自带标点与 ITN，不加载独立标点模型。
  • VAD 使用 FireRedVAD Stream-VAD ONNX；所有模式共用同一模型与参数。
  • manifest 只覆盖身份、文件完整性与 runtime；ONNX 张量、fbank / LFR / CMVN 参数与词表内容不写入 manifest，来源见上表。
  • 模型文件来源、revision 与 SHA-256 由准备阶段冻结并写入安装源；运行期不联网。

4.3 推理运行时：ONNX Runtime CPU / ort

消费项签名 / 类型用途

元数据Session::metadata()读取 LFR / CMVN / ITN / 语言 id / vocab_size 等推理参数。

4.5 错误与处理

AudioError 的变体定义见 voime-core USER §4.5； 本表只记录 provider 触发条件与映射。

错误触发条件处理
NoInputDevice系统没有默认输入设备。daemon 启动失败，stderr + 退出码 1。
DeviceNotFound--input-device 名称不存在。daemon 启动失败。
UnsupportedSampleFormat设备只提供 I16 / U16 / F32 之外的格式。daemon 启动失败。
StreamLost / 流错误哨兵运行期音频流错误。丢弃当前段；连续失败后 daemon 退出。
模型目录 / manifest 缺失firered-vad 或 sensevoice-small 不存在、缺 manifest.json。核心启动失败；不进入运行态。
schema / id / kind 不匹配schema 5 之外的 manifest、目录名不符或 kind 错误。核心启动失败；不接受 schema 5 之外的布局。
文件缺失 / 大小或 SHA-256 不匹配模型文件缺失或被修改。核心启动失败。
张量 / 会话错误ONNX 输入输出与核心预期不符或会话创建失败。核心启动失败。
SenseVoice 推理失败运行期解码 / 会话错误。当前段 SegmentDropped；CPU Final 返回错误，由 daemon 丢弃该段。
空音频 / 空文本段过短或模型输出为空。不产生 Final 文本；daemon 按空段处理。
  • 模型 / 推理错误以 anyhow::Error + 路径 / 张量上下文返回，不伪造统一 Provider 错误枚举。
  • 运行期单段推理错误转为 PipelineEvent::SegmentDropped，不终止 daemon。
  • GPU 模型 / runtime 失败不在本组件处理；daemon 回退到本组件的 CPU Final。
