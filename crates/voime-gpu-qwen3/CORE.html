本文只描述 Qwen worker 的内部文件、类型、签名与关键执行路径。 对 daemon 的帧协议见 voime-gpu-common USER； 模型与 llama.cpp 契约见 PROVIDER。

  • 本 crate 是独立 Cargo workspace / 独立二进制；不进入根 workspace，也不与其它组件共享链接单元或 runtime 目录。
  • worker.rs 负责帧循环、Hello / Ready 与取消标志；engine.rs 只封装 llama-cpp-4 的加载与推理；mtmd.rs 只处理音频 bitmap、prompt 与 chunks。

  • 文档与图表不属于源码结构；模型目录由安装脚本写入，运行期由 daemon 通过 Hello 传入。

2. CONVENTIONS

↑

约定内容
单一 backend feature Cargo.toml 固定启用 llama-cpp-4/mtmd 与且仅一个 backend feature（vulkan 或 cuda）；CI 拒绝同时启用两个 backend，也拒绝未启用 backend 的构建。
无 ORT / ONNX 依赖图中不得出现 ort、onnxruntime 或 ONNX 模型；worker 只链接 llama.cpp / GGML。
模型常驻 Hello 后加载一次 GGUF 主模型与 mmproj；每个 Final 只创建 / 重置 LlamaContext，不重新加载权重。
PCM 直通 daemon 传来的 f32 PCM 直接交给 MtmdBitmap::from_audio；不写 WAV、不做重采样、不做增益归一化。
Prompt 固定 Prompt 由 GGUF 自带 chat template 与 MtmdContext::default_marker() 生成；不拼接用户自由文本，不把识别结果回灌 prompt。
Greedy / EOS 使用 LlamaSampler::greedy()；遇到 model.is_eog_token(token) 或 token 上限即停止；不做采样温度、top-p 或重复惩罚。
清洗集中 所有返回文本必须先经 clean::clean_text；其他模块不得自行截断 <asr_text> 或 language ... 前缀。
空输出 清洗后为空返回空字符串；worker 不把它升级为错误，daemon 按空段丢弃。
输入上限 worker 按 manifest 的 max_segment_ms 计算样本上限并拒绝超长段；默认 30 s，避免 llama.cpp 长音频无输出边界。
取消与超时 解码循环在 token 之间检查 CancelFlag 与 Instant 截止时间；超时返回 common 的 timeout，取消按 voime-gpu-common USER §4.7 处理。
错误映射 加载期错误映射为 runtime_missing / device_unavailable / load_failed；推理期映射为 inference_failed / timeout；不在 worker 内回退 CPU 大模型。
日志 stdout 只写协议帧；日志走 stderr，只记录长度、耗时、错误码与后端名，不记录识别文本。

4. Internal types & method signatures

↑

以下签名定义目标接口；实现可调整名称或参数，但必须保持消息、常量与状态语义。

4.1 main.rs 文件树

fn main() -> std::process::ExitCode;
fn run() -> anyhow::Result<()>;
  • main 只把 run 的结果转换为退出码；不解析模型路径、不读帧、不加载模型。
  • 启动失败写 stderr 并返回非零退出码；不向 stdout 写任何非协议内容。

4.2 worker.rs 文件树

pub const TRANSCRIBE_BUDGET_MS: u64;             // 推荐值 60_000

#[derive(Clone)]
pub struct CancelFlag { /* Arc<AtomicBool> + current id */ }
enum WorkerCommand {
    Transcribe(Transcribe),
    Shutdown,
}
impl CancelFlag {
    pub fn new() -> Self;
    pub fn arm(&self, id: u64);
    pub fn cancel(&self, id: u64);
    pub fn is_cancelled(&self) -> bool;
    pub fn flag(&self) -> &AtomicBool;
    pub fn clear(&self);
}

pub fn run() -> anyhow::Result<()>;
fn validate_hello(hello: &Hello) -> anyhow::Result<()>;

fn handle_transcribe(engine: &mut Engine, manifest: &Manifest,
                     request: &Transcribe) -> anyhow::Result<()>;

fn read_loop(tx: Sender<WorkerCommand>, cancel: CancelFlag);
  • run 先读 Hello，校验 protocol / backend / model_dir，再加载 manifest 与 engine，最后写 Ready 并进入帧循环。
  • 读帧线程把 Transcribe / Shutdown 送入命令通道；每个请求开始前 arm(id)，结束后 clear()。收到 Cancel 时只在该 id 匹配当前请求时置位 CancelFlag，让当前解码在下一个 token 退出；无匹配 id 忽略。
  • TRANSCRIBE_BUDGET_MS 是 worker 侧的保护预算；daemon 仍是超时与杀进程的权威。

4.3 manifest.rs 文件树

pub const MANIFEST_FILE: &str;
pub const SCHEMA_VERSION: u32;
pub const SAMPLE_RATE: u32;

pub struct FileSpec {
    pub path: PathBuf,
    pub sha256: String,
    pub size: u64,
}

pub struct RuntimeSpec {
    pub backend: String,
    pub format: String,
    pub precision: String,
    pub max_segment_ms: u32,
}

pub struct Manifest {
    pub schema: u32,
    pub id: String,
    pub kind: String,
    pub version: String,
    pub license: String,
    pub files: Vec<FileSpec>,
    pub runtime: RuntimeSpec,
}

impl Manifest {
    pub fn load(dir: &Path) -> anyhow::Result<Self>;
    pub fn verify(&self, dir: &Path) -> anyhow::Result<()>;
    pub fn main_model(&self) -> anyhow::Result<&FileSpec>;

    pub fn mmproj(&self) -> anyhow::Result<&FileSpec>;

    pub fn max_segment_samples(&self) -> usize;
}
  • 通用 schema、字段与合法 kind 见 根 CORE §4.8；load 校验 id 与目录名一致、kind == "asr"、runtime.backend == "qwen3"、format == "gguf"、precision == "bf16"。
  • verify 逐文件检查存在、非空、大小与 SHA-256；拒绝绝对路径、.. 与目录外路径。
  • max_segment_ms 必须大于 0 且不超过 30_000；超出范围拒绝 manifest。max_segment_samples 按 max_segment_ms * SAMPLE_RATE / 1000 计算；超出时 worker 返回 inference_failed，不截断音频。

4.4 engine.rs 文件树

pub const MAIN_MODEL_FILE: &str;
pub const MMPROJ_FILE: &str;

pub struct Engine {
    mtmd: MtmdContext,
    model: LlamaModel,
    backend: LlamaBackend,
}

impl Engine {
    pub fn load(manifest: &Manifest, model_dir: &Path, device: &str)
        -> anyhow::Result<Self>;
    pub fn transcribe(&mut self, samples: &[f32], language: Option<&str>,
                      cancel: &CancelFlag, deadline: Instant)
        -> anyhow::Result<String>;
    fn warmup(&mut self) -> anyhow::Result<()>;
    fn context_params(&self) -> LlamaContextParams;

}
  • load 创建 LlamaBackend、加载 BF16 主模型、检查 LlamaModel::ftype()、初始化 MtmdContext，再检查 capabilities(&model).audio 与 audio_sample_rate()。
  • device 来自 Hello；空串使用 backend 默认设备，不支持的值返回 device_unavailable。设备序号传给 LlamaModelParams::with_main_gpu，并显式设置 n_gpu_layers = 999，避免默认参数把模型留在 CPU。
  • warmup 用一段短静音完成一次 mtmd / decode，提前暴露 backend 或模型加载问题；不计入用户 Final。
  • transcribe 每次创建 LlamaContext，调用 mtmd 与 decode，最后调用 clean；不在方法内重新加载模型。
  • context_params 按 30 s 音频编码后的 token 与 MAX_NEW_TOKENS 设置上下文长度；不足时返回 inference_failed，不截断音频。
  • 字段顺序保证 MtmdContext 先于 LlamaModel、LlamaModel 先于 LlamaBackend 释放。

4.5 mtmd.rs 文件树

// 依赖：MtmdBitmap::from_audio(samples: &[f32]) -> mtmd::Result<MtmdBitmap>

pub fn build_prompt(model: &LlamaModel, language: Option<&str>)
    -> anyhow::Result<String>;

pub fn tokenize_audio(mtmd: &MtmdContext, samples: &[f32], prompt: &str)
    -> anyhow::Result<MtmdInputChunks>;

pub fn eval(mtmd: &mut MtmdContext, lctx: &mut LlamaContext<'_>,
            chunks: &MtmdInputChunks, n_past: &mut i32)
    -> anyhow::Result<()>;
  • build_prompt 从 GGUF 的 chat template 生成单轮 prompt，并把 MtmdContext::default_marker() 放入用户内容；语言只作为可选提示，不拼接任意用户文本。
  • tokenize_audio 调用 MtmdBitmap::from_audio(samples)、MtmdInputText::new(prompt, true, true) 与 MtmdContext::tokenize；不写临时 WAV。
  • eval 调用 MtmdContext::eval_chunks 并更新 n_past；不在此处展开 mtmd 的音频编码阶段。

4.6 decode.rs 文件树

pub const MAX_NEW_TOKENS: usize;                    // 推荐值 256

pub fn greedy(model: &LlamaModel, lctx: &mut LlamaContext<'_>,
              n_past: &mut i32, cancel: &CancelFlag,
              deadline: Instant) -> anyhow::Result<Vec<LlamaToken>>;
  • 使用 LlamaSampler::greedy() 与 LlamaBatch；每轮采样、判断 EOS / 上限 / 取消 / 截止时间，再 decode 新 token。
  • MAX_NEW_TOKENS 按 30 s 段的上限设置，防止异常模型无限生成；具体值由金样与性能测试冻结。

4.7 clean.rs 文件树

pub fn clean_text(raw: &str) -> String;

fn strip_asr_text(raw: &str) -> &str;
fn strip_language_prefix(raw: &str) -> &str;
fn strip_nul(raw: &str) -> &str;
fn trim_edges(raw: &str) -> &str;
  • Qwen3-ASR 的典型包装是 language English<asr_text>And so, ...；clean_text 取 <asr_text> 之后的内容，去掉 language ... 前缀与可选的 </asr_text> 尾部。
  • 只做包装清洗、NUL 与首尾空白；模型输出中的标点、大小写、数字与中英文混排保持不变。
  • 清洗后为空返回空字符串；不构造占位文本，不返回半截句子。
  • 所有前缀 / 尾部判断必须按 UTF-8 字符边界处理；禁止对 &str 使用固定字节下标切片。中文输出曾因 trimmed[..9] 落在多字节字符内部而 panic，进而导致 worker 重启与 CPU 回退。

5. Call stack tree

↑

5.1 启动与模型加载

voime_gpu_qwen3::main()
└── voime_gpu_qwen3::run()
    └── worker::run()
        ├── voime_gpu_common::read_frame(stdin)
        ├── 判断 Hello → worker::validate_hello(&hello)
        ├── manifest::Manifest::load(model_dir)
        ├── manifest::Manifest::verify(model_dir)
        ├── engine::Engine::load(&manifest, model_dir, &hello.device)
        │   ├── llama_cpp_4::LlamaBackend::init()
        │   ├── llama_cpp_4::LlamaModel::load_from_file(&backend, main_model, &params)
        │   │   └── params = LlamaModelParams::default().with_n_gpu_layers(999).with_main_gpu(device_id)
        │   ├── 判断 model.ftype() 不是 BF16 → anyhow::bail!("load_failed")
        │   ├── llama_cpp_4::mtmd::MtmdContext::init_from_file(mmproj, &model, MtmdContextParams::default())
        │   ├── mtmd.capabilities(&model).audio
        │   ├── 判断 mtmd.audio_sample_rate() != 16000 → anyhow::bail!("load_failed")
        │   └── Engine::warmup()
        └── voime_gpu_common::write_frame(Ready)
  • Hello 之前不加载模型；加载失败返回 load_failed / device_unavailable / runtime_missing，daemon 保留 CPU Final。
  • LlamaBackend::init() 只会初始化编译时选中的 backend；Vulkan 构建不会探测 CUDA，反之亦然。
  • 模型加载完成后常驻；后续 Final 只创建 / 重置上下文，不重新读取 GGUF。

5.2 Final 请求

worker::run()
└── loop
    ├── voime_gpu_common::read_frame(stdin)
    ├── 判断 Transcribe → worker::handle_transcribe(&mut engine, &manifest, &request)
    │   ├── 判断 samples.len() > manifest.max_segment_samples() → voime_gpu_common::write_frame(Error) // inference_failed
    │   ├── Engine::transcribe(samples, language, &cancel, deadline)
    │   │   ├── model.new_context(&backend, self.context_params())
    │   │   ├── mtmd::build_prompt(&self.model, language)
    │   │   ├── mtmd::tokenize_audio(&self.mtmd, samples, &prompt)
    │   │   │   ├── MtmdBitmap::from_audio(samples)
    │   │   │   ├── MtmdInputText::new(&prompt, true, true)
    │   │   │   └── MtmdContext::tokenize(&text, &[&bitmap], &mut chunks)
    │   │   ├── mtmd::eval(&mut self.mtmd, &mut lctx, &chunks, &mut n_past)
    │   │   │   └── MtmdContext::eval_chunks(&mut lctx, &chunks, 0, 0, n_batch, true, n_past)
    │   │   ├── decode::greedy(&self.model, &mut lctx, &mut n_past, cancel, deadline)
    │   │   ├── self.model.detokenize(&tokens, true, false)
    │   │   └── clean::clean_text(&raw)
    │   └── voime_gpu_common::write_frame(Result) // 文本与耗时
    └── 判断其他请求 → voime_gpu_common::write_frame(Error) // protocol_mismatch
  • Transcribe 的字段与音频帧格式见 voime-gpu-common USER §4.2；本文不复制帧定义。
  • 每次 Final 使用独立 LlamaContext，不跨段保留 KV cache；模型权重与 mtmd 上下文常驻。
  • n_past 从 0 开始并由 eval / decode 推进；状态赋值不展开为调用栈节点。
  • 超长段在进入 mtmd 前拒绝，避免 llama.cpp 在长音频上无输出。

5.3 Greedy 解码与 EOS

decode::greedy(model, lctx, n_past, cancel, deadline)
├── LlamaSampler::greedy()
├── LlamaBatch::new(lctx.n_batch() as usize, 1)
├── loop
│   ├── sampler.sample(&*lctx, -1)
│   ├── 判断 model.is_eog_token(token) → break
│   ├── 判断 tokens.len() >= MAX_NEW_TOKENS → break
│   ├── 判断 cancel.is_cancelled() → anyhow::bail!("cancelled")
│   ├── 判断 Instant::now() >= deadline → anyhow::bail!("timeout")
│   ├── batch.add(token, *n_past, &[0], true)
│   └── lctx.decode(&mut batch)
└── tokens
  • 只做 greedy；不设置 temperature、top-k、top-p 或重复惩罚。
  • EOS 与 token 上限都正常结束并返回已生成 tokens；取消与超时返回错误，由 worker 映射为 common 错误码。
  • 每轮只 decode 一个新 token；不在解码循环中重新 tokenize 音频或重建 prompt。
  • n_past 的步进属于解码状态；调用栈只保留 decode 调用。

5.4 asr_text 清洗

clean::clean_text(raw)
├── clean::strip_asr_text(raw)
│   ├── 判断 raw 含 "<asr_text>" → 取标记之后的内容
│   └── 判断含 "</asr_text>" → 取结束标记之前的内容
├── clean::strip_language_prefix(...)
│   └── 去掉开头的 "language ..." 与空白
├── clean::strip_nul(...)
├── clean::trim_edges(...)
└── 判断结果为空 → String::new()
  • 典型输入 language English<asr_text>And so, ... 清洗后为 And so, ...；标点与大小写保持原样。
  • 没有 <asr_text> 标记时只去掉可识别的 language ... 前缀；不按语言名做业务分支。
  • 清洗后为空按空段处理；不返回 language ... 残留，也不把包装文本提交给前端。

5.5 超时与取消

worker::read_loop(tx, cancel)
├── voime_gpu_common::read_frame(stdin)
├── 判断 Cancel(id) → cancel.cancel(id)          // 仅匹配当前 id 时置位
├── 判断 Shutdown → tx.send(WorkerCommand::Shutdown)
└── 判断 Transcribe → tx.send(WorkerCommand::Transcribe)

worker::handle_transcribe(...)
├── cancel.arm(request.id)
├── 判断 Engine::transcribe(...) 返回 "timeout" → voime_gpu_common::write_frame(Error) // timeout
├── 判断 Engine::transcribe(...) 返回 "cancelled" → voime_gpu_common::write_frame(Error) // inference_failed; message=cancelled
├── 判断其他错误 → voime_gpu_common::write_frame(Error) // inference_failed
└── cancel.clear()
  • Cancel 只置位当前请求的取消标志；请求开始时 arm(id)，结束时 clear()。解码在下一个 token 边界退出，不强行中断 llama.cpp 内部调用。
  • deadline 由 TRANSCRIBE_BUDGET_MS 计算；daemon 的 60 s 预算是权威，超过预算时 daemon 可以直接杀 worker，当前段回退 CPU SenseVoice。
  • 取消 / 超时的响应与退出语义以 voime-gpu-common USER §4.7 为准；daemon 丢弃 Cancel 后的 inference_failed 终态，不执行 CPU 回退。

5.6 关闭

worker::run()
├── 判断 WorkerCommand::Shutdown → break
├── drop(engine)
│   ├── drop(MtmdContext)
│   ├── drop(LlamaModel)
│   └── drop(LlamaBackend)
├── voime_gpu_common::write_frame(Bye)
└── 返回 Ok(())
  • 关闭顺序保证 mtmd、模型与 backend 按依赖逆序释放；不留下 GPU 上下文或孤儿线程。
  • daemon 发送 Shutdown 后等待 5 s；超时强杀，worker 不自行延迟退出。
  • 关闭不得写识别文本到日志或磁盘。
