README — voime-gpu-qwen3

根：README USER CORE PROVIDER ｜ 本组件：USER CORE PROVIDER

voime-gpu-qwen3 是 Voime 的可选 GPU Final 后端 worker。 它由 voimed 按 final.backend = qwen3 拉起，使用 llama-cpp-rs / llama.cpp 加载 Qwen3-ASR 1.7B BF16 GGUF 主模型与 BF16 mmproj，只把完整语音段识别成最终文本。

1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

本地语音输入需要在 GPU 上获得比 CPU 小模型更好的最终识别质量，而 GPU runtime 不能在 核心进程里加载。Qwen3-ASR 1.7B 以 BF16 GGUF 形式发布，可以由 llama-cpp-rs / llama.cpp 直接加载；它自带标点与大小写，适合作为一条独立的 Final 后端。在 AMD Linux 上， llama.cpp 的 Vulkan 路径使用系统 Vulkan loader 与 GPU 驱动；不依赖 ROCm / HIP 栈。

1.2 GOAL：什么算成功

  • 只做 Final：接收 daemon 传来的完整语音段，返回最终文本；不接收活动段、Partial 或 VAD 状态。
  • 固定使用 Qwen3-ASR 1.7B BF16 主模型（约 4.07 GB）与 BF16 mmproj（约 642 MB），合计约 4.7 GB；两者必须来自同一模型版本。
  • 由 llama-cpp-4 0.11.0 的 mtmd feature 与一个 backend feature（vulkan 或 cuda）构建；不链接 ORT / ONNX。
  • 输入为 16 kHz、单声道、f32 PCM；直接进入模型音频输入，不写临时 WAV。
  • 输出保留模型自带的标点与大小写；worker 只清洗 language ... / asr_text 包装，不做第二套标点或文本润色。
  • AMD Linux 只提供 Vulkan；不构建、不安装、不探测 HIP / ROCm。NVIDIA 可使用 CUDA 或 Vulkan。
  • 属于 GPU 模块，不是默认 Final：只有 scripts/install-gpu.sh --backend qwen3 / scripts/install-gpu.ps1 --backend qwen3 或 voime ctl backend qwen3 才启用；安装 GPU 模块本身不改变默认 cpu。
  • worker 不可用、加载失败、超时或崩溃时，daemon 的当前段回退 CPU SenseVoice；核心 Preview 与 VAD 不受影响。
  • 运行期模型常驻；同一时刻只处理一个 Final，不在上一段未完成时接收下一段。
  • 独立 crate、二进制、进程与 runtime 目录；不与其它组件共享链接单元或 runtime。

1.3 非目标

  • 不加载 VAD、不产生 Partial、不做 Preview、不包含平台前端或 UI。
  • 不接收活动段增量音频、流式请求或前端 IPC；只处理完整语音段。
  • 不加载 ONNX / ONNX Runtime，也不提供 ORT GPU 路径。
  • 不提供 HIP / ROCm runtime；AMD Linux 的 Qwen 后端只走 Vulkan。
  • 不做 CPU Qwen3-ASR 大模型推理；GPU 不可用时由 daemon 回退核心 CPU SenseVoice，而不是在 worker 内跑 CPU 大模型。
  • 不做流式识别、增量解码或边录边出字。
  • 不做运行期模型 / runtime 下载、转换、量化或格式迁移；这些只发生在安装 / 发布阶段。
  • 不静默降级到 Q8_0 / FP16，也不混用 Q8 mmproj；精度或 runtime 不满足时该后端直接不可用。
  • 不加载任何第二个标点 / 文本模型；标点与大小写由 Qwen3-ASR 自身产生。
  • 不做文本润色、纠错、翻译、摘要或规则后处理；只做输出包装清洗。
  • 不支持运行中切换 Final 后端；切换通过配置 + daemon 重启生效。

2. 用户交互

↑

场景行为详细契约
安装 Qwen 后端 运行 scripts/install-gpu.sh --qwen3 或 scripts/install-gpu.ps1 --qwen3；安装 Qwen worker、所选 llama.cpp runtime 与 qwen3-asr-1.7b 模型目录。安装 GPU 模块不自动切换 final.backend。 USER §4.4
选择 runtime 用 --qwen-runtime vulkan 或 --qwen-runtime cuda 选择预编译 worker / runtime；AMD Linux 只接受 vulkan，不提供 hip / rocm。 USER §4.2 · PROVIDER §4.4
启用 Qwen Final 安装时用 --backend qwen3，或之后运行 voime ctl backend qwen3；下一次 daemon 启动才生效，运行中不热切换。 根 USER §4.4 · voime USER §4.1
日常使用 用户不直接启动或操作 worker；daemon 在启动时拉起它，前端只显示最终文本。worker 没有窗口、托盘、TUI 或命令行交互。 USER §3.1
诊断 voime doctor 显示 Qwen worker 的 ready / running 状态与不可用原因；不读取 worker 内部模型状态。 voime USER §4.4
卸载 scripts/install-gpu.sh --qwen3 --uninstall 或对应 .ps1；只删除 Qwen worker、runtime 与 qwen3-asr-1.7b 模型，不触碰核心。 USER §4.4
失败回退 worker 不可用、模型 / runtime 缺失、超时或崩溃时，当前段回退 CPU SenseVoice；用户仍能完成输入。 USER §4.3 · 根 USER §4.4
  • worker 不向用户输出识别文本或模型细节；最终文本只通过 daemon 返回前端。
  • 默认 final.backend = cpu；安装 Qwen 后端不等于启用它。
  • Qwen 后端不改变热键、目标、Preview 或提交语义；这些仍由核心与平台前端负责。
