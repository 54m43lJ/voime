1. 环境

↑

项目要求
Ruststable 工具链（rust-toolchain.toml）。
LinuxALSA 开发头文件；Fcitx5 不是 daemon 的构建依赖。
WindowsRust MSVC 工具链；WASAPI 由 cpal 处理。
模型运行前必须安装完整模型包；编译不需要权重。
服务管理Linux systemd user service；Windows daemon 是托盘子进程，随托盘启动和退出，不使用独立服务或独立退出流程。

2. 构建与安装

↑

cargo build --release -p voimed
scripts/install_voimed.sh

# 自定义前缀 / 不重新构建 / 不安装 systemd
scripts/install_voimed.sh --prefix DIR --bindir DIR --no-build --no-systemd
产物说明
target/release/voimedASR 守护进程；ONNX Runtime 随 ort 构建时链接。
scripts/install_voimed.sh安装到 ~/.local/bin，生成 systemd user unit。
~/.config/systemd/user/voime.service用户服务；ExecStart 替换为实际 $BINDIR/voimed。
  • 根 workspace 的完整构建、源码安装与模型安装见 根 BUILD §2 / §3 / §4。
  • Windows 产物为 voimed.exe；由托盘以子进程托管（Job Object），随托盘启动和退出；登录启动由安装器负责，不使用 Session 0 服务。

3. 运行

↑

# systemd user service
systemctl --user daemon-reload
systemctl --user enable --now voime.service
systemctl --user status voime.service

# 或前台启动
voimed --verbose
操作命令 / 契约
停止Linux：voime ctl quit 或 systemctl --user stop voime.service；Windows：退出托盘即停止。
重启systemctl --user restart voime.service；前端会定时重连。
诊断voime doctor 检查端点、daemon、模型、音频与前端。
日志给服务环境设 VOIME_LOG=1（或目录路径）后重启，日志写入 {XDG_STATE_HOME}/voime/logs/voimed.log；Windows 为 %LOCALAPPDATA%\voime\logs\voimed.log。
端点默认 $XDG_RUNTIME_DIR/voime/voimed.sock；自定义端点用 --endpoint（--socket 为兼容别名）。
  • voimed 不需要 WAYLAND_DISPLAY / DISPLAY；它只处理音频与 IPC。
  • 如果已有 daemon 在运行，再次启动会打印提示并以 0 退出。

4. 测试

↑

cargo test -p voimed
cargo clippy -p voimed --all-targets
cargo fmt -p voimed --check
测试覆盖
tests/daemon.rs端点存活、断线角色、daemon 生命周期。
tests/state.rs快照默认值、清空历史、status 字段。
tests/ipc.rs握手、角色、模式与 framing。
tests/segmenter.rs分段端点与最大段长。

5. 升级 / 卸载

↑

操作步骤
升级停止服务；重新运行安装脚本；启动服务；前端自动重连。
迁移配置模型目录与端点路径由 CLI / 安装脚本决定；不迁移历史（不持久化）。
卸载systemctl --user disable --now voime.service；删除 ~/.local/bin/voimed 与 ~/.config/systemd/user/voime.service；模型目录按需保留。
Windows退出托盘（同时停止 daemon）；删除 voimed.exe / voime.exe；按需删除模型目录与登录启动项。
