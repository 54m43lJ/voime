1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

语音识别需要常驻的音频流、模型会话与有状态的分段流水线；这些资源不能放进 Fcitx 进程， 也不应该由每个平台前端各复制一份。voimed 是唯一的识别守护进程：它持有音频、 模型、pipeline 与会话历史，通过本机 IPC 向平台前端、TUI 与控制客户端提供 SegmentStarted / Partial / Final 等事件。

1.2 GOAL：什么算成功

  • Linux 与 Windows 使用同一个 daemon 二进制，只替换本机传输实现。
  • 平台前端只发送 Start / Stop / Toggle 与配置，不接触模型或音频。
  • 同一时刻只有一个语音段；segment_id 由 daemon 分配并广播。
  • Final / State 不丢弃；Partial 可丢弃；慢客户端不会阻塞 daemon。
  • daemon 退出时按顺序停止 pipeline、音频与 IPC，并清理端点。

1.3 非目标

  • 不处理热键、输入焦点、目标绑定、临时窗口或文本提交。
  • 不实现平台 UI、托盘、配置界面或安装器。
  • 不解析命令行模式 / 热键；这些由前端通过 IPC 提供。
  • 不保存音频、按键或历史到磁盘。
  • 不直接依赖 Fcitx / Win32；OS 传输由 voime-transport 负责。

2. 用户交互

↑

角色 / 入口交互契约
平台前端连接 daemon，发送 Hello / Configure / Start / Stop / Toggle，接收 SegmentStarted / State / Partial / Final。USER §4.2 · voime-ipc USER
TUI（voime）连接为 tui，读取 Snapshot / Partial / Final，发送 Start / Stop / ClearHistory。voime USER §4.2
voime ctl连接为 control，发送 Start / Stop / Toggle / Status / ClearHistory / Quit。voime USER §4.3
systemd / 登录启动启动 / 重启 / 停止 daemon；Linux 使用 systemd 用户服务，Windows 由托盘托管 daemon，随托盘启动和退出。本组件 §2
voimed CLI指定模型目录、输入设备、线程数、端点路径与日志。USER §4.1
