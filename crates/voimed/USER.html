本文只定义 daemon 一侧的会话、Final 调度与广播行为。消息形状、字段与编码见 voime-ipc USER；GPU worker 帧协议见 voime-gpu-common USER；Windows / Linux 前端的输入集成见各自 USER。

1. TERMS

↑

术语定义
daemonvoimed 进程；拥有音频、pipeline、会话状态、Final 后端选择、worker 生命周期与 IPC。
会话（session）从 PTT 按下、Toggle 开始或 Continuous 首个段开始，到停止 / 失焦 / 断线为止的一段用户交互。一个 Toggle 会话可以包含多个语音段。
语音段（segment）产品级定义见 根 USER §1；daemon 为每段分配 segment_id。
当前段current_segment；同一时刻最多一个，Final / SegmentDropped 后清空。
阶段（Phase）idle / recording / finalizing；由 daemon 维护并广播。
Final 后端cpu / firered / qwen3，由 final.backend 配置决定；默认 cpu。
GPU workerFireRed 或 Qwen 的独立 Final 推理进程；daemon 只启动配置选中的那个。
Finalizing 门禁进入 Finalizing 后停止产生 Partial、取消未开始的 Preview 推理，并禁止新的 Preview，直到下一个段开始。
广播向所有已连接客户端发送 ServerMessage；客户端队列有界。
Snapshot连接时返回的全量状态；字段见 voime-ipc USER §4.3。
历史（transcript）daemon 内存中的最终结果列表；TUI 重连可恢复，daemon 退出丢失。
慢客户端发送队列已满的客户端；Final / State 满时断开，Partial 满时只丢该条。
pending stopToggle 在两个段之间收到 Stop 时暂存，等下一次 Recording(true) 立即结束。
有效模式（effective mode）前端连接时使用其配置的 Mode；前端断开时 daemon 退回 ptt，避免无人控制 Continuous。
GPU 回退所选 worker 不可用或识别失败时，当前段改用核心 CPU SenseVoice；下一段仍可继续尝试所选后端。

2. CONVENTIONS

↑

约定内容
模式所有权Mode / Hotkey 来自前端 Hello / Configure；daemon 只保存并消费，不解析命令行模式。
Final 后端所有权final.backend 只来自配置文件；daemon 不提供 --backend，也不接受 IPC 热切换。默认 cpu，安装 GPU 不自动切换。
配置读取时机daemon 启动时读取一次 final.backend；切换配置后必须重启 daemon，运行中不重新读取。
单活动段同一时刻只有一个语音段；Recording / Finalizing 期间新的 Start 返回 busy。
ID 分配daemon 递增分配 segment_id；客户端传入的 ID 只是提示；SegmentStarted 是权威值。
Stop 匹配Stop 的非零 ID 在 PTT / Continuous 下必须匹配当前段；0 表示停止当前段。Toggle 忽略 ID，停止当前 Toggle 段。
Toggle 会话VAD 在 Toggle 会话中连续切分多个段；每段 Final 后继续 Recording(true)，直到第二次热键、目标失焦或 daemon 断线。
Continuous仅当前端连接且 Mode=Continuous 时由 VAD 自动开始段；前端断开时 daemon 切回 ptt 并停止当前段。
模式切换时机Idle 时立即应用到 pipeline；非 Idle 时暂存，当前段 Final / 丢弃后应用。
Finalizing 门禁Stop 或 VAD 终点触发后立刻进入 Finalizing：停止产生 Partial、取消未开始的 Preview 推理、只允许一次 Final 推理。
CPU Finalbackend=cpu 时调用核心 Final::transcribe 一次；GPU Final 路径不再调用 SenseVoice ASR。
GPU Finalbackend=firered|qwen3 时只把完整 PCM 发给选中的 worker；Preview 仍由核心 SenseVoice 提供。
GPU 回退worker 加载失败、超时、崩溃、显存不足或推理失败时，当前段回退 CPU SenseVoice；记录错误码与后端名，不记录文本。
worker 生命周期daemon 启动时只启动选中的 GPU worker；默认 cpu 不启动。worker 常驻，空闲不卸载；退出时先停 worker。
后端不可用GPU 模型 / runtime 缺失或设备能力不足时，daemon 仍以 CPU Final 启动；配置值保留，doctor 报原因。
广播优先级Final / State 不丢弃；Partial 可丢弃；慢客户端断开不影响其他客户端。
历史只存最终文本；ClearHistory 保留当前段与 partial。
角色只允许一个 frontend 连接；Configure 只接受前端；Quit 只接受 control。
退出顺序停止 worker → 广播 Bye → 关闭 IPC → 停止 pipeline → 停止音频 → 删除端点。
无持久化不写音频、按键或历史到磁盘；daemon 退出后历史丢失。只有配置由 ctl 写入。
端点daemon 通过 voime-transport 绑定端点；Unix 使用文件系统 socket，Windows 使用命名管道。

3. DIAGRAMS

↑

3.1 会话状态与 Final 调度

  • PTT / Continuous 每段回到 Idle；Toggle 在 Final 后回到 Recording，保留同一个会话。
  • Finalizing 期间 Preview 推理停止；CPU Final 只执行一次，GPU Final 不再调用 SenseVoice ASR。
  • 默认 cpu；GPU 失败时当前段回退 CPU SenseVoice；切换后端需重启 daemon。
  • 空段、识别错误与目标失焦都回到 Idle；最终文本是否保留由前端决定。
  • 前端断线会停止当前段并把有效模式退回 ptt。

3.2 Continuous 自动分段

  • VAD 起点触发 SegmentStarted；无需客户端发送 Start。
  • VAD 终点进入 Finalizing：暂停 Preview，选择 CPU / GPU Final；失败回退 CPU。
  • 完成段进入有界队列，识别慢时丢弃最旧段；音频通道也可能丢弃。

4. INTERFACES

↑

4.1 命令行

voimed [--model-dir <DIR>]
       [--input-device <NAME>]
       [--threads <N>]
       [--endpoint <ENDPOINT>]
       [--verbose]
# ~/.config/voime/config.toml
[final]
backend = "cpu"       # cpu | firered | qwen3
选项 / 配置契约
--model-dir模型根目录；内部仍按一模型一目录读取 firered-vad / sensevoice-small；默认见 voime-core USER §4.1。GPU 模型目录在同一根目录下，由 worker 读取。
--input-device输入设备名，按精确字符串匹配；省略时使用默认设备。
--threadsONNX Runtime intra-op 线程数；必须大于 0。
--endpoint本机传输端点；Unix 为 socket 路径，Windows 为命名管道名。--socket 保留为兼容别名。
--verbose输出启动与运行期诊断到 stderr。
VOIME_LOG环境变量；设为 1 或目录路径时写运行日志。取值与默认目录见 voime-log USER §4.1；识别文本只记长度。
final.backendcpu（默认）/ firered / qwen3；只由 voime ctl backend 或安装脚本写入；daemon 启动时读取一次，不提供命令行覆盖。
退出码含义
0正常退出 / 已有 daemon 在运行（幂等启动）。
1启动或运行期致命错误：核心模型、音频、端点、pipeline 或 IPC 初始化失败。
2命令行参数非法（clap）。

4.2 客户端消息处理

消息前置条件daemon 行为
Hello连接后的第一条消息。校验版本与角色；frontend 连接更新前端状态 / Mode / Hotkey 并广播 Snapshot；其他角色返回 Snapshot。
Configure客户端角色为 frontend。更新 Mode / Hotkey；Idle 时立即应用 pipeline 模式，否则等当前段结束；广播 Snapshot。不处理 Final 后端。
StartPhase=Idle。分配 segment_id、进入 Recording、启动 pipeline、广播 SegmentStarted 与 State。
StopPhase=Recording。校验 ID（Toggle 例外），请求 pipeline 结束当前段；进入 Finalizing。
ToggleIdle 或 Recording。Idle 时等同 Start；Recording 时等同 Stop；Finalizing 时返回 busy。
ClearHistory任意角色。清空历史，保留当前段 / partial；广播 HistoryCleared。
Status任意角色。返回 Status 快照；字段形状保持不变，不新增 backend / worker 字段。
Quit客户端角色为 control。进入关闭流程；其他角色返回 invalid_message。
  • 没有 SetBackend 或热切换消息；后端选择通过配置文件 + daemon 重启完成。

4.3 服务端广播

消息触发语义
SegmentStartedStart / Toggle 成功，或 Continuous / Toggle 续段。携带最终 segment_id 与来源；前端据此绑定 / 跟随目标。
StatePhase 变化。录音 / 收尾状态；前端更新临时窗口。Finalizing 表示 Preview 已中断。
Partialpipeline 在 Recording 阶段产生临时结果。可丢弃；只显示，不提交；Finalizing 后不再出现。
FinalCPU / GPU Final 成功。加入历史；前端清空临时文本并提交。
SnapshotHello、配置变化、前端连接 / 断开。全量状态；字段见 voime-ipc USER §4.3；不含 Final 后端。
Error协议、角色、忙碌或推理失败。按 code 处理；不解析文案。
Byedaemon 关闭。客户端清理并等待重连。
  • 广播形状保持现状，不新增 backend 字段；voime doctor 单独展示所选后端与 worker 状态。

4.4 启动与默认值

项目契约所有者
Final 后端读取 ~/.config/voime/config.toml 的 [final].backend；缺省 cpu。切换后必须重启 daemon。本组件 §2 · 根 USER §4.4
GPU worker仅当后端为 firered / qwen3 时启动对应 worker；默认 cpu 不启动、不探测 GPU。本组件 §2
核心模型目录默认目录（Linux XDG / HOME 回退，Windows %LOCALAPPDATA%\voime\models）见 voime-core USER §4.1；GPU 模型在同一根目录下。voime-core USER §4.1
端点默认 $XDG_RUNTIME_DIR/voime/voimed.sock（未设置时 /tmp/voime-<uid>/voimed.sock）；Windows 默认 \\.\pipe\voime-<session>-<user>。voime-transport USER §4
线程数默认 2；必须大于 0。voime-core USER §4.1
初始模式无前端连接时有效模式为 ptt；前端 Hello 后使用其配置。本组件 §2
GPU 不可用保留配置值但标记不可用；daemon 以 CPU Final 启动；doctor 给出修复命令。本组件 §4.5

4.5 错误与恢复

情况行为
核心模型 / 音频初始化失败启动失败，stderr + 退出码 1；不绑定端点。
GPU 模型 / runtime 缺失不阻塞启动；对应后端标记不可用；Final 回退 CPU SenseVoice；doctor 报路径与错误码。
GPU 设备 / BF16 / Vulkan 不支持不启动对应 worker；只使该后端不可用；CPU Final 继续。
GPU 加载超时 / 握手失败杀掉 worker；后端标记不可用；当前段回退 CPU；按退避重启。
GPU 推理失败 / 超时 / 崩溃当前段回退 CPU SenseVoice；记录错误码与后端名；重启 worker，连续失败标记不可用。
GPU 配置值非法启动失败并提示合法取值；不静默改成 cpu。
端点已被活动 daemon 占用幂等退出（退出码 0）。
单段推理失败广播 Error{code:"inference"}，清空当前段，继续监听。
前端断线前端状态置 disconnected；Continuous 退回 PTT；结束当前段；广播 Snapshot。
慢客户端Final / State 队列满时断开该客户端；Partial 满时丢该条。
pipeline 致命错误daemon 记录并以非零退出；客户端收到 Bye。
