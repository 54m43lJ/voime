本文只定义 daemon 一侧的会话、命令处理与广播行为。消息形状、字段与编码见 voime-ipc USER；Windows / Linux 前端的输入集成见各自 USER。

1. TERMS

↑

术语定义
daemonvoimed 进程；拥有音频、模型、pipeline、会话状态与 IPC 服务。
会话（session）从 PTT 按下、Toggle 开始或 Continuous 首个段开始，到停止 / 失焦 / 断线为止的一段用户交互。一个 Toggle 会话可以包含多个语音段。
语音段（segment）产品级定义见 根 USER §1；daemon 为每段分配 segment_id。
当前段current_segment；同一时刻最多一个，Final / SegmentDropped 后清空。
阶段（Phase）idle / recording / finalizing；由 daemon 维护并广播。
广播向所有已连接客户端发送 ServerMessage；客户端队列有界。
Snapshot连接时返回的全量状态；字段见 voime-ipc USER §4.3。
历史（transcript）daemon 内存中的最终结果列表；TUI 重连可恢复，daemon 退出丢失。
慢客户端发送队列已满的客户端；Final / State 满时断开，Partial 满时只丢该条。
pending stopToggle 在两个段之间收到 Stop 时暂存，等下一次 Recording(true) 立即结束。
有效模式（effective mode）前端连接时使用其配置的 Mode；前端断开时 daemon 退回 ptt，避免无人控制 Continuous。

2. CONVENTIONS

↑

约定内容
模式所有权Mode / Hotkey 来自前端 Hello / Configure；daemon 只保存并消费，不解析命令行模式。
单活动段同一时刻只有一个语音段；Recording / Finalizing 期间新的 Start 返回 busy。
ID 分配daemon 递增分配 segment_id；客户端传入的 ID 只是提示；SegmentStarted 是权威值。
Stop 匹配Stop 的非零 ID 在 PTT / Continuous 下必须匹配当前段；0 表示停止当前段。Toggle 忽略 ID，停止当前 Toggle 段。
Toggle 会话VAD 在 Toggle 会话中连续切分多个段；每段 Final 后继续 Recording(true)，直到第二次热键、目标失焦或 daemon 断线。
Continuous仅当前端连接且 Mode=Continuous 时由 VAD 自动开始段；前端断开时 daemon 切回 ptt 并停止当前段。
模式切换时机Idle 时立即应用到 pipeline；非 Idle 时暂存，当前段 Final / 丢弃后应用。
广播优先级Final / State 不丢弃；Partial 可丢弃；慢客户端断开不影响其他客户端。
历史只存最终文本；ClearHistory 保留当前段与 partial。
角色只允许一个 frontend 连接；Configure 只接受前端；Quit 只接受 control。
退出顺序广播 Bye → 关闭 IPC → 停止 pipeline → 停止音频 → 删除端点。
无持久化不写音频、按键或历史到磁盘；daemon 退出后历史丢失。
端点daemon 通过 voime-transport 绑定端点；Unix 使用文件系统 socket，Windows 使用命名管道。

3. DIAGRAMS

↑

3.1 会话状态

  • PTT / Continuous 每段回到 Idle；Toggle 在 Final 后回到 Recording，保留同一个会话。
  • 空段、识别错误与目标失焦都回到 Idle；最终文本是否保留由前端决定。
  • 前端断线会停止当前段并把有效模式退回 ptt。

3.2 Continuous 自动分段

  • VAD 起点触发 SegmentStarted；无需客户端发送 Start。
  • 完成段进入有界队列，识别慢时丢弃最旧段；音频通道也可能丢弃。

4. INTERFACES

↑

4.1 命令行

voimed [--model-dir <DIR>]
       [--input-device <NAME>]
       [--threads <N>]
       [--endpoint <ENDPOINT>]
       [--verbose]
选项契约
--model-dir包含 manifest.json 的目录；默认见 voime-core USER §4.1。
--input-device输入设备名，按精确字符串匹配；省略时使用默认设备。
--threadsONNX Runtime intra-op 线程数；必须大于 0。
--endpoint本机传输端点；Unix 为 socket 路径，Windows 为命名管道名。--socket 保留为兼容别名。
--verbose输出启动与运行期诊断到 stderr。
VOIME_LOG环境变量；设为 1 或目录路径时写运行日志。取值与默认目录见 voime-log USER §4.1；识别文本只记长度。
退出码含义
0正常退出 / 已有 daemon 在运行（幂等启动）。
1启动或运行期致命错误：模型、音频、端点、pipeline 或 IPC 初始化失败。
2命令行参数非法（clap）。

4.2 客户端消息处理

消息前置条件daemon 行为
Hello连接后的第一条消息。校验版本与角色；fcitx 连接更新前端状态 / Mode / Hotkey 并广播 Snapshot；其他角色返回 Snapshot。
Configure客户端角色为 fcitx。更新 Mode / Hotkey；Idle 时立即应用 pipeline 模式，否则等当前段结束；广播 Snapshot。
StartPhase=Idle。分配 segment_id、进入 Recording、启动 pipeline、广播 SegmentStarted 与 State。
StopPhase=Recording。校验 ID（Toggle 例外），请求 pipeline 结束当前段；进入 Finalizing。
ToggleIdle 或 Recording。Idle 时等同 Start；Recording 时等同 Stop；Finalizing 时返回 busy。
ClearHistory任意角色。清空历史，保留当前段 / partial；广播 HistoryCleared。
Status任意角色。返回 Status 快照。
Quit客户端角色为 control。进入关闭流程；其他角色返回 invalid_message。

4.3 服务端广播

消息触发语义
SegmentStartedStart / Toggle 成功，或 Continuous / Toggle 续段。携带最终 segment_id 与来源；前端据此绑定 / 跟随目标。
StatePhase 变化。录音 / 收尾状态；前端更新临时窗口。
Partialpipeline 产生临时结果。可丢弃；只显示，不提交。
Final完整段识别成功。加入历史；前端清空临时文本并提交。
SnapshotHello、配置变化、前端连接 / 断开。全量状态；字段见 voime-ipc USER §4.3。
Error协议、角色、忙碌或推理失败。按 code 处理；不解析文案。
Byedaemon 关闭。客户端清理并等待重连。

项目契约所有者

4.5 错误与恢复

情况行为
模型 / 音频初始化失败启动失败，stderr + 退出码 1；不绑定端点。
端点已被活动 daemon 占用幂等退出（退出码 0）。
单段推理失败广播 Error{code:"inference"}，清空当前段，继续监听。
前端断线前端状态置 disconnected；Continuous 退回 PTT；结束当前段；广播 Snapshot。
慢客户端Final / State 队列满时断开该客户端；Partial 满时丢该条。
pipeline 致命错误daemon 记录并以非零退出；客户端收到 Bye。
