2. CONVENTIONS

↑

约定内容
事件循环daemon 主线程用 crossbeam_channel::select! 同时等待 IPC 事件、pipeline 事件与 FinalizeResult；100 ms 超时用于检查关闭。
客户端线程accept 线程接受连接；每个客户端一个 reader 线程与一个 writer 线程；daemon 主线程只处理事件与状态。
客户端队列每个客户端一个有界发送队列；Final / State 满时移除客户端，Partial 满时只丢该条。
角色表clients: HashMap<u64, ClientEntry> 由互斥锁保护；set_role 只允许一个 Frontend（线协议同时接受 fcitx 别名）。
TUI 调试控制TUI 只在 FrontendState::Disconnected 时发送 Start / Stop / Toggle；frontend 连接期间这些命令返回 busy，TUI 仅观察。
状态机State.phase 只由 daemon 主线程修改；pipeline 事件与客户端命令都在同一线程串行处理。
段 IDnext_segment 单调递增，wrapping 后跳过 0；当前段在 Final / 丢弃后清空。
模式生效Configure 检测到 Mode 变化：Idle 且无活动会话时立即 pipeline.set_mode；否则暂存 pending_mode 并立即 finish_segment，当前段 Final / 丢弃后应用。
模式切换清理应用前无条件清空 pending_stop 与 session_active；current_segment 与 state.partial 由 Final / 丢弃清空；pipeline.set_mode 再清 collecting、resample_pending、frame_audio 与 partial 调度。旧模式的段、临时文本、完成段队列、音频或 Toggle 会话不得带入新模式。
会话状态session_active 由 Start / Toggle 开启，由硬切分、模式切换、目标失焦（前端 Stop）或断线清除；VAD 软切分不清除。Finalizing 期间没有活动会话时，新的 Start 立即开启新会话，旧段 Final 继续在后台队列中执行。
软切分 / 硬切分软切分只结束当前段，后续 Recording(true) 继续分配下一段；硬切分调用 finish_segment 并停止续段。PTT / Toggle 共用该状态机。
Final 后端Config::load 在启动时读取一次 [final].backend；运行期不重新读取，不提供 IPC 热切换。
worker 生命周期只启动选中的 worker；默认 cpu 时 worker = None。spawn → Hello / Ready → 常驻 → Transcribe → Shutdown。
worker 诊断WorkerShared 保存 status / ready / last_error；Finalizer 空闲轮询用 Worker::is_alive 检测进程退出；Daemon::diagnostics 只读该快照，不启动、不重启 worker。
Finalizing 门禁当前段结束（VAD 软切分或会话硬切分）后进入 Finalizing：停止该段 Partial、取消未开始的 Preview，只允许一次 Final；软切分不关闭会话，下一段由 Recording(true) 续段。Final 在独立 Finalizer 线程串行执行，不阻塞新录音；等待队列最多 5 条。
Final 调度SegmentReady 后由 Daemon::finalize 选择 CPU / GPU；GPU 失败当前段回退 CPU；一次只执行一个 Final。
前端断开前端状态置 disconnected；结束会话与当前段；Continuous 退 PTT；广播 Snapshot。
退出顺序Finalizer shutdown → worker shutdown → 广播 Bye → IPC shutdown → pipeline shutdown → audio stop → 删除端点。
传输边界ipc_server.rs 只使用 voime-transport 的 Listener / Stream；daemon 不 import std::os::unix 或 Win32。
GPU 边界daemon 只通过 voime-gpu-common 的帧类型与 io 函数与 worker 通信；不链接 ORT / llama.cpp，不读取 GPU runtime 细节。
运行日志状态机、IPC 生命周期、段事件、worker 状态、GPU 推理耗时 / RTF 与 CPU 回退耗时经 voime_log::vlog! 记录；机制见 voime-log CORE，隐私约定见 voime-log USER §2。
  • 仓库级进程 / 线程边界见 根 CORE §2；用户可见行为见 USER §2。

    pub fn transcribe(&mut self, samples: &[f32])
        -> anyhow::Result<String>;
    pub fn restart(&mut self) -> anyhow::Result<()>;
    pub fn shutdown(mut self);
    pub fn status(&self) -> WorkerStatus;

fn write_request(worker: &mut Worker, request: &Request)
    -> anyhow::Result<()>;

    -> anyhow::Result<Response>;
fn map_error(code: ErrorCode, message: &str) -> anyhow::Error;
  • spawn 使用 voime-gpu-common 的帧格式；worker 的 stdout 只读协议，stderr 转发到 voime-log。
  • 加载超时、握手失败、进程退出都转为“后端不可用”；当前段由 daemon 回退 CPU。
  • 同一 worker 一次只处理一个 Transcribe；daemon 在上一段完成前不发送下一段。
  • Worker::spawn 保存规范化后的模型根；Qwen3 的 Hello.model_dir 固定为 model_root/qwen3-asr-1.7b，即包含 manifest.json 的目录。
  • Worker::handshake 的设备优先级：调用方显式 device > VOIME_GPU_DEVICE > 空串（backend 默认设备）；Qwen 只接受与编译 feature 匹配的设备前缀。
  • daemon 不向 Qwen 传 --runtime / --log-level 或 runtime 专用环境变量；runtime 由 worker 编译 feature 决定，启动日志只走 stderr。
  • ready / last_error 由 Finalizer 线程写入 WorkerShared；Daemon::diagnostics 只读快照。Worker::is_alive 用 Child::try_wait 发现空闲期退出的进程，Finalizer 在 500 ms 空闲轮询时更新状态。

5.1 启动

systemd --user / voime-tray 子进程（Windows）
└── voimed::main()

    ├── voimed::cli::parse()
    ├── voimed::config::load()
    │   └── FinalConfig::load() → backend
    ├── ipc_server::daemon_running(&endpoint)
    │   └── 判断已运行 → ExitCode::SUCCESS
    ├── voimed::run(args)
    │   ├── voime_core::config::resolve(args)
    │   ├── voime_core::infer::session::SessionFactory::new(config.threads)
    │   ├── voime_core::pipeline::spawn() → (Pipeline, Final)
    │   ├── 判断 backend != Cpu → voimed::worker::Worker::spawn(backend, model_root)
    │   │   └── Worker::handshake()
    │   ├── voime_core::audio::capture::start(config.input_device, audio_tx)
    │   │   └── 构建输入流并保持暂停，等待 Daemon::sync_audio_result()
    │   ├── ipc_server::IpcServer::bind(&endpoint)
    │   └── daemon::Daemon::new(config, pipeline, final, audio, ipc, worker, worker_error)?
    │       ├── Finalizer::spawn(backend, final, worker, worker_shared)
    │       └── Daemon::run()
    └── 判断 Err
        ├── eprintln!()
        └── ExitCode::from(1)
  • 默认 backend = Cpu 时 worker = None，不探测 GPU。
  • GPU worker 握手失败只标记不可用，不阻止 daemon 启动；核心模型失败才阻止启动。Finalizer 在空闲轮询时用 Worker::is_alive 检测进程退出，并把 ready / last_error 写入 WorkerShared；Daemon::diagnostics 只读该快照，由 Diagnostics 返回给 doctor。

5.2 连接、Hello、Configure 与角色

IpcServer accept thread
└── voime_transport::Listener::accept()
    └── ipc_server::spawn_client(stream, client_id, clients, events)
        ├── voime_transport::Stream::try_clone()
        ├── std::thread::Builder::spawn(writer loop)
        └── std::thread::Builder::spawn(reader loop)
            ├── read_until(b'\n')
            ├── serde_json::from_slice::<ClientMessage>()
            └── events.send(ServerEvent::Message)

Daemon::run()
└── Daemon::on_server_event(Message { client_id, message })
    └── Daemon::on_client(client_id, Hello { role, version, config })
        ├── 判断 version != PROTOCOL_VERSION → IpcServer::send_to(Error(version_mismatch))
        │   └── IpcServer::disconnect(client_id)
        ├── IpcServer::set_role(client_id, role)
        ├── State::apply_mode(config.mode)
        ├── Daemon::apply_pipeline_mode()
        ├── Daemon::sync_audio_result()
        └── IpcServer::broadcast(Snapshot)

Daemon::on_client(client_id, Configure { mode, hotkey })
├── 判断 role != Frontend → Daemon::send_error(client_id, invalid_message)
├── 判断 state.mode == mode
│   ├── Daemon::broadcast_snapshot()
│   └── return
├── 判断 state.phase == Idle && !session_active
│   ├── State::apply_mode(mode)
│   └── Daemon::apply_pipeline_mode()
└── 判断 state.phase != Idle || session_active
    ├── Pipeline::finish_segment()
    ├── Pipeline::cancel_preview()
    └── Daemon::broadcast_state()
  • Configure 先更新 hotkey 并清除 pending_stop；模式变化时暂存 pending_mode，旧段 Final / 丢弃后应用。状态字段赋值不展开为调用栈节点。
  • finish_segment 交付旧段的 SegmentReady / SegmentDropped；SegmentReady 清空 current_segment 并进入 FinalizeQueue，全部 pending Final 完成且无新录音后回到 Idle，随后 apply_pending_mode 清 session_active 并调用 pipeline.set_mode。
  • 模式切换不等待旧模式的第二次热键，也不把旧段的音频、Partial、Preview、Toggle 会话或空白窗口带入新模式。
  • 没有旧段时 finish_segment 不产生 SegmentReady；daemon 在收尾后立即应用 pending_mode。

5.3 Start 与 SegmentStarted

Daemon::on_client(client_id, Start { segment_id, source })
├── 判断 role == Tui && state.addon == Connected → Daemon::send_error(client_id, busy)
└── Daemon::request_start(client_id, source)
    ├── 判断 session_active || state.phase == Recording → Daemon::send_error(client_id, busy)
    ├── 判断 current_segment.is_some() → awaiting_segments.push_back(current_segment.take())
    └── Daemon::start_session(source)
        ├── CaptureHandle::play()
        ├── Daemon::allocate_segment()
        ├── Pipeline::start_segment()
        ├── IpcServer::broadcast(SegmentStarted { segment_id, source })
        ├── Daemon::broadcast_state()
        └── Daemon::sync_audio()
  • Finalizing 期间的新 Start 立即开启录音，不等待旧段 Final；旧段若尚未交付 SegmentReady，其 ID 先移入 awaiting_segments。
  • 旧段 Final 在 Finalizer 线程中继续执行；它可能晚于新段 SegmentStarted 到达前端。

5.4 会话开始、软切分与硬切分

Daemon::on_client(client_id, Stop { segment_id, source })
├── 判断 role == Tui && state.addon == Connected → Daemon::send_error(client_id, busy)
└── Daemon::request_stop(client_id, segment_id)
    ├── 判断 mode == Continuous
    │   ├── 判断 segment_id != 0 && segment_id != current_segment → Daemon::send_error(client_id, busy)
    │   ├── 判断 current_segment.is_none() → return
    │   ├── Daemon::broadcast_state()
    │   ├── Pipeline::finish_segment()
    │   ├── Pipeline::cancel_preview()
    │   └── Daemon::sync_audio()
    └── 判断 mode == Ptt / Toggle
        ├── 判断 !session_active → return
        ├── 判断 state.phase == Recording
        │   ├── Pipeline::finish_segment()
        │   └── Pipeline::cancel_preview()
        ├── Daemon::broadcast_state()
        ├── 判断 state.phase == Idle → Daemon::apply_pending_mode()
        └── Daemon::sync_audio()

Daemon::on_client(client_id, Toggle { segment_id, source })
├── 判断 role == Tui && state.addon == Connected → Daemon::send_error(client_id, busy)
├── 判断 mode != Ptt / Toggle → Daemon::send_error(client_id, busy)
├── 判断 session_active
│   ├── Daemon::request_stop(...)
│   └── return
└── Daemon::request_start(client_id, source)

pipeline::PipelineEvent::Recording(true)
├── 判断 !listens(mode, session_active) || pending_stop
│   ├── Pipeline::finish_segment()
│   ├── Pipeline::cancel_preview()
│   └── return
├── 判断 current_segment.is_none()
│   ├── Daemon::allocate_segment()
│   └── IpcServer::broadcast(SegmentStarted { segment_id, source })
└── Daemon::broadcast_state()

pipeline::PipelineEvent::SegmentReady(segment)
├── Daemon::take_ready_segment() → awaiting_segments.pop_front() / current_segment.take()
└── Daemon::enqueue_finalize(FinalizeJob { segment_id, segment })
  • 首段 SegmentStarted 使用 Start / Toggle 的 source；续段使用 continuation_source(mode)，PTT 为 Hold、Toggle 为 Toggle、Continuous 为 Continuous。
  • listens(mode, session_active) || state.phase == Finalizing 决定音频播放 / 暂停；Finalizing 保持采集，确保新 Start 立即有声，pipeline 未监听时丢弃这些音频。
  • 硬切分后 session_active = false；pipeline 已排队的下一段 Recording(true) 由 listens / pending_stop 拦下，不再分配段。
  • 旧段 Final 与新段录音完全解耦：SegmentReady 只入队，Finalizer 线程串行执行；队列最多等待 5 条。

5.5 Finalizing 与 Final 调度

Daemon::enqueue_finalize(job)
├── FinalizeQueue::push(job)
│   └── 判断等待数 >= 5 → Daemon::broadcast_dropped(最旧任务, "Final 队列已满")
├── Daemon::start_next_finalize()
│   └── 判断无 inflight → Finalizer::submit(job)
└── Daemon::refresh_finalize_phase()

Finalizer 线程 finalize_loop(job)
├── 判断 backend == Cpu
│   └── voime_core::Final::transcribe(segment.samples)
├── 判断 backend == Qwen3
│   └── voimed::worker::Worker::transcribe(segment.samples)
│       └── 判断失败 → Daemon::fallback_cpu(segment.samples, error)
│           ├── worker.restart()
│           └── voime_core::Final::transcribe(segment.samples)
├── WorkerShared::update(status, ready, error)
└── FinalizeResult → Daemon::on_finalize_result(...)

Daemon::on_finalize_result(result)
├── FinalizeQueue::complete()
├── 判断成功且非空 → state.transcript.push(text)
│   └── IpcServer::broadcast(Final { segment_id, text })
├── 判断空文本 → Daemon::broadcast_dropped(segment_id, "空识别结果")
├── 判断错误 → Daemon::broadcast_dropped(segment_id, "推理失败")
├── Daemon::start_next_finalize()
└── Daemon::refresh_finalize_phase()

Daemon::refresh_finalize_phase()
├── 判断 current_segment.is_some() → state.phase = Recording
├── 判断 finalize.pending() > 0 → state.phase = Finalizing
└── 否则 state.phase = Idle
    ├── 判断 !session_active → Daemon::apply_pending_mode()
    └── Daemon::sync_audio()

voime_core::pipeline::PipelineEvent::SegmentDropped
└── Daemon::take_ready_segment()
    └── Daemon::broadcast_dropped(segment_id, reason)
  • Finalizer 线程一次只执行一条 Final；等待队列上限 5，正常连续说话时通常只有 0–1 条。满时丢弃最旧任务并广播 segment_dropped。
  • Final 与录音解耦：旧段 Final 可能晚于新段 SegmentStarted；平台前端按 segment_id 保留旧目标。
  • GPU Final 路径不调用 Final::transcribe；只有失败回退时调用一次。
  • cpu Final 只执行一次；Finalizing 不产生该段 Partial。
  • broadcast_dropped 只广播 Error{segment_dropped}；前端是否清空临时文本、是否提示用户由前端决定。
  • GPU 错误只记录错误码、后端名与耗时；不记录识别文本。连续失败达到 MAX_RESTARTS 后把 worker 标记为不可用。

5.6 前端断开与模式回退

ipc_server reader loop 退出
└── events.send(ServerEvent::Disconnected { client_id, role })
    └── Daemon::on_server_event(Disconnected)
        ├── 判断 state.mode == Continuous → Pipeline::set_mode(Ptt)
        ├── 判断 current_segment.is_some() → Pipeline::finish_segment()
        │   └── Pipeline::cancel_preview()
        ├── Daemon::sync_audio()
        └── Daemon::broadcast_snapshot()

5.7 退出

Daemon::on_client(Quit)（role=Control）
└── Daemon::request_shutdown()
    └── Daemon::run() 跳出循环
        ├── Finalizer::shutdown()
        │   ├── 停止接收新任务
        │   └── 等待当前 Final 完成并关闭 worker
        ├── IpcServer::broadcast(Bye)
        ├── IpcServer::shutdown()
        │   ├── shutdown.store(true)
        │   ├── Listener::shutdown()
        │   ├── accept_thread.join()
        │   ├── clients.clear()
        │   └── listener.take()
        ├── Pipeline::shutdown()
        └── CaptureHandle::stop()
  • request_shutdown 置位关闭标志；字段赋值不展开为调用栈节点。
  • 先停 Finalizer / worker 再停 pipeline / 音频，确保没有新的 Final 请求进入 worker。
  • 调用栈只列调用与判断；session_active / pending_stop / pending_mode / state.phase / state.addon 等字段赋值见 §2 与 §4.7 / §4.8 的约定。
