2. CONVENTIONS

↑

约定内容
事件循环daemon 主线程用 crossbeam_channel::select! 同时等待 IPC 事件与 pipeline 事件；100 ms 超时用于检查关闭。
客户端线程accept 线程接受连接；每个客户端一个 reader 线程与一个 writer 线程；daemon 主线程只处理事件与状态。
客户端队列每个客户端一个有界发送队列；Final / State 满时移除客户端，Partial 满时只丢该条。
角色表clients: HashMap<u64, ClientEntry> 由互斥锁保护；set_role 只允许一个 Frontend。
模型选择启动时由 voime-core::config 按 models/backend 解析资源包；daemon.rs 只消费 Config，没有模型目录扫描或候选列表。
GPU 自动回退GPU 初始化失败时 build_runtime 改用 CPU SenseVoice 并写回 backend=cpu；运行期 worker 失败由 try_gpu_fallback 替换 Final 路径，保留 SenseVoice 会话、音频与 IPC。
worker 监督worker.rs 负责 spawn / handshake / transcribe / restart / shutdown；超时、崩溃与显存不足按回退策略处理。
状态机State.phase 只由 daemon 主线程修改；pipeline 事件与客户端命令都在同一线程串行处理。
段 IDnext_segment 单调递增，wrapping 后跳过 0；当前段在 Final / 丢弃后清空。
模式生效Idle 时立即 pipeline.set_mode；非 Idle 时暂存到 pending_mode，段结束后应用。
前端断开前端状态置 disconnected；Continuous 退 PTT；结束当前段；广播 Snapshot。
退出顺序广播 Bye → IPC shutdown → worker shutdown → pipeline shutdown → audio stop → 删除端点。
传输边界ipc_server.rs 只使用 voime-transport 的 Listener / Stream；daemon 不 import std::os::unix 或 Win32。
运行日志状态机、IPC 生命周期与段事件经 voime_log::vlog! 记录；机制见 voime-log CORE，隐私约定见 voime-log USER §2。
  • 仓库级进程 / 线程边界见 根 CORE §2；用户可见行为见 USER §2。

4.8 资源包与后端构建 文件树

// Config 由 voime-core::config::resolve 产生：
//   backend: Backend                 cpu / gpu
//   default_pack                     model_root/default
//   firered_pack                     model_root/firered
//   vad_dir / vad_manifest           始终存在
//   sense_voice_dir / manifest       始终存在
//   fire_red: Option<FireRedConfig> 仅 gpu
//   punc: Option<PuncConfig>        仅 gpu

fn build_runtime(config, factory, audio_rx) -> Result<(Config, FinalRuntime, Option<FinalHandle>)>
    ├── build_final(config, factory)
    │   ├── 判断 backend == Cpu → build_cpu_final(...)
    │   └── WorkerBackend::spawn(&config.fire_red.dir, "auto") + handshake
    ├── 判断 GPU 构建失败且 backend == Gpu → build_cpu_final(...) + fallback=true
    ├── 回退时 clone config，设置 backend=Cpu 并清空 fire_red / punc
    └── pipeline::spawn(&runtime_config, factory, backend, audio_rx)

fn build_cpu_final(config, factory) -> Box<dyn FinalBackend>
    └── SenseVoiceBackend::new_with_factory(
            &config.sense_voice_manifest, factory,
            fbank_config(&config.sense_voice_manifest.fbank))

fn prepare_backend(&self, backend) -> Result<PreparedBackend>
    ├── Cpu → build_cpu_final(...) + Builtin
    └── Gpu → config::load_firered_pack(model_root)
              + WorkerBackend::spawn(&fire_red.dir, "auto") + handshake
              + pipeline::load_punc(...) + External

fn switch_backend(&self, backend) -> Result<()>
    ├── prepare_backend(backend)
    ├── Pipeline::replace_final(FinalUpdate { backend, punc, policy, max_segment_ms })
    ├── 替换 worker handle，关闭旧 worker
    └── 更新 config.backend / fire_red / punc

fn request_backend(client_id, backend)
    ├── 判断角色不是 Frontend / Control → InvalidMessage
    ├── 判断 phase != Idle → Busy
    ├── 判断 backend == config.backend → BackendChanged
    ├── switch_backend(backend)
    ├── 成功 → write_backend(model_root/backend) + 广播 BackendChanged / Snapshot
    └── 失败 → Error(Inference)，保留旧后端
  • 没有模型候选列表或 package_id 选择文件；后端设置由 voime-core::config 读写，资源包解析和 manifest 校验也属于 voime-core。
  • fire_red 与 punc 仅在 backend=gpu 时同时为 Some；firered 不完整时 config::resolve 返回错误。
  • 启动失败时的 GPU 回退已在 build_runtime 完成；运行期回退见 §5.9。

        ├── State::apply_mode(config.mode)
        ├── Daemon::apply_pipeline_mode()
        ├── Daemon::sync_audio_result()
        └── IpcServer::broadcast(Snapshot)

5.4 Stop、Toggle 与连续段

Daemon::on_client(client_id, Stop { segment_id, source })
└── Daemon::request_stop(client_id, segment_id)
    ├── 判断 phase != Recording
    │   ├── 判断 mode == Toggle → pending_stop = true
    │   ├── 判断 mode != Continuous → session_active = false
    │   └── Daemon::sync_audio()
    ├── 判断 segment_id != 0 && segment_id != current
    │   └── 判断 mode != Toggle → send Error(busy)
    ├── 判断 mode != Continuous → session_active = false
    ├── Pipeline::finish_segment()
    └── Daemon::sync_audio()

Daemon::on_client(client_id, Toggle { segment_id, source })
├── 判断 phase == Idle → Daemon::request_start(...)
├── 判断 phase == Recording → Daemon::request_stop(...)
└── 判断 phase == Finalizing → send Error(busy)

pipeline::PipelineEvent::Recording(true)
├── 判断 current_segment.is_none() → allocate_segment + broadcast SegmentStarted
├── state.phase = Recording
├── broadcast_state()
└── 判断 pending_stop → Pipeline::finish_segment()

5.5 Pipeline 事件

Daemon::run()
└── Daemon::on_pipeline(event)
    ├── Recording(true) → phase=Recording + broadcast_state
    ├── Recording(false) → phase=Finalizing + broadcast_state
    ├── Partial(text) → state.partial=Some + broadcast Partial
    ├── Final(text) → transcript.push + phase=Idle + broadcast Final + broadcast_state + Daemon::apply_pending_mode()
    ├── SegmentDropped(reason) → phase=Idle + current_segment=None + broadcast Error(inference) + Daemon::apply_pending_mode()
    └── Fatal(error) → fatal=Some + shutdown=true

5.8 启动时后端选择

voimed::run(args)
└── voime_core::config::resolve(args)
    ├── args.backend 或 read_backend(model_root/backend)，缺省 cpu
    ├── VadManifest::load / verify / rebase(model_root/default/vad)
    ├── SenseVoiceManifest::load / verify / rebase(model_root/default/sense-voice)
    ├── 判断 backend == gpu
    │   ├── 是 → load_firered_pack(model_root)
    │   │       ├── 完整 → FireRedManifest + PuncManifest 加载 / 校验 / 重定位
    │   │       └── 缺失 → anyhow::bail!("GPU 后端需要 firered 资源包…")
    │   └── 否 → fire_red = None, punc = None
    └── 返回 Config

daemon::build_runtime(&config, factory, audio_rx)
├── build_final(config, factory)
│   ├── backend == Cpu → build_cpu_final()
│   └── backend == Gpu → WorkerBackend::spawn(&fire_red.dir, "auto")
│                        + WorkerBackend::handshake()
├── 判断 GPU 构建失败 → build_cpu_final() + write_backend(Cpu) + 日志
├── 回退时设置 backend=Cpu 并清空 config.fire_red / config.punc
└── pipeline::spawn(&runtime_config, factory, backend, audio_rx)

5.9 空闲切换后端与 GPU 运行期回退

ClientMessage::SetBackend { backend }
└── Daemon::on_client → Daemon::request_backend
    ├── 判断角色 / phase → InvalidMessage / Busy
    ├── 判断 backend == config.backend → BackendChanged
    ├── Daemon::switch_backend(backend)
    │   ├── Daemon::prepare_backend(backend)
    │   │   ├── Cpu → build_cpu_final
    │   │   └── Gpu → config::load_firered_pack + WorkerBackend::spawn + handshake
    │   │            + pipeline::load_punc
    │   ├── Pipeline::replace_final(FinalUpdate { ... })
    │   ├── 关闭旧 worker
    │   └── 更新 config
    ├── config::write_backend(model_root/backend)
    └── 广播 BackendChanged + Snapshot

WorkerFinal::transcribe(samples)
└── 最多 3 次：
    ├── WorkerBackend::transcribe
    └── 判断失败 → WorkerBackend::restart() → 重试

PipelineEvent::SegmentDropped(reason)
└── Daemon::on_pipeline → Daemon::try_gpu_fallback(reason)
    ├── 判断 gpu_fallback || worker.is_none() → 返回
    ├── 判断 reason 含 "ASR" / "worker" / "推理" → 继续
    ├── 停止并释放 worker
    ├── prepare_backend(Cpu) + Pipeline::replace_final(...)
    └── 成功 → gpu_fallback = true + backend=Cpu
                + write_backend(Cpu) + 广播 BackendChanged
  • 启动回退与运行期回退都只改变 Final；Preview、VAD、IPC 与前端连接保持。
  • 切换与回退都会写 models/backend 并广播新的后端；前端设置页据此同步。
  • 录音 / 识别中拒绝切换；当前段完成后再重试。
