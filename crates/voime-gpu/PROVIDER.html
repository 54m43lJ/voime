1. TERMS

↑

术语定义
ONNX Runtime GPU带 DirectML / MIGraphX / CUDA EP 的 ONNX Runtime；只由 voime-gpu 加载。
Execution Provider（EP）GPU 推理后端；Linux AMD 使用 MIGraphX，Windows AMD 使用 DirectML，NVIDIA 使用 CUDA / TensorRT。
runtime 包按 OS + EP 拆分的 ORT / EP 动态库包；独立目录、版本、SHA 与签名。

metadataONNX 模型自带的键值元数据；decoder 层数、head、KV cache 形状、sos / eos 等从这里读取。
deviceruntime 暴露的 GPU 设备名；auto 由 EP 选择默认设备。

2. CONVENTIONS

↑

约定内容
进程隔离GPU runtime 只进入 voime-gpu；daemon 只映射 CPU ORT，不加载 ROCm / CUDA / DirectML / MIGraphX。
平台顺序Linux AMD MIGraphX 为 P0；Windows DirectML 与 NVIDIA CUDA / TensorRT 为后续独立 runtime 包。
精度v2 只接受 FP16；临时 v1 接受官方 FP16；加载失败直接报错，不回退其他精度。
模型不可变模型目录运行期只读；worker 加载时再次校验 SHA-256、张量与 metadata。
运行时隔离runtime 包不进入模型目录；模型目录不允许自带可执行文件。
错误边界EP / 设备 / 模型错误映射为 worker 错误码；不把底层文案写进前端。

3. DIAGRAMS

↑

3.1 GPU runtime 边界

  • Voime 作为单一参与者；GPU runtime 与 FireRed AED 模型目录是外部 provider。
  • 仅 Final 路径使用这些 provider；Preview、VAD 与 Punc 不在此边界内。

3.2 模型加载与推理边界

  • 启动时校验 manifest、encoder / decoder、tokens 与 metadata；每个 Final 段只重置解码状态。
  • VAD / Punc 不在 worker 内；它们由 daemon 处理。

4.2 AED 张量与 metadata

项目契约
模型FireRedASR2-AED 1.1B；encoder + decoder + tokens；FP16 权重约 2.2 GB；显存预算 4–6 GB；Apache-2.0。
fbank80 bin、25 / 10 ms、povey、normalize_samples=false、high_freq=0、snip_edges=true；不做 LFR。
CMVN80 维；(x - cmvn_mean) * cmvn_inv_stddev。
Encoderx[1,T,80] f32、x_lens[1] i64 → cross_k / cross_v。
Decodertokens、self KV cache、cross K/V、offset → logits + 更新后的 self KV cache。
解码自回归贪心；sos 起步，eos / max_len / max_token_per_second=8 停止。
Metadatanum_decoder_layers、num_head、head_dim、sos、eos、max_len、CMVN；KV cache 形状必须来自 metadata。v1 decoder 图内固定 self KV cache 长度 1024，worker 从 decoder 输入形状检测并使用。
Partialworker 不产生 Partial；Preview 由 daemon 的 SenseVoice 提供。
标点由 daemon 的 firered/punc（FireRedPunc）处理，worker 不加载 Punc。
资源包完整性firered/fire-red-aed 必须与 firered/punc 同时存在；daemon 在 GPU 后端加载时检查，不完整则回退 CPU。

4.3 GPU runtime 与 EP

平台 / 硬件runtime 包EP说明
Linux + AMDvoime-gpu-linux-migraphxMIGraphXROCm 7.2 + MIGraphX；ORT 1.31.0（ort 2.0.0-rc.14 预编译）；P0 第一实现平台。
Windows + AMDvoime-gpu-windows-directmlDirectMLP1；DirectML 已进入 sustained engineering，新功能转向 WinML。
Linux + NVIDIAvoime-gpu-linux-cudaCUDA / TensorRTP1；独立 runtime 包，不带 AMD 依赖。
Windows + NVIDIAvoime-gpu-windows-cudaCUDA / TensorRTP2；独立 runtime 包。
无 GPU / driver 不匹配——不启动 worker；Final 使用 CPU SenseVoice。
  • 每个 bundle 带本环境的静态 ORT 与同目录 provider 动态库；worker、ORT 与 provider 必须同版本，安装需显式 opt-in。
  • worker 使用自己的静态 ORT，provider 从 worker 同目录加载；不继承 daemon 的 CPU ORT 路径。ROCm / CUDA / DirectML 仍是系统依赖。

4.4 错误与失败策略

错误触发条件处理
RuntimeMissingruntime 目录缺失、版本不匹配或动态库加载失败。worker 退出；daemon 标记 GPU 后端不可用；最终回退 CPU。
DeviceUnavailable无 GPU、驱动不匹配、显存不足。worker 退出；不加载 CPU AED；Preview 继续。
LoadFailedencoder / decoder / metadata / SHA 校验失败。worker 不进入 Ready；daemon 回退 CPU SenseVoice。
InferenceFailed运行期推理失败。当前段丢弃；daemon 重启 worker；连续失败回退 CPU。
Timeouthandshake / transcribe 超预算。daemon 杀 worker；按崩溃路径重建。
ProtocolMismatchworker / daemon 协议版本不一致。拒绝加载；提示升级 runtime 或 daemon。
