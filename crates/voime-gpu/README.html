1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

FireRed AED 是 1.1B 的 GPU 模型，不能放进只加载 CPU ORT 的 voimed。 如果直接在主进程注册 GPU EP，ROCm / CUDA / DirectML 会被迫进入 CPU 路径， GPU 崩溃也会带崩 SenseVoice Preview。Voime 把 GPU Final 隔离为独立的 voime-gpu 进程：daemon 保留 SenseVoice、VAD、标点与 IPC，只把完整语音段 交给 worker；worker 只加载 FireRed AED FP16 并返回文本。

1.2 GOAL：什么算成功

  • CPU daemon 不加载任何 GPU 库；只有 fire-red-aed 与 punc 两个目录都存在且 GPU 初始化成功时才启动 voime-gpu。
  • worker 与 daemon 使用独立协议；GPU 崩溃、超时或显存不足不会中断 SenseVoice Preview。
  • GPU 只做 Final，不产生 Partial；所有 Partial 由常驻 SenseVoice 提供。
  • FireRed AED 只接受 FP16；加载失败直接报错，不回退 FP32 或 int8。
  • Linux AMD MIGraphX 为第一平台；Windows DirectML 与 NVIDIA CUDA / TensorRT 使用独立 runtime 包。

1.3 非目标

  • 不做 VAD、分段、Preview、标点、CPU ASR 或前端 IPC。
  • 不做 CPU 推理；不把 SenseVoice 搬进 worker。
  • 不引入第二推理引擎、Python 运行时或云端 API；只使用 ONNX Runtime。
  • 不在 worker 内保存音频、历史或模型缓存；不联网。
  • 不通过重复运行非流式 AED 伪造 Partial。

2. 用户交互

↑

voime-gpu 没有终端用户界面；它的“用户”是 voimed 与打包 / 诊断脚本。 调用方通过 USER 的协议启动、请求、取消与关闭 worker。

调用方交互契约
voimedspawn、Hello / Ready、Transcribe、Cancel、Shutdown；接收 Result / Error。USER §4.2 · voimed CORE §4.7
voime doctor检查固定模型目录配对、voime-gpu 可执行文件与 GPU runtime；不通过 IPC 查询模型列表。voime USER §4.4
