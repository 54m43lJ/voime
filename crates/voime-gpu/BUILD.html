1. 环境

↑

项目要求
Ruststable ≥ 1.92（ort 2.0.0-rc.14 的 MSRV）；与 daemon 同 workspace，但作为独立二进制构建。
Arch Linux AMDmigraphx（包含 ROCm / MIGraphX 运行库）；ort 自带 libonnxruntime_providers_migraphx.so，不需要 onnxruntime-rocm。P0 验收平台 RX 9070 XT 16 GB。见根 BUILD §1.1。
Arch Linux NVIDIAcuda + cudnn（Arch 当前 CUDA 13.x / cuDNN 9.x）；ort 自带 cuda13 provider，不需要 onnxruntime-cuda。P1 / P2。见根 BUILD §1.1。
Windows AMDDirectML；ort 的 Windows 预编译包自带 DirectML provider。旧系统安装 Microsoft.AI.DirectML。见根 BUILD §1.1。P1。
Windows NVIDIANVIDIA 驱动 + CUDA 13 + cuDNN 9；ort 的 Windows 预编译包自带 CUDA provider。见根 BUILD §1.1。P1 / P2。
模型firered/fire-red-aed 的 FP16 encoder / decoder / tokens；firered/punc 由 daemon 加载。编译不需要权重。
隔离GPU feature 只在本二进制启用；daemon 构建不得打开 directml / migraphx / cuda feature。

2. 构建

↑

# Linux AMD MIGraphX：静态 ONNX Runtime + 同目录 MIGraphX provider
cargo build --release -p voime-gpu --features migraphx

# Linux NVIDIA CUDA：静态 ONNX Runtime + 同目录 CUDA provider
cargo build --release -p voime-gpu --features cuda

# Windows AMD 示例
cargo build --release -p voime-gpu --features directml
产物说明
target/release/voime-gpu独立 GPU 后端 worker；静态链接 ONNX Runtime，约 33 MB。
target/release/libonnxruntime_providers_*.so由 copy-dylibs 生成的 provider 动态库；必须与 worker 同目录。
voime-gpu.exeWindows 产物；由托盘 / daemon 以子进程托管。
runtime 包voime-gpu-linux-migraphx / voime-gpu-windows-directml / voime-gpu-linux-cuda / voime-gpu-windows-cuda；bundle = worker + provider。
  • 基础安装不包含本二进制或 runtime；只有 firered 档 / 显式 opt-in 才安装。
  • 静态 ORT 与 provider 来自同一 ort 预编译包；不要把不同版本的 provider 放到 worker 目录。
  • 不要把 GPU runtime 放入模型目录；模型目录不允许自带可执行文件。

3. 运行与安装

↑

# 安装 FireRed AED + Punc（同时保留 VAD + SenseVoice）
scripts/install_models.sh --gpu --punc-source-dir /path/to/fireredpunc

# Linux AMD runtime；构建自包含 voime-gpu（静态 ORT + provider 同目录）
scripts/install_runtime.sh --runtime linux-migraphx

# Windows AMD runtime
powershell -ExecutionPolicy Bypass -File scripts\install_runtime.ps1 -Runtime windows-directml -Archive D:\voime-gpu-windows-directml.zip
操作契约
安装Arch Linux 先安装 migraphx 或 cuda + cudnn（见根 BUILD §1.1），再由 scripts/install_runtime.sh 构建并安装自包含 worker + provider；Windows 由 install_runtime.ps1 安装 archive 或 URL。
启动由 voimed spawn；用户不直接运行 worker，排障时可手动启动。
停止daemon 发送 Shutdown；5 s 超时后强杀；Windows Job Object / Linux 进程组确保无孤儿。
诊断voime doctor 显示 firered 资源包、后端设置、VOIME_GPU_BIN、provider 目录、driver 与 VRAM。
卸载删除 ~/.local/lib/voime-gpu/<runtime> 与 ~/.local/bin/voime-gpu 符号链接；模型目录按需保留。

4. 测试

↑

cargo test -p voime-gpu
cargo clippy -p voime-gpu --all-targets
cargo fmt -p voime-gpu --check
测试覆盖
协议帧长度、截断、协议版本、Hello / Ready、Transcribe / Result、Cancel、Shutdown。
模型FP16 encoder / decoder、metadata、KV cache 形状、tokens、SHA；FP16 不可用直接失败。
生命周期spawn / handshake / 超时 / 崩溃重启 / 显存不足 / shutdown 无孤儿。
隔离worker 不加载 CPU 模型；daemon 不加载 GPU 库；移除 runtime 后 CPU 后端仍可用。
性能首次加载、RTF、p95 收尾延迟、峰值 VRAM；目标机器冻结。

5. 升级 / 卸载

↑

操作步骤
升级 worker停止 daemon；重新运行 install_runtime.sh 替换整个 bundle（worker + provider）；启动 daemon 重新尝试 GPU 后端；失败时回退 CPU SenseVoice。
升级 runtime升级 ort 后重新构建并替换 bundle；worker、ORT 与 provider 必须同版本；不改变模型目录。
卸载删除 worker bundle 与符号链接；保留 default/；删除或保留 firered/；后端设置缺失时按 CPU 启动。
迁移旧 GPU 包 / 旧 schema 直接拒绝；不建立运行期兼容层。
