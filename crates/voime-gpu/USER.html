本文定义 voime-gpu 对 daemon 暴露的协议与生命周期。模型张量、GPU runtime 与 ONNX Runtime EP 的契约见 PROVIDER；进程监督与回退见 voimed USER §3.4。

1. TERMS

↑

术语定义
workervoime-gpu 进程；只处理 GPU Final，不处理 Partial、VAD 或标点。
协议（protocol）worker 与 daemon 之间的独立帧协议；与前端 IPC 的 PROTOCOL_VERSION 无关。
frameu32 header_len + UTF-8 JSON 头 + u32 audio_len + little-endian f32 PCM。
handshakedaemon 启动 worker 后发送 Hello，worker 加载模型并返回 Ready。
Final 段daemon 已切分完成的完整语音段；worker 不接收逐帧音频。
FP16GPU 产品路径唯一精度；int8 只用于 CPU SenseVoice。
runtime 包按 OS + EP 拆分的 ORT / EP 动态库包；不进入模型目录。

2. CONVENTIONS

↑

约定内容
GPU-onlyworker 只创建 GPU ORT 会话；不加载 SenseVoice、VAD、FireRedPunc 或 CPU 模型。
Final-only只接收完整语音段；不产生 Partial，不缓存跨段状态。
单请求同一时刻只处理一个 Transcribe；新请求在忙时返回 Error{InferenceFailed}。
FP16encoder / decoder 只接受 fp16；加载失败不回退 FP32 / int8。
无持久化不写音频、识别文本、模型缓存或日志到磁盘；日志走 stderr。
stdout只用于协议帧；诊断输出走 stderr，由 daemon 转发到 voime-log。
隐私协议只回传文本与耗时；daemon 记录长度、耗时与错误码，不记录文本。
资源上限单帧音频上限 64 MiB；超限、截断或长度不匹配都是协议错误。

3. DIAGRAMS

↑

3.1 worker 生命周期

  • CPU Final 不启动 worker；GPU Final 才 spawn / handshake。
  • worker 崩溃、超时或显存不足时由 daemon 重启或回退 CPU SenseVoice。

3.2 worker 协议

  • 控制消息是 JSON，音频是原始 little-endian f32 PCM；不使用 base64。
  • Hello 与 Ready 校验协议版本、模型 manifest、device 与能力。

4. INTERFACES

↑

4.1 命令行与环境

voime-gpu --manifest <DIR> --device <auto|DEVICE> [--verbose]
选项 / 环境契约
--manifestFireRed AED 包目录；必须包含 manifest.json、encoder / decoder / tokens / punc。
--deviceauto 或 runtime 支持的设备名；只影响 GPU EP。
--verbose诊断输出到 stderr；stdout 仍只用于协议。
VOIME_LOG由 daemon 传入；worker 只写 stderr，由 daemon 统一落盘；不记录识别文本。
ORT_DYLIB_PATHworker 自己设置 GPU ORT 路径；不继承 daemon 的 CPU ORT 路径。

4.2 协议

Frame
├── u32 header_len
├── header: UTF-8 JSON
├── u32 audio_len
└── audio: f32le mono, 16 kHz, [-1, 1]

Request
├── Hello { protocol, manifest, device }
├── Transcribe { id, sample_rate, language, use_itn }
├── Cancel { id }
└── Shutdown

Response
├── Ready { protocol, backend, provider, device, vram_mb, supports_partial }
├── Result { id, text, latency_ms, rtf }
├── Error { id, code, message }
└── Bye
消息方向语义
Hellodaemon → worker声明协议版本、manifest 路径与 device；worker 校验后加载模型。
Readyworker → daemon模型 / EP / 设备就绪；supports_partial=false 只描述 FireRed Final。
Transcribedaemon → worker发送一个完整 Final 段的 PCM；id 用于匹配 Result / Error。
Resultworker → daemon纯文本、耗时与 RTF；不含 Partial，不做标点。
Canceldaemon → worker取消当前请求；worker 尽快返回 Error{Timeout} 或丢弃结果。
Shutdown / Byedaemon → worker / worker → daemon正常关闭；daemon 等待 5 s，超时强杀。

4.3 错误码

错误码含义daemon 动作
RuntimeMissingGPU runtime 未安装 / 版本不匹配。标记 GPU Final 不可用；Preview / CPU Final 继续；提示安装 runtime。
DeviceUnavailable无 GPU、驱动不匹配、显存不足。worker 不可用；Final 回退 CPU SenseVoice；不加载 AED CPU。
LoadFailed模型 / EP / 张量校验失败。回滚 active；Preview / CPU Final 继续。
InferenceFailed运行期推理失败。当前段丢弃；重启 worker；连续失败标记不可用。
Timeout超过请求预算。杀 worker；按崩溃路径处理。
ProtocolMismatchworker / daemon 协议版本不一致。拒绝加载；提示升级 runtime 或 daemon。

4.4 超时与重启

阶段默认预算失败处理
spawn无法执行 / 退出码非零BackendFailed；Final 回退 CPU。
handshake120 s杀 worker；重试或回退 CPU。
transcribe60 s杀 worker 并重建；当前段丢弃。
health2 s连续失败进入重启；不阻塞录音。
shutdown5 sWindows Job Object / Linux 进程组强杀，确保无孤儿。
  • worker 崩溃退避 1 s / 2 s / 5 s，最多 3 次；仍失败则 Final 回退 CPU SenseVoice 或报错，Preview 继续。
  • CPU Final 不启动 worker；GPU Final 才付出进程与显存成本。
