1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

daemon 在后台运行，用户与运维仍需要一个轻量的观察与控制入口：查看当前模式、热键、 临时结果与历史，手动开始 / 停止，清空历史，检查模型 / 音频 / 前端是否正常。 voime 提供终端 UI（TUI）、一次性控制客户端（ctl）与只读诊断 （doctor）；它不持有音频、模型或键盘，只通过本机 IPC 连接 daemon。

1.2 GOAL：什么算成功

  • TUI 可连接 daemon，显示模式、热键、临时结果与历史；关闭 TUI 不影响热键、临时窗口与上屏。
  • voime ctl 可在脚本中执行 start / stop / toggle / status / clear / quit。
  • voime doctor 用只读检查定位端点、daemon、两个资源包、后端设置、GPU runtime、音频与平台前端问题。
  • 没有 TTY 时 TUI 明确失败；daemon 与 ctl / doctor 不使用 TUI。
  • 客户端不加载模型、不解析音频、不处理热键。

1.3 非目标

  • 不实现平台输入集成；Linux 见 fcitx-addon，Windows 见 windows。
  • 不实现 daemon 会话或识别；这些属于 voimed。
  • 不保存历史到磁盘；TUI 退出后从 daemon 快照恢复。
  • 不提供图形设置界面；配置由平台前端或 Fcitx configtool 负责。

2. 用户交互

↑

入口行为契约
voime进入 TUI，显示历史、当前临时行与底部提示；q / Ctrl+C 只 detach。USER §4.2 · USER §5
voime ctl start|stop|toggle发送一次控制命令并打印结果状态。USER §4.3
voime ctl status打印 recording / finalizing / segment / mode / hotkey / addon / transcript 计数。USER §4.3
voime ctl clear清空 daemon 历史，保留当前段。voimed USER §4.2
voime ctl quit停止 daemon；TUI / 前端不受影响（随后断线）。voimed USER §4.5
voime doctor只读检查端点、daemon、两个资源包、后端设置、GPU runtime、音频与前端；不修改状态。USER §4.4
