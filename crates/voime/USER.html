本文定义 voime 的命令行、TUI 行为与界面。协议消息形状见 voime-ipc USER；daemon 状态语义见 voimed USER。

1. TERMS

↑

术语定义
TUIvoime 无子命令时进入的终端监视器；只读展示并发送控制命令。
ctl一次性控制客户端；执行一个动作并退出。
doctor只读诊断命令；检查端点、daemon、模型、音频与平台前端。
detach退出 TUI 但不停止 daemon；q / Ctrl+C 的行为。
临时行TUI 中显示当前 Partial 的行；不是最终历史。
历史行已收到的 Final 文本；保存在 daemon 内存，TUI 重连后恢复。
跟随（follow）视图自动滚动到最新一行；用户上翻后停止，End 恢复。
viewport去掉底部提示行后的内容区域高度，用于翻页步长。
提示行底部一行显示 Mode / Hotkey / 快捷键；不属于识别内容。

2. CONVENTIONS

↑

约定内容
detach 语义q（无修饰键）与 Ctrl+C 只退出 TUI；daemon、前端、热键与临时窗口继续工作。
停止 daemon只使用 voime ctl quit 或平台服务管理，不用 TUI 退出键。
清空历史Ctrl+X 发送 ClearHistory；不清空当前段与 partial。
手动录音Space 在非 finalizing 时发送 Start；recording 时发送 Stop；来源为 tui。
滚动PageUp / PageDown / Home / End；上翻停止跟随，End 恢复。
内容清洗Final / Partial 中的 \r / \n 替换为空格并 trim；空文本不进入历史。
断线daemon 断开时 TUI 以错误退出（退出码 1）；Bye 视为正常 detach。
doctor 只读不启动/停止 daemon，不修改配置；只报告 OK / WARN / FAIL。
无持久化TUI 不写历史文件；退出后历史只存在于 daemon 内存。

3. DIAGRAMS

↑

3.1 ctl 命令流

  • ctl 以 control 角色连接，先读取 Snapshot，再发送命令。
  • 每个动作等待对应响应或超时；错误以 stderr + 退出码 1 返回。
  • TUI 使用同一 Client，但以 tui 角色连接。

4. INTERFACES

↑

4.1 命令行

voime [--socket <PATH>]
voime ctl <start|stop|toggle|status|clear|quit> [--socket <PATH>]
voime doctor [--socket <PATH>]
命令 / 选项契约
voime进入 TUI；stdin 与 stdout 必须是 TTY。
voime ctl start发送 Start { segment_id: 0, source: Cli }；等待 State 或 Error。
voime ctl stop发送 Stop { segment_id: 0, source: Cli }。
voime ctl toggle发送 Toggle { segment_id: 0, source: Cli }。
voime ctl status发送 Status；打印一行状态。
voime ctl clear发送 ClearHistory；等待 HistoryCleared。
voime ctl quit发送 Quit；等待 Bye。
voime doctor只读检查；退出码 0 表示全部通过，1 表示存在 FAIL。
--socket全局选项；P0 后改为 --endpoint。
退出码含义
0命令成功 / doctor 全部通过。
1连接失败、daemon 错误、超时、TUI 不可用或 doctor 存在 FAIL。
2命令行参数非法（clap）。

4.2 TUI 按键

按键行为
qdetach；不停止 daemon。
Ctrl+Cdetach；不停止 daemon。
Ctrl+X发送 ClearHistory。
Spacerecording 时发送 Stop；否则在非 finalizing 时发送 Start。
PageUp向上翻一页；停止跟随。
PageDown向下翻一页。
Home跳到顶部；停止跟随。
End跳到最新；恢复跟随。

4.3 ctl 输出

# start / stop / toggle
recording=true finalizing=false segment=Some(3)

# status
recording=false finalizing=false segment=None mode=ptt hotkey=Super+F2 addon=Connected transcript=2

# clear
history cleared

# quit
voimed stopped
输出契约
start / stop / toggle打印 State 的 recording / finalizing / segment；Error 走 stderr。
statusStatus 的所有字段；未知 mode / hotkey 显示 -。
clear / quit成功标记；Error 或 Bye 走 stderr / 退出码 1。
超时超时时间内没有响应则报错退出；具体值见 CORE §2。

4.4 doctor 检查

socket: /run/user/1000/voime/voimed.sock
  OK   权限 0600
  OK   daemon 在线
model: /home/user/.local/share/voime/models
  OK   manifest 与 SHA-256 校验通过
audio:
  OK   2 个输入设备，默认 ...
fcitx:
  OK   fcitx5 进程运行中
  OK   addon 描述 /usr/share/fcitx5/addon/voime.conf
  OK   voime.so /usr/lib/fcitx5/voime.so
  OK   未注册输入法条目（Shift 不会切换到 Voime）
  OK   用户配置 /home/user/.config/fcitx5/conf/voime.conf
  OK   Mode=ptt Hotkey=Super+F2 addon=connected
检查契约
端点检查默认路径 / --socket 指定路径；Unix 上检查权限是否 0600。
daemon以 control 角色连接并读取 Snapshot。
模型固定检查默认模型目录；不读取 --model-dir。
音频枚举输入设备并显示默认设备名；不打开流。
平台前端当前 Linux 检查 fcitx5 进程、addon 描述、voime.so、旧 inputmethod 条目与用户配置。
输出每项 OK / WARN / FAIL；存在 FAIL 时退出码 1。
  • doctor 当前是 Linux 实现；Windows 前端落地后按 windows USER §4.4 增加平台检查。
  • 自定义前缀或 --model-dir 部署需要手工确认；doctor 固定检查默认路径。

5. UI

↑

5.1 调色板

TUI 只使用终端自身的背景色与前景色，另加一个红色语义色。不得引入边框色、强调底色、状态色或第二强调色； 终端的主题切换不需要应用适配。

预览Token值语义
recording ANSI bright red（SGR 91）；真彩色终端回退 #E5484D 仅用于 recording 标记的圆点。
background 终端默认背景 整个界面背景；应用不设置背景色。
text 终端默认前景 临时结果、最终结果与提示文本。

5.2 视觉呈现

项目契约
屏幕TUI 可选；进入备用屏幕并隐藏光标，退出时恢复。Fcitx / Windows 临时窗口不受 TUI 控制。
布局两列：左侧 2 个单元格的标记栏，右侧内容列；无边框、标题或状态栏。
Recording 标记●，仅当前语音段采集时显示；Final / 停止后隐藏。
内容临时结果覆盖当前行；最终结果原位替换并保留到退出；下一段另起一行。
提示行底部一行显示当前 Mode 与 Hotkey，例如 Mode: ptt Hotkey: Super+F2 Ctrl+X 清空 q 退出。
滚动PageUp / PageDown / Home / End；用户上翻后停止跟随。
错误启动错误 stderr；运行期错误不进入 TUI 内容区，写日志 / voime doctor。

5.3 原型

原型只示意 TUI 的元素关系；Fcitx / Windows 临时文本窗口由平台前端渲染，不在 TUI 中绘制。

今天下午三点开会。
请把会议纪要发给我。
● 明天的日程帮我确认一
Mode: ptt Hotkey: Super+F2 Ctrl+X 清空 q 退出
  • 前三行是历史结果与当前临时行；底部提示行不属于结果内容。
  • 平台输入面板同时显示当前 Partial 的临时窗口；Final 后按平台规则关闭或保留空白。
  • TUI 关闭后热键、临时窗口与提交继续工作。
