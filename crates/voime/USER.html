USER — voime

根：README USER CORE PROVIDER ｜ 本组件：README CORE PROVIDER

本文定义 voime 的命令行、TUI 行为与界面。协议消息形状见 voime-ipc USER；daemon 状态与 Final 调度见 voimed USER。

1. TERMS

↑

术语定义
TUIvoime 无子命令时进入的终端调试工具；只读展示 daemon 状态与历史；没有 frontend 连接时可发送调试会话命令，不能操作输入法。
ctl一次性控制客户端；执行一个动作并退出。
doctor只读诊断命令；检查端点、daemon、模型、音频、平台前端、Final 后端与 worker 状态。
Final 后端配置~/.config/voime/config.toml 的 [final].backend；ctl backend 负责写入，daemon 启动时读取。
worker ready / runningdaemon 通过只读 Diagnostics 查询返回的当前 GPU worker 状态；doctor 只读，不启动、不重启 worker，也不依赖日志。
detach退出 TUI 但不停止 daemon；q / Ctrl+C 的行为。
临时行TUI 中显示当前 Partial 的行；不是最终历史。
历史行已收到的 Final 文本；保存在 daemon 内存，TUI 重连后恢复。
跟随（follow）视图自动滚动到最新一行；用户上翻后停止，End 恢复。
viewport去掉底部提示行后的内容区域高度，用于翻页步长。
提示行底部一行显示 Mode / Hotkey / 快捷键；不属于识别内容。

2. CONVENTIONS

↑

约定内容
detach 语义q（无修饰键）与 Ctrl+C 只退出 TUI；daemon、前端、热键与临时窗口继续工作。
停止 daemon只使用 voime ctl quit 或平台服务管理，不用 TUI 退出键。
清空历史Ctrl+X 发送 ClearHistory；不清空当前段与 partial。
调试会话控制仅在 addon=disconnected 时，Space 在 ptt / toggle 下发送 Toggle，continuous 下 recording 时发送 Stop、否则发送 Start；来源为 tui。前端连接期间 TUI 只观察，不发送会话命令。
滚动PageUp / PageDown / Home / End；上翻停止跟随，End 恢复。
内容清洗Final / Partial 中的 \r / \n 替换为空格并 trim；空文本不进入历史。
断线daemon 断开时 TUI 以错误退出（退出码 1）；Bye 视为正常 detach。
backend 只写配置voime ctl backend 只写配置文件，不连接 daemon、不发送 IPC、不触发热切换；提示用户重启 daemon。
默认 CPU配置缺失时显示 / 保持 cpu；写入 GPU 后端必须先安装对应模块，但安装脚本不自动切换。
doctor 只读不启动 / 停止 daemon，不修改配置，不启动 worker，不打开音频流；只报告 OK / WARN / FAIL。
worker 状态来源doctor 读取配置、worker 可执行文件 / 模型目录，并向 daemon 发送只读 Diagnostics；Status 与 Snapshot 形状保持不变，不读日志。
无持久化TUI 不写历史文件；退出后历史只存在于 daemon 内存。只有 ctl backend 写配置文件。

3. DIAGRAMS

↑

3.1 ctl 命令流

  • ctl 以 control 角色连接，先读取 Snapshot，再发送命令。
  • backend 是唯一不连接 daemon 的动作：只写配置文件并提示重启。
  • 每个动作等待对应响应或超时；错误以 stderr + 退出码 1 返回。
  • TUI 使用同一 Client，但以 tui 角色连接。

4. INTERFACES

↑

4.1 命令行

voime [--endpoint <ENDPOINT>]
voime ctl <start|stop|toggle|status|clear|quit> [--endpoint <ENDPOINT>]
voime ctl backend <cpu|qwen3>
voime doctor [--endpoint <ENDPOINT>]
命令 / 选项契约
voime进入调试 TUI；stdin 与 stdout 必须是 TTY；不操作输入法、不提交文本。
voime ctl start发送 Start { segment_id: 0, source: Cli }；PTT / Toggle 下开启会话并持续到 stop，Continuous 下开始手动段；等待 State 或 Error。
voime ctl stop发送 Stop { segment_id: 0, source: Cli }；PTT / Toggle 下硬切分会话，Continuous 下停止当前段。
voime ctl toggle发送 Toggle { segment_id: 0, source: Cli }，按当前会话状态开启或硬切分。
voime ctl status发送 Status；打印一行状态；不显示 Final 后端。
voime ctl clear发送 ClearHistory；等待 HistoryCleared。
voime ctl quit发送 Quit；等待 Bye。
voime ctl backend <id>原子写入 [final].backend；不连接 daemon；即使全局解析到 --endpoint 也会拒绝并以退出码 2 结束；输出重启提示；非法值退出码 2。
voime doctor只读检查；退出码 0 表示全部通过，1 表示存在 FAIL。
--endpoint全局选项；Unix 为 socket 路径，Windows 为命名管道名；同时接受 --socket 别名。ctl backend 不使用该选项；出现时按上述规则拒绝。
退出码含义
0命令成功 / doctor 全部通过。
1连接失败、daemon 错误、超时、配置文件写入失败、TUI 不可用或 doctor 存在 FAIL。
2命令行参数非法（clap），包括非法 backend 值。

4.2 TUI 按键

按键行为
qdetach；不停止 daemon。
Ctrl+Cdetach；不停止 daemon。
Ctrl+X发送 ClearHistory。
Space仅在没有 frontend 连接时用于调试 daemon 会话：ptt / toggle 发送 Toggle；continuous 在 recording 时 Stop、否则 Start。前端连接期间 TUI 只观察，按键不发送命令；不绑定输入目标、不提交文本。
PageUp向上翻一页；停止跟随。
PageDown向下翻一页。
Home跳到顶部；停止跟随。
End跳到最新；恢复跟随。
  • TUI 不提供 backend 切换、worker 状态或 GPU 配置；这些只在 ctl backend / doctor。
  • TUI 是调试工具，不绑定输入目标、不提交文本；平台输入仍由 Fcitx / Windows 前端处理。

4.3 ctl 输出

# start / stop / toggle
recording=true finalizing=false segment=Some(3)

# status
recording=false finalizing=false segment=None mode=ptt hotkey=Super+F2 addon=Connected transcript=2

# clear
history cleared

# quit
voimed stopped

# backend
final.backend = qwen3
restart voimed to apply
输出契约
start / stop / toggle打印 State 的 recording / finalizing / segment；Error 走 stderr。
statusStatus 的所有字段；未知 mode / hotkey 显示 -；不新增 backend 字段。
clear / quit成功标记；Error 或 Bye 走 stderr / 退出码 1。
backend打印写入值与重启提示；不声称已生效；写入失败退出码 1。
超时超时时间内没有响应则报错退出；具体值见 CORE §2。

  OK   2 个输入设备，默认 ...

  OK   VOIME_LOG 已设置，daemon 与托盘将写入 ~/.local/state/voime/logs

  OK   fcitx5 进程运行中
  OK   addon 描述 /usr/share/fcitx5/addon/voime.conf
  OK   voime.so /usr/lib/fcitx5/voime.so

  OK   用户配置 /home/user/.config/fcitx5/conf/voime.conf
  OK   Mode=ptt Hotkey=Super+F2 addon=connected
检查契约
端点检查默认端点 / --endpoint 指定端点；Unix 上检查权限是否 0600。
daemon以 control 角色连接并读取 Snapshot。
Final 后端读取 ~/.config/voime/config.toml（Windows 为 %APPDATA%\voime\config.toml），显示 cpu / qwen3 的选择结果；不修改配置。
worker分别检查 CPU / Qwen 的可用性、worker 可执行文件与模型目录；对已选择的后端通过 daemon Diagnostics 读取 ready / running / unavailable 与 runtime / device / 错误原因；未选择的后端不要求运行，不计为 FAIL。
模型固定检查默认模型根目录的核心模型 manifest 与 SHA-256；已安装的 GPU 模型只校验 manifest，不加载权重。
音频枚举输入设备并显示默认设备名；不打开流。
日志报告 VOIME_LOG 启用状态与日志文件位置；未启用时给出默认目录，不计为 FAIL。
平台前端（Linux）检查 fcitx5 进程、系统 addon 描述、voime.so 与系统 ABI、用户配置；不检查inputmethod 条目；不检查 FCITX_ADDON_DIRS。
平台前端（Windows）检查命名管道、麦克风隐私、输入设备、voime-tray.exe 进程、模型与 TSF 注册（若启用）。
输出每项 OK / WARN / FAIL；存在 FAIL 时退出码 1。
  • doctor 在 Linux 与 Windows 均可用；示例输出是 Linux，Windows 将 fcitx 段替换为命名管道、麦克风隐私与前端进程检查。
  • 自定义前缀或 --model-dir 部署需要手工确认；doctor 固定检查默认路径。
  • worker 状态只来自 daemon 的只读 Diagnostics 响应；daemon 离线或旧 daemon 不支持该消息时，doctor 只报告无法读取状态，不读取日志、不触发 worker 启动或模型加载。

5. UI

↑

5.1 调色板

TUI 只使用终端自身的背景色与前景色，另加一个红色语义色。不得引入边框色、强调底色、状态色或第二强调色； 终端的主题切换不需要应用适配。

预览Token值语义
recording ANSI bright red（SGR 91）；真彩色终端回退 #E5484D 仅用于 recording 标记的圆点。
background 终端默认背景 整个界面背景；应用不设置背景色。
text 终端默认前景 临时结果、最终结果与提示文本。

5.2 视觉呈现

项目契约
屏幕TUI 可选；进入备用屏幕并隐藏光标，退出时恢复。Fcitx / Windows 临时窗口不受 TUI 控制。
布局两列：左侧 2 个单元格的标记栏，右侧内容列；无边框、标题或状态栏。
Recording 标记●，仅当前语音段采集时显示；Final / 停止后隐藏。
内容临时结果覆盖当前行；最终结果原位替换并保留到退出；下一段另起一行。
提示行底部一行显示当前 Mode 与 Hotkey，例如 Mode: ptt Hotkey: Super+F2 Ctrl+X 清空 q 退出。
滚动PageUp / PageDown / Home / End；用户上翻后停止跟随。
错误启动错误 stderr；运行期错误不进入 TUI 内容区，写日志 / voime doctor。

5.3 原型

原型只示意 TUI 的元素关系；Fcitx / Windows 临时文本窗口由平台前端渲染，不在 TUI 中绘制。

今天下午三点开会。
请把会议纪要发给我。
● 明天的日程帮我确认一
Mode: ptt Hotkey: Super+F2 Ctrl+X 清空 q 退出
  • 前三行是历史结果与当前临时行；底部提示行不属于结果内容。
  • 平台输入面板同时显示当前 Partial 的临时窗口；Final 后按平台规则关闭或保留空白。
  • TUI 关闭后热键、临时窗口与提交继续工作。
