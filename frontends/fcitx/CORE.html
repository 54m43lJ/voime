2. CONVENTIONS

↑

约定内容
系统 addon 路径addon 库写入 Fcitx5 系统 addon 目录，例如 /usr/lib/fcitx5/voime.so；多架构发行版按 pkg-config --variable=libdir Fcitx5Core + /fcitx5 解析。描述文件写入 /usr/share/fcitx5/addon/voime.conf。
sudo 范围只有 addon 安装 / 卸载申请 sudo；脚本不整体以 root 运行，voimed、voime、模型与配置仍由用户拥有。安装入口与选项见 根 README §2。
不设置 FCITX_ADDON_DIRS只依赖 Fcitx5 默认系统 addon 目录；不读取用户 addon 目录，不把用户可写目录加入库搜索路径。拒绝提权或安装失败时不静默降级到用户目录。
ABI 诊断voime doctor 检查系统 addon 路径、voime.so、描述文件与 ABI；不检查inputmethod 条目。
线程所有 Fcitx API 调用、socket 事件与定时器都在 Fcitx 事件循环线程内；IpcClient 不做后台线程。
事件监听按键使用 watchEvent<InputContextKeyEvent>(PreInputMethod)；焦点失焦使用 watchEvent<InputContextFocusOut>(PreInputMethod)。
热键消费命中热键后调用 filterAndAccept()；未命中立即返回，不影响 Fcitx 普通路由。
PTT 状态holdActive_ 表示会话开启；松开按记录的 keycode 匹配并发送 Stop（硬切分），无论当前是否 recording；auto-repeat 消费后忽略。
Toggle 状态toggleActive_ 表示会话开启；第二次按下发送 Stop（硬切分），Finalizing 时也可关闭；toggleCode_ 防止同一次按键的 press / release 重复切换。
软切分续段SegmentStarted 更新 segmentId_ 与目标段 ID；目标沿用会话目标。PTT / Toggle 不需要重新按键，也不重新发送 Start。
目标TargetRef 保存 TrackableObjectReference<InputContext> 与 segment_id；提交前检查 focused()。
Finalizing 预览finalizing_ 为 true 后忽略新的 Partial，不调用 Preview::show / clear；保留最后一条 Partial，直到 Final 或清空路径。
不链接 GPU / 模型只链接 Fcitx5Core 与 nlohmann/json；不链接 ONNX Runtime / llama.cpp / ROCm / CUDA / Vulkan，不加载模型，不感知 final.backend。
重连2 s 定时器每次重新 setNextInterval 与 setOneShot；只重连不阻塞事件循环。
socket非阻塞 Unix socket；读写缓冲在 IpcClient 内，断线时先关闭 fd 再禁用事件源。
配置readAsIni / safeSaveAsIni 不会自动补 .conf；路径必须写全。
  • 仓库级线程 / 进程边界见 根 CORE §2；用户可见行为见 USER §2。
  • addon 只从系统 addon 目录加载；安装辅助与诊断不改变 Fcitx 的库搜索路径。

FCITX_ADDON_FACTORY_V2(voime, VoimeAddonFactory)
  • 继承 InputMethodEngineV2 仅为获得 AddonInstance 生命周期；keyEvent 不参与普通输入。
  • starting_ 表示已发送 Start 但尚未收到 daemon State.recording=true。
  • FCITX_ADDON_FACTORY_V2 导出 addon 工厂；Fcitx 通过系统描述文件的 Library=voime 加载系统 addon 目录中的 voime.so。
  • finalizing_ 为 true 时 onIpcMessage(Partial) 直接返回；State.finalizing 只更新标志，不调用 clearPreview()。
  • Configure 改变 Mode 时，setConfig 先清除 holdActive_ / toggleActive_ / starting_ 并停止旧模式的热键路径；recording_ / finalizing_ 与目标保留到旧段 Final / Error，随后清理，避免旧会话残留空白窗口或吞掉下一次热键。

  • connect 成功后发送 Hello { role: "frontend", version, config }；线协议接受 fcitx 别名；当前实现写 frontend。

  • addon 不解析 Final 的生成后端；IPC 中只出现 Partial / Final / Error 等前端消息。

5.2 PTT 热键

fcitx5::InputContextKeyEvent
└── VoimeAddon::handleKey(event)
    ├── 判断 mode == Continuous → 返回
    ├── 判断 !client_.connected() → 返回
    ├── KeyEvent::checkKeyList(hotkey, MatchAllNormalizedKeys)
    └── VoimeAddon::handlePtt(event, matches)
        ├── 判断 event.isRelease() && holdActive_ && code == holdCode_
        │   ├── VoimeAddon::stopPtt()
        │   │   ├── holdActive_ = false
        │   │   ├── 判断 recording_ → finalizing_ = true
        │   │   ├── IpcClient::stop(segmentId, Hold)
        │   │   └── 判断 !recording_ && !finalizing_ → clearPreview()
        │   └── KeyEvent::filterAndAccept()
        ├── 判断 !matches → 返回
        ├── KeyEvent::filterAndAccept()
        ├── 判断 holdActive_ || starting_ || recording_ → 返回
        ├── 判断 finalizing_ → VoimeAddon::bindPendingTarget(event.inputContext())
        │   └── 否则 VoimeAddon::bindTarget(event.inputContext())
        ├── holdActive_ = true; starting_ = true
        └── IpcClient::start(pendingSegmentId_ 或 segmentId_, Hold)
  • 松开是硬切分：即使当前处于 Finalizing 或两段之间，也发送 Stop 关闭会话；软切分续段不重新按热键。
  • 松开后若当前段在录，不调用 clearPreview()；进入 Finalizing 时保留最后一条 Partial，等待 Final 到达。
  • Finalizing 期间再次按下允许开始下一句：旧目标移入 pendingFinals_，新目标先存入 pendingTarget_，在下一个 SegmentStarted 切换；旧 Final 仍按旧 segment_id 提交。

5.3 Toggle 热键

VoimeAddon::handleToggle(event, matches)
├── 判断 release && toggleCode_ 匹配
│   ├── toggleCode_ = 0
│   └── KeyEvent::filterAndAccept()
├── 判断 !matches → 返回
├── KeyEvent::filterAndAccept()
├── 判断 !toggleActive_ && !starting_ && !recording_
│   ├── 判断 finalizing_ → VoimeAddon::bindPendingTarget(event.inputContext())
│   │   └── 否则 VoimeAddon::bindTarget(event.inputContext())
│   ├── toggleActive_ = true; starting_ = true
│   ├── VoimeAddon::refreshTogglePreview()
│   └── IpcClient::start(pendingSegmentId_ 或 segmentId_, Toggle)
└── 判断 toggleActive_
    └── VoimeAddon::stopToggle()
        ├── toggleActive_ = false
        ├── 判断 recording_ → finalizing_ = true
        ├── IpcClient::stop(0, Toggle)
        ├── 判断 !recording_ && !finalizing_ → clearPreview()
        └── 判断 !finalizing_ → target_.ref.unwatch() + segmentId_.reset()
  • 第二次按下即使处于 Finalizing（软切分后的 Final 中）也发送 Stop 关闭会话；Final 到达后不再保留空白窗口。
  • 无活动会话且 Finalizing 时按下可开始下一句；旧目标保留在 pendingFinals_，新目标在下一个 SegmentStarted 生效。
  • 录音中停止 Toggle 时保留最后一条 Partial，Final 到达后清空并提交；无当前段且无 Final 在途时直接清空。

5.4 SegmentStarted / Partial

IpcClient::onReadable()
└── IpcClient::handleLine(line)
    └── VoimeAddon::onIpcMessage(message)
        ├── SegmentStarted
        │   ├── 判断 segmentId_ 与 message.segmentId 不同 → pendingFinals_[旧 ID] = target_
        │   ├── 判断 pendingTarget_ → target_ = pendingTarget_; reset pending
        │   ├── segmentId_ = message.segmentId
        │   ├── target_.segment_id = *message.segmentId
        │   ├── 判断 source 非 Hold / Toggle → 绑定 mostRecentInputContext()
        │   ├── 判断 (holdActive_ || toggleActive_) && !target_.focused() → stopPtt() / stopToggle()
        │   └── 判断 toggleActive_ → refreshTogglePreview()
        └── Partial
            ├── 判断 finalizing_ → 返回
            ├── 判断 segmentId 不匹配 → 忽略
            ├── 判断 target_.focused() → Preview::show
            └── 否则 clearPreview()

5.5 Finalizing 与 Final

VoimeAddon::onIpcMessage(State)
├── recording_ = message.recording
├── finalizing_ = message.finalizing
├── 判断 finalizing_ → 保留 Preview（不调用 show / clear）
├── 判断 recording_ → starting_ = false
├── 判断 !recording_ && !finalizing_ → 清空 / 空白 / 清理
└── 判断 !recording_ && !finalizing_ && !toggleActive_ && !holdActive_ → unwatch + reset

VoimeAddon::onIpcMessage(Final)
├── 判断 segmentId == segmentId_ → 当前目标：Preview::clear + commitString + 清理
│   └── segmentId_.reset()
├── 否则判断 pendingFinals_.find(segmentId) → 对该目标 Preview::clear + commitString
│   └── pendingFinals_.erase(segmentId)
└── 否则忽略
  • Finalizing 门禁只停止刷新，不清空最后 Partial；Final 到达后才调用 Preview::clear 并提交。
  • 旧段 Final 可能晚于新段 SegmentStarted；该旧目标保存在 pendingFinals_，仍按原 segment_id 提交。
  • Finalizing 期间到达的迟到 Partial 在 §5.4 被忽略。

5.6 失焦、断线与错误

fcitx5::InputContextFocusOut
└── focusWatcher_ lambda
    ├── 判断 target_.get() != event.inputContext() → 返回
    ├── 判断 pendingTarget_ → Preview::clear(target_.get()); return
    ├── 判断 holdActive_ → VoimeAddon::stopPtt()
    ├── 判断 toggleActive_ → VoimeAddon::stopToggle()
    └── 否则 Preview::clear(target_.get())

IpcClient::fail() / EOF
└── VoimeAddon::onDaemonDisconnected()
    ├── clearPreview()
    ├── target_.ref.unwatch()
    ├── segmentId_.reset()
    ├── pendingTarget_ / pendingSegmentId_.reset()
    ├── holdActive_ / starting_ / recording_ / finalizing_ / toggleActive_ = false
    └── 热键恢复为普通按键

VoimeAddon::onIpcMessage(Error)
├── 判断 role_conflict / version_mismatch / invalid_message
│   └── IpcClient::disconnect() → 2 s 后重连
├── 判断 busy
│   └── pendingTarget_ / pendingSegmentId_.reset(); starting_ = false
├── 判断 segment_dropped && message.segmentId == segmentId_
│   ├── 判断 toggleActive_ → 重置当前段 + refreshTogglePreview()
│   ├── 判断 holdActive_ → 重置当前段 + clearPreview()
│   └── segmentId_.reset()
├── 判断 segment_dropped && pendingFinals_.contains(message.segmentId)
│   └── pendingFinals_.erase(message.segmentId)
├── 判断 其它 code → 记录错误码，不改变当前会话
└── 判断 !recording_ && !finalizing_
    └── 清理 Toggle / PTT / target / preview
  • 目标失焦或断线时不再有 Final 可提交；清空临时窗口，最终文本保留在 daemon / TUI。旧目标失焦时为 pendingTarget_ 保留新目标，不停止已排队的新会话；旧段 Final 仍通过 pendingFinals_ 按原 segment_id 处理。
  • 错误处理只按 IPC 错误码；segment_dropped 只处理与当前 segmentId_ 匹配的段，GPU Final 失败与 CPU 回退由 daemon 负责，addon 不感知后端。
