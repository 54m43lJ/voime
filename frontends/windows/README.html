1. WHAT & WHY

↑

1.1 IDEAL：要解决的问题

Windows 没有 Fcitx 等价的后台 addon 模型：键盘、焦点与文本提交分散在 Win32、UI Automation 与 TSF 中。Voime 需要一个独立前端，在不复制识别链路的前提下，把热键、目标输入位置、 临时浮层与最终文本注入接到 voimed。MVP 是后台听写：普通桌面进程 + 全局热键 + SendInput；TSF 是可选阶段，用于需要系统输入法身份的场景。

1.2 GOAL：什么算成功

  • 用户按热键说话，浮层显示 Partial，Final 注入语音段开始时聚焦的输入位置。
  • 目标失焦、提权窗口、注入失败时不误提交；最终文本保留在 daemon 历史 / TUI。
  • 前端不加载模型、不做 VAD / CTC / 分段；只消费 IPC 消息。
  • 命名管道只允许当前用户；不记录按键、音频或识别文本到磁盘。
  • 安装、登录启动、托盘、卸载形成闭环；不把 daemon 装成 Session 0 服务。

1.3 非目标

  • MVP 不做 TSF；TSF 作为可选 P4，且不承诺与 keyboard TIP 并行。
  • 不承诺覆盖提权窗口、游戏 / Raw Input、锁屏 / 安全桌面、所有 UWP / 终端。
  • 不做跨平台 UI 抽象；Linux 前端与 Windows 前端各自实现。
  • 不使用 loopback TCP；默认传输是命名管道。
  • 不在前端内保存模型或识别历史。
