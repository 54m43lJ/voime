2. CONVENTIONS

↑

约定内容
独立构建根frontends/windows 使用独立 Cargo workspace 与独立 Cargo.lock；不进入根 cargo test --workspace。
平台只构建 Windows 目标；Linux CI 不构建本 crate。
无模型不链接 ONNX Runtime，不加载模型，不做 VAD / Preview / 分段；GPU runtime 不属于本 crate。
安装核心安装脚本 scripts/install-core.ps1 安装托盘、daemon 与核心模型，并写入登录启动；GPU 安装脚本 scripts/install-gpu.ps1 安装 worker、runtime 与 GPU 模型。前端不执行安装、不探测 GPU runtime。
事件循环主线程拥有托盘与消息循环；IPC reader 线程把消息送入有界通道；热键 / 目标 / 浮层更新回到主线程。设置窗口在独立进程（voime-tray.exe --settings）运行唯一的 egui 事件循环，托盘轮询设置子进程并在其退出后重载配置。
daemon 生命周期daemon 由托盘以子进程启动，并加入设置了 JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE 的 Job Object；托盘退出或崩溃即终止 daemon；托盘是 daemon 的唯一所有者。GPU worker 由 voimed 按配置拉起，托盘不启动、不停止、不重启 worker。
目标所有权目标窗口 / 焦点元素属于前端私有类型；协议只传 segment_id 与事件。
单实例每用户一个前端进程；重复启动激活已有托盘。
提交边界SendInput 只在目标复核通过后调用；失败不重试其他窗口。
Finalizing收到 State.finalizing 后保留最后一条 Partial，不再更新浮层；Final 或丢弃结果到达后清空浮层，Final 继续提交，丢弃结果只清理。不感知 Final 来自 CPU 还是 GPU。
日志只记录错误码、端点、热键注册与目标变化；不记录按键内容或识别文本。
  • 仓库级依赖方向见 根 CORE §2；平台 API 与安全约束见 PROVIDER。

4.9 control.rs 文件树

pub struct Daemon { /* child + job handle + stopped */ }

impl Daemon {
    pub fn start() -> anyhow::Result<Self>;
    pub fn has_exited(&mut self) -> bool;
    pub fn stop(&mut self);
}

pub fn stop_existing();
pub fn quit_running() -> anyhow::Result<()>;
  • start 以 CREATE_NO_WINDOW 拉起同目录 voimed.exe，并把子进程 AssignProcessToJobObject 到 JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE 的 Job Object；Job 创建或分配失败时降级为仅在正常退出时停止 daemon。
  • stop 先以 Control 角色发送 Quit，最多等 3 秒，超时 kill；Drop 关闭 Job 句柄兜底终止。
  • stop_existing 在托盘启动时停止外部 daemon 并等待命名管道释放（最多 2 秒），保证托盘是唯一所有者。
  • 托盘只拉起 voimed.exe；GPU worker 由 voimed 启动时按配置加载，本模块不创建 worker 进程。

↑

5.1 启动与连接

Windows 登录启动 / 用户双击
└── frontends_windows::main()
    ├── 判断 --settings → settings::run_process()（独立设置进程，见 §5.5）
    ├── voime_log::init("voime-tray")
    ├── ensure_single_instance()
    ├── config::load()
    └── run(Frontend::new(config))
        ├── ComGuard::init()（STA，UIA 使用）
        ├── Tray::create(&mut frontend)
        ├── frontend.attach_window(tray.hwnd())
        ├── Overlay::create()
        ├── frontend.start_daemon()
        │   ├── control::stop_existing()
        │   └── control::Daemon::start()          // 只拉起 voimed.exe
        └── Windows 消息循环（退出 → frontend.shutdown()）

voimed（control::Daemon::start() 的子进程）
└── voimed::main()
    └── 判断 final.backend != Cpu → voimed::worker::Worker::spawn(...)

frontend.tick()（消息循环每轮）
├── poll_settings()
├── poll_daemon()
│   └── 判断 daemon 子进程已退出 → on_disconnect()
├── 判断未连接且到达重连间隔 → frontend.try_connect()
│   ├── IpcClient::connect(&Endpoint::NamedPipe(name))
│   ├── IpcClient::send(Hello { role: Frontend, config })
│   ├── IpcClient::snapshot()
│   ├── frontend.sync_hotkey()
│   └── frontend.on_message(snapshot)
├── IpcClient::try_event() → frontend.on_message(...)
├── 判断 PTT 激活且 !config.hotkey.is_down() → stop_segment(Hold)
└── 判断 target::focused() 失败 → on_target_lost()

frontend.shutdown()
├── on_disconnect()
└── 判断有托管子进程 → control::Daemon::stop()；否则 control::quit_running()
  • start_daemon 先停止外部 daemon 再拉起自己的子进程；连接失败时按 10 秒节奏重试拉起。
  • Daemon::start 只拉起 voimed.exe；GPU worker 由 voimed 按配置加载，托盘不启动 worker。核心 / GPU 安装脚本只在安装期运行，不进入本调用栈。
  • 热键注册依赖托盘窗口句柄，因此在 Tray::create 之后、首次连接成功时执行。
  • Daemon::stop 发送 Quit 后最多等 3 秒，超时 kill；Drop 关闭 Job 句柄兜底终止。

5.2 热键到提交

WM_HOTKEY
└── frontend::on_hotkey()
    ├── 判断 hotkey_down → 按住期间的重复通知直接忽略
    ├── 判断 Mode == Ptt
    │   └── 判断 !recording → start_segment(Hold)
    └── 判断 Mode == Toggle
        ├── 判断 toggle_active → stop_segment(Toggle)
        └── 判断 !toggle_active → start_segment(Toggle)

frontend.tick()
└── 判断 PTT 激活且热键已松开（GetAsyncKeyState 轮询 key-up）
    └── stop_segment(Hold)

start_segment(source)
├── target::capture()
├── IpcClient::send(Start { segment_id: 0, source })
├── 判断 finalizing → pending_target = target
│   └── 否则 → 当前 target = target; current_segment = None
└── recording = true; finalizing = false

stop_segment(source)
├── 判断 source == Hold → ptt_active = false
├── 判断 source == Toggle → toggle_active = false
├── IpcClient::send(Stop { segment_id, source })
└── 判断 !recording && !finalizing → Overlay::hide()

frontend::on_message(State)
├── 判断 finalizing → 停止预览更新，保留最后一条 Partial
└── 判断 !recording && !finalizing && !ptt_active && !toggle_active → 清理目标 / 浮层

frontend::on_message(Partial)
└── 判断 segment_id 匹配目标且非 finalizing → Overlay::show(text, &target)

frontend::on_message(Final)
├── 判断 message.segment_id == target.segment_id
├── 判断 target::focused(&target) → 否则 on_target_lost()
├── 判断 Toggle 会话 active → Overlay::show_empty(&target)
├── 其他模式 → Overlay::hide()
└── commit::commit(&target, &text)

frontend::on_message(Error)
├── 判断 segment_dropped && message.segment_id == target.segment_id
│   ├── 判断 Toggle 会话 active → Overlay::show_empty(&target)
│   ├── 其他模式 → Overlay::hide()
│   └── 清理当前段 / target
├── 判断 role_conflict / version_mismatch / invalid_message → on_disconnect()
└── 判断 其他 code → 记录日志
  • PTT 的 key-up 不依赖低级键盘钩子，由主循环用 GetAsyncKeyState 轮询；松开是硬切分，即使当前处于 Finalizing 也发送 Stop 关闭会话。
  • 会话内 VAD 软切分续段不重新发送 Start；SegmentStarted 更新段 ID，目标沿用会话目标。Finalizing 期间允许再次按热键开始下一句：新目标先存入 pending_target，旧段 Final 提交后才在 SegmentStarted 切换，避免旧结果按新段 ID 丢弃。
  • Finalizing 期间保留最后一条 Partial，不再更新；Final 或丢弃结果到达后清空浮层，Final 按模式提交。Final 的来源是 CPU 还是 GPU 不影响本路径。
  • Configure 改变 Mode 时，前端清除 ptt_active / toggle_active / 热键按下标志；目标保留到旧段 Final / Error 后再清理，避免旧会话残留空白浮层或吞掉下一次热键。

5.3 Continuous 与目标失效

frontend::on_message(SegmentStarted)
├── 判断 pending_target 且 current_segment.is_none() → target = pending_target
├── 判断 source == Continuous → target::capture()
├── 判断 PTT / Toggle 续段且原 target 失焦 → on_target_lost()
└── 判断 target::focused → 保留会话目标；否则 on_target_lost()

frontend::on_focus_change()
├── 判断 !target::focused → Overlay::hide()
├── 判断 pending_target.is_some() → 清旧 target / current_segment，保留 pending_target
├── 判断 Mode == Ptt / Toggle && (ptt_active || toggle_active || recording || finalizing)
│   └── stop_segment(Hold / Toggle)
└── 放弃当前段提交

IpcClient reader thread
└── read_message() 返回 EOF / 错误
    └── frontend::on_disconnect()

        ├── target.clear()

        └── 定时重连
