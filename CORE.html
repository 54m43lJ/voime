2. CONVENTIONS

↑

约定内容
依赖方向 voime-core → voime-ipc（当前仅为 Mode）；voimed → core + ipc + transport + log；voime → core + ipc + transport + log（doctor）；前端 → ipc + transport + log。前端不依赖 core，core 不依赖 transport / daemon / 前端；voime-log 是零依赖叶子 crate，被 daemon、CLI doctor 与 Windows 前端消费；当前仅保留 voime-ipc 的 Mode 类型依赖，后续按 PLATFORM §3.4 继续收敛。
OS API 位置 Unix socket、named pipe、权限与路径只出现在 voime-transport 与平台前端；voime-core / voime-ipc / voimed 的业务代码不直接调用 OS 传输 API。
前端传输例外 Rust daemon / CLI 通过 voime-transport 访问端点；frontends/fcitx/src/ipc.cpp 是 C++ 前端，直接使用 Unix socket 并按同一路径 / 权限契约实现。
进程边界 fcitx5 进程加载 addon；voimed 是独立进程；voime TUI 是独立客户端；Windows 前端是独立桌面进程，TSF DLL 加载到目标应用进程。
线程边界 addon 的 Fcitx 调用在 Fcitx 事件循环线程；daemon 由事件循环 + accept / reader / writer 线程组成；pipeline 只有一个工作线程串行执行 VAD / CTC / 标点；TUI 使用自己的输入线程。
协议单一来源 消息形状、编码、错误码只在 voime-ipc USER 定义；daemon 与前端只实现行为，不复制类型。
模型单一来源 模型清单、SHA-256、张量契约只在 voime-core PROVIDER 定义；安装脚本与 runtime 校验共用同一清单。
前端职责 前端只做热键、目标、临时文本与提交；不加载模型、不做 VAD / CTC / 分段、不保存识别文本。
测试分层 根 tests/ 覆盖跨组件协议、分段与状态；组件单测覆盖内部算法；平台 transport / 前端在各自 runner 上跑 conformance 测试。
无异步运行时 Rust 侧使用标准线程、crossbeam-channel 与事件循环；不引入 tokio / async-std。
无持久化 不写音频、按键或识别历史到磁盘；daemon 退出后会话历史丢失。

5.4 TUI、控制与退出

voime::main()
├── 判断无子命令 → voime::client::Client::connect(Endpoint)
├── 判断 ctl → voimed 控制命令
└── 判断 doctor → 只读检查

voime ctl quit
└── voimed::daemon::Daemon::on_client(Quit)
    ├── voime_ipc::encode_message(Bye)
    ├── voime_core::pipeline::Pipeline::shutdown()
    ├── voime_core::audio::capture::CaptureHandle::stop()
    └── voime_transport::Listener::shutdown()
  • voimed::ipc_server::IpcServer::shutdown() 调用 Listener::shutdown()，由 transport 删除端点。
  • TUI 的 q 只 detach，不发送 Quit；停止 daemon 只使用 ctl quit 或平台服务管理。
