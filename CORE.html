2. CONVENTIONS

↑

约定内容
依赖方向 voime-core → voime-ipc（当前仅为 Mode）；voimed → core + ipc + transport + log + gpu-common；voime → core + ipc + transport + log；前端 → ipc + transport + log。voimed 不依赖任一 backend crate；voime-gpu-firered 只依赖 common + ORT；voime-gpu-qwen3 只依赖 common + llama.cpp。
OS API 位置 Unix socket、named pipe、权限与路径只出现在 voime-transport 与平台前端；voime-core / voime-ipc / voimed 的业务代码不直接调用 OS 传输 API。
前端传输例外 Rust daemon / CLI 通过 voime-transport 访问端点；frontends/fcitx/src/ipc.cpp 是 C++ 前端，直接使用 Unix socket 并按同一路径 / 权限契约实现。
进程边界 fcitx5 进程加载 addon；voimed 是独立进程；voime TUI 是独立客户端；Windows 前端是独立桌面进程，TSF DLL 加载到目标应用进程；FireRed / Qwen worker 是 voimed 拉起的独立进程。
线程边界 addon 的 Fcitx 调用在 Fcitx 事件循环线程；daemon 由事件循环 + accept / reader / writer 线程组成；pipeline 只有一个工作线程串行执行 VAD / Preview / CPU Final；GPU Final 在 worker 进程内执行；TUI 使用自己的输入线程。
协议单一来源 前端消息形状、编码、错误码只在 voime-ipc USER 定义；GPU worker 帧协议只在 voime-gpu-common USER 定义；daemon 与前端只实现行为，不复制类型。
模型单一来源 核心模型与 CPU 契约在 voime-core PROVIDER；FireRed 模型与 ORT GPU 契约在 voime-gpu-firered PROVIDER；Qwen 模型与 llama.cpp 契约在 voime-gpu-qwen3 PROVIDER。安装脚本与运行期校验共用同一份 manifest。
Final 调度 voimed 读取 final.backend，在 Finalizing 调用核心 CPU Final 或选中的 GPU worker；voime-core 不感知后端选择，只提供 Preview 取消与 CPU Final。
前端职责 前端只做热键、目标、临时文本与提交；不加载模型、不做 VAD / Preview / 分段、不保存识别文本、不感知 Final 后端。
测试分层 根 tests/ 覆盖跨组件协议、分段、状态、manifest 与 Final 后端；组件单测覆盖内部算法；平台 transport / 前端在各自 runner 上跑 conformance 测试。
无异步运行时 Rust 侧使用标准线程、crossbeam-channel 与事件循环；不引入 tokio / async-std。
无持久化 不写音频、按键或识别历史到磁盘；daemon 退出后会话历史丢失。模型与配置只读 / 由安装与 ctl 写入。

5. Call stack tree

↑

5.1 冷启动

systemd --user / voime-tray 子进程（Windows）
└── voimed::main()
    ├── voime_log::init("voimed")
    ├── voimed::cli::parse()
    ├── voimed::config::load() → FinalConfig { backend }
    ├── voime_core::config::resolve()
    ├── voime_core::model::load_models(model_root)
    │   ├── ModelManifest::load(firered-vad/manifest.json)
    │   └── ModelManifest::load(sensevoice-small/manifest.json)
    ├── voime_core::infer::session::SessionFactory::new()
    ├── voime_core::pipeline::spawn() → (Pipeline, Final)
    ├── 判断 backend != Cpu → voimed::worker::Worker::spawn(backend, model_root)
    │   └── GPU Hello / Ready handshake
    ├── voime_core::audio::capture::start()
    ├── voimed::ipc_server::IpcServer::bind()
    └── voimed::daemon::Daemon::run()

fcitx5 / Windows 前端
└── 前端连接
    └── voime_ipc::write_message(Hello)
  • 默认 backend = Cpu 时不启动 GPU worker，也不探测 GPU runtime；核心仍完成模型校验与 pipeline 启动。
  • GPU worker 加载失败不阻塞 daemon 启动：daemon 保留 CPU Final，并把该后端标记为不可用。
  • IpcServer::bind() 内部调用 voime_transport::bind()；当前实现见 voimed CORE §5.1。

5.2 热键到最终提交

fcitx5::InputContextKeyEvent / Windows 热键回调
└── fcitx_addon::VoimeAddon::handleKey() / frontends_windows::Frontend::on_hotkey()
    ├── fcitx_addon::VoimeAddon::bindTarget() / frontends_windows::target::capture()
    ├── voime_ipc::write_message(Start)
    └── voimed::ipc_server（接收）
        └── voimed::daemon::Daemon::on_client(Start)
            ├── voime_core::audio::capture::CaptureHandle::play()
            ├── voime_core::pipeline::Pipeline::start_segment()
            └── voime_ipc::encode_message(SegmentStarted)

voime_ipc::read_message(Partial) / voime_transport::Stream::read()
└── fcitx_addon::VoimeAddon::onIpcMessage(Partial) / frontends_windows::Frontend::on_message(Partial)
    └── fcitx_addon::Preview::show() / frontends_windows::preview::Overlay::show()

voimed::daemon::Daemon::on_client(Stop)（硬切分）
├── voime_core::pipeline::Pipeline::finish_segment()
├── voime_core::pipeline::Pipeline::cancel_preview()
├── voime_core::pipeline::PipelineEvent::SegmentReady(segment)
└── voimed::daemon::Daemon::finalize(segment)
    ├── 判断 backend == Cpu → voime_core::Final::transcribe(segment.samples)
    ├── 判断 backend == Firered → voimed::worker::Worker::transcribe(segment.samples)
    ├── 判断 backend == Qwen3 → voimed::worker::Worker::transcribe(segment.samples)
    ├── 判断 GPU 失败 → voime_core::Final::transcribe(segment.samples)
    └── voime_ipc::encode_message(Final / SegmentDropped)

voime_ipc::read_message(Final) / voime_transport::Stream::read()
└── fcitx_addon::VoimeAddon::onIpcMessage(Final) / frontends_windows::Frontend::on_message(Final)
    ├── fcitx_addon::TargetRef::focused() / frontends_windows::target::focused()
    └── fcitx::InputContext::commitString() / frontends_windows::commit::commit()
  • PTT / Toggle 的 Start 只开启会话；会话内 VAD 每次软切分重复 SegmentStarted / Partial / Final，Stop 是硬切分。
  • 上一段的 Final 先于下一段的 SegmentStarted 广播；前端可继续用当前目标提交上一段。
  • PTT / Toggle 的目标绑定与提交顺序见 fcitx-addon CORE §5.2 与 windows CORE §5.2。
  • Finalizing 期间不再产生 Partial；CPU Final 只调用一次，GPU Final 不再调用 SenseVoice ASR。
  • daemon 内部的分段、背压与广播见 voimed CORE §5.5。

5.3 Continuous 自动分段

voimed::daemon::Daemon::run()
├── voime_core::pipeline::Pipeline events
│   ├── 判断 Recording(true) → voimed::daemon::Daemon::on_pipeline(...)
│   ├── 判断 Partial → voimed::daemon::Daemon::on_pipeline(...)
│   ├── 判断 SegmentReady → voimed::daemon::Daemon::finalize(segment)
│   └── 判断 SegmentDropped → voimed::daemon::Daemon::on_pipeline(...)
└── fcitx_addon::VoimeAddon::onIpcMessage(SegmentStarted / Partial / Final) / frontends_windows::Frontend::on_message(...)
  • Continuous 的每个段独立进入 Finalizing；VAD 继续监听下一段，完成段由 daemon 的有界队列串行处理。

5.4 TUI、控制与退出

voime::main()
├── 判断无子命令 → voime::client::Client::connect(Endpoint)
├── 判断 ctl → voimed 控制命令 / 写 Final 后端配置
└── 判断 doctor → 只读检查

voime ctl backend firered
└── voime::config::write_backend(Firered)
    └── 写入 ~/.config/voime/config.toml [final].backend

voime ctl quit
└── voimed::daemon::Daemon::on_client(Quit)
    ├── voimed::worker::Worker::shutdown()
    ├── voime_ipc::encode_message(Bye)
    ├── voime_core::pipeline::Pipeline::shutdown()
    ├── voime_core::audio::capture::CaptureHandle::stop()
    └── voime_transport::Listener::shutdown()
  • voimed::ipc_server::IpcServer::shutdown() 调用 Listener::shutdown()，由 transport 删除端点。
  • TUI 的 q 只 detach，不发送 Quit；Linux 停止 daemon 使用 ctl quit 或 systemd；Windows 由托盘以子进程托管 daemon，退出托盘即停止（见 windows CORE §4.9）。
  • 配置切换不通过 IPC；ctl backend 只写文件，下一次 daemon 启动读取新值。
