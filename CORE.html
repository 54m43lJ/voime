2. CONVENTIONS

↑

约定内容
线程边界 主线程拥有终端、App 与 ClipboardWriter；cpal 回调只做格式转换并把 AudioChunk 送入有界通道；VAD / ASR / 标点全部在单个 pipeline 工作线程内串行执行。
采集常开 音频流在启动后保持运行；PTT 模式通过 StartSegment / FinishSegment 命令决定是否收集样本，不反复启停设备。
模型生命周期 启动时校验并加载三个模型包，会话对象常驻内存；每个语音段只重置解码状态，不重新加载权重。
单段串行 同一时刻只有一个语音段处于识别或收尾状态。最终识别优先于临时识别；已排队的临时任务在新最终任务到来时丢弃。
有界队列 continuous 模式下 VAD 持续运行，完成段进入容量 2 的待识别队列；队列满时丢弃最旧的未处理段，保证当前语音不被阻塞。PTT 模式不使用该队列。
音频格式 内部统一为 16 kHz、单声道、f32 样本；设备原生采样率与声道数在 audio::resample 中转换，混音取各声道平均。音频不落盘。
分段上限 语音段长度上限由 MAX_SEGMENT_MS 控制，推荐 20_000；不得超过 FireRedASR2-AED 的 60 s 硬上限。达到上限时由 Segmenter::force_end 结束当前段。
临时识别 每 PARTIAL_INTERVAL（推荐 800 ms）对当前段已采集样本执行一次 ASR，不加标点；若上一次临时任务未完成则跳过，同一时刻最多一个临时任务。
最终识别 语音段结束后对完整段执行一次 ASR，再对整段文本执行 FireRedPunc；空文本不产生结果行，也不修改剪贴板。
剪贴板 由主线程在收到 PipelineEvent::Final 后写入；内容为全部结果行以 \n 连接，无末尾换行。写入失败不影响结果行展示。
终端状态 进入 raw mode、备用屏幕、隐藏光标并禁用鼠标上报；Tui 的析构或显式 restore 必须在正常退出、错误退出与 panic 时恢复终端。
错误策略 进入 TUI 前的致命错误写 stderr 并以 1 退出；进入 TUI 后的单段推理失败丢弃该段并继续监听；音频流持续失败时恢复终端并以 1 退出。错误不进入 TUI 内容区。
无异步运行时 使用标准线程、crossbeam-channel 与 crossterm::event::poll；不引入 tokio/async-std。
路径与编码 路径使用 std::path::PathBuf；终端文本统一 UTF-8；不经过 shell，不拼命令行字符串。

4.6 src/pipeline.rs 文件树

use std::thread::JoinHandle;

pub enum PipelineCommand {
    StartSegment,
    FinishSegment,
    Shutdown,
}

pub enum PipelineEvent {
    Recording(bool),
    Partial(String),
    Final(String),
    SegmentDropped,
}

pub struct Pipeline {
    pub events: crossbeam_channel::Receiver<PipelineEvent>,
    commands: crossbeam_channel::Sender<PipelineCommand>,
    worker: JoinHandle<()>,
}

pub fn spawn(
    config: &Config,
    factory: infer::session::SessionFactory,
    audio_rx: crossbeam_channel::Receiver<audio::capture::AudioChunk>,
) -> anyhow::Result<Pipeline>;

impl Pipeline {
    pub fn start_segment(&mut self) -> anyhow::Result<()>;
    pub fn finish_segment(&mut self) -> anyhow::Result<()>;
    pub fn shutdown(self) -> anyhow::Result<()>;
}

struct Worker {
    mode: cli::Mode,
    vad: vad::firered::FireRedVad,
    segmenter: vad::segmenter::Segmenter,
    asr: asr::firered_aed::FireRedAed,
    punc: punc::firered::FireRedPunc,
    resampler: audio::resample::StreamResampler,
    ready: crossbeam_channel::Sender<anyhow::Result<()>>,
    events: crossbeam_channel::Sender<PipelineEvent>,
    queue: std::collections::VecDeque<vad::segmenter::Segment>,
    last_partial: std::time::Instant,
}

impl Worker {
    fn run(
        self,
        audio_rx: crossbeam_channel::Receiver<audio::capture::AudioChunk>,
        commands: crossbeam_channel::Receiver<PipelineCommand>,
    );
    fn handle_audio(&mut self, chunk: &audio::capture::AudioChunk) -> anyhow::Result<()>;
    fn handle_command(&mut self, command: PipelineCommand) -> anyhow::Result<bool>;
    fn emit_partial(&mut self) -> anyhow::Result<()>;
    fn finalize(&mut self, segment: vad::segmenter::Segment) -> anyhow::Result<()>;
    fn drain_queue(&mut self) -> anyhow::Result<()>;
}

pub const PARTIAL_INTERVAL_MS: u64;        // 推荐值 800
pub const PTT_AUTO_END_SILENCE_MS: u64;    // 推荐值 1_200
pub const MAX_SEGMENT_MS: u64;             // 推荐值 20_000
pub const SEGMENT_QUEUE_CAPACITY: usize;   // 推荐值 2
  • spawn 创建内部事件通道，并在工作线程内建立 VAD / ASR / Punc 会话；spawn 等待 ready 信号后再返回，模型加载失败在进入 TUI 前返回错误。
  • 工作线程串行处理命令与音频；临时识别任务可被新的最终任务取消，最终结果通过 PipelineEvent::Final 交给主线程。
  • queue 只保存已完成的 continuous 语音段；队列满时丢弃最旧段，正在采集的语音段不受影响。

}

}

pub const MAX_TOKENS: usize;    // 推荐值 400

  • 文本超过 max_tokens 时按标点 / 字符边界切块，逐块预测后拼接；不得截断丢弃尾部。

5. Call stack tree

↑

5.1 启动

main::main()
├── cli::parse()
├── config::Config::resolve(args)
│   ├── config::default_model_dir()
│   └── model::ModelManifest::load(model_dir/manifest.json)
│       └── model::ModelManifest::verify(model_dir)
├── infer::session::SessionFactory::new(config.threads)
├── pipeline::spawn(&config, factory, audio_rx)
│   ├── vad::firered::FireRedVad::new(...)
│   ├── asr::firered_aed::FireRedAed::new(...)
│   ├── punc::firered::FireRedPunc::new(...)
│   └── std::thread::Builder::spawn(pipeline::Worker::run)
├── audio::capture::start(config.input_device, audio_tx)
├── clipboard::ClipboardWriter::new()
└── app::run(config.mode, pipeline, clipboard)
    └── ui::Tui::init()
  • 模型校验、会话创建、音频流与剪贴板都在 ui::Tui::init 之前完成；任一步失败都不会进入备用屏幕。
  • pipeline 工作线程先于音频流启动，保证第一批 AudioChunk 不会落入无人接收的通道；capture 由 main::run 持有到退出。

5.2 PTT 按键

app::run()
├── crossterm::event::poll(timeout)
├── crossterm::event::read()
└── app::App::on_key(key, &mut pipeline)
    ├── 判断 Ctrl+C / q → Control::Quit
    ├── 判断 mode == Ptt 且 Space 且 !recording 且 !finalizing
    │   ├── pipeline::Pipeline::start_segment()
    │   │   └── crossbeam_channel::Sender::send(PipelineCommand::StartSegment)
    │   │       └── pipeline::Worker::handle_command(StartSegment)
    │   │           ├── vad::firered::FireRedVad::reset()
    │   │           └── vad::segmenter::Segmenter::reset()
    │   └── app::App::recording = true
    ├── 判断 mode == Ptt 且 Space 且 recording
    │   ├── pipeline::Pipeline::finish_segment()
    │   │   └── crossbeam_channel::Sender::send(PipelineCommand::FinishSegment)
    │   │       └── pipeline::Worker::handle_command(FinishSegment)
    │   │           ├── vad::segmenter::Segmenter::force_end()
    │   │           └── pipeline::Worker::finalize(segment)
    │   └── app::App::finalizing = true
    └── 判断 PageUp / PageDown / Home / End → app::ScrollState::page_up / page_down / home / end
  • 第二次 Space 后 recording 立即置为 false，标记消失；最终结果到达前当前行保留最后一条临时文本。
  • 最终结果未完成时再次按 Space 被忽略，避免并发使用同一个 ASR 会话。
  • PTT 下 VAD 静音自动结束也走 Worker::finalize，不进入 continuous 队列；界面回到等待下一次 Space 的空闲状态。

5.3 Continuous 监听

pipeline::Worker::run(self, audio_rx, commands)
└── loop
    ├── crossbeam_channel::Receiver::recv_timeout(50ms)
    │   ├── 判断 AudioChunk → pipeline::Worker::handle_audio(chunk)
    │   │   └── audio::resample::StreamResampler::push(chunk)
    │   │       └── vad::firered::FireRedVad::push(samples_16k)
    │   │           └── vad::segmenter::Segmenter::push(frame, samples, mode)
    │   │               ├── 判断 SegmenterEvent::SpeechStart → PipelineEvent::Recording(true)
    │   │               ├── 判断 PARTIAL_INTERVAL_MS 到期 → pipeline::Worker::emit_partial()
    │   │               └── 判断 SegmenterEvent::SpeechEnd(segment)
    │   │                   ├── PipelineEvent::Recording(false)
    │   │                   └── queue.push_back(segment)
    │   └── 判断 PipelineCommand → pipeline::Worker::handle_command(command)
    ├── pipeline::Worker::drain_queue()
    │   └── pipeline::Worker::finalize(segment)
    └── 判断 Shutdown → break
  • continuous 模式下 VAD 与分段始终运行；PTT 模式下只有收到 StartSegment 后的音频进入分段器，其他帧仍被 VAD 消费但不累积为结果。
  • VAD 事件与音频块在同一工作线程串行处理，分段器不需要锁。

5.4 临时识别

pipeline::Worker::emit_partial()
├── 判断 segmenter.is_active() 且 now - last_partial >= PARTIAL_INTERVAL_MS
├── asr::features::Fbank::compute(segmenter.active_samples())
├── asr::firered_aed::FireRedAed::transcribe(features)
├── 判断 text 非空 → PipelineEvent::Partial(text)
└── last_partial = now
  • 临时识别不加标点，不写剪贴板；同一时刻最多一个临时任务，finalize 到来时取消尚未开始的临时任务。
  • 临时结果为空时保留上一行文本，避免界面闪烁；最终结果为空才丢弃整段。

5.5 最终识别与标点

pipeline::Worker::finalize(segment)
├── asr::features::Fbank::compute(segment.samples)
├── asr::firered_aed::FireRedAed::transcribe(features)
├── 判断 asr.text 非空
│   └── punc::firered::FireRedPunc::punctuate(asr.text)
└── 判断 final_text 非空 → PipelineEvent::Final(final_text)
  • 标点只执行一次，使用完整语音段的 ASR 文本；临时文本不参与。
  • ASR 或标点返回错误时发送 SegmentDropped 并继续监听，界面不新增结果行。

5.6 剪贴板与退出

app::App::on_pipeline(PipelineEvent::Final(line))
├── app::App::push_final(line)
└── clipboard::ClipboardWriter::set_transcript(&app.transcript)

main::run()
├── app::run() → Control::Quit
│   ├── ui::Tui::restore()
│   └── pipeline::Pipeline::shutdown()
│       ├── crossbeam_channel::Sender::send(PipelineCommand::Shutdown)
│       └── std::thread::JoinHandle::join()
├── audio::capture::CaptureHandle::stop(capture)
└── return Ok(())
  • set_transcript 失败不改变 app.transcript；下一次最终结果会再次整体写入。
  • 退出顺序固定为恢复终端 → 停止工作线程 → 停止音频；未完成的语音段直接丢弃，不写入剪贴板。
