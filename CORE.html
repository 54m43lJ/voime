2. CONVENTIONS

↑

约定内容
线程边界 主线程拥有终端、App 与 ClipboardWriter；cpal 回调只做格式转换并把 AudioChunk 送入有界通道；VAD / ASR / 标点全部在单个 pipeline 工作线程内串行执行。
采集常开 音频流在启动后保持运行；PTT 模式通过 StartSegment / FinishSegment 命令决定是否收集样本，不反复启停设备。
安装期与运行期分离 Python / PyTorch / ONNX 导出 / 量化只存在于安装脚本的虚拟环境；Rust 二进制不依赖 Python，不包含下载器。安装脚本负责下载官方权重、生成 ONNX 模型包、写 manifest 与 SHA-256，并以原子替换方式写入模型目录。
模型生命周期 启动时校验并加载三个模型包，会话对象常驻内存；每个语音段只重置解码状态，不重新加载权重。
单段串行 同一时刻只有一个语音段处于识别或收尾状态。临时识别与最终识别在同一工作线程串行执行，不存在重叠任务；正在执行的临时识别不能被取消。
有界队列 continuous 模式下 VAD 持续运行，完成段进入容量 2 的待识别队列；队列满时丢弃最旧的未处理段，保证当前语音不被阻塞。PTT 模式不使用该队列。
音频格式 内部统一为 16 kHz、单声道、f32 样本；设备原生采样率与声道数在 audio::resample 中转换，混音取各声道平均。音频不落盘。
分段上限 语音段长度上限由 manifest 的 max_segment_ms 控制，默认 10_000；不得超过 FireRedASR2-AED 的 60 s 硬上限。达到上限时 Segmenter::push 返回带 MaxDuration 的 SpeechEnd；PTT 保持收集，余下语音进入下一段。
临时识别 按动态间隔对当前段末尾最多 6 s 音频执行 greedy ASR，不加标点；间隔同时受新增音频量与上次耗时约束，避免慢推理后逐帧重复触发。
最终识别 语音段结束后对完整段执行一次 ASR，再对整段文本执行 FireRedPunc；空文本不产生结果行，也不修改剪贴板。
剪贴板 由主线程在收到 PipelineEvent::Final 后写入；内容为当前会话（最近一次 Ctrl+X 清空后）的全部结果行以 \n 连接，无末尾换行。写入失败不影响结果行展示。
清空工作区 Ctrl+X 只清空 App.transcript 与界面结果行，并把滚动状态复位为跟随；不修改 partial、recording、finalizing，不向 pipeline 发送命令，也不调用 ClipboardWriter。清空后下一次 Final 只把新会话写入剪贴板。
终端状态 进入 raw mode、备用屏幕、隐藏光标并禁用鼠标上报；Tui 的析构或显式 restore 必须在正常退出、错误退出与 panic 时恢复终端。
错误策略 进入 TUI 前的致命错误写 stderr 并以 1 退出；进入 TUI 后的单段推理失败丢弃该段并继续监听；音频流持续失败时恢复终端并以 1 退出。错误不进入 TUI 内容区。
无异步运行时 使用标准线程、crossbeam-channel 与 crossterm::event::poll；不引入 tokio/async-std。
路径与编码 路径使用 std::path::PathBuf；终端文本统一 UTF-8；不经过 shell，不拼命令行字符串。

4.5 src/app.rs 文件树

use crossterm::event::KeyEvent;

pub enum Control {
    Continue,
    Quit,
}

pub struct App {
    pub mode: cli::Mode,
    pub transcript: Vec<String>,
    pub partial: String,
    pub recording: bool,
    pub finalizing: bool,
    pub scroll: ScrollState,
    pub clipboard: clipboard::ClipboardWriter,
    pub fatal: Option<String>,
    pub viewport_height: u16,
}

pub fn run(mode: cli::Mode, pipeline: &mut Pipeline, clipboard: clipboard::ClipboardWriter) -> anyhow::Result<()>;

impl App {
    pub fn new(mode: cli::Mode, clipboard: clipboard::ClipboardWriter) -> Self;
    pub fn on_key(&mut self, key: KeyEvent, pipeline: &mut Pipeline) -> Control;
    pub fn on_pipeline(&mut self, event: PipelineEvent);
    pub fn push_final(&mut self, line: String);
    pub fn set_partial(&mut self, text: String);
    pub fn clear_history(&mut self);
}

pub struct ScrollState {
    pub offset: usize,
    pub follow: bool,
}

impl ScrollState {
    pub fn page_up(&mut self, height: u16);
    pub fn page_down(&mut self, height: u16);
    pub fn home(&mut self);
    pub fn end(&mut self);
}
  • on_key 处理 q / Ctrl+C、Ctrl+X、PTT 的 Space 与四个滚动键；continuous 模式下 Space 无动作。
  • clear_history 执行 self.transcript.clear() 并把 scroll 重置为默认的跟随状态；保留 partial、recording、finalizing 与剪贴板内容。它不经过 pipeline，因此不会取消当前语音段或正在进行的最终识别。
  • on_pipeline 收到 Final 时先追加结果行、清空临时行，再调用 ClipboardWriter::set_transcript；复制失败不回滚。清空后的第一次 Final 只把新结果写入剪贴板。
  • PTT 收到 Recording(false) 时置 recording = false、finalizing = true；continuous 只置 recording = false。
  • SegmentDropped 清除 recording / finalizing 与临时行文本，不新增结果行，也不修改剪贴板。

struct Worker {

pub const PARTIAL_INTERVAL_MS: u64;        // 推荐值 800
pub const PARTIAL_MIN_NEW_AUDIO_MS: u64;   // 推荐值 800
pub const PARTIAL_MAX_MS: u64;             // 推荐值 6_000
pub const PARTIAL_BEAM_SIZE: usize;        // 推荐值 1
pub const VAD_BATCH_MS: u64;               // 推荐值 100
pub const PTT_AUTO_END_SILENCE_MS: u64;    // 推荐值 1_200
pub const MAX_SEGMENT_MS: u64;             // 推荐值 10_000

  • queue 只保存已完成的 continuous 语音段；队列满时丢弃最旧段，正在采集的语音段不受影响。

4.8 src/audio/capture.rs 文件树

use cpal::traits::{DeviceTrait, HostTrait, StreamTrait};

pub struct AudioChunk {
    pub sample_rate: u32,
    pub channels: u16,
    pub samples: Vec<f32>,              // 交织排列，已归一化到 [-1, 1]
}

pub struct CaptureHandle {
    stream: Option<cpal::Stream>,
}

pub fn start(
    device_name: Option<&str>,
    tx: crossbeam_channel::Sender<AudioChunk>,
) -> anyhow::Result<CaptureHandle>;

impl CaptureHandle {
    pub fn stop(self);
}

pub const AUDIO_CHANNEL_CAPACITY: usize;    // 推荐值 2048
  • 回调中只做样本格式转换与 try_send；通道满时丢弃当前块并立即返回，绝不阻塞音频线程。2048 块按 10–20 ms 回调约覆盖 20–40 s 同步 ASR 积压。
  • 流错误回调把零长度 AudioChunk 作为标记写入同一有界通道；工作线程连续收到 3 次后发送 PipelineEvent::Fatal 并退出。通道满时标记可能被丢弃，连续错误计数可能低估。
  • 设备名按 DeviceTrait::name() 精确匹配；未指定时使用 default_input_device。

pub struct Tokenizer {
    vocab: Vec<String>,
    sos_id: u32,
    eos_id: u32,
    pad_id: u32,
}

impl Tokenizer {
    pub fn load(path: &std::path::Path) -> anyhow::Result<Self>;
    pub fn sos_id(&self) -> u32;
    pub fn eos_id(&self) -> u32;
    pub fn pad_id(&self) -> u32;
    pub fn vocab_size(&self) -> usize;

}

5.1 启动

main::main()
├── cli::parse()
├── config::Config::resolve(args)
│   ├── config::default_model_dir()
│   └── model::ModelManifest::load(model_dir/manifest.json)
│       └── model::ModelManifest::verify(model_dir)
├── infer::session::SessionFactory::new(config.threads)
├── pipeline::spawn(&config, factory, audio_rx)
│   ├── vad::firered::FireRedVad::new(...)
│   ├── asr::firered_aed::FireRedAed::new(...)
│   ├── punc::firered::FireRedPunc::new(...)
│   └── std::thread::Builder::spawn(pipeline::Worker::run)
├── audio::capture::start(config.input_device, audio_tx)
├── clipboard::ClipboardWriter::new()
└── app::run(config.mode, pipeline, clipboard)

  • 模型校验、会话创建、音频流与剪贴板都在 ui::Tui::init 之前完成；任一步失败都不会进入备用屏幕。
  • pipeline 工作线程先于音频流启动，保证第一批 AudioChunk 不会落入无人接收的通道；capture 由 main::run 持有到退出。

5.2 按键处理

app::run()
├── crossterm::event::poll(timeout)
├── crossterm::event::read()
└── app::App::on_key(key, &mut pipeline)
    ├── 判断 Ctrl+C / q → Control::Quit
    ├── 判断 Ctrl+X → app::App::clear_history()
    ├── 判断 mode == Ptt 且 Space 且 !recording 且 !finalizing
    │   ├── pipeline::Pipeline::start_segment()
    │   │   └── crossbeam_channel::Sender::send(PipelineCommand::StartSegment)
    │   │       └── pipeline::Worker::handle_command(StartSegment)
    │   │           ├── vad::firered::FireRedVad::reset()
    │   │           └── vad::segmenter::Segmenter::reset()
    │   └── app::App::recording = true
    ├── 判断 mode == Ptt 且 Space 且 recording
    │   ├── pipeline::Pipeline::finish_segment()
    │   │   └── crossbeam_channel::Sender::send(PipelineCommand::FinishSegment)
    │   │       └── pipeline::Worker::handle_command(FinishSegment)
    │   │           ├── vad::segmenter::Segmenter::force_end()
    │   │           └── pipeline::Worker::finalize(segment)
    │   └── app::App::finalizing = true
    └── 判断 PageUp / PageDown / Home / End → app::ScrollState::page_up / page_down / home / end
  • 第二次 Space 后 recording 立即置为 false，标记消失；最终结果到达前当前行保留最后一条临时文本。
  • 最终结果未完成时再次按 Space 被忽略，避免并发使用同一个 ASR 会话。
  • PTT 下 VAD 静音自动结束也走 Worker::finalize，不进入 continuous 队列；界面回到等待下一次 Space 的空闲状态。
  • PTT 达到 max_segment_ms 时由 Segmenter 切段，但保持 collecting；余下按住期间的语音另起一段，只有静音自动结束或松键才回到等待。
  • Ctrl+X 在两种模式下都映射到 App::clear_history；它只修改 UI 内存状态，不经过 pipeline，录音中按下也不会丢弃当前段。

5.3 Continuous 监听

pipeline::Worker::run(self, audio_rx, commands)
└── loop
    ├── crossbeam_channel::select_biased!（命令优先，50 ms 超时）
    │   ├── 判断 PipelineCommand → pipeline::Worker::prepare_command(command, audio_rx)
    │   │   └── pipeline::Worker::handle_command(command)
    │   └── 判断 AudioChunk → pipeline::Worker::handle_audio(chunk)
    │       ├── audio::resample::StreamResampler::push(chunk)
    │       └── pipeline::Worker::process_pending_audio(false)
    │           └── pipeline::Worker::process_vad_batch(batch, frame_samples)
    │               └── vad::firered::FireRedVad::push(batch)
    │                   └── pipeline::Worker::handle_frame(frame, audio)
    │                       └── vad::segmenter::Segmenter::push(frame, samples, mode)
    │                           ├── 判断 SegmenterEvent::SpeechStart → PipelineEvent::Recording(true)
    │                           ├── 判断临时识别门槛到期 → pipeline::Worker::emit_partial()
    │                           └── 判断 SegmenterEvent::SpeechEnd { segment, reason }
    │                               ├── PipelineEvent::Recording(false)
    │                               ├── 判断 MaxDuration 且 PTT → 继续收集
    │                               └── 判断 Continuous → queue.push_back(segment)
    ├── pipeline::Worker::drain_queue()
    │   └── pipeline::Worker::finalize(segment)
    └── 判断 Shutdown → break
  • continuous 模式下 VAD 与分段始终运行；PTT 模式下只有收到 StartSegment 后的音频进入分段器，其他帧仍被 VAD 消费但不累积为结果。
  • VAD 事件与音频块在同一工作线程串行处理，分段器不需要锁。

5.4 临时识别

pipeline::Worker::emit_partial()
├── 判断 segmenter.is_active()
├── 截取 active_samples() 末尾 PARTIAL_MAX_MS
├── asr::features::Fbank::compute(tail)
├── asr::firered_aed::FireRedAed::transcribe_with_beam(features, PARTIAL_BEAM_SIZE)
├── 判断 text 非空 → PipelineEvent::Partial(text)，截断时加 “…”
└── pipeline::Worker::finish_partial_schedule(started)
    ├── next_partial_samples = 当前样本数 + max(PARTIAL_MIN_NEW_AUDIO_MS, 2 × 本次耗时)
    └── next_partial_at = now + max(PARTIAL_INTERVAL_MS, 本次耗时)
  • 临时识别不加标点，不写剪贴板；它与最终识别串行执行，正在执行的临时识别不会被取消。
  • 临时结果为空时保留上一行文本，避免界面闪烁；最终结果为空才丢弃整段。
  • FinishSegment 排空音频通道时设置 suppress_partials，不会把积压音频逐帧变成临时识别。

5.5 最终识别与标点

pipeline::Worker::finalize(segment)
├── asr::features::Fbank::compute(segment.samples)
├── asr::firered_aed::FireRedAed::transcribe(features)
├── 判断 asr.text 非空
│   └── punc::firered::FireRedPunc::punctuate(asr.text)
└── 判断 final_text 非空 → PipelineEvent::Final(final_text)
  • 标点只执行一次，使用完整语音段的 ASR 文本；临时文本不参与。
  • ASR 或标点返回错误时发送 SegmentDropped 并继续监听，界面不新增结果行。

5.6 剪贴板、清空与退出

app::App::on_key(KeyEvent Ctrl+X)
└── app::App::clear_history()
    ├── app.transcript.clear()
    ├── app.scroll = ScrollState::default()
    └── 不调用 clipboard::ClipboardWriter

app::App::on_pipeline(PipelineEvent::Final(line))
├── app::App::push_final(line)
└── clipboard::ClipboardWriter::set_transcript(&app.transcript)

main::run()
├── app::run(mode, &mut pipeline, clipboard) → Result
│   └── ui::Tui::restore()
├── pipeline::Pipeline::shutdown()
│   ├── crossbeam_channel::Sender::send(PipelineCommand::Shutdown)
│   └── std::thread::JoinHandle::join()
├── audio::capture::CaptureHandle::stop(capture)
└── return
  • Ctrl+X 清空不调用 set_transcript，因此剪贴板保持最后一次写入的内容；清空后的下一次 Final 用新的 transcript 覆盖写入，剪贴板只包含清空后的结果。
  • set_transcript 失败不改变 app.transcript；下一次最终结果会再次整体写入。
  • 退出顺序固定为恢复终端 → 停止工作线程 → 停止音频；未完成的语音段直接丢弃，不写入剪贴板。
