2. CONVENTIONS

↑

约定内容
进程边界 fcitx5 进程加载 addon，拥有 Fcitx 主循环、按键事件、InputPanel 与 IPC 客户端；voimed 是独立进程，拥有音频、模型、pipeline、会话历史与 socket 服务；voime TUI 只连接 socket。
线程边界 addon 的所有 Fcitx 调用在 Fcitx 事件循环线程内完成；voimed 的事件循环处理 socket / 命令 / 状态，pipeline 工作线程串行执行 VAD / CTC / 标点；TUI 使用自己的线程。
Mode / Hotkey 所有权 addon 从 ~/.config/fcitx5/conf/voime.conf 读取 Mode / Hotkey；通过 Hello / Configure 同步给 daemon；daemon 不解析命令行模式。
addon 加载 addon 使用 OnDemand=False 随 Fcitx 启动加载；不安装 inputmethod/voime.conf，因此不出现在输入法组，也不会被 Shift / Super+Space 切换选中。
目标输入框 PTT / Toggle 在按键事件中立即绑定目标 InputContext；continuous 与 TUI / ctl 在收到 SegmentStarted 广播时绑定当时聚焦的上下文。段内不再改变；最终提交前检查存在且 hasFocus()。
临时窗口 addon 在收到 Partial 时调用 InputPanel::setPreedit 并 updateUserInterface(InputPanel)；Toggle 会话在 Final / 空段 / 单段错误后显示空白 preedit 并保留窗口，直到 toggle off；停止 / 目标丢失 / 断线时清空。
最终提交 addon 先清空临时窗口，再对目标 InputContext 调用 commitString；不重新选择当前窗口。
键盘所有权 Fcitx 持有键盘；Voime 不读取 / 转发 / 注入按键。普通按键完全由 Fcitx 路由。
单段串行 同一时刻只有一个语音段处于识别或收尾状态；Recording / Finalizing 期间新的 Start 被忽略。Toggle 会话可以连续包含多个顺序语音段，段间保持空白临时窗口。
有界队列 continuous 的完成段进入容量 2 的待识别队列；队列满时丢弃最旧段。pipeline 只有一个工作线程，VAD / CTC / 标点串行执行，音频通道（容量 2048）仍是独立背压点；不承诺慢识别时音频零丢失。
音频格式 内部统一为 16 kHz、单声道、f32；设备原生格式在 audio::resample 转换；音频不落盘。
模型生命周期 启动时校验并加载 VAD / CTC / Punc；会话常驻内存；每个语音段只重置解码状态，不重新加载权重。
CTC 单 ONNX、CMVN 从 metadata 读取、greedy 解码；每帧更新 prev（包括 blank），仅当 id != 0 && id != prev 时输出；final 与尾部 partial 共用同一会话；默认分段上限 30_000 ms。
Fbank 生命周期 StreamingFbank 只服务 VAD，保留滑动窗口和未消费样本；Fbank::compute 每次从完整音频段独立计算，服务 CTC final / partial；两者不共享实例。输入统一乘 32768。
临时识别 按动态间隔对当前段末尾最多 6 s 音频执行 CTC，不加标点；结果只用于 Fcitx 临时窗口与 TUI。
最终识别 段结束后对完整段执行 CTC，再执行 FireRedPunc；空文本不产生 Final。
IPC 背压 每个客户端有有界队列；Final / State 不丢，Partial 可丢；慢 TUI 被断开，不阻塞 daemon。
错误策略 启动错误写 stderr / Fcitx 日志并以非零码退出；运行期单段失败丢弃该段；addon 断线放行热键，不影响普通输入。
无异步运行时 Rust 侧使用标准线程、crossbeam-channel 与事件循环；addon 使用 Fcitx EventLoop::addIOEvent；不引入 tokio / async-std。
无持久化 不写音频、按键或识别历史到磁盘；daemon 退出后会话历史丢失。

  • voimed 与 Fcitx 的启动顺序不敏感；addon 的 timer 固定每 2 s 检查连接，断线后自动重连。
  • 重连 timer 的回调每次都重新 setNextInterval(2000000) 与 setOneShot()，否则部分事件循环后端只触发一次。
  • 模型校验、会话创建与音频流在 socket 服务前完成；任一步失败不进入运行态。
  • addon 未连接 daemon 时不消费热键；Fcitx 继续正常输入。

5.2 热键与模式

fcitx5::InputContextKeyEvent
└── VoimeAddon::handleKey(event)
    ├── 判断 Mode == Continuous → 直接返回
    ├── KeyEvent::checkKeyList(VoimeConfig::hotkey)
    ├── 判断 Mode == Ptt
    │   ├── 判断 event.isRelease() 且 holdActive_
    │   │   ├── finalizing_ = recording_; recording_ = false; starting_ = false
    │   │   └── IpcClient::stop(segment_id, Hold)
    │   └── 判断 press 且 !holdActive_ 且 !starting_ 且 !recording_ 且 !finalizing_
    │       ├── target_ = event.inputContext()->watch()
    │       ├── holdActive_ = true; starting_ = true
    │       └── IpcClient::start(segment_id, Hold)
    └── 判断 Mode == Toggle
        ├── 判断 toggleCode_ 且 release → 消费
        └── 判断 press
            ├── 判断 !toggleActive_ 且 !starting_ 且 !recording_ 且 !finalizing_
            │   ├── target_ = event.inputContext()->watch()
            │   ├── toggleActive_ = true; starting_ = true
            │   ├── Preview::showEmpty(target_.get())
            │   └── IpcClient::start(segment_id, Toggle)
            └── 判断 toggleActive_
                └── VoimeAddon::stopToggle()
                    └── IpcClient::stop(0, Toggle)
  • 命中热键后调用 KeyEvent::filterAndAccept()；未命中立即返回，不影响 Fcitx 的普通路由。
  • hold 的松开按记录的 keycode 匹配，不重新比较完整组合键；auto-repeat 消费后忽略。
  • starting_ 表示已发送 Start 但尚未收到 daemon State.recording=true；期间不会再次启动新段，Error 时统一清理。

5.3 Continuous 监听

pipeline::Worker::run(audio_rx, commands)
└── loop
    ├── crossbeam_channel::select_biased!（命令优先，50 ms 超时）
    │   ├── 判断 PipelineCommand::StartSegment / FinishSegment / Shutdown
    │   │   └── Worker::handle_command(command)
    │   └── 判断 AudioChunk
    │       └── Worker::handle_audio(chunk)
    │           ├── audio::resample::StreamResampler::push(chunk)
    │           └── Worker::process_pending_audio(false)
    │               └── Worker::process_vad_batch(batch, frame_samples)
    │                   └── vad::firered::FireRedVad::push(batch)
    │                       └── Worker::handle_frame(frame, audio)
    │                           └── vad::segmenter::Segmenter::push(frame, samples, mode)
    │                               ├── 判断 SpeechStart → PipelineEvent::Recording(true)
    │                               ├── 判断 partial 门槛 → Worker::emit_partial()
    │                               └── 判断 SpeechEnd → Worker::finalize(segment)
    └── Worker::drain_queue()
  • continuous 由 daemon 的 Mode=continuous 驱动；addon 不参与分段。
  • Toggle 由 addon 的 Start/Stop 驱动；VAD 结束时 worker 立即开始下一个段并继续收集，直到 Stop。
  • VAD 与分段器在同一工作线程串行执行，不需要锁。
  • pipeline 只有一个 worker；容量 2 的队列只缓存已完成段，慢识别时音频通道仍可能丢弃，不承诺零丢失。

5.5 最终识别与提交

├── asr::features::Fbank::compute(segment.samples)
├── asr::firered_ctc::FireRedCtc::transcribe(features)
├── 判断 text 非空
│   └── punc::firered::FireRedPunc::punctuate(text)

  • Toggle 会话在提交后重新写入空白 preedit，保持输入面板窗口到 toggle off 或目标失焦；PTT / continuous 仍然关闭窗口。

5.7 断线、目标丢失与模式切换

└── IpcClient::fail() → VoimeAddon::onDaemonDisconnected()
    ├── Preview::clear(target_.get())
    ├── target_.ref.unwatch(); segmentId_.reset()
    ├── holdActive_ / starting_ / toggleActive_ = false
    └── 热键恢复为普通按键（不消费）

Daemon::apply_mode(mode)
├── Mode=continuous → 允许 VAD 自动分段
└── Mode=ptt / toggle → 等待 addon 的 Start / Stop

fcitx5::InputContextFocusOut(target_)
└── VoimeAddon::focusWatcher_ lambda
    ├── 判断 toggleActive_
    │   └── VoimeAddon::stopToggle()
    │       ├── Preview::clear(target_.get())
    │       ├── IpcClient::stop(0, Toggle)
    │       └── 判断 !finalizing_
    │           ├── target_.ref.unwatch()
    │           └── segmentId_.reset()
    └── 判断 !toggleActive_ → Preview::clear(target_.get())
  • Fcitx 在目标失焦时隐藏输入面板；Toggle 会话同时发送 Stop，daemon 结束当前段，目标无焦点时最终文本保留在 daemon/TUI 而不提交。
  • Toggle 的后续 SegmentStarted 只在会话仍有效时跟随当前焦点，避免失焦停止后重新绑定到新窗口。
  • Fcitx 重启后 addon 重新加载并重连；daemon 不重启。
  • 模式切换在下一个语音段生效；当前段继续到结束。
