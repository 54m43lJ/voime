PROVIDER — Voime

README USER CORE

根 PROVIDER 定义产品与外部世界之间的下边界：平台宿主、音频设备、推理运行时与模型目录。 具体消费的 API、消息和张量契约由各组件的 PROVIDER 定义；本文只做边界映射与全局约束。

1. TERMS

↑

术语定义
外部 provider Voime 不能拥有、只能消费的下层系统：桌面输入框架 / OS 输入栈、音频设备与驱动、ONNX Runtime、llama.cpp、模型文件、终端。
平台宿主 为前端提供键盘、焦点与提交路径的系统组件。Linux 上是 Fcitx5；Windows 上是 Win32 / UIA 或 TSF。
音频栈 从麦克风到 cpal 的整条采集链路；Voime 只消费设备枚举、默认配置与 PCM 回调。
CPU ORT 核心安装内的 ONNX Runtime CPU Execution Provider；只执行 FireRedVAD 与 SenseVoice。
FireRed ORT GPU FireRed worker 使用的 ONNX Runtime GPU Execution Provider：Linux NVIDIA 为 CUDA，Linux AMD 为 MIGraphX，Windows 为 CUDA / DirectML。
Qwen llama.cpp / Vulkan Qwen worker 使用的 llama.cpp / GGML runtime；AMD Linux 固定 Vulkan，不安装 ROCm / HIP。
模型目录 ~/.local/share/voime/models/<model>/ 的一模型一目录；每个目录自包含 manifest.json、权重与辅助文件，运行期只读。
本地端点 daemon 与客户端之间的本机传输端点：Linux Unix domain socket，Windows named pipe。
隐私边界 音频、按键与识别文本只在本机内存与本地端点之间流动，不落盘、不出网。

2. CONVENTIONS

↑

约定内容
本地性运行期所有 provider 调用在本机完成；模型、音频与 IPC 不经过网络。
核心只 CPU ORT核心安装只加载 CPU Execution Provider；核心二进制不链接、不探测 CUDA / MIGraphX / DirectML / Vulkan。
GPU runtime 隔离FireRed 的 ORT GPU 与 Qwen 的 llama.cpp 各自放在独立 worker 的 runtime 目录；不共享打包库，不写全局 LD_LIBRARY_PATH。
Qwen AMD 只 VulkanAMD Linux 的 Qwen worker 只接受 Vulkan；不构建、不安装、不探测 ROCm / HIP。
模型不可变模型目录运行期只读；启动时校验 manifest、SHA-256 与文件大小，失败不进入运行态。
模型布局一模型一目录；目录名是稳定标识，版本写在 manifest.json，不把版本号拼进目录名。
运行期不联网不下载、不转换、不量化、不改写模型；这些只发生在安装脚本与发布流程。
下载失败安装脚本非零退出并清理临时目录；不写 manifest、不做 rename，不留下半成品模型目录。
OS API 收敛OS 输入、传输与权限 API 只出现在 voime-transport 与平台前端；核心、协议、daemon 与 worker 业务代码不直接调用。
键盘最小化Fcitx 持有键盘；Windows 前端只监听配置热键，不记录、不转发普通按键。
音频不落盘设备 PCM 只在内存中重采样、分段、预览与推理；不写文件、不做网络上传。
错误映射Provider 错误在边界处转换为项目错误类型并附上下文；核心模型失败阻止核心进入运行态，GPU 模型 / runtime 失败只标记对应后端不可用。
版本契约Provider 版本要求写在各组件 PROVIDER；实现只消费已声明的子集，不依赖未记录行为。

3. DIAGRAMS

↑

3.1 Provider 边界

  • Voime 作为单一参与者；内部组件不展开。
  • 平台宿主、音频栈、CPU ORT、FireRed ORT GPU、Qwen llama.cpp 与模型目录是外部 provider；本地端点是 daemon 与客户端之间的传输 provider。
  • 每条边的消费 API 由对应组件 PROVIDER 定义；GPU runtime 只由对应 worker 消费。

3.2 模型加载与推理边界

  • 核心启动时读取并校验 firered-vad / sensevoice-small，创建 CPU 会话；每个语音段只重置解码状态，不重新加载权重。
  • FireRed worker 启动时校验 fireredasr2-aed / fireredpunc，创建 ORT GPU 会话。
  • Qwen worker 启动时校验 qwen3-asr-1.7b，加载 BF16 GGUF 主模型与 BF16 mmproj；能力自检失败只使该后端不可用。
  • 具体张量名、形状、CMVN 与 fbank 参数见 voime-core PROVIDER §4.2、voime-gpu-firered PROVIDER §4.1 与 voime-gpu-qwen3 PROVIDER §4.1。

4.3 Provider 失败策略

失败阶段行为
没有输入设备 / 设备名不存在核心启动daemon 启动失败，stderr + 非零退出；doctor 显示原因。
音频流错误运行丢弃当前段；连续失败达到阈值后 daemon 退出。
核心模型缺失 / SHA 不匹配 / schema 不符核心启动daemon 启动失败；不进入 TUI / runtime。
核心模型推理失败运行丢弃当前段并继续监听；错误进入日志 / IPC Error。
GPU 模型 / runtime 缺失启动对应后端标记为不可用；daemon 以 CPU Final 启动，doctor 报原因。
GPU 设备不可用 / BF16 不支持启动不启动 worker；对应后端不可用；Final 回退 CPU SenseVoice。
GPU 推理失败 / 超时 / 崩溃运行当前段回退 CPU SenseVoice；按崩溃路径重启 worker，连续失败标记不可用。
worker 协议版本不匹配启动拒绝 worker；后端不可用；提示重装 GPU 模块。
模型下载失败安装安装脚本非零退出并清理临时目录；不留下半成品目录。
端点被占用 / 无法绑定启动已有 daemon 时幂等退出；其他绑定错误启动失败。
平台宿主不可用运行前端放行热键、清空临时文本；不影响普通输入。
TSF 注册 / 编辑会话失败运行不提交；保留 daemon 历史；前端记录平台错误。
  • 各 provider 的具体错误码与建议动作见对应组件 PROVIDER。
  • 任何失败都不得把文本注入到非目标窗口。
  • GPU 失败只影响 Final 路径；VAD 与 Preview 始终由核心提供。
